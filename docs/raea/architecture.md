# RAEA 与北冥：源码对照

研究日期：2026-11-06（Asia/Shanghai）。主流程运行版本为 canary.2（主流程实测）；RAEA 本地源码快照为 fb3f70844e03cc40185e3a06c394060d26c5cd38；北冥快照为 a65c172246d04351e3e380f2d5925d2a6ff1950a。以下行号对应这两个本地快照。

本报告沿编译入口、JS 宿主、React 提交、页面布局、场景转换、渲染调度、GPU 合成、读回和编码链路核对实际类型、函数与调用者。核心分析覆盖 core、gpu、io、runtime、engine、systems；SDK 和角色接口的补充见 [集成指引](integration.md)。没有逐行审计所有第三方代码，也未运行每项公开功能。

证据分为源码落实、实跑验证、待验证。后续实跑已完成：Mac/Windows toon fixture，以及 RTX 5090 上 240 帧原生 10 秒实验。最终编码、响度和限制见 [实测记录](experiment.md)。本报告中“未测试”仅指该项能力，不表示实验整体仍未完成。

所有源码链接固定到研究时的提交，避免后续更新使行号漂移。本文是原创源码分析，不包含上游运行时副本。

**最重要的结论是：两者的抽象层级不同，RAEA 不能直接替代北冥的美术管线。** RAEA 是带嵌入式 JS、React→ECS 桥、原生页面渲染和 Bevy 3D 的综合运行时；北冥是浏览器中明确编排的 Three.js 风格化影片管线。RAEA 已落实的 GPU 合成和平台编码接口具有不同的数据流优势；北冥已有的 ID 墨线、Kuwahara、纸纹和显示层顺序，则是 RAEA 内置 toon 并不等价覆盖的具体视觉算法。

## README 的承诺需要按层解读

| 声明 | 源码核对 | 仍不能由源码确认 |

## 从 TSX 到画面，RAEA 的主链路可分成以下实际步骤

~~~mermaid
flowchart TD
  A[TSX / TS] --> B[Rolldown 打包 JS 与 CSS]
  B --> C[JSC 或 QuickJS / CPU]
  C --> D[React 提交 JSON / 通道]
  D --> E[React 节点 ECS]
  E --> F[Blitz DOM / 样式与布局]
  F --> G[Vello 页面纹理]
  E --> H[Node3 / Program / FrameRows]
  H --> I[Bevy 场景系统与渲染]
  I --> J[3D 目标纹理]
  G --> K[共享设备上的 fed 合成]
  J --> K
  K --> L[GPU RGBA8 转 NV12 或 P010]
  L --> M[映射读回 / Vec 字节]
  M --> N[Apple / soft / av1 / FFmpeg 编码后端]
~~~

这个图描述已追踪的离线 React + 页面/3D fed 路径；HTML、单张 PNG、旧 engine 输出及 live 路径有不同分支，不是所有入口都必经每个节点。

1. **打包不是把任意 JavaScript 编译成 GPU shader。** engine/bundle 用 Rolldown 生成 IIFE，配置 Browser platform、production 和 JSX automatic；CSS 由内部插件处理。runtime/bundle 另有 live/game 的 lite 编译选择，普通 render 保留 React。GPU K 是另一门受限的小型整数 DSL，有自身解释器和 WGSL 生成器。证据：[RAEA · engine/bundle/src/lib.rs:49](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/bundle/src/lib.rs#L49)、[RAEA · engine/bundle/src/lib.rs:86](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/bundle/src/lib.rs#L86)、[RAEA · runtime/bundle/src/lib.rs:118](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/bundle/src/lib.rs#L118)、[RAEA · core/k/src/lib.rs:1](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/core/k/src/lib.rs#L1)、[RAEA · systems/k/src/wgsl.rs:31](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/systems/k/src/wgsl.rs#L31)。
2. **JS 确实在宿主线程执行。** js_thread 启动默认引擎，注册 __raea_flush、__raea_log、__raea_now，执行 prelude、native 安装和 bundle。Apple 默认 JSC，portable/其他平台默认 QuickJS；显式选择未编入的引擎返回错误，不悄悄切换。证据：[RAEA · runtime/react/src/thread.rs:38](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/react/src/thread.rs#L38)、[RAEA · runtime/jsengine/src/lib.rs:125](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/jsengine/src/lib.rs#L125)。
3. **React 是描述与提交层。** flush 把批次送到 Rust 通道，apply_commits 创建/更新 ReactNode、ReactKind、ReactProps、文本和父子关系；ReactPlugin 在 PreUpdate 应用这些提交。之后再由 page 的遍历和 scene 的转换消费这些实体。不是 React 在 GPU 上执行，也不是每个 JSX 节点直接就是 Bevy PBR mesh。证据：[RAEA · runtime/react/src/thread.rs:7](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/react/src/thread.rs#L7)、[RAEA · runtime/react/src/commits.rs:81](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/react/src/commits.rs#L81)、[RAEA · runtime/react/src/lib.rs:110](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/react/src/lib.rs#L110)、[RAEA · runtime/page/src/bevy_page.rs:64](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/page/src/bevy_page.rs#L64)、[RAEA · runtime/scene/src/lib.rs:331](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/scene/src/lib.rs#L331)。
4. **原生调用与世界数据有真实桥接。** __raea_call 的注册表连接 Rust 功能；runtime/shared 对 world.watch/world.write 等排队，在 PreUpdate 写入，在 Last 推送变化；存在 React App 与渲染 Engine App 的分流，不能简单理解为所有状态都在同一个 World。反射类型、队列和可用注册决定可调用范围。证据：[RAEA · engine/native/src/lib.rs:31](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/native/src/lib.rs#L31)、[RAEA · engine/native/src/lib.rs:49](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/native/src/lib.rs#L49)、[RAEA · runtime/shared/src/lib.rs:56](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/shared/src/lib.rs#L56)、[RAEA · runtime/shared/src/lib.rs:222](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/shared/src/lib.rs#L222)、[RAEA · runtime/shared/src/lib.rs:226](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/runtime/shared/src/lib.rs#L226)。
5. **“能用 npm/浏览器代码”有宿主边界。** web shims 和 Node builtins 是仓库实现的适配，不能自动等同完整 Chromium 或完整 Node；调用允许列表本身也有宿主配置差异，ALLOW 为 None 时表示全放行。证据：[RAEA · engine/native/src/lib.rs:17](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/native/src/lib.rs#L17)、[RAEA · engine/native/src/lib.rs:31](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/native/src/lib.rs#L31)、[RAEA · engine/native/src/node.rs:17](https://github.com/shinyobjectz/raea/blob/fb3f70844e03cc40185e3a06c394060d26c5cd38/engine/native/src/node.rs#L17)。这里仅说明架构边界，没有进行安全审计。
