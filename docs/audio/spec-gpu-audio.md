## 1. 问题定义与教训

新架构必须正面解决北冥实测踩实的四条硬坑，不能换汤不换药。〔v1.0〕

1. **教训 A · 纯手工公式合成过不了写实听感（《鲤鱼跃龙门》剪纸翻车复盘）**：用 `modal_impact('metal_plate')` 加 15 ms 白噪凑「剪子剪宣纸」，人耳一秒听出是「敲铁板 + 鼠标微动」而非「双刃行进剪切纸纤维」。上游 earshot 项目在自己的验证文档里实证了同一结论：纯公式日常拟音盲听 0/24。
2. **教训 B · 手写混音曲线与死板门禁极易伤音乐或漏遮蔽**：《鲤鱼跃龙门》v1 里 12 剪特写误挂背景 foley 母线，电平比同期琵琶低 8.0 ~ 14.5 dB 却漏过旧门禁；为凑静音死规则又曾逐段变速（把乐队拉跑调 71 cents）并在 160 ms 内把音乐硬掐到 -240 dBFS（听感像断电）。
3. **教训 C · 脱离画面的纯音频分类器当不了闸门**（2026-11-12 远端工作站 vmax 第一轮域内实测）：75 个真实 CC0 样本上，纯音频分类器借公开集阈值表现差：paper 0/2、twig_snap 0/2，钟碗误报人声，通过耳检的衣料 robe1 误报机械，93 s 成片期望标签召回仅 0.19。根因：不看画面运动孤立猜声音；只算正类绝对分，没算「目标机制 vs 难负例」的对比边际。
4. **教训 D · 仓库与 CI 是无 GPU 轻量环境**：主仓 `.venv` 不装 `torch`，GitHub Actions 的冒烟任务限时约一分钟，绝不能强拉数 GB 的 CUDA PyTorch。GPU 能力必须走独立隔离环境或原生内核，缺 GPU 时退回 CPU 或报标准退出码 3。

对应的解法分层：教训 A 由 L1（ERB 分析再合成）与 L2（按需生成补库，待过 0C）解决；教训 B 现仍沿用 `director.py`、`editorial.py` 与 `qa.py --strict-masking` 守门（L4 0A 掩蔽自动避让已因超时与真峰值抬升判 `No-Go` 砍掉，§4.2）；教训 C 由 L3 纯 CPU 物理取证（B1/B3/B4 + 不可翻转）与运动学同步核解决（CLAP2-L 与 B2 已按 0B 实测及 Item 24 裁定砍掉，§4.3）；教训 D 是全部层级的部署红线（§2.3）。

## 3. 主人既定原则（不可违背）

**判断与护栏原则**〔v1.0〕：

1. **判断模型免训练**：不微调、不更新预训练大模型权重；判别层只做免训练特征提取加北冥域样本标定的逐类阈值。
2. **复核大模型只有「降级标存疑权」**：多模态大模型只能把通过项降级标为 `suspect` 送人审，不能把硬物理 / 掩蔽门禁判挂的项翻转为通过。
3. **护栏必须强制行为**：只打日志不阻断、不修偏的指标不算有效改进；规则化必须同时验证「能抓住原失败」且「不误伤合法留白（如『间』挂留呼吸）」。

**主人已确认事项**（原话存档，可写成定案）：

5. **2026-11-21 · 修法纪律**：不要靠剪辑修合成缺陷，要从根上修。原话「不要靠剪辑，要从根本上修，既然选择这个方式，就做彻底」。

## 4. 分层规格

四层沿用 v1.0 的编号。层级与依赖：L1 声源合成与 L2 声源铸造厂是「声音从哪来」，L4 混音与 L3 裁判是「声音怎么合、怎么判」。推进顺序按主人确认的 L1 收尾 → L4 → L3 → L2（§5）。

### 4.1 L1 声源合成：96 带 ERB 复基带分析-再合成（已建成，收尾进行中）

大白话原理：从一段声音（真录音、程序化合成器的输出、文生音效模型的输出都行）里学出一个**不含原始波形**的「这台机器怎么发声」模型，之后再按新种子合成「同一件东西的另一下」：起音一样脆，细节是新抽的，连敲时每下都不一样。〔仓库〕

**现状**：已合入 `main`（`engine/audio/erb/`，含 CPU 参考实现 `core.py`、CUDA / cuFFT 内核 `erb_cuda.cu` + `gpu.py`、命令行 `npm run audio:erb`、测试 20 项；环境变量 `BEIMING_NVCC`、`BEIMING_ERB_CACHE` 已登记 `tools/env/spec.json` 与 `docs/ENVIRONMENT.md`）。〔仓库〕

**设计要点**：

- **起音因果约束（根上修，不拼接）**：对每个「先静后响」的起音，分析时存低 / 中 / 高（解析包络）加全带（实信号 RMS）的前 30 ms / 后 40 ms 轮廓（约 1700 个 dB 数，不含波形），合成时放进交替投影做时域约束。曾经试过把原录音的起音那截直接盖到合成版上（拼接），被主人否掉并删除，不得加回。〔原型实测；主人已确认 2026-11-21〕
- **vary（变体差异）按真实 take 校准**：从 18 条录音里同一段内连续的 417 对真实 take 量得每次真实差异的量级（响度差 4.1 dB、音色差 5.4 dB、时长差 42% 等），现在 `vary=1` 约等于这个量级；钟 / 铜 / 锣这类纯音占比高的不动音高。〔原型实测〕
- **连敲从几下里学变化**：`analyze_takes` / `render_takes` 从同一动作至少 2 ~ 3 下（建议不少于 3 下）分别学「咔」与声身的频谱协方差，生成时轮流借某一下的时间骨架，叠加单份瑞利细节重抽；来源选最有代表性的一下（medoid），不能取第一下（曾因取到最闷的一下出错过题）。〔原型实测〕
- **整条颗粒约束（GRAIN）**：低 / 中 / 高三段 1 ~ 1.5 ms 细包络的起伏放进交替投影与重抽噪声，权重按原录音局部峭度门控（风、锣权重 0 不误伤；布料、慢剪、火把全开），把再合成普遍砍半的细碎爆裂「尖」托回来（布料波峰差 -4.12 → -1.22 dB）。〔原型实测〕
- **CPU / GPU 同一份模型**：`core.plan()` 只预抽规划段的随机数并带上 RNG 状态，CPU 与 GPU 执行同一份规划；默认（`host_noise=False`）GPU 的纹理重抽白噪与噪声载波由设备端 Philox 生成（种子取自 `plan.rng`），与 CPU 不是同一组随机数、逐采样对不上，只保证同一份规划在同一设备路径重跑逐比特相同；`vary > 0` 且没给 `eq_db` 时，GPU 为让整批共用一个 `m_base` 会把 FFT 点数定在抖动上界，FFT 点数也与 CPU 不同，所以不承诺跨路径逐采样一致（见 `engine/audio/erb/README.md`「随机数与可复现」）；GPU 内核 nvcc 现场编译并按「源码 + nvcc 版本 + GPU 型号」哈希缓存；同模型同 FFT 点数的 take 整批上 GPU，显存不够自动折半分块。〔仓库〕

| 速度（exact=8、vary=1） | 单条 5.6 ~ 54 ms（CPU 86 ~ 1726 ms）；64 条整批 0.14 ~ 3.3 s，约为 CPU 的 30 ~ 43 倍 |
| 显存边界（5.0 GB 空闲） | 单声道最长实测 100 s（663 ms）；120 s 真显存不足后恢复且 `auto` 退回 CPU |

**听感结论**：原型阶段共四轮试听（2026-11-21 至 11-22）。第 1 轮暴露起音根因（零相位子带滤波把起音往前抹开），根因修复后第 2 轮真假辨别已是瞎猜水平；变形对比中时长拉伸稳赢；连敲对「同几下轮播加随机变调」的传统做法 5/5 胜出。2026-11-22 主人（专业录音师）表示基本听不出差别，**听感关通过**，第 5 轮盲听与两项改进（节奏学习、窄低频带不重抽）暂缓记为已知短板。〔原型实测；主人已确认 2026-11-22〕

**已知短板**（不阻塞收尾，逐条记录在案）：〔原型实测〕

- 纹理类（风、水，无起音）没有起音约束；非「先静后响」的后续起音（堂鼓后几下）不闸不塑形。
- 连敲的节奏层面内部小咔嗒时刻重复（借骨架所致；快门对真实连敲累计 0/4），且低频偏薄（快门 < 200 Hz 能量占比比真实低约 1 ~ 3 dB）。
- 模型约为原 WAV 的 24 倍，所以只存 WAV、现场分析；命令行输入不超过 60 s（这是做音效的，不是做长片的）。〔仓库〕
- 无限环境床的缝合（quilt）是简化版；水滴音头仍偏软约 4 dB（度量噪声为主）。

**未达成的目标**：原型阶段定的「批量 64 条 < 100 ms」未达成（实测整批 0.14 ~ 3.3 s；分项计时分布很平，最大内核只占 11%，瓶颈是时域约束里的双精度超越函数，要再提速得重排那几个内核）。〔原型实测〕是否继续追这个数，见 §7。

**验收线（按 ERB 路线重写，替代 v1.0 面向可微拟合的那套数字）**：

1. **听感**：主人的耳朵是最终关；机器指标全部只做必要条件，与耳朵冲突时不当反驳依据。〔主人已确认 2026-11-22〕
2. **确定性**：同一份规划在同一设备路径重跑逐比特相同；「GPU 对 CPU 逐波形信噪比 ≥ 101 dB」只指 `host_noise=True`（主机抽好随机数再上传）的专用对拍配置，默认设备端随机数路径不适用；默认路径改看统计口径，即设备端随机数对 CPU 无系统偏移；compute-sanitizer 零错误。〔仓库，均已达成〕
3. **根上修**：合成缺陷在模型或约束里修，输出不拼原采样；报指标时区分「约束本身保证的」与「没被约束的独立指标」。〔主人已确认 2026-11-21〕
4. **实片验收**（进行中项）：接入作品拟音链路后，全片过 `npm run audio:qa` 与 `npm run audio:cuecheck`，再由主人全速带声看片认可；沿用仓库既有闸门（`docs/quality/QA-GATE.md`），本规格不另立标准。

**进行中**：接入拟音链路（入口 `erb.render_many` 与 `npm run audio:erb`，尚未接进任何作品的 sound / foley 脚本）＋ 未入库试制片《鲤鱼跃龙门》（papercut）实片验证 ＋ 落库遗留文件（本规格书入库属于此项）。〔主人已确认 2026-11-22〕

### 4.2 L4 混音：LR4 分频 + Zwicker 掩蔽自动避让（0A `No-Go` → 主人裁定砍掉）

**v1.0 方案为什么被否**〔评估〕：v1.0 的端到端梯度混音（把增益矩阵乘在 STFT 复频谱上、40 ~ 60 步 Adam 反传全片波形）有三处硬伤：一是预振铃，临界频带的低频分辨率要求约 2048 ~ 4096 样本窗（42 ~ 85 ms），快速变化的增益直接乘 STFT 再重建，会让琵琶、打击乐的瞬态前缘提前 20 ~ 40 ms 发糊；二是立体声塌缩，左右独立算增益会撕裂声像；三是杀鸡用牛刀，分轨已知时每帧每个临界频带让多少 dB 是功率域里的一个小规模带约束问题（20 s 音频在 10 ms × 12 频带下只是约 2000 × 12 的小矩阵），不需要对约 96 万样本的波形做 60 轮反向传播。

**0A 替代设计及 No-Go 结论（已砍掉，未合入主干）**〔评估；0A 实测；主人已确认 2026-11-23〕：

- 原拟方案：12 段 Linkwitz-Riley 四阶分频（加兄弟子树全通相位补偿）+ `< 300 Hz` 硬锁 0 dB + 10 ms 控制面 Zwicker 向上掩蔽求解 + 干声差量路径，以及待定的运动学早期反射。
- **0A 实测未过线根因**：20 s 混音纯 CPU 稳态中位耗时 **`1745.52 ms`**（冷启动 `3143.85 ms`），超 `< 300 ms` 门限 5.8 倍；且因 12 路全通相位补偿与干声差量路径不同相，动态瞬态峰值抬升 `+2.68 dB`，触发 `audio.truepeak = -0.89 dBTP`（QA `exit 4` 硬失败），同时整机传递函数因全通补偿不再满足字面最小相位。
- **处置结果**：按 spec「0A 不过线当场砍掉，不带病进工程化」，主人裁定砍掉掩蔽自动避让；现有工程继续沿用 `engine/audio/director.py`、`editorial.py` 与 `qa.py --strict-masking` 组合。详细 0A 实测数字见 §6.2。

### 4.3 L3 裁判：纯 CPU 物理取证（B1/B3/B4 + 不可翻转）加运动学同步核（已落地开 PR）

**被砍项与原因**〔0B 实测；主人已确认 2026-11-23〕：

- **CLAP2-L 对比边际头（已砍）**：0B 在无泄漏 `s75` 去偏 + 严格 LOO 下实测，75 样本 21 类 top-1 为 `44/75`、`cloth` `6/6`（`robe1 +6.65`）零机械误报，但 **`papercut_v4` 真剪纸 `0/16`、`curated20` `0/20`、`twig_snap vs mech4` `0/2`、`paper vs mech4` `1/2`**。诊断 `raw_freesound_long` 长录正边际达 `11/12`（中位 `+9.68`），锁定根因是 NaFlex（160 ms/token、训练桶 6.9–30.1 s）在 29–192 ms 单剪瞬态上结构性失效。按 0B Go/No-Go 规则及主人 Item 24 裁定当场砍掉，零 `torch` / `open_clip_torch` 依赖引入主仓。
- **B2 倒谱梳状金属振铃（已砍）**：0B 实测在 `cc0_75` 上误伤真实木鱼/梆子/板鼓/堂鼓等谐振腔体 **`10/75`（`13.3%`）**；而需要拦截的程序化敲铁板 `v1_recon`（`modal_impact("metal_plate")`）呈非谐模态分布（`f_n ∝ n²`），`B2` 检出为 **`0/16`**（该类失真实际由 `B4` 16/16 精准拦截）。主人 Item 24 裁定不合入通用硬门。
- **Synchformer / Qwen2.5-Omni（延续延后）**：前者 200 ms 离散分辨率远粗于 1 ~ 2 帧（42 ~ 83 ms）同步门槛，后者仅可作后续离线降级参考。

**已落地纯 CPU 版 L3 架构（零新依赖）**〔仓库；0B 实测；本分支实测〕：

1. **模块 B · 纯 CPU 物理取证增强与不可翻转状态机（`engine/audio/sfx_judge.py`）**：
   - **`B1` `detect_digital_click`（二阶差分内部数字咔嗒）**：对局部极大 `|d2[i]|` 计算排除中心 `[i-4..i+4]` 后的 `±3 ms` 环形邻域 RMS + 活动区 P90 地板稳健尺度（立体声逐声道取最差），超过 `ratio_thr = 18.0` 判硬拒。
   - **`B3` `detect_nyquist_alias`（奈奎斯特镜像折叠混叠）**：活动帧 Welch 功率谱经 `1500 Hz` 滑窗平坦化后，对折返轴 `(sr/6, sr/4, sr/3, 8k, 11.025k, 12k, 16k)` 做镜像相关（门限 `corr_thr = 0.55` 且折叠带能量 `≥ -45 dB`，并要求折叠带谱峰占空比 `≥ 8%` 以豁免少数孤立对称纯正弦和弦）。
   - **`B4` `measure_deenv_kurtosis`（2–8 kHz 去包络峭度）**：仅在活动样本（`env_s ≥ 15%` 峰值）计算 2–8 kHz 带通信号除 8 ms 包络后的峰度（高斯 = 3），吸收 0B 边界结论分为三档：`< 2.9` 或 `> 45.0` 判 **`reject`**、`[2.9, 3.2)` 判 **`suspect`**、`[3.2, 45.0]` 判 **`pass`**；**保留原型门控**（仅启用 `B4_ACTIVE_ARCHETYPES = ('foley_snap', 'friction_cloth', 'impact', 'wood')`，当清单显式 `lp < 4000 Hz` 时亦自动豁免）。
   - **不可翻转契约状态机 `combine_physics_gate`**：`judge_wave` 返回 `physics_hard_fail`、`flippable`、`forensics`；任何物理硬挂（`status == 'reject'` / `physics_hard_fail == True`）在状态机上锁定 `flippable = False`，任何上层评分或大模型只能降级标 `suspect`，绝对不可将物理拒收翻转为通过。
2. **模块 C · 纯 CPU 运动学对冲击同步核（`engine/audio/sync_kernel.py` + `qa.py` + `tools/audio/qa.mjs`）**：
   - **视觉主路径与退化链**：`kinematics.json` 角色加速度突峰 `actor`（`(|Δ²x| + |Δ²y| + 0.5·|Δ²scale|)·visible`）→ 自动退化 `screen.motion` → 无遥测时经 `ffmpeg` 管道流式解灰度缩略帧算一阶帧差 `d1` / 正部二阶差分 `d2+`（缺 `ffmpeg` 时抛出 `FfmpegUnavailableError`，CLI 返回标准 `EXIT.ENV = 3`）。
   - **音频侧**：6 对数频带 `Onset Flux`（`stft(..., boundary='zeros', padded=True)` + 相对噪声地板 `log1p` + 居中帧格平均池化），归一化互相关加抛物线亚帧内插。
   - **一拍二（12 fps）抗 12 Hz 守卫**：内置 `detect_actor_on_twos` 与 `apply_on_twos_guard`（零相移对称核 `[0.25, 0.5, 0.25]`），消除重复帧 12 Hz 零值梳状伪峰；支持 `--sync-fps-mode auto|24fps|12fps`。
   - **CLI 与 QA 集成**：独立入口 `python -m engine.audio.sync_kernel --audio <wav> (--kinematics <json> | --video <mp4>)`；集成进 `npm run audio:qa` / `python -m engine.audio.qa`（新增可选参数 `--kinematics`、`--video`、`--sync-stem`、`--sync-path`、`--sync-fps-mode`、`--sync-warn-frames`、`--sync-fail-frames`，产出 `audio.sync` 检查项；未传视频或遥测参数时 `audio:qa` 行为与退出码保持完全不变）。

**已知边界（必须如实声明）**〔0B 实测；本分支实测〕：

1. **`B3` 与 `bandwidth_95_hz` 互补**：`B3` 专抓无抗混叠（ZOH / 线性插值）产生的镜像折叠；若素材先经严格多相抗镜像低通再劣质升频（无镜像折返），仍依赖现有 `bandwidth_95_hz` 拦截，二者互补不相互替代。
2. **`B4` 原型门控与 `2.9–3.2` `suspect` 软边界**：`B4` 仅对 `foley_snap`、`friction_cloth`、`impact`、`wood` 四类原型启用（豁免乐音/环境/留白）；长剪辑慢变包络高斯噪声与个别真剪纸（如 `v4` `snip_q_2 = 2.934`、`cc0_75` `wood1 = 2.981`）贴近 `3.0`，因此将 `[2.9, 3.2)` 设为 `suspect` 送耳审，仅严格 `< 2.9` 或 `> 45.0` 才硬拒绝。
3. **一拍二（12 fps）半帧相移与门限口径**：一拍二零阶保持存在约 `-0.5 ~ -0.8f` 固有相移，偶相 `+2f` 漂移估算约 `+1.15 ~ +1.40f`。因此 24 fps 默认告警与硬门限均为 `1.5f`；12 fps 启用更紧的 **`1.1f`**（工程建议 `1.1–1.2f`）告警门限与 `1.5f` 硬门限并在输出中显式标注。
4. **全混音叠加一拍二偶相伪峰提示**：全混音（含强周期配乐节拍）叠加 12 fps 偶相极限工况下在 `+4f` 可出现周期配乐对齐伪峰（实测 `0f` 口径偏移导致 `max|err| = 3.993f`）；系统优先选用 `stems/sfx.wav`（或 `fx.wav`），当退回全混音且处于 `12fps` 时在报告 `warnings` 显式告警提醒优先用 `sfx` 分轨或 24 fps 遥测复核。
5. **物理硬门不可翻转铁律**：`sfx_judge` 判定 `reject`（含削波、B1、B3、B4 硬挂等）时 `flippable=False`，上层评分或复核模型无权翻转（§3 原则 2）。

### 4.4 L2 声源铸造厂：按需加载的生成补库（0C 已过、主人已批准，按需子进程服务已落地开 PR）

**定位变化**：v1.0 设想在 5090 上常驻推理服务；评估实测 5090 当日仅余约 5.3 GB 显存（§2.1），改为**单次按需拉起、空闲自动卸载（约 5 分钟）加本地 SHA256 缓存（48 kHz / 24 bit）**，绝不与既有进程抢常驻显存。〔评估〕

**EzAudio-XL 被否及原因**〔评估〕：代码与权重虽为 MIT，但 `sample_rate = 24000`、单声道，奈奎斯特硬截断在 12 kHz；实测北冥 20 条剪纸切片的 95% 能量带宽中位数 14,181 Hz（最高 18,853 Hz），一半样本的 > 12 kHz 能量占比 ≥ 10%，快剪切片高达 34.2% ~ 73.2%。12 kHz 一刀切死，刀剑、剪纸、玉牌、水沫的空气感与脆裂细节全没了。

**候选 `MOSS-SoundEffect-v2.0`**〔评估〕：Apache-2.0；输出采样率 48 kHz（DAC VAE），奈奎斯特上限 24 kHz；有效带宽与高频真实性待 0C 对生成结果实测；1.3B DiT 加 Flow Matching，Qwen3-1.7B 中英双语文本编码器（对中国传统器物的中文提示词友好），最长 30 s；全权重 11.23 GB，BF16 推理约 8 ~ 10 GB 显存（5090 按需拉起可承接）。已知风险必须先实测证伪：官方默认 100 步推理可能慢，需测 25 / 50 / 100 步的质量与耗时曲线、底噪水平与短促单点拟音能力。

**0C 实验与立项**〔评估〕：在 5090 上测北冥最缺的 6 类中国器物干声（宣纸裁切、宣纸折叠、青铜编钟、硬木榫卯落锁、丝绸衣袂、竹林水花）各 4 条。过线线：实测 95% 能量带宽 > 12 kHz；`sfx_judge` 物理取证通过率 ≥ 50%；主人亲耳验收 ≥ 4/6 类达标。**不过线就放弃自建拟音大模型**，继续走「CC0 加商用干声切片加物理壳混合」，把 L2 记为 No-Go 归档。

**0C 结果与立项**〔0C 实测〕〔主人已确认 2026-11-23：批准建 L2〕：实测数据见 §6.4。95% 能量带宽 > 12 kHz 在 24 条里 21 条达标；L3 `sfx_judge` 严格通过 11/24、通过加存疑 21/24；峰值显存 15.4 GiB；进程内卸载后仍残留约 1 GiB CUDA 上下文；同参数跨会话输出不逐字节相同。

**工程落地：按需子进程服务**〔本分支〕：实现在 `engine/audio/foundry.py`（主控，不 import torch）、`foundry_worker.py`（推理子进程，只在隔离 venv 里跑）、命令 `npm run audio:foundry`（`gen` 批处理 / `serve` 常驻调度 / `probe` 只查守门）。
- **显存守门 fail-closed**：拉起前 `nvidia-smi`（`--ssh` 时经 ssh）查空闲显存，低于 `--min-free-gib`（默认 18）退出 5，查不到退出 3，只有明确 `--skip-vram-check` 才跳过。
- **用「子进程退出」卸载**：进程内卸载会残留约 1 GiB，所以 `gen` 跑完本批就退出推理子进程，`serve` 的轻量调度器空闲 `--idle-timeout`（默认 300 s）后结束子进程并 `wait()` 回收，收到 `shutdown` 或信号同样清理；再来请求重新过守门再拉起。
- **SHA256 缓存存产物**：键是规范化请求（模型标识与版本、prompt、negative_prompt、duration、steps、cfg、sigma_shift、seed）的 SHA256；存 48 kHz / 24 bit 单声道 WAV 加旁路 JSON（请求、模型指纹、生成耗时、L3 verdict 与指标、许可证）。写入是进程唯一临时文件加 `os.replace` 的原子提交，读取校验 WAV 与 JSON，损坏或含 NaN/Inf 按未命中重生成；命中不拉起子进程。因为跨会话不逐字节相同，缓存复用的是第一次的产物，不是靠种子重算。
- **L3 取证接入**：新产物过 `sfx_judge`，verdict（pass / suspect / reject）与指标写进 JSON；默认只标注、照常落盘，`--strict` 只收 pass，其余整批退出 4。不做强制动态处理、不截断，仅在峰值超过 0.999 满幅时线性衰减防截顶并记录衰减量。
- **远端 `--ssh`**：免密 ssh 到 `rog-5090` 这类主机，主机名白名单、不以 `-` 开头、用 `--` 分隔、列表形式启动、不经本机 shell；worker 源码经 `python -I -c` 送过去，WAV 经协议回传，远端不需要本仓库。

**高频超分（BWE）兜底**：`FlashSR` / `NovaSR`（均 Apache-2.0）只作老旧 16 kHz 存量素材的急救工具，不作主力链路补丁（这类超分主要面向语音谐波，对非周期脆裂高频容易脑补出伪嘶声）。〔评估〕

**与 L1 的衔接**：铸造厂输出的干声与 CC0 实录音效同级，都是 ERB 再合成的合格输入（ERB 输入不必是真录音：程序化合成器输出已实测跑通，木 / 铜 / 瓷 / 竹四种材质起音前 +0.0 ~ +0.1 dB、频谱误差 0.04 ~ 1.2 dB）。〔原型实测〕

### 6.2 L4 掩蔽自动避让（0A `No-Go` 已砍）

- **环境声明**〔0A 实测〕：Intel Core i9-14900HX（CPU scaling 49%，机器含其它后台负载，非独占；Python 3.12.14 / NumPy 2.5.4 / SciPy 1.18.1，`torch: None`），输入《鲤鱼跃龙门》v4 composed + Suno cover 真实分轨（48 kHz/2ch/PCM24，19.500 s + 0.5 s 静音凑 20.0 s，22 条前景事件）。
- **0A 实测数字**〔0A 实测〕：
  - **20 s 混音纯 CPU 耗时（不过）**：冷启动 `3143.85 ms`；稳态 12 轮中位 **`1745.52 ms`**（min `1551.37` / max `2573.24` ms），约为 `< 300 ms` 门限的 5.82 倍；瓶颈在 Python/NumPy 逐样本 12 带包络与 FFT 卷积（`profile` 仅包络就占 `1.375 s`，控制面 `[T, 12]` 求解仅 `0.156 s`）。

  - **非冲突段保真（过）**：253 个 50 ms 窗最大变动 `0.00 dB`（逐样本精确 0）。
