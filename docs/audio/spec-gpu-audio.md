## 1. 问题定义与教训

新架构必须正面解决北冥实测踩实的四条硬坑，不能换汤不换药。〔v1.0〕

1. **教训 A · 纯手工公式合成过不了写实听感（《鲤鱼跃龙门》剪纸翻车复盘）**：用 `modal_impact('metal_plate')` 加 15 ms 白噪凑「剪子剪宣纸」，人耳一秒听出是「敲铁板 + 鼠标微动」而非「双刃行进剪切纸纤维」。上游 earshot 项目在自己的验证文档里实证了同一结论：纯公式日常拟音盲听 0/24。
2. **教训 B · 手写混音曲线与死板门禁极易伤音乐或漏遮蔽**：《鲤鱼跃龙门》v1 里 12 剪特写误挂背景 foley 母线，电平比同期琵琶低 8.0 ~ 14.5 dB 却漏过旧门禁；为凑静音死规则又曾逐段变速（把乐队拉跑调 71 cents）并在 160 ms 内把音乐硬掐到 -240 dBFS（听感像断电）。
3. **教训 C · 脱离画面的纯音频分类器当不了闸门**（2026-11-12 远端工作站 vmax 第一轮域内实测）：75 个真实 CC0 样本上，纯音频分类器借公开集阈值表现差：paper 0/2、twig_snap 0/2，钟碗误报人声，通过耳检的衣料 robe1 误报机械，93 s 成片期望标签召回仅 0.19。根因：不看画面运动孤立猜声音；只算正类绝对分，没算「目标机制 vs 难负例」的对比边际。
4. **教训 D · 仓库与 CI 是无 GPU 轻量环境**：主仓 `.venv` 不装 `torch`，GitHub Actions 的冒烟任务限时约一分钟，绝不能强拉数 GB 的 CUDA PyTorch。GPU 能力必须走独立隔离环境或原生内核，缺 GPU 时退回 CPU 或报标准退出码 3。

对应的解法分层：教训 A 由 L1（分析再合成）与 L2（生成补库）解决，教训 B 由 L4（掩蔽自动避让）解决，教训 C 由 L3（对比边际 + 物理取证 + 运动学同步核）解决，教训 D 是全部四层的部署红线（§2.3）。

### 2.3 部署红线（教训 D 的落地）

1. 根 `requirements.in` / `requirements.lock` 不加 `torch`；需要 GPU Python 环境时用独立 venv 并经环境变量指过去（与仓库现有 `BEIMING_PY` 契约同构）。〔v1.0，经评估确认〕
2. 前向 DSP（渲染、混音）不上 PyTorch：ERB 已走本机 nvcc 13.5 + cuFFT 的原生内核路线〔主人已确认 2026-11-21；仓库已落地〕；PyTorch 只留给需要 autograd 或模型权重的活（如 CLAP 裁判）〔主人已确认 2026-11-21〕。
3. 无 GPU 环境自动退回 CPU 或报标准退出码 3（`EXIT.ENV`）；`engine/audio/erb/` 已按此实现（`device='auto'` 自动退 CPU）〔仓库〕。
4. 远端 5090 一律按需拉起、空闲卸载，不与既有进程抢常驻显存〔评估〕。

## 3. 主人既定原则（不可违背）

**判断与护栏原则**〔v1.0〕：

1. **判断模型免训练**：不微调、不更新预训练大模型权重；判别层只做免训练特征提取加北冥域样本标定的逐类阈值。
2. **复核大模型只有「降级标存疑权」**：多模态大模型只能把通过项降级标为 `suspect` 送人审，不能把硬物理 / 掩蔽门禁判挂的项翻转为通过。
3. **护栏必须强制行为**：只打日志不阻断、不修偏的指标不算有效改进；规则化必须同时验证「能抓住原失败」且「不误伤合法留白（如『间』挂留呼吸）」。

**主人已确认事项**（原话存档，可写成定案）：

4. **2026-11-21 · 技术栈与 L1 路线**：借鉴 earshot 的再合成思路、不合并其代码，自研 96 带 ERB 分析-再合成；Python 原型先过耳，再下沉 C++ / CUDA（nvcc + cuFFT）；Rust（PyO3）只承接 CPU 串行 DSP；PyTorch 只留给需要 autograd 或模型权重的活。原话「可以，确认」。
5. **2026-11-21 · 修法纪律**：不要靠剪辑修合成缺陷，要从根上修。原话「不要靠剪辑，要从根本上修，既然选择这个方式，就做彻底」。
6. **2026-11-22 · 听感关**：听感以主人（专业录音师）的耳朵为准，他说听不出差别就算过耳，不再加盲听轮次与统计显著性检验。原话「我作为专业录音师其实基本上也听不出来差别了……先正常往下推进」。
7. **2026-11-22 · 推进顺序**：先把 ERB 接进拟音链路并实片验证、落库遗留文件，之后混音（L4）→ 裁判（L3）→ 铸造厂（L2）逐层开 PR，合并前都问主人。原话「按推荐顺序开工」。

由此派生的验收写法（全规格书通用）：听感以主人耳朵为准，不设盲听统计；机器指标只做必要条件，与耳朵冲突时只当内部自检；输出里不拼原采样；护栏要能抓到原失败且不误伤合法留白。

## 4. 分层规格

四层沿用 v1.0 的编号。层级与依赖：L1 声源合成与 L2 声源铸造厂是「声音从哪来」，L4 混音与 L3 裁判是「声音怎么合、怎么判」。推进顺序按主人确认的 L1 收尾 → L4 → L3 → L2（§5）。

### 4.1 L1 声源合成：96 带 ERB 复基带分析-再合成（已建成，收尾进行中）

大白话原理：从一段声音（真录音、程序化合成器的输出、文生音效模型的输出都行）里学出一个**不含原始波形**的「这台机器怎么发声」模型，之后再按新种子合成「同一件东西的另一下」：起音一样脆，细节是新抽的，连敲时每下都不一样。〔仓库〕

**现状**：已合入 `main`（`engine/audio/erb/`，含 CPU 参考实现 `core.py`、CUDA / cuFFT 内核 `erb_cuda.cu` + `gpu.py`、命令行 `npm run audio:erb`、测试 20 项；环境变量 `BEIMING_NVCC`、`BEIMING_ERB_CACHE` 已登记 `tools/env/spec.json` 与 `docs/ENVIRONMENT.md`）。〔仓库〕

**设计要点**：

- **起音因果约束（根上修，不拼接）**：对每个「先静后响」的起音，分析时存低 / 中 / 高（解析包络）加全带（实信号 RMS）的前 30 ms / 后 40 ms 轮廓（约 1700 个 dB 数，不含波形），合成时放进交替投影做时域约束。曾经试过把原录音的起音那截直接盖到合成版上（拼接），被主人否掉并删除，不得加回。〔原型实测；主人已确认 2026-11-21〕
- **vary（变体差异）按真实 take 校准**：从 18 条录音里同一段内连续的 417 对真实 take 量得每次真实差异的量级（响度差 4.1 dB、音色差 5.4 dB、时长差 42% 等），现在 `vary=1` 约等于这个量级；钟 / 铜 / 锣这类纯音占比高的不动音高。〔原型实测〕
- **连敲从几下里学变化**：`analyze_takes` / `render_takes` 从同一动作至少 2 ~ 3 下（建议不少于 3 下）分别学「咔」与声身的频谱协方差，生成时轮流借某一下的时间骨架，叠加单份瑞利细节重抽；来源选最有代表性的一下（medoid），不能取第一下（曾因取到最闷的一下出错过题）。〔原型实测〕
- **整条颗粒约束（GRAIN）**：低 / 中 / 高三段 1 ~ 1.5 ms 细包络的起伏放进交替投影与重抽噪声，权重按原录音局部峭度门控（风、锣权重 0 不误伤；布料、慢剪、火把全开），把再合成普遍砍半的细碎爆裂「尖」托回来（布料波峰差 -4.12 → -1.22 dB）。〔原型实测〕
- **CPU / GPU 同一份模型**：`core.plan()` 先把这一下的全部随机数抽好，CPU 与 GPU 执行同一份规划；GPU 内核 nvcc 现场编译并按「源码 + nvcc 版本 + GPU 型号」哈希缓存；同模型同 FFT 点数的 take 整批上 GPU，显存不够自动折半分块。〔仓库〕

**验证数字**（本机 RTX 4070 Laptop、CUDA 13.5，2026-11-22）：〔仓库〕

| 项目 | 结果 |
|---|---|
| GPU 对 CPU 逐波形（同一份规划、同一组主机随机数） | 24 条素材 × 8 种配置，信噪比全部 ≥ 101 dB |
| 设备端随机数 vs CPU（vary=0） | 192 项检验 |z| > 3 为 0，平均 z 在 -0.25 ~ +0.20 |
| 设备端随机数 vs CPU（vary=1 配对种子） | 24 条 × 6 度量，跨素材平均差均 < 0.1 dB，标准差比 ±6% 内；144 项仅 1 个 |z| > 3（随机期望 2.9） |
| compute-sanitizer | memcheck、initcheck、racecheck 零错误零泄漏 |
| CPU 参考实现对 Python 原型 | 64 例逐采样一致 |
| 速度（exact=8、vary=1） | 单条 5.6 ~ 54 ms（CPU 86 ~ 1726 ms）；64 条整批 0.14 ~ 3.3 s，约为 CPU 的 30 ~ 43 倍 |
| 显存边界（5.0 GB 空闲） | 单声道最长实测 100 s（663 ms）；120 s 真显存不足后恢复且 `auto` 退回 CPU |

**听感结论**：原型阶段共四轮试听（2026-11-21 至 11-22）。第 1 轮暴露起音根因（零相位子带滤波把起音往前抹开），根因修复后第 2 轮真假辨别已是瞎猜水平；变形对比中时长拉伸稳赢；连敲对「同几下轮播加随机变调」的传统做法 5/5 胜出。2026-11-22 主人（专业录音师）表示基本听不出差别，**听感关通过**，第 5 轮盲听与两项改进（节奏学习、窄低频带不重抽）暂缓记为已知短板。〔原型实测；主人已确认 2026-11-22〕

**已知短板**（不阻塞收尾，逐条记录在案）：〔原型实测〕

- 纹理类（风、水，无起音）没有起音约束；非「先静后响」的后续起音（堂鼓后几下）不闸不塑形。
- 连敲的节奏层面内部小咔嗒时刻重复（借骨架所致；快门对真实连敲累计 0/4），且低频偏薄（快门 < 200 Hz 能量占比比真实低约 1 ~ 3 dB）。
- 模型约为原 WAV 的 24 倍，所以只存 WAV、现场分析；命令行输入不超过 60 s（这是做音效的，不是做长片的）。〔仓库〕
- 无限环境床的缝合（quilt）是简化版；水滴音头仍偏软约 4 dB（度量噪声为主）。

**未达成的目标**：原型阶段定的「批量 64 条 < 100 ms」未达成（实测整批 0.14 ~ 3.3 s；分项计时分布很平，最大内核只占 11%，瓶颈是时域约束里的双精度超越函数，要再提速得重排那几个内核）。〔原型实测〕是否继续追这个数，见 §7。

**验收线（按 ERB 路线重写，替代 v1.0 面向可微拟合的那套数字）**：

1. **听感**：主人的耳朵是最终关；机器指标全部只做必要条件，与耳朵冲突时不当反驳依据。〔主人已确认 2026-11-22〕
2. **确定性**：同一份规划重跑逐比特相同；GPU 对 CPU 逐波形信噪比 ≥ 100 dB；设备端随机数对 CPU 无系统偏移；compute-sanitizer 零错误。〔仓库，均已达成〕
3. **根上修**：合成缺陷在模型或约束里修，输出不拼原采样；报指标时区分「约束本身保证的」与「没被约束的独立指标」。〔主人已确认 2026-11-21〕
4. **实片验收**（进行中项）：接入作品拟音链路后，全片过 `npm run audio:qa` 与 `npm run audio:cuecheck`，再由主人全速带声看片认可；沿用仓库既有闸门（`docs/quality/QA-GATE.md`），本规格不另立标准。

**进行中**：接入拟音链路（入口 `erb.render_many` 与 `npm run audio:erb`，尚未接进任何作品的 sound / foley 脚本）＋ 未入库试制片《鲤鱼跃龙门》（papercut）实片验证 ＋ 落库遗留文件（本规格书入库属于此项）。〔主人已确认 2026-11-22〕

### 4.2 L4 混音：CPU 掩蔽自动避让加运动学早期反射（评估建议，待主人拍板）

**v1.0 方案为什么被否**〔评估〕：v1.0 的端到端梯度混音（把增益矩阵乘在 STFT 复频谱上、40 ~ 60 步 Adam 反传全片波形）有三处硬伤：一是预振铃，临界频带的低频分辨率要求约 2048 ~ 4096 样本窗（42 ~ 85 ms），快速变化的增益直接乘 STFT 再重建，会让琵琶、打击乐的瞬态前缘提前 20 ~ 40 ms 发糊；二是立体声塌缩，左右独立算增益会撕裂声像；三是杀鸡用牛刀，分轨已知时每帧每个临界频带让多少 dB 是功率域里的一个小规模带约束问题（20 s 音频在 10 ms × 12 频带下只是约 2000 × 12 的小矩阵），不需要对约 96 万样本的波形做 60 轮反向传播。

**替代设计（纯 CPU，零新依赖）**〔评估〕：

1. **分频母线**：10 ~ 12 段 Linkwitz-Riley 四阶（LR4）最小相位分频。LR4 相邻频带在交越点同相相加、幅度恒为 0 dB（全通平坦重建），从结构上杜绝预振铃；强制立体声联动（用 Mid 侧链算同一份增益同时乘 L / R，锁死声场）；`< 300 Hz` 频带硬锁 0 dB 衰减保住配乐根基。
2. **控制面求解**：10 ms 帧率下用 Zwicker 向上掩蔽扩散矩阵算每帧前景事件的真实可闻度缺口，在 `[T, 12]` 小矩阵上用解析下界加非对称平滑包络（前视约 6 ms 起音、90 ~ 150 ms 释放、L1 稀疏惩罚只压碰撞帧）求最小损伤让位曲面；同一套规则统一接管对白避让（`carve_dialogue_pocket`）与音效避让，彻底消灭手写 `volume_curve` 关键帧。
3. **冗余清理**：顺手修掉混音链里重复的响度积分（`integrated()` 重复约 40 次、约 1.26 s）与重采样（`resample_poly` 11 次、约 0.98 s），20 s 成片混音从实测 4.96 s 压到 1.2 s 以内（纯 CPU、CI 与本机结果一致）。
4. **运动学早期反射**：由 `kinematics.json` 的逐帧位置与尺度驱动 4 ~ 6 抽头时变早期反射延迟线加空气高频吸收，纯 CPU 约 30 ~ 60 ms，不需要 GPU。

**验收线（先跑最小实验 0A：不动 `engine/audio/` 主干，用《鲤鱼跃龙门》分轨真音频出数）**〔评估〕：

- 机器必要条件：20 s 混音 CPU 耗时 < 300 ms；`npm run audio:qa --fail-on-warn` 零警告；前景事件 `2–10 kHz` 信噪比全部 ≥ +4.0 dB；非冲突段配乐变动 < 0.2 dB。
- 听感终判：主人 A/B 对比确认无预振铃、无抽吸、不闷音乐（给自由试听文件，不强制盲听计分）。
- **Go / No-Go**：0A 不过线当场砍掉，不带病进工程化；过线才把方案合入 `engine/audio/director.py` 与 `mixing.py`。

### 4.3 L3 裁判：对比边际加物理取证加运动学同步核（评估建议，待主人拍板）

**v1.0 组件的去留**〔评估〕：

- **Synchformer 延后**：实查官方配置，它在 ±2 s 上分 21 个离散类，**分辨率 200 ms**，远粗于北冥 1 ~ 2 帧（42 ~ 83 ms）的同步门槛；通用实拍集上首位准确率仅 47.2%（容差 ±1 类也只 67.4%），只有说话人唇形准（86.6%）。北冥大量一拍二（12 fps 重复帧）、剪纸平面位移、水墨留白画面，实拍预训练的视觉编码器会大规模失灵。仅保留给未来真人口播、3D 写实角色对口型镜头。
- **Qwen2.5-Omni 延后**：约 16 GB 显存；2026-11-15 视觉实测已证明多模态大模型看风格化动画易幻觉；且按主人原则只有降级标存疑权。延后至后续阶段离线复核，严禁进第一批实施。

**替代设计三件套**〔评估〕：

1. **CLAP2-L 对比机制边际（免训练）**：底座 `laion/clap2-large-audioxl-s1B`（Apache-2.0，340M，约 1.4 GB 显存，本机 4070 可跑，任意长度音频不截断）。对每个事件同时算目标机制正提示词与同场景难负例（给「剪纸」配敲铁板、白噪、鼠标微动、口技；给「衣料」配棘轮、门锁、电机），输出边际分 `Δz = z(正) - max z(负)`，加语料库中心化去偏，按北冥域样本逐类定阈值。背景：2026-11-12 实测挂掉的是打标器路由加借阈值，而 CLAP 自定义提示词本身 top1 已达 47/75、top3 66/75 且在难类上多命中。
2. **无模型物理取证增强**：现有 `sfx_judge` 的 `hf_envelope_buzz`、`hf_whistle_db` 等继续担纲，建议新增二阶差分内部数字咔嗒检测、倒谱梳状金属振铃检测、奈奎斯特折叠混叠检测、`2–8 kHz` 去包络峭度真实度检验，与 CLAP2 边际串联（物理层挡形态错配，边际层分语义与材质）。
3. **运动学对冲击的同步核**：直接用 `kinematics.json` 的速度 / 加速度突峰（无遥测时退化为帧差 / 光流能量二阶差分）对音频多频带冲击度（Onset Flux）做互相关，精度 1 帧（24 fps 下 41.7 ms），不挑画风、近零显存，替代 Synchformer。

**验收线（最小实验 0B：固定对照集上回归破案）**〔评估〕：

- 机器必要条件：《鲤鱼跃龙门》v1 敲铁板假剪纸 100% 负边际拦截、v4 真剪纸 100% 正边际通过；2026-11-12 的 75 样本基准里 paper、twig_snap 拉回正边际；衣料 robe1 零误报机械。
- 铁律：样本不足 50 条 / 类时只标「存疑送耳听」，不越权自动拒绝；判挂的项不能被大模型复核翻转（§3 原则 1、2）。
- **Go / No-Go**：0B 不过线就砍掉 CLAP2 边际头，只保留物理取证与运动学同步核继续服务 QA 门。

### 4.4 L2 声源铸造厂：按需加载的生成补库（评估建议，待主人拍板；未开始）

**定位变化**：v1.0 设想在 5090 上常驻推理服务；评估实测 5090 当日仅余约 5.3 GB 显存（§2.1），改为**单次按需拉起、空闲自动卸载（约 5 分钟）加本地 SHA256 缓存（48 kHz / 24 bit）**，绝不与既有进程抢常驻显存。〔评估〕

**EzAudio-XL 被否及原因**〔评估〕：代码与权重虽为 MIT，但 `sample_rate = 24000`、单声道，奈奎斯特硬截断在 12 kHz；实测北冥 20 条剪纸切片的 95% 能量带宽中位数 14,181 Hz（最高 18,853 Hz），一半样本的 > 12 kHz 能量占比 ≥ 10%，快剪切片高达 34.2% ~ 73.2%。12 kHz 一刀切死，刀剑、剪纸、玉牌、水沫的空气感与脆裂细节全没了。

**候选 `MOSS-SoundEffect-v2.0`**〔评估〕：Apache-2.0；原生 48 kHz（DAC VAE，直接覆盖 0 ~ 24 kHz）；1.3B DiT 加 Flow Matching，Qwen3-1.7B 中英双语文本编码器（对中国传统器物的中文提示词友好），最长 30 s；全权重 11.23 GB，BF16 推理约 8 ~ 10 GB 显存（5090 按需拉起可承接）。已知风险必须先实测证伪：官方默认 100 步推理可能慢，需测 25 / 50 / 100 步的质量与耗时曲线、底噪水平与短促单点拟音能力。

**先过 0C 实验再立项**〔评估〕：在 5090 上测北冥最缺的 6 类中国器物干声（宣纸裁切、宣纸折叠、青铜编钟、硬木榫卯落锁、丝绸衣袂、竹林水花）各 4 条。过线线：实测 95% 能量带宽 > 12 kHz；`sfx_judge` 物理取证通过率 ≥ 50%；主人亲耳验收 ≥ 4/6 类达标。**不过线就放弃自建拟音大模型**，继续走「CC0 加商用干声切片加物理壳混合」，把 L2 记为 No-Go 归档。

**高频超分（BWE）兜底**：`FlashSR` / `NovaSR`（均 Apache-2.0）只作老旧 16 kHz 存量素材的急救工具，不作主力链路补丁（这类超分主要面向语音谐波，对非周期脆裂高频容易脑补出伪嘶声）。〔评估〕

**与 L1 的衔接**：铸造厂输出的干声与 CC0 实录音效同级，都是 ERB 再合成的合格输入（ERB 输入不必是真录音：程序化合成器输出已实测跑通，木 / 铜 / 瓷 / 竹四种材质起音前 +0.0 ~ +0.1 dB、频谱误差 0.04 ~ 1.2 dB）。〔原型实测〕

## 7. 待主人确认

以下是把 §4 里标了「评估建议，待主人拍板」的设计点与验收数字汇总成的短清单，逐条点头或改判后才开工对应层：

1. **L4 方案**：用「CPU 上的 LR4 分频 + Zwicker 掩蔽控制面」替代 v1.0 的端到端梯度混音；含 0A 过线数字（CPU < 300 ms、前景 `2–10 kHz` 信噪比 ≥ +4.0 dB、非冲突段配乐变动 < 0.2 dB、`audio:qa --fail-on-warn` 零警告）。
2. **L4 早期反射**：`kinematics.json` 驱动 4 ~ 6 抽头早期反射延迟线纳入 L4 范围。
3. **L3 方案**：CLAP2-L 对比边际 + 运动学同步核替代 Synchformer（Synchformer 与 Qwen2.5-Omni 延后）；含 0B 过线数字（假剪纸 100% 拦截、真剪纸 100% 通过、paper / twig_snap 回正、robe1 零误报）。
4. **L3 物理取证新增四项检测**：数字咔嗒、倒谱梳状金属振铃、奈奎斯特折叠混叠、`2–8 kHz` 去包络峭度。
5. **L2 方案**：换型 `MOSS-SoundEffect-v2.0`、按需拉起加空闲卸载、先过 0C 再立项；含 0C 过线数字（95% 能量带宽 > 12 kHz、`sfx_judge` 通过率 ≥ 50%、亲耳 ≥ 4/6 类达标，不过线整个 L2 记 No-Go）。
6. **L1 性能目标**：原型阶段定的「批量 64 条 < 100 ms」未达成（当前约为 CPU 的 30 ~ 43 倍，瓶颈在时域约束的双精度超越函数），是否继续追这个数，还是按现速度进入收尾。
7. **验收条目的迁移**：0A / 0B 里针对《鲤鱼跃龙门》的具体条数（16 剪、12 项警告）换别的实片时是否照套，还是逐片重定。
