# 在 NVIDIA RTX 工作站上渲染

让无头 Chrome 用上 RTX 独显，把原生 4K 的整片渲染压到约 30 秒。

## 思路

北冥引擎在无头 Chrome 里用 WebGL 逐帧渲染。在同时装有核显和独显的机器上，Chrome 默认的 ANGLE 后端（Windows 上是 D3D11）会选中核显：three.js 连 WebGL 上下文都建不起来，页面直接报错。

把 ANGLE 切到 Vulkan 后端，Chrome 才会用上 RTX 独显。引擎通过环境变量完成这件事：

```
BEIMING_ANGLE=vulkan
```

它会给 Chrome 传 `--use-angle=vulkan`。想用系统装的 Chrome 而不是自带的无头版，再加 `BEIMING_CHROME=<chrome 可执行文件路径>`。

实测，同一段重着色器（每像素循环 400 次噪声，1920×1040）的帧时：

| 设备 | 每帧 |
|---|---|
| RTX 5090（Vulkan） | **0.52 ms** |
| Mac M5 Pro（Metal） | 5.17 ms |

引擎的 3D 样例在 RTX 5090 + Vulkan 下渲出的画面与 Mac 上一致。

原生 4K 的整片（10 秒，240 帧，3840×2080）在 RTX 5090 上约 **31 秒**。

## 环境准备

| 项 | 说明 | 实测版本 |
|---|---|---|
| Node.js | 运行渲染脚本 | 24 |
| Google Chrome | 无头渲染 | 156 |
| FFmpeg | 编码与封装 | 9.0 |
| 显卡驱动 | 需支持 Vulkan | 当前稳定版 |

准备时留意两点：

- 4K 逐帧渲染会产生大量中间文件，输出目录和缓存目录放在容量充裕的盘上。
- 路径尽量用英文，避开老工具在非 ASCII 路径上的编码问题。

装好后，先确认 Chrome 在 Vulkan 后端下选中的是独显，再开始渲染。换机器或升级驱动之后都值得重做一遍。

## 渲染

```bash
BEIMING_ANGLE=vulkan node engine/render/video.mjs . --size 3840x2080 --workers 8 --out out/film_4k.mp4
```

- `.` 是工程目录。
- `--size` 为实际输出像素。镜头按 1040 高的设计尺寸摆位，任意分辨率下构图一致。
- `--workers` 是并行的浏览器进程数。实测 6 个与 10 个相差约 2 秒，设到 6 至 10 即可。

跑 4K 时的资源占用（6 worker）：GPU 平均 46%，显存最高约 18.8 GB，功耗平均 108 W。

## RTX Video Super Resolution

RTX Video Super Resolution 是 NVIDIA 的视频超分。实测它对手绘风镜头不合适。

- 大块平涂区会长出蚯蚓状纹理，像过度锐化的油画，纸感被破坏。
- 端到端约 3 分钟，其中模型只占每帧 0.017 秒，大头是逐帧 PNG 的读写。
- 画质不如直接渲染原生 4K。

所以北冥的手绘风镜头一律走**原生 4K**。

超分适合另一类素材：拿不到原生分辨率、只有低分辨率成片的视频，例如 AI 生成的视频镜头。对这类素材，先把逐帧读写改为显存内直通，可以去掉大部分耗时。

## 常见坑

| 现象 | 原因与处理 |
|---|---|
| 页面报错，建不起 WebGL 上下文 | ANGLE 落到了核显。设置 `BEIMING_ANGLE=vulkan`。 |
| 与 Mac 的画面有细微差别 | 只在显示层文字边缘，由系统字体光栅化不同造成，肉眼不可见。 |
| 工作站上 1080 反而不比 Mac 快 | 启动 Chrome 的固定开销占比高。差距在 4K 才拉开。 |
| 加 worker 没变快 | 实测 6 个之后收益很小，不必一味加大。 |
| 机器有别的 GPU 任务 | 渲染前先看显存和占用。计时受共用负载影响，应在空闲时测。 |
| 中文路径下某些工具出错 | 工程与输出路径改用英文。命令行先切到 UTF-8，Python 设 `PYTHONUTF8=1`。 |
