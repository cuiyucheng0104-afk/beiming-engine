# 送审单模板

> **怎么用**：每次送用户看（⛔1–⛔4 任一关口）前，复制本页到 `films/<名>/review/<闸>-<日期>.md`，按节填写，连同证据文件一起给用户。用户回复后，用 `node engine/production/film.js review …` 把结论记成同名的 `.json`（命令见第 6 节）；`.md` 是给人看的送审单，`.json` 才是状态机认的记录。
> 标尺与规程见 [RUBRIC.md](RUBRIC.md)；闸门规则见 [README.md](README.md)。填写说明（以「填写说明」开头的行）交稿前删掉。

---

# 《作品名》· <闸>送审（YYYY-MM-DD）

## 1. 这次送审什么

填写说明：关口（⛔1 structure / ⛔2 look / ⛔3 animatic / ⛔4 final）、看什么、怎么看（⛔4 必须全速、带声、从头到尾）。文件写作品目录内的相对路径与 sha256（`shasum -a 256 <文件>`；Windows 用 `Get-FileHash <文件>`）。

| 文件 | sha256 | 是什么 |
|---|---|---|
| `stills/look_01.png` | `…` | 风格帧：镜头 B 第 96 帧 |

作品描述：`film.json` 的镜头表 [填 `node engine/production/film.js expect films/<名> --json` 输出的 `shots`]，整片 N 帧 @ fps。

## 2. 和上次相比改了什么

填写说明：上次的结论与原话（引用上一份记录的文件名），这次逐条改了什么、改了哪个文件；第一次送审写「首次送审」。

- 联系表：

- 事件帧条（起点、峰值、终点）：
- 声音数据（积分响度、真峰值、静默电平、打点与起音偏差）：
- 读字与安全区：
- 与参照并排（风格基准帧、style-lock、对标片）：

## 4. 代理评分（内部门槛，不代替用户认可）

填写说明：每个分数附证据帧号；没看过的维度写「未评」。

| 维度 | 分数 | 证据帧 | 一句理由 |
|---|---|---|---|
| `style` 画风与质感 | | | |
| `subject` 主体与构图 | | | |
| `camera` 镜头与连续性 | | | |
| `motion` 动作与表演 | | | |
| `rhythm` 节奏与声音 | | | |
| `text` 文字与信息 | | | |

一票否决项（RUBRIC §3）：无 ／ 列出 id 与帧号。

代理结论：代理检查通过 ／ 代理检查未通过（未通过不送审，先返修）。

## 5. 问题清单

填写说明：一条一行，字段同 [issue.schema.json](issue.schema.json)；帧号是全局帧号；区域是 0–1 比例坐标。

| id | 帧 | 镜头 | 区域 | 层 | 维度 | 问题（现象） | 改法 | 优先级 | 证据 | 状态 |

## 6. 用户的结论

填写说明：照录用户原话（含标点，不改写、不概括）；写出处（会话与消息序号、聊天时间、邮件主题）与时间。再用下面一条命令记录，命令里的 `--quote` 与这里一字不差。

> 原话：

- 出处：
- 时间：
- 结论：认可（approve）／否定（reject：否定的维度、下次必须改什么）／跳过本关（waive，只限 look、animatic）

```sh
node engine/production/film.js review films/<名> --gate <闸> --decision <approve|reject|waive> \
  --file films/<名>/<所看文件> --quote "<原话>" --source-ref "<出处>" --source-at "<时间>"
```
