# kernel/conformance/：一致性入口

把最小出帧链路实跑一遍，把看到的东西写成核对记录，交给契约的校验器，再对校准场景的标准答案。

```sh
node beiming/kernel/conformance/run.mjs
```

它做的事：读 `fixtures/film.json`（两个镜头，都是校准场景「匀速方块」；第二个从全片第 49 帧起、不设背景）→ 每个镜头起两个浏览器 → three 帧源出帧 → 落盘 → 量几样要进记录的读数 → 写核对记录 → 逐个对象过校验 → 对标准答案。先写记录再对答案，对答案出错不影响记录。

产物在 `out/skeleton/`（每次运行先清空，不提交）：

| 路径 | 内容 |
|---|---|
| `<镜头>/frames/f<帧号>/` | 第一个浏览器按帧号顺序渲的帧：四个层文件、`meta.json`、`preview.png` |
| `<镜头>/probes/` | 同一个会话里的探测：同一帧再渲一遍、单子帧采样（`sub` 不为 0 的时刻）、只要元数据 |
| `<镜头>/rerun/` | 第二个浏览器：新会话只渲一帧、再开会话乱序渲 |
| `checks/` | `time-check.json`（全片一份），每个镜头的 `<镜头>.shot-check.json`、`<镜头>.source-check.json`、`<镜头>.meta-check.json` |
| `summary.json` | 每个对象过没过、违反哪条；每道门；各层的哈希；量到的读数；对标准答案的读数；静态扫描的结果 |

## 记录里哪些是量的，哪些是记账，哪些只是声明

| 量 | 来历 |
|---|---|
| 逐帧采样的帧号、子帧相位、辅助层的时刻 | 记账：帧源每次叫宿主写状态，宿主记下 `(f, sub)` |
| `accumulation.average` | 量的：把同一帧的各个子帧单独渲一遍，自己算线性平均和 sRGB 编码值上的平均，看帧源交回的累积结果对得上哪个。只在两种算法差得出来的数上比。量不出就不写 |
| `auxSample.pixelOffset` | 量的：在四分之一像素的格点上各求交一遍，看编号层和哪个位置对得上。这一帧分不出就整段 `auxSample` 不写 |
| `auxSample.samples`、`auxSample.shutterAngleDeg` | 记账：辅助层写了几次状态、这几次的时刻跨了多长 |
| `auxSample.apertureM` | **声明**：能力声明的 `auxAt` 是 `sub0`（针孔）。量不到 |
| `colorCall` | 量的：元数据里的颜色哈希是页面里算的，拿它去找这次运行里哪次调用交回的颜色层是这个哈希。同一帧原样渲两遍时分不出，算自己那次 |
| `colorTransfer` | 量的：场景里两个已知的自发光量级，读数和规格成不成比例 |
| `holds`、`rng` | 对机制的探测：镜头代码自己没用一拍二，也没用随机 |
| `build`、`languages` | 推出来的：走到写记录这一步说明装载成功；页面宿主只装得进 JS |

## 退出码 0 要过的门

- 每个对象（片子描述、能力声明、每份元数据、每份核对记录）结构合法、一条不违反。
- 同一帧的每一层在两个浏览器、几种渲法下逐位相同，元数据去掉 `timing` 之后相同。
- 元数据的帧号和相位就是量的那个状态；每次调用交回的颜色层对得上它的元数据里的哈希；子帧采样数和要的一样。
- 每个交付帧都量出了平均方式；每个镜头至少有一帧量出了辅助层的像素内位置；量和比的过程没有出错。
- 编号层对照规格逐像素求交：方块重心的差不超过规格的容差，并且编号不同的像素只许出现在「边压着像素中心」的像素上。上限的来历：把采样位置在像素中心周围挪十六分之一像素（OpenGL ES 3.0 只保证光栅化有 4 位子像素精度），期望编号会变的那些像素；数出来多少就是这一帧的上限。
- 深度层和求交的深度的相对差不超过规格给的容差。
- 真正累积出来的颜色层：拖影按线性亮度加权的重心，对快门中点那一刻的画面按自发光值加权的重心，差不超过规格的容差。
- 单子帧采样必须正好落在答案的时刻（不落在就算不过，不换别的比法），那一刻方块的重心对得上求交。
- 状态投到屏幕对得上答案；规格点名的像素打到的物体和深度对得上。

「编号层重心直接对方块中心的投影」单独列出、不进退出码：方块不在画面中间时侧面会露出来，把轮廓的重心拉离中心的投影。

| 文件 | 管什么 |
|---|---|
| `run.mjs` | 入口 |
| `records.mjs` | 把观测整理成核对记录；只整理，不补数 |
| `scan.mjs` | 静态扫描：渲染路径里的墙钟和不带种子的随机 |
| `compare.mjs` | 读层文件、求重心、照规格逐像素求交、判平均方式、量像素内位置 |
| `fixtures/film.json` | 最小片子描述；`params` 里的相机、背景、物体是从校准场景抄的，测试盯着两边一致 |
| `fixtures/moving-cube.shot.js` | 镜头代码，两个镜头共用 |

测试：`node --test 'beiming/kernel/conformance/*.test.mjs'`（不起浏览器）
