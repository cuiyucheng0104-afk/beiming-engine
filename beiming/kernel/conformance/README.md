# kernel/conformance/：一致性入口

把最小出帧链路实跑一遍，把看到的东西写成核对记录，交给契约的校验器，再对校准场景的标准答案。

```sh
node beiming/kernel/conformance/run.mjs
```

它做的事：读 `fixtures/film.json`（三个镜头：前两个是校准场景「匀速方块」，第二个不设背景；第三个是校准场景「辅助样本」；后两个都不从全片第 0 帧起）→ 求值核算出每个镜头的镜头输入 → 每个镜头起两个帧源进程（两个浏览器）→ 只经帧源接口出帧、拿层引用 → 量几样要进记录的读数 → 写核对记录 → 逐个对象过校验 → 对标准答案。先写记录再对答案，对答案出错不影响记录。

产物在 `out/skeleton/`（每次运行先清空，不提交）：

| 路径 | 内容 |
|---|---|
| `<镜头>/a-sequential/` | 第一个进程的主会话：按帧号顺序渲的帧、同一帧再渲一遍、单子帧采样、只要元数据、纯函数门的各个时刻。每次 render 一个目录：帧源写的层文件，加入口写的 `meta.json` |
| `<镜头>/a-moment-<序号>/` | 新开会话只求一个时刻 |
| `<镜头>/a-locked/` | 带着例子锁装载再渲一帧 |
| `<镜头>/a-stranger/` | 场景里多一条线（辅助层画不了的对象）时不要辅助层的那一帧 |
| `<镜头>/b-single/`、`<镜头>/b-shuffled/` | 第二个进程：新会话只渲一帧、再开会话乱序渲 |
| `checks/` | `time-check.json`（全片一份），每个镜头的 `<镜头>.shot-check.json`、`<镜头>.source-check.json`、`<镜头>.meta-check.json` |
| `summary.json` | 每个对象过没过、违反哪条；每道门；留下的层文件的哈希；量到的读数；对标准答案的读数；静态扫描的结果 |

量平均方式时单独渲的各个子帧，颜色层用完就删，不留在产物里。

## 帧源里面的事从哪看

帧源是黑盒，入口只调它的六个函数。里面发生了什么，靠两样：

- **观测点** `fixtures/observe.js`：包在夹具镜头代码外面，站在帧源和镜头代码之间。它记下 `build` 跑了几次、`state` 每次收到的 `(f, sub)`、场景停在那个状态时被画了几遍和各是哪一种（镜头自己的材质还在是颜色，被换了材质是辅助层）、`meta(f)` 交回的键、`ctx.cards.use` 被调的次数、`ctx.rng` 开出的流的名字对不对和出的数。这些数经 `meta(f)` 的 `readings` 交出来。
- **读回的像素**：层文件自己读、哈希自己算，再照校准场景的规格求交去对。

## 记录里每一段的来历

| 量 | 来历 |
|---|---|
| 逐帧采样的 `f`、`samples`、`aux`，`auxSample.samples`、`auxSample.shutterAngleDeg` | 旁观：观测点记下的。颜色采样是「场景带着镜头自己的材质被画的那些状态」，辅助层的时刻是「被换了材质画的那些状态」 |
| `frames[].shutterAngleDeg`、帧源核对记录的 `shutterAngleDeg`、`shutterSamples`、`size`、`opens[]` 的前六个字段 | 请求：入口照自己传的参数算 |
| `accumulation.average` | 量的：把同一帧的各个子帧单独渲一遍（单独渲的那几次落在哪由观测点确认），自己算线性平均和 sRGB 编码值上的平均，看帧源交回的累积结果对得上哪个。量不出就留空 |
| `auxSample.pixelOffset` | 量的：在四分之一像素的格点上各求交一遍，正好一个位置解释得了这张编号层才写 |
| `auxSample.apertureM` | 不写：从外面量不到，只有声明 |
| `evaluations[].digest` | 量的：只取一个子帧采样渲那个时刻（它落在快门角 ÷ 720，由观测点确认），摘要是那张颜色层文件的哈希。相位到了 0.5 的时刻要不到，不排 |
| `layerRefs[].fileSha256`、`colorFileSha256`、`orderRuns[].digest` | 量的：读层文件重算 |
| `status`、`code`、`meta`、`layers`、`metas`、`metaBytes` | 量的：数交回的东西 |
| `caps`、`manifest`、`metaEntities`、`metaFrame`、`metaShotFrame`、`metaHashColor`、`colorRef`、`sources`、`entities` | 自报：帧源交回的东西里的字段 |
| `rng[].name` | 自报，间接取的：宿主展开的流名经 `ctx.rng` 交给镜头代码，观测点当场比它等不等于期望的名字，相等才把这个名字写进记录 |
| `rng[].digest` | 量的：观测点取出的数的摘要 |
| `buildCalls`、`metaKeys`、`cardUses` | 观测点记下的。`cardUses` 只数得到次数：一次都没调写空数组 |
| `build`、`languages`、`scan` | 量的：`open` 成功还是报错；从入口文件和它直接引用的文件认语言；自己扫文件 |
| `unsupportedOpts`、`unfitOutputs` | 请求：入口知道自己故意要了什么、往场景里放了什么 |
| `colorTransfer` | 不写：要用灰阶场景量，这条链路没接 |

## 退出码 0 要过的门

- 每个对象（片子描述、例子锁、能力声明、镜头输入、实体清单、每份元数据、每个层引用、每份核对记录）结构合法、一条不违反。
- 每次 `open`、`render`、`query` 的结局和打算的一样：该成功的成功，故意造的错报的是那个错误码。
- 同一帧的每一层在两个进程、几种渲法下逐位相同，元数据去掉 `timing` 之后相同；带着例子锁装载渲出的各层和不带锁的相同。
- 子帧采样数和要的一样；只求一个时刻的每次调用都落在要的时刻上。
- 镜头代码拿到的随机流名字对、序列和参考实现相同。
- 每个交付帧都量出了平均方式；每个镜头至少有一帧量出了辅助层的像素内位置；量和比的过程没有出错。
- 编号层对照规格逐像素求交：主物体重心的差不超过规格的容差，并且编号不同的像素只许出现在边缘带里（采样位置在像素中心周围挪十六分之一像素，期望编号会变的那些像素）。
- 深度层和求交的深度的相对差不超过规格给的容差；什么都没打到的像素编号 0、深度 1e10、法线 `(0, 0, 0)`。
- 真正累积出来的颜色层：拖影按线性亮度加权的重心，对快门中点那一刻的画面按自发光值加权的重心，差不超过规格的容差。
- 单子帧采样必须正好落在答案的时刻（不落在就算不过，不换别的比法），那一刻主物体的重心对得上求交。
- 规格点名的像素打到的物体和深度对得上；主物体重心处的法线朝着相机。

| 文件 | 管什么 |
|---|---|
| `run.mjs` | 入口 |
| `records.mjs` | 把观测整理成核对记录；只整理，不补数 |
| `scan.mjs` | 静态扫描：渲染路径里的墙钟和不带种子的随机 |
| `compare.mjs` | 读层文件、求重心、照规格逐像素求交、判平均方式、量像素内位置 |
| `fixtures/film.json`、`fixtures/lock.json` | 最小片子描述；例子锁（里面的镜像哈希和内建卡是照契约的例子填的示意值） |
| `fixtures/calib-scene.js` | 照校准场景的规格搭镜头 |
| `fixtures/observe.js` | 观测点，和从 `readings` 里把观测读出来的函数 |
| `fixtures/<名字>.shot.js`、`fixtures/<名字>.scene.json` | 入口文件和它旁边的规格（从校准目录抄的相机、背景、物体，测试盯着两边一致） |
