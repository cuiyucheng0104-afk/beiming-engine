# 契约写法约定

`kernel/contracts/` 里每份契约都照这份约定写。只有集成负责人能改契约文件和这份约定；别人要改，提变更单。

## 1. 一份契约一个目录

```
kernel/contracts/<名字>/
  CONTRACT.md            条文，唯一的规范来源
  schema/<对象>.schema.json   数据对象的结构定义（JSON Schema 2020-12）
  types.d.ts             函数接口的签名（只当文档，不编译；没有函数接口就不写）
  examples/<短名>.json    正例
  examples/index.json    不带 format 的正例各对哪份结构定义（没有这种正例就不写）
  counterexamples/<不变量编号>-<短名>.json   反例
  counterexamples/index.json   每个反例违反哪一条、为什么
  check.mjs              判定函数：每条不变量一个，照第 4 节「怎么查」一栏写
```

- `check.mjs` 导出 `checks`，键是不变量编号，值是函数：收一个顶层对象，返回发现的问题（字符串数组），空数组表示没违反。记录里没出现的段不判。判定函数只读传进来的东西，不读文件、不读时钟。
- 条文要查登记表时（「必须是登记过的」这一类），登记表从第二个参数拿：`(obj, { registries, schema }) => …`。`registries` 的键是契约目录名，值是那个目录里同名的 JSON（`errors/errors.json`、`predicates/predicates.json`、`ownership/ownership.json`、`source/source.json`）；登记表不抄进判定函数。
- 正例和反例由 `node beiming/kernel/contracts/validate.mjs` 真的跑一遍：正例必须结构合法且一条不违反；反例必须正好被 `index.json` 写的那一条判出来，不多不少。

- 条文和结构定义说法不一样时，以 `CONTRACT.md` 为准，并且算一个缺陷。
- 反例文件本身是纯数据，不往里加「我违反了哪条」这类字段；这些信息写在 `counterexamples/index.json` 里：`[{ "file": "...", "violates": ["T2"], "why": "一句话" }]`。
- 一个反例只违反一条不变量，其余全部合法，结构也必须合法：结构不合法的对象校验器不再跑判定函数。
- 一条不变量可以有不止一个反例。条文里有几种违反方式（「或」「并且」的每一支），每一种配一个反例，文件名都以这条的编号开头。
- 不带 `format` 的内嵌值当正例或反例时，要登记它是哪份结构定义：正例写在 `examples/index.json`（`[{ "file": "…", "schema": "<schema/ 里的文件名>" }]`），反例在 `counterexamples/index.json` 的那一项里加 `"schema"`。判定函数从第二个参数的 `schema` 认这是哪种内嵌值，不靠字段猜。

## 2. `CONTRACT.md` 的七节

顺序固定，标题照抄：

| 节 | 写什么 |
|---|---|
| 版本 | 文件开头一行：`版本：0.1.0-draft`。冻结时去掉 `-draft` |
| 1. 范围 | 这份契约管什么、不管什么（不管的写明归哪份契约） |
| 2. 术语 | 本契约用到的词，每个一句话。别的契约定义过的词只引用，不重写 |
| 3. 结构 | 字段表：字段、类型、单位、必填、值域、说明。函数接口写签名表 |
| 4. 不变量 | 表格：编号、条文、怎么查、反例文件 |
| 5. 口径 | 条文里提到的量怎么量：在哪个空间、取哪个样本、容差多少 |
| 6. 待定 | 起草时做的选择、等实测的占位、等决定的字段 |
| 7. 变更记录 | 日期、改了哪条、为什么 |

## 3. 条文怎么写

- 只用三个词表达强度：**必须**、**不得**、**可以**。不写「应当」「尽量」「一般」「合理」。
- 一条不变量一句话，读的人能判定「满足」或「不满足」。「怎么查」一栏写出判定的办法：比哪两个值、容差多少。
- 编号定了不改。删掉的条文留空号，写「已撤」。新条文只往后加。
- 等实测的数写 `待探针：<量什么>`；等决定的值域写 `待定：<决定的名字>`。不编数，不替人拍板。
- 口径还没定的量（门槛写着「不定」、量法写着「待探针」），它的字段不得是「必填、不可空」：要么这次把口径定下来，要么字段改成可选。一个看着有数、其实各家算法不同的字段，比没有这个字段更糟。
- 凡是「由帧源定」「由宿主定」的默认值，必须写在能力声明这类能读到的地方，不得在运行时临时另定一个数。

## 3.1 核对记录：每个字段写明来历

核对记录是一致性测试工具写下来的观测。判定函数只看记录里的值，不管值是怎么来的；所以契约必须写明每个字段的来历，一共四种：

| 来历 | 含义 |
|---|---|
| `请求` | 测试工具自己发出去的东西：调了什么、要了什么、传了什么参数 |
| `量的` | 测试工具从产物上独立量出来的：读回的像素、算出的哈希、比对得出的结论 |
| `旁观` | 测试工具在被测方之外的观测点数到的：一次调用里写了几次状态、文件有没有落盘 |
| `自报` | 被测方自己说的：它声明自己用了什么做法 |

- 来历是相对测试工具说的。测试工具在被测方之外；被测方是被测的那一对（渲染器加宿主），它里面任何代码产出的值都是 `自报`，从被测方交回的东西（元数据、能力声明、报错）里直接抄出来的字段也是 `自报`。
- 第 3 节里核对记录的字段表加一栏「来历」，每个字段填上面四个词之一；格式标识、`ext`、各段的数组和对象本身不是观测，来历写「—」。各契约表前不再重抄这几句，引用本节。
- 一条不变量的「怎么查」如果只读 `自报` 的字段，这条不算判过：要么给出能独立量的办法、把字段改成 `量的`，要么在第 6 节登记「这条现在只有声明，没有判定」。被测方把实现改坏而记录不变的条文，等于没有这条条文。
- 观测了、结果是空的，写空数组；没观测，这一段不出现。不许为了让记录完整去填一个猜的值。
- 运行时对象（片子描述、元数据、能力声明这些）不用标来历：它们本身就是被测方交出来的东西。

## 5. 通用口径

所有契约共用，各契约不重复定义，只引用这一节。

| 项 | 口径 |
|---|---|
| 长度 | 米 |
| 坐标系 | 右手系，Y 向上，相机看向自己的 −Z |
| 角度 | 弧度；字段名里带 `Deg` 的才是度 |
| 时间 | 整数帧。帧号从 0 起。秒只在入口换算一次，换算式写在时间键契约里 |
| 颜色 | 字段说明里必须写明：场景线性，还是显示空间。没写的算缺陷 |
| 字段名 | 小驼峰（`visibleToCamera`）。卡名用点分小写（`particle.ballistic`）；谓词名、通道名各以自己的登记表为准（谓词登记表契约 5.1、输出通道契约 3.1） |
| 格式标识 | `<名字>/<主版本>.<次版本>`，例如 `meta/0.1`。每个顶层对象必须带 `format` 字段；内嵌值和接口值不带 `format`。核对记录的格式标识写成 `<名字>-check/<主版本>.<次版本>`；核对记录只为承载行为类条文的判定，不是运行时对象。全部格式标识见第 4 节的总表 |
| 缺字段 | 必填字段缺了就是非法。可选字段不出现，表示「没有」 |
| `null` | `null` 表示「没有值」，不表示 0。每个可以是 `null` 的字段必须在说明里写明原因是哪一种：这次没算、这个帧源交不出、这次没有。同一个字段不得既可以不出现、又可以是 `null`：必填可空和可选不空二选一。哪些字段可以是 `null`，契约里逐个列出；没列的不得是 `null` |
| 未知字段 | 顶层对象不得出现契约没定义的字段。要带私有数据，放进 `ext` 对象，键用带点的前缀。片子描述、锁文件、事件表、补丁四个顶层对象不收 `ext`（它们要逐位比较或由服务器生成），其余带 `format` 的顶层对象都收。读到契约没定义的字段时必须报错，错误码是 `contract.unknown-key`，诊断照错误码表契约（ER）5.5 |
| 数值 | 帧号、计数、编号是整数。其余是 IEEE 754 双精度。不得出现 `NaN` 和无穷 |
| 路径 | 相对路径，正斜杠，不带 `..`，不以 `/` 开头 |
| 哈希 | 字段名里没有算法名的哈希一律写 `sha256:` 加 64 位小写十六进制。核对记录里的状态摘要 `digest` 除外：它只用来比两个状态是否相同，写小写十六进制，8 到 64 位，不带前缀。 |
| 二进制表 | 数值一律小端；浮点是 32 位，整数是无符号 32 位 |
| 确定性 | 同样的输入必须得到同样的输出。条文里说「一致」时写明是逐位相同，还是在某个容差内 |

## 6. 版本和修改

- 草稿期（标签 `contracts-v0.1` 之前）可以自由改。
- 冻结后：加可选字段不算破坏，当天生效。别的修改都是破坏性的，要升次版本，先停止扇出，所有在跑的工作包收到同一份变更说明。
- 谁都能提变更单，只有集成负责人能改契约文件。
