# 卡文件格式

版本：0.1.0-draft

## 1. 范围

管：

- 卡文件 `card/0.1` 的全部字段：名字、版本、类别、落点、每个落点的卡的入口、参数表、端口、先验、适用条件、校准场景、验证、消融、坑、来历、验证状态、挂的题、耗时。
- 类别、落点、耦合、参数类型、端口数据类型的词表，`ports.order` 的写法。
- 验证状态四级各自的条件。
- 哪些内容不得写进卡文件。
- 卡的哈希对哪些文件算、怎么算。

不管：

- 入口函数 `create`、`evaluate` 的调用形状，`Handle`，装载顺序怎么从 `ports.order` 排出来：卡的运行时接口契约（CR）。
- 卡的引用 `<卡名>@<版本>` 的写法：CR 契约 3.3。
- 卡文件和实现放在哪个目录、归谁：目录归属表契约（OW）。
- 锁文件里怎么记一张卡的版本、哈希、落点、验证状态：锁文件契约（LK）。
- 卡自带的断言怎么写、谓词名有哪些：谓词登记表契约（PR）。
- 题号的写法：题目文件格式契约（QF）。
- 片子描述里怎么给卡的参数赋值、资产别名怎么写：片子描述契约（D）。
- 宿主怎么把时刻展开成镜头局部帧号交给卡：时间键契约（T）、卡的运行时接口契约（CR）。
- 私有覆盖层的格式：不在这个仓库里。

## 2. 术语

卡、卡的实现、形状、卡的引用、求值核、`tracks`：见卡的运行时接口契约（CR）第 2 节。帧源、宿主：见帧源接口契约（F）第 2 节。落点、验证状态：见锁文件契约（LK）第 2 节。谓词：见谓词登记表契约（PR）第 2 节。时刻算式、资产别名：见片子描述契约（D）第 2 节和 5.1。镜头局部帧号：见时间键契约（T）第 2 节。

| 词 | 含义 |
|---|---|
| 卡文件 | 描述一张卡的一个数据文件：它是什么、参数有哪些、实现在哪、验到了哪一级。 |
| 卡名 | 卡的名字，点分小写，例如 `camera.fit`。 |
| 类别 | 一张卡属于十六类里的哪一类；查卡时按它过滤。 |
| 卡的入口 | 卡在一个落点上的实现文件。 |
| 耦合 | 一个参数的取值跟着什么变：场景尺度、显示变换、分辨率这类。 |
| 端口 | 卡对外声明的一个有类型的输入或输出。 |
| 先验 | 来自案例的参考值，带着它成立的条件。先验不是默认值。 |
| 自带测试 | 只靠这个仓库就能重跑的测试。 |
| 卡的对拍 | 把卡的输出和一份真值比，过一组门。 |
| 私有覆盖层 | 仓库外面按卡名放的一份补充数据，放指向仓库外面的地址和出处。 |
| 卡级校准题 | 只考这一张卡的题，写成 `cal:<卡名>`。 |

## 3. 结构

卡文件的任何一层都不得出现本节没列的键。

### 3.1 卡文件

顶层对象，`format` 是 `card/0.1`。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `format` | 字符串 | 是 | `card/0.1` | 格式标识 |
| `id` | 字符串 | 是 | 卡名，写法见 5.1 | 卡名，不带版本 |
| `version` | 字符串 | 是 | 三段十进制数，用 `.` 连接 | 版本 |
| `kind` | 字符串 | 是 | 5.2 的十六个词 | 类别 |
| `title` | 字符串 | 是 | 不空 | 标题 |
| `intent` | 字符串 | 是 | 不空 | 这张卡要达到什么 |
| `visibleToAgent` | 布尔 | 否 | | 查卡查不查得到。不出现时：`kind` 是 `mechanism` 的算 `false`，别的算 `true`。查不到的卡照样进锁文件、照样有验证状态 |
| `livesIn` | 数组 | 是 | 5.3 的词，不重复，至少 1 项 | 落点 |
| `impl` | 数组 | 是 | 至少 1 项，每项见 3.2 | 每个落点的卡的入口 |
| `params` | 对象 | 是 | `{ 参数名: 参数 }`，参数见 3.3；没有参数写空对象 | 参数表。参数名是字母、数字，以小写字母开头 |
| `ports` | 对象 | 是 | 见 3.4 | 端口 |
| `priors` | 数组 | 否 | 每项 `{ param, value, when, case }` | 先验：哪个参数、参考值、在什么条件下成立、出自哪个案例 |
| `conditions` | 对象 | 是 | `{ appliesWhen, notWhen }`，都是字符串数组 | 什么时候用，什么时候不用 |
| `calibration` | 字符串 | 是 | 不空 | 校准场景的编号 |
| `verify` | 对象 | 是 | 见 3.5 | 验证 |
| `ablation` | 数组 | 否 | 每项 `{ metric, delta, unit }` | 关掉这张卡，哪个量变多少；`delta` 是双精度，`unit` 是它的单位 |
| `pitfalls` | 数组 | 否 | 每项 `{ symptom, fix }`，都是不空的字符串 | 现象和修法 |
| `provenance` | 对象 | 是 | `{ cases, note }`；`cases` 是字符串数组，`note` 是不空的字符串 | 来历：案例编号，一句话 |
| `status` | 数组 | 是 | 至少 1 项，每项见 3.6 | 验证状态 |
| `exams` | 数组 | 是 | 至少 1 项，不重复；题号，或 `cal:<卡名>` | 挂的题 |
| `cost` | 数组 | 否 | 每项 `{ host, msPerFrame }`；`msPerFrame` 是双精度，单位毫秒，≥ 0 | 每帧耗时，按宿主 |
| `ext` | 对象 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `impl[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `livesIn` | 字符串 | 是 | 5.3 的词 | 这个卡的入口在哪个落点 |
| `entry` | 字符串 | 是 | 路径，从 `beiming/` 算 | 卡的入口 |
| `shape` | 字符串 | 是 | `create`、`evaluate` | 形状，见 CR 契约 |
| `hosts` | 数组 | 是 | 每项 `{ host, version }`，都是不空的字符串；可以是空数组 | 这个卡的入口挂在哪些宿主、各是什么版本。`source:three` 的 `host` 是页面宿主（three 帧源的渲染器主干在过渡期是 WebGL 加 GLSL），`version` 是 `0.187.0`；`source:core` 的 `host` 是离屏宿主。这两处按倾向定，合作者不同意时再改；宿主名怎么拼见第 6 节 |
| `selftest` | 字符串 | 是 | 路径，从 `beiming/` 算 | 自带测试 |

### 3.3 参数

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `type` | 字符串 | 是 | `number`、`integer`、`boolean`、`string`、`color`、`time`、`asset`、`text`、`data` | 类型。`string`、`time`、`asset`、`text`、`data` 的值是什么见下表 |
| `unit` | 字符串 | 是 | 不空；没有单位写 `none`；角度写 `deg` | 单位。角度一律用度，见 CF11 |
| `space` | 字符串 | 见 CF5 | `scene-linear-rec709`、`display` | 颜色是场景线性还是显示空间。`scene-linear-rec709` 和输出通道契约（PS）是同一个词 |
| `range` | 数组 | 见 CF4 | `[下限, 上限]`，双精度，两端都算在内 | 取值范围 |
| `schema` | 字符串 | 见 CF9 | 路径，从卡文件所在的目录算 | `data` 类型的值的结构定义（JSON Schema 2020-12） |
| `default` | 任意 JSON 值 | 是 | 和 `type` 相符：`number` 的必须是数，`integer` 的必须是整数，`boolean` 的必须是布尔，`string`、`text` 的必须是字符串；另外四种类型的见第 6 节 | 默认值 |
| `coupling` | 字符串 | 是 | 5.4 的词 | 耦合 |

| `type` | 值是什么 |
|---|---|
| `string` | 字符串。不得是文件路径，判法见 5.10；要指向文件必须用 `asset` |
| `time` | 时刻。片子描述里写全片帧号或时刻算式（D 契约 5.3） |
| `asset` | 资产别名：这个镜头或全片 `assets` 里的一个别名，写法见 D 契约 5.1 |
| `text` | 画面上要出现的文字，字符串 |
| `data` | 任意 JSON 值。卡目录里必须带一份结构定义，参数条目用 `schema` 指它 |

卡拿到的帧号一律是镜头局部帧号。`time` 类型的值由宿主在交给卡之前展开，并减去镜头的 `in`；结果可以是负数，也可以不小于镜头帧数，表示时刻在镜头之外。`data` 类型的值里面的帧号也是镜头局部帧号。

### 3.4 `ports`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `in` | 数组 | 是 | 每项 `{ name, type }`；`type` 是 5.5 的词 | 输入端口 |
| `out` | 数组 | 是 | 每项 `{ name, type }`；`type` 是 5.5 的词 | 输出端口 |
| `order` | 对象 | 是 | `{ before, after }`，都是卡名的数组，不重复 | 本卡必须排在 `before` 里的卡之前、`after` 里的卡之后 |
| `requires` | 数组 | 是 | 不空的字符串 | 前置条件 |

### 3.5 `verify`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `selftest` | 字符串 | 是 | 不空 | 自带测试测的是什么 |
| `parity` | 对象 | 否 | `{ gates, mutation, negative }`；`gates` 是字符串数组，另两个是不空的字符串 | 卡的对拍：门、变异检查、负对照。没有真值的卡不出现 |
| `predicates` | 数组 | 是 | 不空的字符串，每项只写一条断言，写法见 PR 契约 5.5，不得带 ` ; `；可以是空数组 | 卡自带的断言 |

### 3.6 `status[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `level` | 字符串 | 是 | `read`、`reproduced`、`measured`、`film-verified` | 验到哪一级，条件见 5.6 |
| `host` | 字符串 | 是 | 不空 | 在哪个宿主上验的 |
| `source` | 字符串 | 是 | 不空 | 那个宿主所在的帧源或工具当时的版本 |
| `gpu` | 字符串 | 是 | 不空；没用显卡写 `none` | 在哪块显卡上验的 |
| `parityReport` | 字符串 | 否 | `sha256:` 加 64 位小写十六进制 | 卡的对拍报告的哈希，写法照通用口径「哈希」 |
| `date` | 字符串 | 是 | `YYYY-MM-DD` | 哪天验的 |

`host`、`source`、`gpu`、`level` 四个字段和 LK 契约 3.4 的 `verified` 是同一组词。

### 3.7 不得出现的五个键

这五个键属于私有覆盖层。结构定义认得它们，为的是能单独报出来；出现就违反 CF7。

| 键 | 在覆盖层里放什么 |
|---|---|
| `provenance.studied` | 学的是哪个文件哪一行 |
| `provenance.lab` | 机制笔记和插桩脚本在仓库外面的位置 |
| `verify.parity.truth` | 真值的地址 |
| `ablation[].lab` | 消融结果的地址 |
| `priors[].source` | 这条先验出自哪个文件哪一行 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| CF1 | `impl` 里各项的 `livesIn` 不得重复，它们合起来必须正好是顶层的 `livesIn`。 | `impl[].livesIn` 没有两项相同；作为集合等于顶层 `livesIn` | `CF1-landing-without-impl.json` |
| CF2 | 落点是 `data` 的卡的入口 `shape` 必须是 `evaluate`，落点以 `source:` 开头或是 `comp` 的卡的入口 `shape` 必须是 `create`。 | 逐项比 `impl[].livesIn` 和 `shape`；`bake` 不判 | `CF2-data-impl-create.json` |
| CF3 | 落点是 `data` 的卡的入口，`entry` 必须在 `kernel/eval/` 之下，或在 `cards/<本卡的 kind>/` 之下。 | `entry` 以 `kernel/eval/` 开头，或以 `cards/` 加 `kind` 加 `/` 开头 | `CF3-data-impl-outside.json` |
| CF4 | `type` 是 `number` 或 `integer` 的参数必须带 `range`，并且 `range[0] ≤ default ≤ range[1]`。 | 逐个这两种类型的参数：`range` 在；`default` 是数（JSON 的数，写成字符串或布尔的不算）；三个数按数值比 | `CF4-default-out-of-range.json` |
| CF5 | `type` 是 `color` 的参数必须带 `space`，别的类型的参数不得带 `space`。 | 逐个参数看 `type` 和 `space` 在不在 | `CF5-space-on-number.json` |
| CF6 | `status` 里不得有两项的 `host`、`source`、`gpu` 三个都相同。 | 三个字符串逐字符比 | `CF6-duplicate-status-key.json` |
| CF7 | 卡文件里不得出现 3.7 的五个键。 | 逐个键看在不在 | `CF7-overlay-field-in-card.json` |
| CF8 | `verify.predicates` 每一项必须只写一条断言，这条断言的谓词名必须是谓词登记表里登记过的。 | 断言里出现 ` ; `（空格、分号、空格）算违反；照 PR 契约 5.5 取每条断言的谓词名，在 `predicates/predicates.json` 的 `name` 里逐字符找 | `CF8-unregistered-predicate.json`、`CF8-semicolon-joined.json` |
| CF9 | `type` 是 `data` 的参数必须带 `schema`，别的类型的参数不得带 `schema`。 | 逐个参数看 `type` 和 `schema` 在不在 | `CF9-data-without-schema.json` |
| CF10 | `type` 是 `string` 的参数，`default` 不得是文件路径。 | 逐个这种类型的参数，照 5.10 判 `default` | `CF10-string-default-is-path.json` |
| CF11 | 参数名以 `Deg` 结尾的，`unit` 必须是 `deg`；`unit` 是 `deg` 的，参数名必须以 `Deg` 结尾；`unit` 不得是 `rad`。 | 逐个参数比参数名的末三个字符和 `unit`，逐字符比 | `CF11-degree-without-suffix.json` |

## 5. 口径

### 5.1 卡名

两段以上，用 `.` 连接；每段是小写字母、数字、连字符，以字母开头。例：`camera.fit`、`fx.post-state`。卡名的第一段只是起名习惯，和类别不必对应；过滤一律按 `kind`。

### 5.2 类别

| `kind` | 类别 | `kind` | 类别 |
|---|---|---|---|
| `time` | 时间 | `form` | 造型 |
| `camera` | 相机 | `material` | 材质 |
| `assembly` | 拼装 | `motion` | 动作 |
| `particle` | 粒子 | `two-d` | 二维 |
| `post` | 后期 | `audio` | 声音 |
| `shading` | 着色 | `delivery` | 交付 |
| `lighting` | 光照 | `asset` | 资产 |
| `atmosphere` | 大气 | `mechanism` | 机制：基础设施类的卡 |

### 5.3 落点

| `livesIn` | 在哪 |
|---|---|
| `data` | 求值核，输出进 `tracks` |
| `source:three` | three 帧源 |
| `source:blender` | Blender 帧源 |
| `source:core` | 核心帧源 |
| `bake` | Blender 一侧的烘焙作业，结果写回数据 |
| `comp` | 合成 |

一张卡可以有不止一个落点。编排类的卡暂时落在帧源一侧时写那个帧源；移进求值核时改成 `data`，并升主版本。锁文件的 `cards.*.impl` 用的就是这张表的词，一张卡有几个落点就列几个（LK 契约）。

### 5.4 耦合

| `coupling` | 跟着什么变 |
|---|---|
| `none` | 不跟着别的变 |
| `scene-scale` | 场景的米制尺度 |
| `view-transform` | 显示变换 |
| `resolution` | 分辨率与像素比 |
| `fps` | 帧率 |
| `asset-batch` | 在哪批资产上标定的 |
| `host-api` | 宿主的接口，例如内置着色片段的原文、节点插口名 |

### 5.5 端口的数据类型

`scene-linear-rgba`、`depth-view`、`object-id`、`normal-view`、`events`、`frame-meta`、`bbox-world`，以及以 `tracks.` 开头的名字（例如 `tracks.camera`）。各类型的数值口径归输出通道契约（PS）、事件表契约（EV）、每帧元数据契约（M）。类型名里不写位深：`scene-linear-rgba`、`depth-view`、`object-id`、`normal-view` 的分量和位深照输出通道契约 3.1 的 `color`、`depth`、`objectId`、`normal` 四行，卡不得另按别的位深传。

### 5.6 验证状态四级

| `level` | 名称 | 条件 |
|---|---|---|
| `read` | 只读过 | 有机制笔记，没有这个仓库里的实现 |
| `reproduced` | 复现过 | 这个仓库里的实现过了自带测试、校准场景和纯函数门 |
| `measured` | 量测通过 | 过了卡的对拍的门，带负对照和变异检查；没有真值的卡，过校准场景上的全部谓词 |
| `film-verified` | 成片验证过 | 被 2 部不同的、过了基础谓词的片子用过（出生的那部算一部），挂的题通过 |

状态按「宿主、版本、显卡」这个键分别记，一个键一项。`status` 只能由复核方改，实现方不得改自己那张卡的 `status`。

### 5.7 卡的入口的路径

`entry` 和 `selftest` 从 `beiming/` 算，`schema` 从卡文件所在的目录算，写法都见通用口径「路径」。落点是 `data` 的卡的入口放哪由 CF3 管；卡文件自己一律放在 `cards/` 下面（OW 契约 5.3）。

### 5.8 `exams`

每项是一个题号（写法见 QF 契约 5.1），或 `cal:` 加一个卡名。每张卡至少挂一道。

### 5.9 先验和默认值

`priors` 里的值只是参考：片子描述里没写这个参数时，生效的是 `default`，不是先验。

### 5.10 文件路径怎么认

一个字符串里含 `/` 或 `\`，就算文件路径。`string` 类型的参数在片子描述里给的值照同一条判，那一侧的判定要有片子描述才能做。

### 5.11 卡的哈希

卡的哈希对卡目录下的全部文件算：路径按字节序排，每个文件算 SHA-256，再对「路径、换行、哈希、换行」拼起来的串算一次。卡目录是卡文件所在的那个目录。结果记在锁文件的 `cards.*.sha256`，写法见 LK 契约。
