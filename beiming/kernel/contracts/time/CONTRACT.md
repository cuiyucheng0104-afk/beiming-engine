# 时间键

版本：0.1.0-draft

## 1. 范围

管：

- 时间键 `TimeKey`、帧率 `Fps`、镜头种子的写法，帧和秒的换算式。
- 状态对时间的依赖：纯函数、不读墙钟、随机只走命名随机流，流名怎么展开。
- 快门窗口的相位、子帧采样、子帧累积和后期链的先后、辅助层取哪个样本。
- 镜头局部帧号和 `hold`。
- 判定以上各条用的「时间核对记录」。

不管：

- 帧率、快门角、种子、镜头表写在片子描述的哪个字段：片子描述契约（D）。
- 全片种子，以及由全片种子派生镜头种子的算法：片子描述契约（D）和锁文件契约（LK）。
- `ctx.rng`、`state(f, sub)` 的调用形状：镜头契约（S）。
- 每帧元数据里的时间字段：每帧元数据契约（M）。
- 帧源对外的求帧接口、帧源名的值域：帧源接口契约（F）。
- 辅助层各通道的定义和数值口径：输出通道契约（PS）。

## 2. 术语

帧源、宿主、能力声明：见帧源接口契约（F）第 2 节。生效的快门角：一次 `render` 实际用的快门角，怎么定见帧源接口契约（F）5.9。

| 词 | 含义 |
|---|---|
| 帧 | 输出的一格画面，用整数编号，从 0 起。 |
| 全片帧号 | 从全片第一帧数起的帧号。 |
| 镜头 | 片子描述的镜头表里的一项，占全片帧号的一个连续区间 `[起始帧, 起始帧 + 帧数)`；其余定义见镜头契约（S）。 |
| 镜头局部帧号 | 从本镜头第一帧数起的帧号，记作 `f`。 |
| 子帧相位 | 一帧之内的时刻，记作 `sub`，取值在 `[0, 1)`，0 是帧起点。 |
| 时间键 | `{ frame, sub }` 一对值，表示「第 `frame` 帧起点之后 `sub` 帧」这个时刻。 |
| 帧率 | 每秒多少帧，写成有理数字符串。 |
| 种子 | 本契约里一律指镜头种子：一个镜头一个的整数，这个镜头里所有随机都由它派生；定义见锁文件契约（LK）第 2 节。全片种子只用来派生镜头种子，不进流名。 |
| 状态 | 某个时刻场景里会影响画面、辅助层或元数据的全部量。 |
| 状态摘要 | 对状态算出的一个字符串，用来比较两个状态是否相同。 |
| 纯函数 | 输出只由写明的输入决定的函数：不读别的东西，也不留下会影响下次调用的东西。 |
| 渲染路径 | 从拿到时间键到交出一帧的画面、辅助层和元数据之间执行的全部代码，包括帧源（渲染器和宿主）、镜头代码和卡。静态扫描扫其中哪些文件见 5.3，镜头代码那一部分不按「执行了」算。 |
| 墙钟 | 任何返回当前真实时间的调用。 |
| 单调时钟 | 只用来量两个时刻之间隔了多久的时钟，读数不对应真实时间。 |
| 命名随机流 | 由流名唯一决定的一条随机数序列。 |
| 流名 | 四段的字符串 `<镜头种子>/<镜头>/<用途>/<对象>`。 |
| 快门角 | 快门开着的时长占一帧的比例乘以 360，单位是度。 |
| 快门窗口 | 一帧里快门开着的时间区间。 |
| 子帧采样 | 帧源为了算一帧，在快门窗口里取的一个时刻。 |
| 子帧累积 | 把一帧的多个子帧采样的结果平均成一帧。 |
| 逐子帧累积 | 帧源自己对每个子帧采样各渲一次再平均的做法；用渲染器原生运动模糊的帧源不属于这一种。 |
| 居中分层 | 把快门窗口等分成 N 段、每段取中点的排法，算式见 T14。 |
| 后期链 | 场景渲完之后在画面上依次跑的处理步骤。 |
| 辅助层 | 颜色之外随帧交出、取辅助样本的那几层：输出通道契约（PS）3.1 通道登记表里取法是 `sub0` 的通道；名单和各层的定义都只在那里。 |
| 硬切 | 相邻两个镜头在整数帧上的直接切换。 |
| 场景参考镜头 | 渲染结果先落在场景线性的 HDR 目标上的镜头。 |
| 显示参考镜头 | 片子描述里 `colorRef` 是 `display` 的镜头：没有场景线性的 HDR 目标；照 F2，它交出的颜色层仍是线性编码，数值是显示空间的画面取了线性编码。 |
| 一拍二 | 画面每 2 帧才变一次的做法。 |
| 核对记录 | 一致性测试把一次观测写下来的数据对象，只用来判定不变量；帧源（渲染器和宿主）、镜头代码和卡都不需要产出它。 |

## 3. 结构

### 3.1 时间键 `TimeKey`

内嵌值，不带 `format`，不得有别的字段。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 帧号。是全片帧号还是镜头局部帧号，由用到时间键的那个字段写明 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 子帧相位 |

例子：`{ "frame": 150, "sub": 0 }` 是第 150 帧的起点；`{ "frame": 150, "sub": 0.375 }` 是第 150 帧起点之后八分之三帧的时刻。

### 3.2 帧率 `Fps`

字符串 `"<分子>/<分母>"`。分子和分母是十进制正整数，不带前导零，两者互质。

合法：`"30/1"`、`"24000/1001"`。不合法：`"29.97"`、`"30"`、`"60/2"`。

### 3.3 种子

镜头种子。整数，值域 `[0, 4294967295]`。

### 3.4 流名

调用方给的参数是 `"<用途>/<对象>"`：正好一个 `/`，两段都不空，都不含 `/` 和空白。流名由宿主展开成四段：

| 段 | 取值 |
|---|---|
| 镜头种子 | 这个镜头的镜头种子的十进制写法 |
| 镜头 | 镜头的标识 |
| 用途 | 参数的第一段 |
| 对象 | 参数的第二段 |

例子：镜头 `s02`，它的镜头种子是 20261118，参数 `"scatter/rock.03"`，流名是 `20261118/s02/scatter/rock.03`。

### 3.5 `hold`

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `hold(f, n)` | `f`：镜头局部帧号，整数，≥ 0；`n`：整数，≥ 1，单位帧 | 整数，单位帧 | 把 `f` 压到不超过它的最近一个 `n` 的倍数 |

一拍二写成 `hold(f, 2)`。`hold` 只在镜头代码和卡里用，宿主发下来的时间键不因它改变。

### 3.6 时间核对记录

顶层对象，`format` 是 `time-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。观测了、结果是空的写空数组；没观测的段和字段不出现。

「来历」一栏的四个词见契约写法约定 3.1。格式标识、`ext`、各段的数组和对象本身不是观测，来历写「—」，段里的字段各自标。来历是相对测试工具说的，测试工具在被测帧源（渲染器加宿主的一对）之外：

- 被测帧源里面任何代码产出的值都是 `自报`，宿主自己记的账也算在内，不得填进 `旁观`、`量的` 的字段。
- 测试工具放进夹具镜头代码、夹具卡里的观测点得到的值是 `旁观`，例如夹具镜头的 `state` 自己记下收到的 `(f, sub)`；前提是观测点是测试工具自己的代码，不是渲染器或宿主的代码。
- 测试工具自己读产物算出来的值是 `量的`。

没有这样的观测点时，来历是 `旁观` 的字段所在的那一项不出现。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `time-check/0.1` | — | 格式标识 |
| `fps` | 字符串 | 帧每秒 | 是 | 写法见 3.2，由 T3 管 | `请求` | 全片帧率，测试工具从片子描述（它据此算出交给帧源的镜头输入）里读。全片只有这一处 |
| `shots` | 数组 | 无 | 是 | 至少 1 项，区间互不重叠 | — | 镜头表，每项见下表 |
| `evaluations` | 数组 | 无 | 否 | | — | 纯函数门的观测，每项见下表 |
| `frames` | 数组 | 无 | 否 | | — | 逐帧采样的观测，每项见下表 |
| `holds` | 数组 | 无 | 否 | | — | `hold` 的观测，每项见下表 |
| `rng` | 数组 | 无 | 否 | | — | 命名随机流的观测，每项见下表 |
| `localized` | 数组 | 无 | 否 | | — | 全片时刻换成镜头局部帧号的观测，每项见下表 |
| `scan` | 对象 | 无 | 否 | | — | 静态扫描的命中，见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

`shots[]`：测试工具从片子描述（它据此算出交给帧源的镜头输入）和锁文件里读。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 见 D 契约 5.1 | `请求` | 镜头的标识 |
| `start` | 整数 | 帧 | 是 | ≥ 0 | `请求` | 起始帧，全片帧号；就是片子描述里这个镜头的 `in` |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | `请求` | 帧数 |
| `seed` | 整数 | 无 | 是 | 见 3.3 | `请求` | 这个镜头的镜头种子 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | `请求` | 这个镜头的快门角；0 表示没有运动模糊 |

`evaluations[]`：对某个镜头的某个时刻求一次状态。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | `请求` | 哪个镜头 |
| `f` | 整数 | 帧 | 是 | `[0, 该镜头帧数)` | `请求` | 镜头局部帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | `请求` | 子帧相位 |
| `mode` | 字符串 | 无 | 是 | `single`、`shuffled`、`sequential` | `请求` | 求值方式，见 5.4 |
| `digest` | 字符串 | 无 | 是 | 小写十六进制，8 到 64 位 | `量的` | 状态摘要，测试工具对求出的状态自己算 |

`frames[]`：帧源算一个输出帧时实际做了什么。一次 `render` 写一项；同一帧渲了不止一次时，同一个帧号可以出现不止一项，各项独立判，不要求合并。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | 落在 `shot` 的帧区间内 | `请求` | 输出帧的全片帧号，下文记作 F；测试工具由它请求的镜头局部帧号加镜头的起始帧算出 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | `请求` | 这一帧所属的镜头 |
| `f` | 整数 | 帧 | 是 | ≥ 0 | `旁观` | 夹具镜头代码收到的帧号 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | `请求` | 这一帧生效的快门角，测试工具照帧源接口契约（F）5.9 的次序从自己传的参数算：这次 `render` 覆盖了就是覆盖后的，没覆盖就是镜头的。每帧都写，不靠缺省；帧源核对记录里同名的字段意思相同 |
| `samples` | 数组 | 无 | 是 | 至少 1 项 | — | 子帧采样，每项见下表 |
| `accumulation` | 对象 | 无 | 否 | | — | 这一帧是逐子帧累积出来的，以及累积怎么做的。被测帧源的能力声明里 `motionBlur.mode` 是 `accumulate` 时出现，是 `native` 时不出现；里面的字段一个都没观测到时写空对象 |
| `accumulation.linearErr` | 双精度 | 无（场景线性值） | 否 | ≥ 0 | `量的` | 帧源交回的累积颜色层，对「各个子帧采样时刻的预言图在线性值上取算术平均」的最大绝对差，边缘带里的像素不计入；量法见 5.6。这一帧量不出就不出现 |
| `accumulation.postRuns` | 整数 | 次 | 否 | ≥ 0 | `自报` | 这一帧上后期链跑了几次；没有后期链就不出现 |
| `accumulation.postInput` | 字符串 | 无 | 与 `postRuns` 同时出现 | `average`、`sample` | `自报` | 后期链吃的是平均后的结果，还是单个子帧 |
| `aux` | `TimeKey` | 帧 | 否 | 全片帧号 | `旁观` | 辅助层取的时刻；没出辅助层就不出现 |
| `auxMismatch` | 整数 | 个（像素） | 否 | ≥ 0 | `量的` | 帧源交回的编号层，对「照校准场景的规格在这一帧的 `sub = 0`、针孔、像素中心求交」的预言图，编号对不上、又不在边缘带里的像素有几个；量法见 5.7。这一帧量不出就不出现 |
| `postDepth` | `TimeKey` | 帧 | 否 | 全片帧号 | `自报` | 后期链用的深度取的时刻 |

`frames[].samples[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | ≥ 0 | `旁观` | 采样时刻的全片帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | `旁观` | 采样时刻的子帧相位 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | `旁观` | 这个采样是对哪个镜头的状态求值得到的 |

`holds[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `f` | 整数 | 帧 | 是 | ≥ 0 | `请求` | 传进去的镜头局部帧号 |
| `n` | 整数 | 帧 | 是 | ≥ 1 | `请求` | 每几帧变一次 |
| `result` | 整数 | 帧 | 是 | ≥ 0 | `量的` | `hold` 返回的值 |

`localized[]`：宿主把一个全片时刻交给镜头代码或卡之前换成镜头局部帧号的一次观测，由夹具镜头代码或夹具卡里的观测点记下，换算见 5.8。交给镜头代码的是 `ctx.events` 的值和 `meta(f)` 收到的帧号（这时 `frame` 是这次出帧的全片帧号），交给卡的是时刻参数。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | `请求` | 交给哪个镜头的镜头代码或卡 |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | `请求` | 这个时刻的全片帧号：时刻参数换成的，或者测试工具放进镜头输入 `events` 里的 |
| `f` | 整数 | 帧 | 是 | 可以是负数，也可以不小于这个镜头的帧数 | `旁观` | 夹具镜头代码或夹具卡收到的帧号 |

`rng[]`：一次运行里取用的一条命名随机流。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `run` | 字符串 | 无 | 是 | 不空 | `请求` | 哪一次运行。两次运行可以是同一个镜头加删对象前后 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | `请求` | 哪个镜头 |
| `arg` | 字符串 | 无 | 是 | 见 3.4 | `请求` | 调用方给的参数 |
| `name` | 字符串 | 无 | 是 | 不空 | `自报` | 宿主展开出的流名 |
| `digest` | 字符串 | 无 | 是 | 小写十六进制，8 到 64 位 | `量的` | 这条流前若干个数的摘要，测试工具取数自己算 |

`scan`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `wallClock` | 数组 | 无 | 是 | 每项 `{ path, call }` | `量的` | 渲染路径里读墙钟的地方，测试工具自己扫源码得出 |
| `unseededRandom` | 数组 | 无 | 是 | 每项 `{ path, call }` | `量的` | 渲染路径里用不带种子的随机的地方，测试工具自己扫源码得出 |

`path` 是相对路径，`call` 是命中的调用名，都是不空的字符串。

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| T1 | 同一个 `(frame, sub, 种子)` 求出的状态必须逐位相同，与求值的次序、次数、之前求过哪些帧无关。 | `evaluations` 里 `shot`、`f`、`sub` 都相同的观测条目，`digest` 必须逐位相同 | `T1-order-dependent.json` |
| T2 | 渲染路径不得读墙钟；5.3 白名单里的调用不算。 | `scan.wallClock` 必须是空数组；扫描清单、白名单和不扫的范围见 5.3 | `T2-wall-clock.json`、`T2-new-date-no-parens.json`、`T2-performance-time-origin.json` |
| T3 | 帧率必须是最简的正有理数字符串，一部片子必须只有一个帧率。 | `fps` 符合 3.2 的写法并且分子分母互质；记录里别处不得再出现帧率 | `T3-decimal-fps.json`、`T3-not-reduced.json`、`T3-fps-elsewhere.json` |
| T4 | 一帧的每个子帧采样必须落在这一帧所属镜头的帧区间内，并且必须对这个镜头的状态求值。 | `frames[i].samples` 每一项：`frame` 落在 `frames[i].shot` 的 `[start, start + frames)` 内，`shot` 等于 `frames[i].shot` | `T4-sample-from-previous-shot.json` |
| T5 | 快门在帧起点打开：第 F 帧的每个子帧采样必须落在 `[F, F + 快门角 ÷ 360)` 内，快门角是 0 时必须只有 `sub = 0` 一个采样。 | `frames[i].samples` 每一项：`frame` 等于 F，`sub` 小于这一帧生效的快门角 ÷ 360；生效的快门角是 0 时正好一项，`sub` 等于 0。生效的快门角取 `frames[i].shutterAngleDeg` | `T5-centered-shutter.json`、`T5-override-narrows-window.json`、`T5-zero-angle-two-samples.json`、`T5-sample-at-window-end.json`、`T5-sample-in-next-frame.json` |

## 5. 口径

### 5.1 帧和秒

- 帧到秒：秒 = (`frame` + `sub`) × 分母 ÷ 分子。
- 秒到帧只在数据入口换算一次：帧 = ⌊秒 × 分子 ÷ 分母 + 0.5⌋。换算之后全程用整数帧。例：`"30/1"` 下 0.467 秒是 14 帧。

### 5.2 状态摘要和「逐位相同」

本契约说两个状态「逐位相同」，指它们的状态摘要作为字符串完全相等，没有容差。摘要算法由做一致性测试的工具定，同一份记录里必须用同一种。

### 5.3 静态扫描的清单

- 墙钟至少包括：`Date.now`、`performance.now`、`performance.timeOrigin`、不带参数的 `new Date()`（括号省掉的 `new Date` 也算）、不带 `new` 的 `Date()`、`time.time`。
- 不带种子的随机至少包括：`Math.random`、`crypto.getRandomValues`、`crypto.randomUUID`、Python `random` 模块里没有显式种子的调用。
- 上面两份清单里的成员，用点号取和用方括号取（`Math['random']`）都算。
- 扫描范围是渲染路径里本仓库的文件，只扫本仓库里的文件。命中一处就写一项 `{ path, call }`。
- 渲染路径里镜头代码这一部分，扫哪些文件照镜头契约（S）5.7 和它第 6 节「扫描顺着哪些引用追」一行：从入口文件出发，只顺着路径写死成字符串的引用一直追，路径是拼出来的（变量、模板字符串、字符串相加）不追。拼出来的路径引进来的文件即使被执行了，也不在本条的扫描范围里，不记进 `scan`，T2、T11 不因它判红；拼出来的路径算不算违反照那一行，现在待定。
- 白名单：宿主可以读单调时钟量耗时，读到的数只许写进每帧元数据（M）的 `timing` 和信封（EN）的 `cost`。这样的调用不记进 `scan.wallClock`。
- 合规档是 `limited` 的帧源（`legacy-page`、`ext.<名字>`，见 F 契约 3.5）里第三方作品的源码不做 T2、T11 的静态扫描，改判 T1 的行为门（5.4）。

### 5.4 三种求值方式

- `single`：新开一次求值，只求这一个时刻。
- `shuffled`：把一批时刻打乱次序求。
- `sequential`：按帧号从小到大求。

T1 的门是同一批时刻用这三种方式各求一遍，再比摘要。合规档是 `limited` 的帧源判其中哪几种，见 F 契约 3.5。

T9 只在起始帧不是 0 的镜头上有判力：只有一个镜头的片子里，镜头局部帧号恒等于全片帧号，传错了也看不出。一致性夹具必须至少有两个镜头，并且必须渲非首镜头。这一句是对夹具的要求，不立不变量。

### 5.5 快门窗口

- 窗口是半开区间 `[F, F + 快门角 ÷ 360)`，用采样的 `frame` 和 `sub` 直接比，没有容差。快门角是这一帧生效的快门角：这次 `render` 覆盖了快门就用覆盖后的角度，没覆盖就用镜头的。
- 逐子帧累积的帧源，窗口里的 N 个采样照居中分层排（T14）：把窗口等分成 N 段，每段取中点。用原生运动模糊的帧源，采样怎么排由渲染器定，T14 不判。
- 默认以帧为中心开快门的渲染器（Blender 是这样），它的帧源适配层必须改成帧起点打开。
- 改过之后两个帧源的快门相位差是 0.0035 帧：探针的运动场景里快门窗口的中点（名义值）是 F + 0.25，Blender 帧源的拖影中点量出来在 F + 0.2465；three 帧源的快门窗口由宿主的子帧累积构造，按定义就在名义值上，因为 T14 把采样排成了关于窗口中点对称。出处：探针数据表第 7 行，Mac 和 5090 两台机器读数相同。这个数是读数，不是容差：没有哪条不变量拿它去比，窗口照本节第一条判，没有容差。

### 5.6 在线性光里取平均

- 场景参考镜头：每个子帧采样只渲到后期链之前的场景线性 HDR 目标，逐像素取算术平均。
- 显示参考镜头：把每个子帧的 8 位帧线性化，再逐像素取算术平均。
- 用渲染器原生运动模糊的帧源（例如 Cycles）用渲染器自己的子帧累积，T6、T7、T14 不判，T4、T5、T8 照判。
- 量法（`accumulation.linearErr`），在校准场景上量：
  1. 对照校准场景的规格，在这一帧的每个子帧采样时刻、镜头孔径按 0（针孔）、像素中心求交，每个时刻得一张预言图。采样时刻照 T14 的算式算，N 是这次 `render` 生效的子帧采样数（帧源接口契约（F）5.9）；不用记录里记下的 `samples`。求交用的规格时刻是镜头局部帧号加子帧相位：t = (F − 这个镜头的 `start`) + `sub`，`sub` 是这个采样的相位；校准场景的第 0 帧对的是镜头的第 0 帧，不拿全片帧号 F 当 t。边缘带的求交时刻同样这样取。
  2. 把这些预言图在场景线性值上逐像素、逐分量取算术平均。
  3. 拿帧源交回的累积颜色层和这张平均图逐像素、逐分量相减，`linearErr` 是差的绝对值里最大的一个。边缘带里的像素不比：每个子帧采样时刻各照输出通道契约（PS）5.1 的办法算一遍边缘带（求交的时刻换成这个采样时刻，挪哪几个位置、怎么算在边缘带里照那里不变），落在任何一个时刻的边缘带里的像素不计入。这些像素上，合规的帧源判到边的哪一侧都行，预言图定不下来。
- 边缘带的 δ 用输出通道契约（PS）5.1 的那个数：光栅化的帧源是十六分之一像素，光线追踪的帧源还是 `待探针`。本契约不另定。
- `linearErr` 不得超过 1e-4（T6）；这个数的来历见第 6 节。
- 边缘带之外的像素在各个采样时刻的预言图里处处相同时（没有运动，或者只有一个子帧采样），两种平均分不出来，测试工具量不出，`linearErr` 不出现，T6 对这一帧不判。
- 预言图是针孔、每像素一个像素中心样本，所以颜色层在像素里另取样本或带景深时，预言图在边缘一圈、离焦的物体上定不下来。下面两种情形测试工具量不出，`linearErr` 不出现，T6 对这一帧不判：这次 `render` 生效的每像素采样数（帧源接口契约（F）3.3 的取法）大于 1；或者这一帧带景深，即校准场景的规格写了镜头孔径，或者这一帧的元数据带 `focusDist`、`fstop`（每帧元数据契约（M）3.2）。颜色层可以带景深，本契约不禁止。
- 预言图在校准场景规格的画幅上求交，即规格里相机的 `widthPx` × `heightPx`。这次 `render` 的输出尺寸不等于这个画幅（生效的缩放不是 1，缩放的取法见帧源接口契约（F）3.3）时，测试工具量不出，`linearErr` 不出现，T6 对这一帧不判。不在缩小后的像素格上另求预言图：缩放后的尺寸怎么取整还没定（帧源接口契约（F）第 6 节）。
- 上面这几种情形都让 T6 不判，夹具全落在里面时 T6 一帧都判不了。一致性夹具必须至少有一个镜头渲不带镜头孔径的校准场景，这个镜头的元数据不带 `focusDist`、`fstop`，生效的每像素采样数是 1，生效的缩放是 1、输出尺寸等于规格的画幅，生效的快门角大于 0、生效的子帧采样数至少 2，并且有在动的物体、在边缘带之外的像素上各个采样时刻的预言图不全相同，好让 `linearErr` 量得出。这一句是对夹具的要求，不立不变量。
- 这个量法只用帧源交回的累积颜色层：一致性测试不需要单独的子帧，帧源接口不为它加「只渲某个子帧」的口子。

### 5.7 辅助层

辅助层见第 2 节。它们取同一个样本：时刻是这一帧的 `sub = 0`，镜头孔径按 0（针孔），快门按 0，不做子帧累积，像素内的位置取像素中心。后期链要用深度时取同一个。

量法（`auxMismatch`），在校准场景上量：

1. 对照校准场景的规格，在这一帧的 `sub = 0`、镜头孔径按 0、像素中心求交，每个像素得到打到的实体，或者没打到；这是预言图。求交用的规格时刻是镜头局部帧号加子帧相位：t = (F − 这个镜头的 `start`) + 0；校准场景的第 0 帧对的是镜头的第 0 帧，不拿全片帧号 F 当 t。第 3 步边缘带的求交时刻同样这样取。
2. 拿帧源交回的 `objectId` 层的 `id` 和预言图逐像素比，按实体名对，怎么对见输出通道契约（PS）5.4。
3. `auxMismatch` 是对不上、又不在边缘带里的像素数。边缘带照输出通道契约（PS）5.1 算，求交的时刻是这一帧的 `sub = 0`；δ 用那边的数（光栅化的帧源是十六分之一像素），本契约不另定。

- `auxMismatch` 必须等于 0（T8），没有容差。
- 这个数只用帧源交回的编号层和校准场景的规格。帧源自己说辅助层怎么取的那句话在能力声明的 `motionBlur.auxAt` 里（帧源接口契约（F）3.4），不进核对记录。
- 取错了要场景里有对应的东西才看得出：开着孔径，要有离对焦面远的物体；开着快门、做了子帧累积，要有在动的物体；不取像素中心，要有斜着扫过像素网格的边。量 T8 用的校准场景必须三样都有（它开着孔径，量不出 `linearErr`；量 T6 的镜头另备，见 5.6）；缺了哪一样，对应的那种取法在这一帧上看不出。这一句是对夹具的要求，不立不变量。
- 这一帧渲的不是校准场景、测试工具手里没有能独立求交的规格时，量不出，`auxMismatch` 不出现，T8 对这一帧只判 `aux` 和 `postDepth`。
- 这次 `render` 的输出尺寸不等于校准场景规格的画幅（生效的缩放不是 1）时同样量不出，`auxMismatch` 不出现，T8 对这一帧只判 `aux` 和 `postDepth`；理由同 5.6，不在缩小后的像素格上另求预言图。

`denoiseAlbedo`、`denoiseNormal` 不是辅助层，照输出通道契约（PS）自己的规定。

### 5.8 镜头局部帧号的换算

- 镜头的起始帧就是片子描述里这个镜头的 `in`（全片帧号），核对记录里记作 `start`。
- 片子描述里的时刻参数写全片帧号或时刻算式（文法见 D 契约 5.3）。宿主交给卡之前必须先换成全片帧号，再减去镜头的起始帧。
- 事件表由帧源上面的一层展开一次，展开好的全片帧号经镜头输入的 `events` 交给帧源（帧源接口契约（F）3.2）。宿主不重新展开事件：`ctx.events` 的值、时刻算式里 `event(x)` 的值，都取镜头输入 `events` 里的全片帧号。
- 减出来的数不截断：可以是负数，也可以不小于镜头帧数，表示这个时刻在镜头之外。
- `ctx.shot`、`ctx.events` 见 S 契约 3.2。类型是 `data` 的卡参数（见 CF 契约 3.3）里面的帧号也是镜头局部帧号：作者直接写镜头局部帧号，宿主不换算（D 契约 5.3）。
