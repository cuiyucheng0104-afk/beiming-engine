# 时间键

版本：0.1.0-draft

## 1. 范围

管：

- 时间键 `TimeKey`、帧率 `Fps`、种子的写法，帧和秒的换算式。
- 状态对时间的依赖：纯函数、不读墙钟、随机只走命名随机流，流名怎么展开。
- 快门窗口的相位、子帧采样、子帧累积和后期链的先后、辅助层取哪个子帧。
- 镜头局部帧号和 `hold`。
- 判定以上各条用的「时间核对记录」。

不管：

- 帧率、快门角、种子、镜头表写在片子描述的哪个字段：片子描述契约（D）。
- `ctx.rng`、`state(f, sub)` 的调用形状：镜头契约（S）。
- 每帧元数据里的时间字段：每帧元数据契约（M）。
- 帧源对外的求帧接口、帧源名的值域：帧源接口契约（F）。
- 辅助层各通道的定义和数值口径：输出通道契约（PS）。

## 2. 术语

| 词 | 含义 |
|---|---|
| 帧 | 输出的一格画面，用整数编号，从 0 起。 |
| 全片帧号 | 从全片第一帧数起的帧号。 |
| 镜头 | 片子描述的镜头表里的一项，占全片帧号的一个连续区间 `[起始帧, 起始帧 + 帧数)`；其余定义见镜头契约（S）。 |
| 镜头局部帧号 | 从本镜头第一帧数起的帧号，记作 `f`。 |
| 子帧相位 | 一帧之内的时刻，记作 `sub`，取值在 `[0, 1)`，0 是帧起点。 |
| 时间键 | `{ frame, sub }` 一对值，表示「第 `frame` 帧起点之后 `sub` 帧」这个时刻。 |
| 帧率 | 每秒多少帧，写成有理数字符串。 |
| 种子 | 一次出片用的一个整数，全片一个，所有随机都由它派生。 |
| 状态 | 某个时刻场景里会影响画面、辅助层或元数据的全部量。 |
| 状态摘要 | 对状态算出的一个字符串，用来比较两个状态是否相同。 |
| 纯函数 | 输出只由写明的输入决定的函数：不读别的东西，也不留下会影响下次调用的东西。 |
| 渲染路径 | 从拿到时间键到交出一帧的画面、辅助层和元数据之间执行的全部代码，包括帧源、宿主、镜头代码和卡。 |
| 墙钟 | 任何返回当前真实时间的调用。 |
| 命名随机流 | 由流名唯一决定的一条随机数序列。 |
| 流名 | 四段的字符串 `<种子>/<镜头>/<用途>/<对象>`。 |
| 快门角 | 快门开着的时长占一帧的比例乘以 360，单位是度。 |
| 快门窗口 | 一帧里快门开着的时间区间。 |
| 子帧采样 | 帧源为了算一帧，在快门窗口里取的一个时刻。 |
| 累积 | 把一帧的多个子帧采样的结果平均成一帧。 |
| 逐子帧累积 | 帧源自己对每个子帧采样各渲一次再平均的做法；用渲染器原生运动模糊的帧源不属于这一种。 |
| 后期链 | 场景渲完之后在画面上依次跑的处理步骤。 |
| 辅助层 | 颜色之外随帧交出的图层：深度、物体编号、法线。 |
| 硬切 | 相邻两个镜头在整数帧上的直接切换。 |
| 场景参考镜头 | 渲染结果先落在场景线性的 HDR 目标上的镜头。 |
| 显示参考镜头 | 渲染结果直接是 8 位显示空间帧、没有 HDR 目标的镜头。 |
| 一拍二 | 画面每 2 帧才变一次的做法。 |
| 帧源 | 按时间键交出一帧画面、辅助层和元数据的渲染后端；以帧源接口契约（F）的定义为准。 |
| 宿主 | 装载镜头、驱动帧源逐帧求值的那层程序；以帧源接口契约（F）的定义为准。 |
| 核对记录 | 一致性测试把一次观测写下来的数据对象，只用来判定不变量；帧源、宿主、镜头代码都不需要产出它。 |

## 3. 结构

### 3.1 时间键 `TimeKey`

内嵌值，不带 `format`，不得有别的字段。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 帧号。是全片帧号还是镜头局部帧号，由用到时间键的那个字段写明 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 子帧相位 |

例子：`{ "frame": 150, "sub": 0 }` 是第 150 帧的起点；`{ "frame": 150, "sub": 0.375 }` 是第 150 帧起点之后八分之三帧的时刻。

### 3.2 帧率 `Fps`

字符串 `"<分子>/<分母>"`。分子和分母是十进制正整数，不带前导零，两者互质。

合法：`"30/1"`、`"24000/1001"`。不合法：`"29.97"`、`"30"`、`"60/2"`。

### 3.3 种子

整数，值域 `[0, 4294967295]`。

### 3.4 流名

调用方给的参数是 `"<用途>/<对象>"`：正好一个 `/`，两段都不空，都不含 `/` 和空白。流名由宿主展开成四段：

| 段 | 取值 |
|---|---|
| 种子 | 种子的十进制写法 |
| 镜头 | 镜头的标识 |
| 用途 | 参数的第一段 |
| 对象 | 参数的第二段 |

例子：种子 20261118，镜头 `s02`，参数 `"scatter/rock.03"`，流名是 `20261118/s02/scatter/rock.03`。

### 3.5 `hold`

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `hold(f, n)` | `f`：镜头局部帧号，整数，≥ 0；`n`：整数，≥ 1，单位帧 | 整数，单位帧 | 把 `f` 压到不超过它的最近一个 `n` 的倍数 |

一拍二写成 `hold(f, 2)`。`hold` 只在镜头代码和卡里用，宿主发下来的时间键不因它改变。

### 3.6 时间核对记录

顶层对象，`format` 是 `time-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `time-check/0.1` | 格式标识 |
| `fps` | 字符串 | 帧每秒 | 是 | 写法见 3.2，由 T3 管 | 全片帧率。全片只有这一处 |
| `seed` | 整数 | 无 | 是 | 见 3.3 | 种子 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | 快门角；0 表示没有运动模糊 |
| `shots` | 数组 | 无 | 是 | 至少 1 项，区间互不重叠 | 镜头表，每项见下表 |
| `evaluations` | 数组 | 无 | 否 | | 纯函数门的观测，每项见下表 |
| `frames` | 数组 | 无 | 否 | | 逐帧采样的观测，每项见下表 |
| `holds` | 数组 | 无 | 否 | | `hold` 的观测，每项见下表 |
| `rng` | 数组 | 无 | 否 | | 命名随机流的观测，每项见下表 |
| `scan` | 对象 | 无 | 否 | | 静态扫描的命中，见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`shots[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 小写字母、数字、连字符 | 镜头的标识 |
| `start` | 整数 | 帧 | 是 | ≥ 0 | 起始帧，全片帧号 |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 帧数 |

`evaluations[]`：对某个镜头的某个时刻求一次状态。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | 哪个镜头 |
| `f` | 整数 | 帧 | 是 | `[0, 该镜头帧数)` | 镜头局部帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 子帧相位 |
| `mode` | 字符串 | 无 | 是 | `single`、`shuffled`、`sequential` | 求值方式，见 5.4 |
| `digest` | 字符串 | 无 | 是 | 小写十六进制，8 到 64 位 | 状态摘要 |

`frames[]`：帧源算一个输出帧时实际做了什么。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | 落在 `shot` 的帧区间内 | 输出帧的全片帧号，下文记作 F |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | 这一帧所属的镜头 |
| `f` | 整数 | 帧 | 是 | ≥ 0 | 交给镜头代码的帧号 |
| `samples` | 数组 | 无 | 是 | 至少 1 项 | 子帧采样，每项见下表 |
| `accumulation` | 对象 | 无 | 否 | | 逐子帧累积怎么做的；用原生运动模糊的帧源不出现 |
| `accumulation.average` | 字符串 | 无 | 是 | `linear`、`encoded` | 在线性光里平均，还是在编码后的值上平均 |
| `accumulation.postRuns` | 整数 | 次 | 否 | ≥ 0 | 这一帧上后期链跑了几次；没有后期链就不出现 |
| `accumulation.postInput` | 字符串 | 无 | 与 `postRuns` 同时出现 | `average`、`sample` | 后期链吃的是平均后的结果，还是单个子帧 |
| `aux` | `TimeKey` | 帧 | 否 | 全片帧号 | 辅助层取的时刻；没出辅助层就不出现 |
| `postDepth` | `TimeKey` | 帧 | 否 | 全片帧号 | 后期链用的深度取的时刻 |

`frames[].samples[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 采样时刻的全片帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 采样时刻的子帧相位 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | 这个采样是对哪个镜头的状态求值得到的 |

`holds[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `f` | 整数 | 帧 | 是 | ≥ 0 | 传进去的镜头局部帧号 |
| `n` | 整数 | 帧 | 是 | ≥ 1 | 每几帧变一次 |
| `result` | 整数 | 帧 | 是 | ≥ 0 | `hold` 返回的值 |

`rng[]`：一次运行里取用的一条命名随机流。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `run` | 字符串 | 无 | 是 | 不空 | 哪一次运行。两次运行可以是同一个镜头加删对象前后 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | 哪个镜头 |
| `arg` | 字符串 | 无 | 是 | 见 3.4 | 调用方给的参数 |
| `name` | 字符串 | 无 | 是 | 不空 | 宿主展开出的流名 |
| `digest` | 字符串 | 无 | 是 | 小写十六进制，8 到 64 位 | 这条流前若干个数的摘要 |

`scan`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `wallClock` | 数组 | 无 | 是 | 每项 `{ path, call }` | 渲染路径里读墙钟的地方 |
| `unseededRandom` | 数组 | 无 | 是 | 每项 `{ path, call }` | 渲染路径里用不带种子的随机的地方 |

`path` 是相对路径，`call` 是命中的调用名，都是不空的字符串。

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| T1 | 同一个 `(frame, sub, 种子)` 求出的状态必须逐位相同，与求值的次序、次数、之前求过哪些帧无关。 | `evaluations` 里 `shot`、`f`、`sub` 都相同的条目，`digest` 必须逐位相同 | `T1-order-dependent.json` |
| T2 | 渲染路径不得读墙钟。 | `scan.wallClock` 必须是空数组；扫描清单见 5.3 | `T2-wall-clock.json` |
| T3 | 帧率必须是最简的正有理数字符串，一部片子必须只有一个帧率。 | `fps` 符合 3.2 的写法并且分子分母互质；记录里别处不得再出现帧率 | `T3-decimal-fps.json` |
| T4 | 一帧的每个子帧采样必须落在这一帧所属镜头的帧区间内，并且必须对这个镜头的状态求值。 | `frames[i].samples` 每一项：`frame` 落在 `frames[i].shot` 的 `[start, start + frames)` 内，`shot` 等于 `frames[i].shot` | `T4-sample-from-previous-shot.json` |
| T5 | 快门在帧起点打开：第 F 帧的每个子帧采样必须落在 `[F, F + 快门角 ÷ 360)` 内，快门角是 0 时必须只有 `sub = 0` 一个采样。 | `frames[i].samples` 每一项：`frame` 等于 F，`sub` 小于 `shutterAngleDeg ÷ 360`；`shutterAngleDeg` 是 0 时正好一项，`sub` 等于 0 | `T5-centered-shutter.json` |
| T6 | 逐子帧累积必须在线性光里取平均。 | `frames[i].accumulation.average` 必须是 `linear`；实测办法见 5.6 | `T6-average-encoded.json` |
| T7 | 逐子帧累积时，后期链在每个输出帧上必须正好跑 1 次，输入必须是平均后的结果。 | `accumulation.postRuns` 出现时必须等于 1，`accumulation.postInput` 必须是 `average` | `T7-post-per-sample.json` |
| T8 | 辅助层和后期链用的深度必须取这一帧 `sub = 0` 的单个采样，不得做累积。 | `aux`、`postDepth` 出现时必须等于 `{ "frame": F, "sub": 0 }` | `T8-aux-mid-shutter.json` |
| T9 | 交给镜头代码和卡的帧号必须是镜头局部帧号，等于全片帧号减去镜头的起始帧。 | `frames[i].f` 必须等于 `frames[i].frame` 减去该镜头的 `start` | `T9-global-frame-leaked.json` |
| T10 | `hold(f, n)` 必须等于 `f − (f mod n)`。 | `holds` 每一项：`result` 等于 `f − (f mod n)` | `T10-hold-rounds-up.json` |
| T11 | 渲染路径里的随机数必须全部取自命名随机流，不得调用不带种子的随机。 | `scan.unseededRandom` 必须是空数组；扫描清单见 5.3 | `T11-unseeded-random.json` |
| T12 | 流名必须等于 `<种子>/<镜头>/<用途>/<对象>`，后两段是调用方给的参数。 | `rng` 每一项：`arg` 符合 3.4，`name` 等于 `seed` 的十进制写法、`shot`、`arg` 用 `/` 连起来 | `T12-stream-name-without-seed.json` |
| T13 | 一条命名随机流产出的序列只由流名决定，与别的流是否存在、调用的先后无关。 | `rng` 里 `name` 相同的条目，不论 `run` 是否相同，`digest` 必须逐位相同 | `T13-stream-disturbed.json` |

## 5. 口径

### 5.1 帧和秒

- 帧到秒：秒 = (`frame` + `sub`) × 分母 ÷ 分子。
- 秒到帧只在入口换算一次：帧 = ⌊秒 × 分子 ÷ 分母 + 0.5⌋。换算之后全程用整数帧。例：`"30/1"` 下 0.467 秒是 14 帧。

### 5.2 状态摘要和「逐位相同」

本契约说两个状态「逐位相同」，指它们的状态摘要作为字符串完全相等，没有容差。摘要算法由做一致性测试的工具定，同一份记录里必须用同一种。

### 5.3 静态扫描的清单

- 墙钟至少包括：`Date.now`、`performance.now`、不带参数的 `new Date()`、`time.time`。
- 不带种子的随机至少包括：`Math.random`、Python `random` 模块里没有显式种子的调用。
- 扫描范围是渲染路径的全部源码。命中一处就写一项 `{ path, call }`。

### 5.4 三种求值方式

- `single`：新开一次求值，只求这一个时刻。
- `shuffled`：把一批时刻打乱次序求。
- `sequential`：按帧号从小到大求。

T1 的门是同一批时刻用这三种方式各求一遍，再比摘要。

### 5.5 快门窗口

- 窗口是半开区间 `[F, F + 快门角 ÷ 360)`，用采样的 `frame` 和 `sub` 直接比，没有容差。
- 默认以帧为中心开快门的渲染器（Blender 是这样），它的帧源适配层必须改成帧起点打开。
- 改过之后两个帧源之间实际还差多少：`待探针：同一运动场景下两个帧源的快门相位差，单位帧`。

### 5.6 在线性光里取平均

- 场景参考镜头：每个子帧采样只渲到后期链之前的场景线性 HDR 目标，逐像素取算术平均。
- 显示参考镜头：把每个子帧的 8 位帧线性化，再逐像素取算术平均。
- 用渲染器原生运动模糊的帧源（例如 Cycles）用渲染器自己的累积，T6、T7 不判，T4、T5、T8 照判。
- 实测办法：静止场景下 8 个子帧采样的累积结果必须等于单个采样的结果，容差 `待探针：静止场景下多子帧累积与单子帧结果的数值差`。

### 5.7 辅助层

深度、物体编号、法线取 `sub = 0` 那一个采样的结果，不带运动模糊。后期链要用深度时取同一个。
