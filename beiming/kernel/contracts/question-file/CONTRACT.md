# 题目文件格式

版本：0.1.0-draft

## 1. 范围

管：

- 题目文件 `question/0.1` 的全部字段：题号、难度、题面、交付规格、自带资产、参考、基础谓词、判分、对照、要用的卡、预算、标记、校准信息。
- 题号的写法。
- 判分权重的要求。

不管：

- 基础谓词的写法、谓词名有哪些：谓词登记表契约（PR）。
- 指标怎么算：不归本契约，归属见第 6 节。
- 题目怎么挂到一部片上、挂上之后谁能改基础谓词：片子描述契约（D）D7。
- 卡名的写法：卡文件格式契约（CF）5.1。
- 帧率的写法：时间键契约（T）3.2。
- 题目文件放在哪个目录：目录归属表契约（OW）。

## 2. 术语

帧、帧率：见时间键契约（T）第 2 节。卡：见卡的运行时接口契约（CR）第 2 节。卡名：见卡文件格式契约（CF）第 2 节。谓词、断言：见谓词登记表契约（PR）第 2 节。

| 词 | 含义 |
|---|---|
| 题目 | 一道考题：给一段需求和规格，按写死的断言和判分判一部成片。 |
| 题目文件 | 描述一道题的一个数据文件。 |
| 题号 | 题目的标识，例如 `28-1`。 |
| 题面 | 写给做题方看的需求原文。 |
| 基础谓词 | 题目自带的断言。做题方只能加，不能删，不能放松。 |
| 指标 | 判分用的一种有名字的量，点分小写，例如 `loop.closure-psnr`。 |
| 对照 | 证明判分没有失灵的两类提交：标准答案必须得满分，负对照必须判不合格。 |
| 隐藏题 | 做题方只看得到题面、看不到判分细则的题。 |
| 噪声地板 | 同一份标准答案重复出片时，指标自己的波动幅度。 |

## 3. 结构

题目文件的任何一层都不得出现本节没列的键；`scoring[].args` 里面不受这一条管。

### 3.1 题目文件

顶层对象，`format` 是 `question/0.1`。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `format` | 字符串 | 是 | `question/0.1` | 格式标识 |
| `id` | 字符串 | 是 | 题号，写法见 5.1 | 题号 |
| `level` | 整数 | 是 | ≥ 1 | 难度级别 |
| `title` | 字符串 | 是 | 不空 | 标题 |
| `brief` | 字符串 | 是 | 不空 | 题面 |
| `deliverable` | 对象 | 是 | 见 3.2 | 交付规格 |
| `assets` | 对象 | 是 | `{ 别名: 资产引用 }`；别名是 ASCII 字母、数字、下划线；可以是空对象 | 题目自带的资产 |
| `refs` | 数组 | 否 | 路径，写法见通用口径 | 参考材料 |
| `basePredicates` | 数组 | 是 | 至少 1 项，不重复；每项是一条断言，写法见 PR 契约 5.5，一项里不用 `;` 连几条 | 基础谓词 |
| `scoring` | 数组 | 是 | 至少 1 项，每项见 3.3 | 判分 |
| `controls` | 对象 | 是 | 见 3.4 | 对照 |
| `needs` | 数组 | 是 | 卡名，不带版本，不重复；可以是空数组 | 这道题要用到的卡 |
| `budget` | 对象 | 是 | 见 3.5 | 做这道题的预算 |
| `flags` | 对象 | 是 | 见 3.6 | 标记 |
| `calibration` | 对象 | 是 | 见 3.7 | 这道题的阈值校准到什么程度 |
| `ext` | 对象 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `deliverable`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `width` | 整数 | 像素 | 是 | ≥ 1 | 宽 |
| `height` | 整数 | 像素 | 是 | ≥ 1 | 高 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 帧率 |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 总帧数 |
| `audio` | 字符串 | 无 | 是 | `none`；别的取值 `待定：有声音的题怎么写` | 要不要声音 |

### 3.3 `scoring[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `metric` | 字符串 | 是 | 指标名，点分小写 | 用哪个指标 |
| `source` | 字符串 | 否 | 不空 | 指标读什么数据，例如 `frame-meta` |
| `args` | 对象 | 否 | | 给指标的参数 |
| `pass` | 字符串 | 是 | 不空 | 怎样算过 |
| `weight` | 双精度 | 是 | `(0, 1]` | 权重 |

### 3.4 `controls`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `referencePass` | 字符串 | 是 | 不空 | 标准答案必须得到什么结果 |
| `negative` | 字符串 | 是 | 不空 | 哪份负对照必须判不合格 |
| `random` | 字符串 | 否 | 不空 | 随机对照：任取一帧的命中率当基线。对拍点类的题必须写 |

### 3.5 `budget`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `tokens` | 整数 | 个 | 是 | ≥ 1 | 模型 token 上限 |
| `wallSeconds` | 双精度 | 秒 | 是 | > 0 | 墙钟上限。这是记账的数，不进渲染路径 |
| `gpuSeconds` | 双精度 | 秒 | 是 | ≥ 0 | 显卡秒上限 |

### 3.6 `flags`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `hidden` | 布尔 | 是 | | 是不是隐藏题 |
| `expectedFail` | 布尔 | 是 | | 是不是预期现在做不出来的题 |
| `blockedBy` | 数组 | 是 | 不空的字符串；可以是空数组 | 被什么挡着，现在不能考 |

### 3.7 `calibration`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `status` | 字符串 | 是 | `uncalibrated`；别的取值 `待定：校准状态还有哪几个值` | 校准状态；`uncalibrated` 是初值、还没校准 |
| `source` | 字符串 | 是 | 不空 | 阈值的出处 |
| `noiseFloor` | 双精度或 `null` | 是 | | 噪声地板；`null` 表示还没量。`待探针：每道题的指标在标准答案重复出片时的波动` |
| `version` | 整数 | 是 | ≥ 0 | 校准过几次 |

可以是 `null` 的字段只有 `calibration.noiseFloor`。

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| QF1 | `scoring` 各项的 `weight` 加起来必须等于 1。 | 按书写顺序求和，和 1 的差的绝对值不超过 1e-9 | `QF1-weights-sum-1.1.json` |
| QF2 | `basePredicates` 每一条的谓词名必须是谓词登记表里登记过的。 | 照 PR 契约 5.5 取每条断言的谓词名，在 `predicates/predicates.json` 的 `name` 里逐字符找 | `QF2-unregistered-predicate.json` |

## 5. 口径

### 5.1 题号

两个正整数用一个 `-` 连接，十进制，不带前导零：前一个是这道题出自的案例的编号，后一个是它在这个案例里的序号。例：`28-1`、`29-2`。

### 5.2 基础谓词

一项一条断言。题目挂到片上之后，这些断言由服务器按题号重新展开进那部片的基础谓词；做题方提交的副本不算数（D7）。

### 5.3 指标名和卡名

两种名字都是点分小写。在文字里单独提到指标时，一律写成 `metric:` 加指标名，例如 `metric:audio.loudness`；卡名不带前缀，例如 `audio.master`。`scoring[].metric` 这个字段里只写指标名，不带前缀。

### 5.4 对照

每道题必须同时有 `referencePass` 和 `negative`：标准答案得不到满分，或者负对照没被判不合格，这道题的判分就不可信，不能用来记成绩。

### 5.5 隐藏题

`flags.hidden` 是 `true` 的题，做题方只拿得到 `brief`、`deliverable`、`assets`；`scoring`、`controls`、`calibration` 不回给做题方。

## 6. 待定

| 项 | 现在怎么写 | 等什么 |
|---|---|---|
| 字段名 | 需求来源用下划线：`base_predicates`、`reference_pass`、`expected_fail`、`blocked_by`、`noise_floor`、`tol_px`。照通用口径改成小驼峰 | 集成负责人确认 |
| 格式标识 | 需求来源没有；照通用口径加 `"format": "question/0.1"` | 集成负责人确认 |
| 落盘的文件名和序列化 | 需求来源的样例是 YAML。本契约只定数据的结构，例子用 JSON | 集成负责人确认 |
| `deliverable.fps` | 需求来源的样例写的是数 `24`；照时间键契约写成字符串 `"24/1"` | 集成负责人确认 |
| `budget` 的字段名 | 需求来源的样例是 `wall_s`、`gpu_s`；【起草者补】写成 `wallSeconds`、`gpuSeconds`，和建工作区时的预算用同一组名字 | 集成负责人确认 |
| `calibration.status` 的词 | 需求来源的样例是中文「初值未校准」。【起草者补】写成 `uncalibrated`；还有哪几个值不定 | 集成负责人确认 |
| `deliverable.audio` | 只知道 `none` | 第一道有声音的题 |
| 题号的写法 | 【起草者补】从两个样例定；库外案例的题怎么编号不定 | 集成负责人确认 |
| `level` 的上限、各级的含义 | 不定 | 集成负责人确认 |
| 资产引用的写法 | 样例是 `calib/mech-head-proxy@1`，和片子描述里资产引用的写法不是一种；本契约只要求不空 | 片子描述契约（D）5.5 |
| 断言里的 `subject` 怎么对到实体 | 样例用资产的别名当实参；它怎么对到实体名或角色不定 | 谓词登记表契约（PR）、每帧元数据契约（M） |
| `refs` 能指向哪里 | 需求来源的样例指向仓库外面的私有目录。本契约只收仓库里的相对路径，例子里是示意值 | 集成负责人确认 |
| 指标的登记表 | 没有；`metric` 只要求点分小写 | 集成负责人指派归哪份契约 |
| `blockedBy` 里写什么 | 不定，现在是自由文字 | 集成负责人确认 |
| `needs` 和卡文件 `exams` 要不要互相对上 | 不定，没有立成不变量 | 集成负责人确认 |
| `deliverable` 和 `delivery(…)` 那条基础谓词要不要对上 | 样例里两边的数相同；没有立成不变量 | 集成负责人确认 |
| QF1 | 【起草者补】样例的三个权重加起来是 1，立成条文 | 集成负责人确认 |
| 5.5 隐藏题回哪几个字段 | 需求来源只说「只回题面，不回判分细则」；字段清单是【起草者补】，没有立成不变量 | 集成负责人确认 |
| 例子里的预算、阈值、出处、路径 | `full` 照需求来源的样题抄，`refs` 和 `calibration.source` 换成了示意值；`minimal` 全是示意值 | 样题入库时换 |
