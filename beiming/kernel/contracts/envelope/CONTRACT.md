# 信封

版本：0.1.0-draft

## 1. 范围

管：

- 信封 `envelope/0.1` 的全部字段：每个动词的每次返回都包在它里面，成功、失败都一样。
- 信封里的错误对象、诊断、交付物引用、成本、下一步。
- `ok`、`exitCode`、`error` 三者的关系。

不管：

- 错误码有哪些、前缀对哪个退出码：错误码表契约（ER）。
- 诊断里的修法 `fix`、补丁：补丁格式契约（PA）。
- 诊断的 `at` 用的路径写法：片子描述契约（D）5.4。
- 一条谓词的判定结果长什么样：谓词登记表契约（PR）3.5。
- 修订号对不上时怎么拒：D6。
- `data` 里面放什么：各动词自己定，不归本契约。
- 动词表、每个动词的返回上限：不归本契约，归属见第 6 节。

## 2. 术语

帧：见时间键契约（T）第 2 节。路径、修订号：见片子描述契约（D）第 2 节。修法：见补丁格式契约（PA）第 2 节。错误码、前缀、退出码：见错误码表契约（ER）第 2 节。

| 词 | 含义 |
|---|---|
| 信封 | 一次返回的最外层对象。命令行、HTTP、MCP 三个调用入口交回的是同一个形状。 |
| 动词 | 一个 HTTP 方法加一条路径，例如 `POST /v1/films/f_8k2/verify`。 |
| 诊断 | 一条检查结果：哪里、哪一层、出了什么事、怎么修。 |
| 层 | 验收的五层之一，写成 `L1` 到 `L5`。 |
| 交付物引用 | 信封里指向一个落盘文件的一项：种类、地址、哈希。 |
| 成本 | 这一次调用花掉的 token、显卡秒和墙钟。 |
| 下一步 | 信封里建议接着调的动词和理由。 |

## 3. 结构

信封的任何一层都不得出现本节没列的键。

### 3.1 信封

顶层对象，`format` 是 `envelope/0.1`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `envelope/0.1` | 格式标识 |
| `ok` | 布尔 | 无 | 是 | | 成没成，见 EN1 |
| `exitCode` | 整数 | 无 | 是 | 0、1、2、3、4、5、124 | 退出码；0 是成功，其余的含义见 ER 契约 5.1 |
| `error` | 对象或 `null` | 无 | 是 | 见 3.2 | 出了什么错；`null` 表示这次没有错误 |
| `outputs` | 数组 | 无 | 是 | 每项见 3.3；可以是空数组 | 这次调用产出的文件 |
| `data` | 对象 | 无 | 是 | 可以是空对象 | 这个动词自己的结果 |
| `diagnostics` | 数组 | 无 | 是 | 每项见 3.4；可以是空数组 | 诊断 |
| `cost` | 对象 | 无 | 是 | 见 3.5 | 成本 |
| `next` | 数组 | 无 | 是 | 每项见 3.6；可以是空数组 | 下一步 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `error`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `code` | 字符串 | 是 | 错误码，写法见 ER 契约 5.2 | 哪一种错 |
| `message` | 字符串 | 是 | 不空 | 一句话：出了什么事 |
| `hint` | 字符串 | 否 | 不空 | 下一步怎么做；没有就不出现 |

### 3.3 `outputs[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `kind` | 字符串 | 是 | 小写字母、数字、连字符，以字母开头 | 种类；现在用到的有 `master`、`web`、`contact`、`report`、`lock` |
| `url` | 字符串 | 是 | 不空 | 只读文件路由上的地址，取的时候要带工作区令牌 |
| `sha256` | 字符串 | 否 | 64 位小写十六进制 | 文件内容的哈希 |

### 3.4 `diagnostics[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `code` | 字符串 | 无 | 是 | 错误码，写法见 ER 契约 5.2 | 哪一种问题 |
| `layer` | 字符串 | 无 | 是 | `L1`、`L2`、`L3`、`L4`、`L5` | 哪一层查出来的 |
| `severity` | 字符串 | 无 | 是 | `error`、`warning` | 是错误还是警告 |
| `at` | 字符串 | 无 | 否 | 路径，写法见 D 契约 5.4 | 问题在片子描述的哪里 |
| `message` | 字符串 | 无 | 是 | 不空 | 一句话：出了什么事 |
| `value` | 任意 JSON 值，不得是 `null` | 无 | 否 | | 实测到的值；没有就不出现 |
| `expected` | 字符串 | 无 | 否 | 不空 | 应该是什么 |
| `atFrames` | 数组 | 帧 | 否 | 全片帧号，整数，≥ 0 | 反例帧 |
| `evidence` | 字符串 | 无 | 否 | 不空 | 证据的编号；没有就不出现 |
| `hint` | 字符串 | 无 | 否 | 不空 | 怎么修的提示；没有就不出现 |
| `fix` | 修法 | 无 | 否 | 见 PA 契约 3.3 | 机械的修法 |

### 3.5 `cost`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `tokens` | 整数 | 个 | 是 | ≥ 0 | 这次调用里服务器替调用方花掉的模型 token |
| `gpuSeconds` | 双精度 | 秒 | 是 | ≥ 0 | 显卡秒 |
| `wallMs` | 整数 | 毫秒 | 是 | ≥ 0 | 墙钟。这是记账的数，不进渲染路径 |

### 3.6 `next[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `verb` | 字符串 | 是 | 方法、一个空格、路径；方法是 `GET`、`POST`、`PUT`、`DELETE`，路径以 `/v1/` 开头，不含空白 | 建议接着调的动词 |
| `why` | 字符串 | 否 | 不空 | 为什么 |

### 3.7 哪些字段可以是 `null`

只有 `error` 一个，它必填可空：`null` 的原因是「这次没有」（这次没有错误）。别的字段不得是 `null`；`error.hint`、`diagnostics[].value`、`diagnostics[].evidence`、`diagnostics[].hint` 是可选不空，没有就不出现。

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| EN1 | `ok` 必须在 `exitCode` 是 0 时是 `true`，不是 0 时是 `false`。 | 比 `ok` 和 `exitCode === 0` | `EN1-ok-false-exit-0.json` |
| EN2 | `exitCode` 是 0 时 `error` 必须是 `null`，不是 0 时 `error` 必须是对象。 | 看 `exitCode` 和 `error` 的类型 | `EN2-exit-4-without-error.json` |
| EN3 | `error` 是对象时，`exitCode` 必须等于 `error.code` 的前缀在错误码表里对到的退出码。 | 在错误码表的 `prefixes` 里找 `error.code` 开头的那一项，比它的 `exitCode` 和信封的 `exitCode`；`prefixes` 里找不到这样一项时本条不判，这种码归 EN4（ER 契约的 ER1 要求登记过的码都以 `prefixes` 里的某一项开头，所以这种码一定没登记）；`prefix` 的写法是小写字母加一个 `.`（ER 契约 3.2），两个前缀不会一个是另一个的开头，取哪一项和表里的次序无关 | `EN3-busy-code-exit-4.json` |
| EN4 | `error.code` 和每条诊断的 `code` 必须是错误码表里登记过的码。 | 在错误码表的 `codes` 里逐字符找 | `EN4-unregistered-code.json`、`EN4-unknown-prefix.json` |

## 5. 口径

### 5.1 错误码表

EN3、EN4 说的错误码表是 `errors/errors.json`，结构见 ER 契约。

### 5.2 三个调用入口

命令行、HTTP、MCP 三个调用入口交回同一个信封。命令行进程的退出码等于信封的 `exitCode`。HTTP 状态码怎么对见第 6 节。

### 5.3 文字

`message`、`hint`、`why` 是给人和 agent 读的中文句子，不是机器接口；机器只认 `code`、`at`、`fix`。
