# 输出通道

版本：0.1.0-draft

## 1. 范围

管：

- 通道登记表：每个通道的名字、分量、位深、单位、色彩空间、取法、抗不抗锯齿。
- 各通道的数值定义：深度量什么、编号是什么数、法线在哪个空间、运动矢量怎么算。
- 通道声明 `passes/0.1` 的全部字段。核心帧源和标准答案机各写一份，照同一张登记表；别的帧源只列自己交得出的通道。
- 深度、编号、法线、运动矢量取辅助样本，不取平均。
- 判定以上各条用的「通道核对记录」。

不管：

- 一次 `render` 能要哪些输出、交不出时怎么报错、能力声明里的 `outputs` 和 `channels`：帧源接口契约（F）。F 契约 `OutputName` 的值域是 `meta` 加 3.1 登记表里的全部通道名；同名的输出是同一层，数值定义以本契约为准；只有一处例外：显示参考镜头的 `color`，数值含义以 F 契约 5.2 为准，见本契约 5.2。
- 快门窗口：时间键契约（T）。辅助样本的时刻在 5.1，和 T 契约的 T8 是同一个规定。
- 编号和实体的对应、屏幕坐标、平面深度这个词：每帧元数据契约（M）。
- 实体的编号从哪来：帧源接口契约（F）3.6。本契约只引用。
- 场景、灯、相机从哪里来：场景包契约（SP）。
- 帧源交的各层怎么装进文件（层文件的格式、层引用）：帧源接口契约（F）3.3。
- 参考包里的各层怎么装、采样数、种子、采样图案、像素滤波、参考噪声地板：参考包契约（RP）。
- 降噪之后的颜色、过了显示变换的颜色：不在这一套通道里。显示参考镜头的 `color` 是什么：帧源接口契约（F）5.2，本契约只引用。
- 两侧的同名层差多少算过：谓词登记表契约（PR）。

## 2. 术语

帧、子帧相位、时间键、快门角、快门窗口、种子、辅助层、场景参考镜头、显示参考镜头、核对记录：见时间键契约（T）第 2 节。帧源、宿主、能力声明、输出、实体清单、层文件：见帧源接口契约（F）第 2 节。编号、平面深度：见每帧元数据契约（M）第 2 节。实体：见镜头契约（S）第 2 节。场景包、实例、镜像实例：见场景包契约（SP）第 2 节。

| 词 | 含义 |
|---|---|
| 通道 | 随一帧交出的一层有名字的逐像素数据，由一个或几个分量组成。 |
| 分量 | 通道里的一个数，例如颜色的 `R`。 |
| 位深 | 一个分量用什么数值类型存：`f32` 是 32 位浮点，`u32` 是 32 位无符号整数。 |
| 核心帧源 | 帧源名是 `core` 的帧源。 |
| 标准答案机 | 用 Cycles 出参考答案的那套程序，本契约里写作 `oracle`。它不是帧源，不在帧源名的值域里。 |
| 出层方 | 交出这一套通道的一方：`core` 或 `oracle`。 |
| 通道对拍 | 把两个出层方对同一个场景、同一帧交出的同名通道逐层相比。 |
| 样本 | 为了算一个像素，从相机经这个像素射进场景的一条路径和它算出的结果。 |
| 辅助样本 | 辅助层（3.1 登记表里取法是 `sub0` 的通道）共用的那一个样本：每个像素一个，不参加样本累积，取法见 5.1。 |
| 样本累积 | 把一个像素的全部样本按像素滤波的权重合成一个值。 |
| 像素滤波 | 样本落在像素内不同位置时各占多少权重的规则。 |
| 抗锯齿 | 一个通道的值是样本累积出来的，物体边缘上的像素得到两边的混合值。 |
| 覆盖率 | 一个像素颜色层的全部样本里，打到的编号和辅助样本相同的样本所占的比例。 |
| 边缘带 | 比两张编号图时不计入「不相同」的那些像素，定义见 5.1。 |
| 分灯组 | 只算某一组灯的贡献的一层颜色。组名取自场景包里灯的 `group`，见 3.1。 |
| 降噪特征通道 | 专门喂给降噪器的反照率层和法线层。 |
| 通道登记表 | 3.1 的那张表，全系统只有这一张。 |
| 通道声明 | 一个出层方把自己交的每个通道的属性写下来的数据对象，结构见 3.2。 |
| 通道核对记录 | 一致性测试把对出层方的观测写下来的数据对象，只用来判定不变量；出层方不需要产出它。 |

## 3. 结构

### 3.1 通道登记表

通道名是下表第一列的词，大小写照写。`lightgroup:<名>` 里的 `<名>` 是小写字母、数字、连字符，以字母或数字开头；它取场景包里灯的 `group`，灯没写 `group` 时取灯名（场景包契约 SP 3.6），同一个 `<名>` 下的灯算进同一层。一个声明里可以有 0 个或更多个分灯组。前七行叫「固定通道」。

| 通道名 | 分量（次序固定） | 位深 | 单位 | 色彩空间 `colorSpace` | 取法 `sample` | 抗锯齿 `antialiased` | 是什么 |
|---|---|---|---|---|---|---|---|
| `color` | `R`、`G`、`B`、`A` | 四个都是 `f32` | `R`、`G`、`B` 是辐亮度，口径见 5.2；`A` 无单位 | `scene-linear-rec709`：场景线性，Rec.709 原色 | `accumulate` | `true` | 线性颜色，未降噪 |
| `depth` | `Z` | `f32` | 米 | `none`：不是颜色 | `sub0` | `false` | 平面深度 |
| `objectId` | `id`、`coverage` | `id` 是 `u32`，`coverage` 是 `f32` | 无 | `none` | `sub0` | `false` | 物体编号加覆盖率 |
| `normal` | `X`、`Y`、`Z` | 三个都是 `f32` | 无 | `none` | `sub0` | `false` | 法线，相机空间 |
| `motion` | `X`、`Y` | 两个都是 `f32` | 像素每帧 | `none` | `sub0` | `false` | 运动矢量 |
| `denoiseAlbedo` | `R`、`G`、`B` | 三个都是 `f32` | 无 | `scene-linear-rec709` | `accumulate` | `true` | 降噪用的反照率 |
| `denoiseNormal` | `X`、`Y`、`Z` | 三个都是 `f32` | 无 | `none` | `accumulate` | `true` | 降噪用的法线 |
| `lightgroup:<名>` | `R`、`G`、`B` | 三个都是 `f32` | 辐亮度，口径同 `color` | `scene-linear-rec709` | `accumulate` | `true` | 分灯组：这一组灯单独样本累积出的颜色，未降噪 |

`sample` 是 `accumulate` 的通道做样本累积、抗锯齿；是 `sub0` 的通道是辅助层，取辅助样本（见 5.1）、不抗锯齿。`objectId` 的 `coverage` 是从颜色层的全部样本数出来的比例，算法见 5.4；它所在的通道仍然按 `sub0` 登记。

### 3.2 通道声明 `PassTable`

顶层对象，`format` 是 `passes/0.1`。本契约里没有可以是 `null` 的字段。出层方（`core`、`oracle`）的声明必须交齐七个固定通道；别的帧源的声明只列自己交得出的通道。两样都由 PS1 管；「交齐七个固定通道」在哪里判，见 3.3。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `passes/0.1` | 格式标识；能力声明的 `channels` 写的就是它 |
| `channels` | 数组 | 无 | 是 | 至少 1 项；含哪些通道由 PS1 管 | 这个出层方交的每个通道，每项见下表；次序不算数 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`channels[]`，不得有别的字段：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 3.1 的通道名 | 通道名 |
| `components` | 数组 | 无 | 是 | 至少 1 项，每项 `{ name, type }`：`name` 是不空的字符串，`type` 是 `f32` 或 `u32`；取值由 PS2 管 | 分量和各自的位深，次序算数 |
| `colorSpace` | 字符串 | 无 | 是 | `scene-linear-rec709`、`none` | 色彩空间：场景线性加 Rec.709 原色，或者不是颜色。写的是场景参考镜头下的含义；出层方交的这一套通道里没有显示空间的层。显示参考镜头的 `color` 见 5.2 |
| `sample` | 字符串 | 无 | 是 | `accumulate`、`sub0` | 取法：全部样本累积，或只取辅助样本 |
| `antialiased` | 布尔 | 无 | 是 | | 抗不抗锯齿 |

### 3.3 通道核对记录

顶层对象，`format` 是 `passes-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。只看通道声明就能判的不变量（PS1 里对名字的要求）对单独的一份通道声明也照判；PS1 里「七个固定通道齐全」和 PS2 只对 `sides` 里出层方的声明判。

「来历」一栏的四个词见契约写法约定 3.1。格式标识、`ext` 和各段的数组本身不是观测，来历写「—」，段里的字段各自标。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `passes-check/0.1` | — | 格式标识 |
| `sides` | 数组 | 无 | 是 | 1 项或 2 项，`producer` 不重复（PS6） | — | 被测的出层方和它的通道声明，每项见下表 |
| `pixels` | 数组 | 无 | 否 | | — | 把某个像素的各个样本和交出来的值摆在一起的观测，每项见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

`sides[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `producer` | 字符串 | 无 | 是 | `core`、`oracle` | `请求` | 哪个出层方 |
| `table` | `PassTable` | 无 | 是 | 见 3.2 | `自报` | 它交出的通道声明，整份收进来 |

`pixels[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `producer` | 字符串 | 无 | 是 | `sides` 里出现过的 `producer`（PS6） | `请求` | 这个像素是谁渲的 |
| `x` | 整数 | 像素 | 是 | ≥ 0 | `请求` | 像素的列号，从画面左边数，从 0 起 |
| `y` | 整数 | 像素 | 是 | ≥ 0 | `请求` | 像素的行号，从画面上边数，从 0 起 |
| `aux` | 对象 | 无 | 是 | 字段同 `samples[]` 的一项，见下表 | `自报` | 出层方报的：这个像素的辅助样本（照 5.1 取的那一个）打到了什么 |
| `samples` | 数组 | 无 | 是 | 至少 1 项，每项见下表 | `自报` | 出层方报的：这个像素颜色层做样本累积用的全部样本，照采样次序排；辅助样本不在里面 |
| `out` | 对象 | 无 | 是 | 见下表 | — | 测试工具从交出来的各层里读回的这个像素的值 |

`pixels[].aux` 和 `pixels[].samples[]` 的每一项。样本什么都没打到时，四个字段写 5.1 给这种情况定的值：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `id` | 整数 | 无 | 是 | ≥ 0 | `自报` | 这个样本打到的实体的编号；0 表示没打到任何实体，见 5.1 |
| `depth` | 双精度 | 米 | 是 | ≥ 0 | `自报` | 这个样本命中点的平面深度 |
| `normal` | 数组 | 无 | 否 | `[x, y, z]` | `自报` | 这个样本命中点的法线，相机空间 |
| `motion` | 数组 | 像素每帧 | 否 | `[x, y]` | `自报` | 这个样本命中点的运动矢量 |

`pixels[].out`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `depth` | 双精度 | 米 | 是 | ≥ 0 | `量的` | `depth` 通道里这个像素的值 |
| `id` | 整数 | 无 | 是 | ≥ 0 | `量的` | `objectId` 通道的 `id` 分量 |
| `coverage` | 双精度 | 无 | 是 | `[0, 1]` | `量的` | `objectId` 通道的 `coverage` 分量 |
| `normal` | 数组 | 无 | 否；出现时 `aux` 必须有 `normal`（PS4） | `[x, y, z]` | `量的` | `normal` 通道里这个像素的值 |
| `motion` | 数组 | 像素每帧 | 否；出现时 `aux` 必须有 `motion`（PS4） | `[x, y]` | `量的` | `motion` 通道里这个像素的值 |

哪几条的查法靠的是 `自报` 的字段，见第 6 节「靠出层方自己的说法判的条文」一行。

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| PS1 | 通道声明里每一项的名字必须是 3.1 登记表里的通道名，名字不得重复；出层方（`core`、`oracle`）的通道声明还必须含七个固定通道各正好一项。 | 把 `channels[].name` 收成一列：每个名字要么是七个固定通道名之一，要么符合 3.1 的 `lightgroup:<名>` 写法；整列没有重复。`sides` 里的每份声明另外查：`color`、`depth`、`objectId`、`normal`、`motion`、`denoiseAlbedo`、`denoiseNormal` 各出现正好 1 次 | `PS1-missing-denoise-normal.json`、`PS1-unregistered-name.json`、`PS1-duplicate-name.json` |
| PS2 | 出层方的通道声明里每个通道的 `components`、`colorSpace`、`sample`、`antialiased` 必须和通道登记表里同名的那一行逐项相同。 | `sides` 里每份声明的 `channels` 每一项：按 `name` 找 3.1 的行（`lightgroup:<名>` 都找最后一行），`components` 的项数、每项的 `name` 和 `type`、次序，以及另外三个字段，逐个比，必须全部相等。名字不在登记表里的项不归这一条，归 PS1 | `PS2-depth-antialiased.json`、`PS2-normal-components-reversed.json`、`PS2-albedo-colorspace-none.json` |
| PS3 | 通道对拍的两个出层方的通道声明里，通道名的集合必须相同。 | `sides` 里 `core` 和 `oracle` 都出现时：两份 `table.channels` 的 `name` 各收成一个集合，一边有、另一边没有的名字必须是 0 个。次序不比。同名通道的字段相不相等不归这一条，归 PS2：两侧各自等于登记表，同名通道就相等 | `PS3-core-lacks-lightgroup.json`、`PS3-oracle-lacks-lightgroup.json` |
| PS4 | 辅助层 `depth`、`objectId` 的 `id`、`normal`、`motion` 在每个像素上必须等于这个像素辅助样本的值，不得是多个样本的平均或别的合成。 | `pixels` 每一项：`out.depth` 必须等于 `aux.depth`，`out.id` 必须等于 `aux.id`；`out.normal`、`out.motion` 出现时，`aux` 必须有同名数组，并且两个数组逐个数相等；`aux` 没有同名数组算不相等。都没有容差 | `PS4-depth-id-averaged.json`、`PS4-normal-averaged.json`、`PS4-motion-aux-missing.json` |
| PS5 | `objectId` 的 `coverage` 必须等于这个像素颜色层的样本里编号和辅助样本相同的样本数除以样本总数。 | `pixels` 每一项：数出 `samples` 里 `id` 等于 `aux.id` 的项数 k，`samples` 的项数 n；`out.coverage` 和 `k ÷ n` 的差的绝对值必须不大于 0.000001，按双精度的值比 | `PS5-coverage-is-one.json` |
| PS6 | 通道核对记录里 `sides` 各项的 `producer` 不得重复，`pixels` 每一项的 `producer` 必须是 `sides` 里出现过的 `producer`。 | 把 `sides[].producer` 收成一列：整列没有重复；`pixels` 每一项的 `producer` 必须在这一列里 | `PS6-sides-producer-twice.json`、`PS6-pixel-producer-not-in-sides.json` |

## 5. 口径

### 5.1 样本和辅助样本

- 颜色层一个像素取多少个样本、用哪种采样图案、哪种像素滤波，由出这一帧的设置定，记在参考包清单里（参考包契约 RP）。
- 辅助层指 `depth`、`objectId`、`normal`、`motion` 四个通道。它们取同一个样本，叫辅助样本：时刻是这一帧的 `sub = 0`，镜头孔径按 0（针孔），快门按 0，不做样本累积，像素内的位置取像素中心。这和时间键契约（T）的 T8 是同一个规定。
- 辅助样本每个像素正好一个，和颜色层的样本数、种子、采样图案都无关。它不是颜色层的样本里的某一个。
- `denoiseAlbedo`、`denoiseNormal` 不是辅助层，照 5.7。
- `objectId` 的 `id` 是 0，表示辅助样本没打到任何实体。辅助样本打到了不属于任何实体的东西时，`id` 是 0，`depth`、`normal`、`motion` 照命中点如实写。
- 辅助样本什么都没打到时：`id` 是 0，`depth` 是 1e10（米），`normal` 是 `(0, 0, 0)`，`motion` 是 `(0, 0)`。1e10 用 32 位浮点能精确表示；法线的长度是 0，和打到东西时的长度 1 分得开。
- 探针量到的口径（探针数据表第 4 行，Mac 和 5090 两台机器读数一致）：three 帧源和 Blender 帧源的编号层都不抗锯齿、取像素中心。宽度不到 1 像素的物体可以在编号层里一个像素都不占：它落在像素中心之间时，没有辅助样本打到它。
- 两个出层方都取像素中心。物体边缘上两侧取到的编号还差多少：`待探针：编号边缘，核心帧源和标准答案机的 id 不相同的像素占全画面的比例`。
- 边缘带，比两张编号图时用。把辅助样本在像素内的位置从像素中心沿 x、沿 y 各挪 −δ、0、+δ（单位是像素；除去像素中心自己，一共 8 个位置），别的照本节的规定不变，对同一个场景各求交一次；只要有一个位置得到的编号和像素中心得到的不同，这个像素就在边缘带里。这几次求交由做通道对拍的测试工具照场景的规格自己做，不取任何一个出层方交的编号图；所以边缘带只由场景、相机和 δ 决定，和被比的两张图无关。两张编号图在边缘带里的像素上对不上（怎么对见 5.4），不计入「不相同」。
- δ 取多少，光栅化的帧源：十六分之一像素。页面宿主的三种后端子像素位数都不少于 4（Metal 是 4，Vulkan 和软件渲染是 8，探针数据表「5090 读数」一节后面的表），顶点取整到的格子不粗于十六分之一像素，取整误差不超过三十二分之一像素；最小出帧链路用这个数量的编号层，边缘带之外对不上的像素是 0。光线追踪的帧源：`待探针：光线追踪的帧源编号层的边缘带宽度`。这两个数和上面「编号边缘」的比例不是同一个量。

### 5.2 `color` 和分灯组

- 本节的定义只管场景参考镜头。显示参考镜头的 `color` 仍是线性编码、Rec.709 原色，但数值不是场景线性的辐亮度，是显示空间的画面取了线性编码：它的数值含义以帧源接口契约（F）5.2 为准，本契约不另定。
- 出层方（`core`、`oracle`）不出显示参考镜头：它们照登记表交的 `color` 都是下面说的场景线性，通道对拍只在场景参考镜头上做。
- `R`、`G`、`B` 是场景线性的辐亮度，原色是 Rec.709，没有过显示变换，没有降噪，没有夹到 `[0, 1]`。数值的量纲和 Cycles 合成层的读数相同。
- 取法是样本累积：全部样本按像素滤波的权重合成。
- `A` 是这个像素被对相机可见的东西遮住的比例，无单位，`[0, 1]`，同样是样本累积出来的。背景对相机可见时背景算进去，`A` 是 1。镜头没设背景、或者背景对相机不可见（场景包的 `world.visibleToCamera` 是 `false`）时只算几何：什么都没打到的样本 `A` 记 0，`R`、`G`、`B` 记 0。
- 颜色预乘 `A`：`R`、`G`、`B` 是样本累积的原值，不除以 `A`。
- 分灯组只对名字对应的那一组灯的贡献做样本累积，别的规矩同 `color`。哪盏灯归哪一组，看场景包里那盏灯的 `group`；没写 `group` 的灯自成一组，组名是灯名（场景包契约 SP 3.6）。
- 线性度怎么量、过线多少，用帧源接口契约（F）5.3 的「颜色线性度」一项：`待探针：线性度，灰阶各级读数和已知反射率的相对误差`。
- 同一盏灯两个出层方的亮度差多少，用场景包契约（SP）5.5 的那一项探针，本契约不另立。

### 5.3 `depth`

- 辅助样本命中点的平面深度，单位米。平面深度的定义见每帧元数据契约（M）第 2 节：沿相机 −Z 方向的分量，不是到相机的直线距离。
- 不做归一化，不取倒数，不写成裁剪空间的值。
- 辅助样本什么都没打到时没有命中点，写 5.1 定的那个数。
- 它和已知距离差多少，用帧源接口契约（F）5.3 的「深度口径」一项。探针量到的（探针数据表第 3 行，Mac 和 5090 两台机器读数一致）：three 帧源和 Blender 帧源交的都是平面深度，单位米；口径一致时两边相差不超过 0.001 米。

### 5.4 `objectId`

- `id` 是辅助样本打到的那个实体的编号，和帧源的实体清单、每帧元数据的 `entities[].id` 是同一个数；编号从哪来只在帧源接口契约（F）3.6 定，本契约不另定。0 表示没打到任何实体（5.1）。写的是叶子实体的编号：场景包的实例表只列叶子实体（场景包契约 SP 5.9），装配体占哪些像素由名字前缀推出（每帧元数据契约 M 5.3）。
- 编号只在一个镜头的一次装载里有意义（F 契约 3.6）。比两个出层方的编号图时按实体名对，不按编号对：两侧各照自己这一次装载的编号和实体名的对应（帧源是实体清单；标准答案机是场景包的实例表和 `instances.names`，场景包契约 SP 5.9）把 `id` 换成实体名再比；两侧都是 0 算相同，只有一侧是 0 算不相同。本契约里说两张编号图「相同」「不相同」，都是这样对出来的。PS4、PS5 比的是同一个出层方同一次装载里的编号，直接比数。
- `coverage` 是从这个像素颜色层的全部样本数出来的：打到的编号等于辅助样本编号的样本数，除以样本总数。每个样本算一份，不乘像素滤波的权重。辅助样本自己不算在里面。
- `coverage` 存成 32 位浮点，所以 PS5 留了 0.000001 的差。

### 5.5 `normal`

- 辅助样本命中点的法线，相机空间：相机坐标照通用口径，相机看向自己的 −Z，Y 向上。
- 是着色法线：顶点法线插值之后的法线；背对相机的面，法线翻向相机。含不含法线贴图：`待探针：法线层含不含法线贴图，three 和 Cycles 各是哪种`。
- 三个分量是带符号的原值，长度是 1，不搬到 `[0, 1]`。正对相机的面，`Z` 是正的。辅助样本什么都没打到时除外，写 5.1 定的值。
- 镜像实例的法线照场景包契约（SP）5.4 处理之后再变到相机空间。
- 它和已知法线差多少，用帧源接口契约（F）5.3 的「法线空间」一项：`待探针：法线夹角中位，单位度`。

### 5.6 `motion`

- 取辅助样本的命中点，把这个点在快门打开那一刻和快门关上那一刻的位置各投到屏幕上一次，得到两个屏幕位置。
- 值等于（关上那一刻的屏幕位置 − 打开那一刻的屏幕位置）÷（快门角 ÷ 360），单位是像素每帧。
- 这里的快门是这一帧颜色层用的快门，快门角是这次 `render` 生效的快门角。辅助样本自己的快门按 0，只用来定命中点。
- 屏幕坐标照每帧元数据契约（M）5.2：原点在左上角，x 向右，y 向下。
- 快门打开的时刻是时间键 `{ frame: F, sub: 0 }`，关上的时刻是 F 加上快门角 ÷ 360，照时间键契约（T）5.5。两个出层方的快门实际差多少，用 T 契约 5.5 的探针。探针量到的（探针数据表第 7 行，Mac 和 5090 两台机器读数相同）：Blender 把快门位置设成帧起点之后，拖影中点在 F + 0.2465 帧，名义值是 F + 0.25 帧；three 帧源的快门窗口由宿主的子帧累积构造，按定义是 F + 0.25 帧。两个帧源的快门相位差是 0.0035 帧。

### 5.7 `denoiseAlbedo` 和 `denoiseNormal`

- 两层都做样本累积，取全部样本的平均，规则照 Cycles 的降噪特征通道。
- 两个出层方的这两层差多少：`待探针：降噪特征通道，核心帧源和标准答案机的反照率层、法线层的逐像素差`。

### 5.8 为什么不取平均

写进条文的反例。一个像素压在两个物体的边上：前面的物体编号 3，离相机 2 米；后面的物体编号 7，离相机 5 米。这个像素的辅助样本（像素中心）打到 3 号；颜色层取 4 个样本，依次打到 3、7、7、3。

- 合法：辅助样本打到 3 号，所以 `depth` 是 2，`id` 是 3，`coverage` 是 2 ÷ 4 = 0.5。
- 不合法：把四个样本平均，`depth` 是 3.5，`id` 是 5。3.5 米处什么都没有；5 号要么不存在，要么是一个和这个像素毫无关系的实体。这违反 PS4。
- 法线和运动矢量同理：两个面的法线平均出来的方向哪个面都不是。

所以这四个通道在边缘上是锯齿状的，这是对的；要知道边缘上混了多少，看 `coverage`。

### 5.9 通道对拍比什么

- 通道对拍只比同名的通道。两侧的通道声明对不上（PS2、PS3）就不比。
- `accumulate` 的通道带噪声，两侧差多少算过，门槛从参考噪声地板来（参考包契约 RP）。
- `sub0` 的通道不带噪声，两侧都取像素中心；比编号时按实体名对（5.4），边缘带里的像素不计入「不相同」（5.1），边缘上还差多少见 5.1 的探针。

### 5.10 一致性测试

- 核心帧源交出的通道声明和标准答案机的通道声明逐项对得上（PS2、PS3）。
- 例子 `examples/table-full.json` 这份声明，两个出层方都能照着交出每一层。
