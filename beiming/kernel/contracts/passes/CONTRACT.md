# 输出通道

版本：0.1.0-draft

## 1. 范围

管：

- 通道登记表：每个通道的名字、分量、位深、单位、色彩空间、取法、抗不抗锯齿。
- 各通道的数值定义：深度量什么、编号是什么数、法线在哪个空间、运动矢量怎么算。
- 通道声明 `passes/0.1` 的全部字段。核心帧源和标准答案机各写一份，照同一张登记表。
- 深度、编号、法线、运动矢量取首个样本，不取平均。
- 判定以上各条用的「通道核对记录」。

不管：

- 一次 `render` 能要哪些输出、交不出时怎么报错、能力声明里的 `outputs` 和 `channels`：帧源接口契约（F）。本契约的通道名和 F 契约的 `OutputName` 里同名的输出是同一层，数值定义以本契约为准。
- 辅助层取哪个时刻、快门窗口：时间键契约（T）。
- 编号和实体的对应、屏幕坐标、平面深度这个词：每帧元数据契约（M）。
- 场景、灯、相机从哪里来：场景包契约（SP）。
- 各层怎么装进文件、采样数、种子、采样图案、像素滤波、噪声地板：参考包契约（RP）。
- 降噪之后的颜色、过了显示变换的颜色：不在这一套通道里。
- 两侧的同名层差多少算过：谓词登记表契约（PR）。

## 2. 术语

帧、子帧相位、时间键、快门角、快门窗口、种子、核对记录：见时间键契约（T）第 2 节。帧源、宿主、能力声明、输出：见帧源接口契约（F）第 2 节。编号、平面深度：见每帧元数据契约（M）第 2 节。实体：见镜头契约（S）第 2 节。场景包、实例、镜像实例：见场景包契约（SP）第 2 节。

| 词 | 含义 |
|---|---|
| 通道 | 随一帧交出的一层有名字的逐像素数据，由一个或几个分量组成。 |
| 分量 | 通道里的一个数，例如颜色的 `R`。 |
| 位深 | 一个分量用什么数值类型存：`f32` 是 32 位浮点，`u32` 是 32 位无符号整数。 |
| 核心帧源 | 帧源名是 `core` 的帧源。 |
| 标准答案机 | 用 Cycles 出参考答案的那套程序，本契约里写作 `oracle`。它不是帧源，不在帧源名的值域里。 |
| 出层方 | 交出这一套通道的一方：`core` 或 `oracle`。 |
| 对拍 | 把两个出层方对同一个场景、同一帧交出的同名通道逐层相比。 |
| 样本 | 为了算一个像素，从相机经这个像素射进场景的一条路径和它算出的结果。 |
| 首个样本 | 一个像素的全部样本按采样次序排，排在第 0 个的那一个。 |
| 累积 | 把一个像素的全部样本按像素滤波的权重合成一个值。 |
| 像素滤波 | 样本落在像素内不同位置时各占多少权重的规则。 |
| 抗锯齿 | 一个通道的值是累积出来的，物体边缘上的像素得到两边的混合值。 |
| 覆盖率 | 一个像素的全部样本里，编号和首个样本相同的样本所占的比例。 |
| 分灯组 | 只算某一组灯的贡献的一层颜色。 |
| 降噪特征通道 | 专门喂给降噪器的反照率层和法线层。 |
| 通道登记表 | 3.1 的那张表，全系统只有这一张。 |
| 通道声明 | 一个出层方把自己交的每个通道的属性写下来的数据对象，结构见 3.2。 |
| 通道核对记录 | 一致性测试把对出层方的观测写下来的数据对象，只用来判定不变量；出层方不需要产出它。 |

## 3. 结构

### 3.1 通道登记表

通道名是下表第一列的词，大小写照写。`lightgroup:<名>` 里的 `<名>` 是小写字母、数字、连字符，以字母或数字开头；一个声明里可以有 0 个或更多个分灯组。前七行叫「固定通道」。

| 通道名 | 分量（次序固定） | 位深 | 单位 | 色彩空间 `colorSpace` | 取法 `sample` | 抗锯齿 `antialiased` | 是什么 |
|---|---|---|---|---|---|---|---|
| `color` | `R`、`G`、`B`、`A` | 四个都是 `f32` | `R`、`G`、`B` 是辐亮度，口径见 5.2；`A` 无单位 | `scene-linear-rec709`：场景线性，Rec.709 原色 | `accumulate` | `true` | 线性颜色，未降噪 |
| `depth` | `Z` | `f32` | 米 | `none`：不是颜色 | `first-sample` | `false` | 平面深度 |
| `objectId` | `id`、`coverage` | `id` 是 `u32`，`coverage` 是 `f32` | 无 | `none` | `first-sample` | `false` | 物体编号加覆盖率 |
| `normal` | `X`、`Y`、`Z` | 三个都是 `f32` | 无 | `none` | `first-sample` | `false` | 法线，相机空间 |
| `motion` | `X`、`Y` | 两个都是 `f32` | 像素每帧 | `none` | `first-sample` | `false` | 运动矢量 |
| `denoiseAlbedo` | `R`、`G`、`B` | 三个都是 `f32` | 无 | `scene-linear-rec709` | `accumulate` | `true` | 降噪用的反照率 |
| `denoiseNormal` | `X`、`Y`、`Z` | 三个都是 `f32` | 无 | `none` | `accumulate` | `true` | 降噪用的法线 |
| `lightgroup:<名>` | `R`、`G`、`B` | 三个都是 `f32` | 辐亮度，口径同 `color` | `scene-linear-rec709` | `accumulate` | `true` | 分灯组：这一组灯单独累积出的颜色，未降噪 |

`sample` 是 `accumulate` 的通道抗锯齿，是 `first-sample` 的通道不抗锯齿。`objectId` 的 `coverage` 是从全部样本数出来的比例，算法见 5.4；它所在的通道仍然按 `first-sample` 登记。

### 3.2 通道声明 `PassTable`

顶层对象，`format` 是 `passes/0.1`。本契约里没有可以是 `null` 的字段。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `passes/0.1` | 格式标识；能力声明的 `channels` 写的就是它 |
| `channels` | 数组 | 无 | 是 | 至少 1 项；含哪些通道由 PS1 管 | 这个出层方交的每个通道，每项见下表；次序不算数 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`channels[]`，不得有别的字段：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 3.1 的通道名 | 通道名 |
| `components` | 数组 | 无 | 是 | 至少 1 项，每项 `{ name, type }`：`name` 是不空的字符串，`type` 是 `f32` 或 `u32`；取值由 PS2 管 | 分量和各自的位深，次序算数 |
| `colorSpace` | 字符串 | 无 | 是 | `scene-linear-rec709`、`none` | 色彩空间：场景线性加 Rec.709 原色，或者不是颜色。本套通道里没有显示空间的层 |
| `sample` | 字符串 | 无 | 是 | `accumulate`、`first-sample` | 取法：全部样本累积，或只取首个样本 |
| `antialiased` | 布尔 | 无 | 是 | | 抗不抗锯齿 |

### 3.3 通道核对记录

顶层对象，`format` 是 `passes-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。只看通道声明就能判的条目（PS1、PS2）对单独的一份通道声明也照判。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `passes-check/0.1` | 格式标识 |
| `sides` | 数组 | 无 | 是 | 1 项或 2 项，`producer` 不重复 | 被测的出层方和它的通道声明，每项见下表 |
| `pixels` | 数组 | 无 | 否 | | 把某个像素的各个样本和交出来的值摆在一起的观测，每项见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`sides[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `producer` | 字符串 | 无 | 是 | `core`、`oracle` | 哪个出层方 |
| `table` | `PassTable` | 无 | 是 | 见 3.2 | 它的通道声明 |

`pixels[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `producer` | 字符串 | 无 | 是 | `sides` 里出现过的 `producer` | 这个像素是谁渲的 |
| `x` | 整数 | 像素 | 是 | ≥ 0 | 像素的列号，从画面左边数，从 0 起 |
| `y` | 整数 | 像素 | 是 | ≥ 0 | 像素的行号，从画面上边数，从 0 起 |
| `samples` | 数组 | 无 | 是 | 至少 1 项，每项见下表 | 这个像素的全部样本，照采样次序排；第 0 项是首个样本 |
| `out` | 对象 | 无 | 是 | 见下表 | 这个像素在各通道里交出来的值 |

`pixels[].samples[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 整数 | 无 | 是 | ≥ 0 | 这个样本打到的实体的编号；0 是背景 |
| `depth` | 双精度 | 米 | 是 | ≥ 0 | 这个样本命中点的平面深度 |
| `normal` | 数组 | 无 | 否 | `[x, y, z]` | 这个样本命中点的法线，相机空间 |
| `motion` | 数组 | 像素每帧 | 否 | `[x, y]` | 这个样本命中点的运动矢量 |

`pixels[].out`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `depth` | 双精度 | 米 | 是 | ≥ 0 | `depth` 通道里这个像素的值 |
| `id` | 整数 | 无 | 是 | ≥ 0 | `objectId` 通道的 `id` 分量 |
| `coverage` | 双精度 | 无 | 是 | `[0, 1]` | `objectId` 通道的 `coverage` 分量 |
| `normal` | 数组 | 无 | 否；出现时 `samples` 的第 0 项必须有 `normal` | `[x, y, z]` | `normal` 通道里这个像素的值 |
| `motion` | 数组 | 像素每帧 | 否；出现时 `samples` 的第 0 项必须有 `motion` | `[x, y]` | `motion` 通道里这个像素的值 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| PS1 | 通道声明的 `channels` 必须含七个固定通道各正好一项，其余每项的名字必须是 `lightgroup:<名>`，名字不得重复。 | 把 `channels[].name` 收成一列：`color`、`depth`、`objectId`、`normal`、`motion`、`denoiseAlbedo`、`denoiseNormal` 各出现正好 1 次；剩下的每个名字符合 3.1 的 `lightgroup:<名>` 写法；整列没有重复 | `PS1-missing-denoise-normal.json` |
| PS2 | 通道声明里每个通道的 `components`、`colorSpace`、`sample`、`antialiased` 必须和通道登记表里同名的那一行逐项相同。 | `channels` 每一项：按 `name` 找 3.1 的行（`lightgroup:<名>` 都找最后一行），`components` 的项数、每项的 `name` 和 `type`、次序，以及另外三个字段，逐个比，必须全部相等。名字不在登记表里的项不归这一条，归 PS1 | `PS2-depth-antialiased.json` |
| PS3 | 对拍的两个出层方的通道声明必须逐项相同：通道名的集合相同，同名通道的每个字段相同。 | `sides` 里 `core` 和 `oracle` 都出现时：两份 `table.channels` 按 `name` 配对，一边有、另一边没有的名字必须是 0 个；配上对的两项 `components`、`colorSpace`、`sample`、`antialiased` 必须全部相等。次序不比 | `PS3-core-lacks-lightgroup.json` |
| PS4 | `depth`、`objectId` 的 `id`、`normal`、`motion` 在每个像素上必须等于这个像素首个样本的值，不得是多个样本的平均或别的合成。 | `pixels` 每一项：`out.depth` 必须等于 `samples[0].depth`，`out.id` 必须等于 `samples[0].id`；`out.normal`、`out.motion` 出现时必须和 `samples[0]` 的同名数组逐个数相等。都没有容差 | `PS4-depth-id-averaged.json` |
| PS5 | `objectId` 的 `coverage` 必须等于这个像素里编号和首个样本相同的样本数除以样本总数。 | `pixels` 每一项：数出 `samples` 里 `id` 等于 `samples[0].id` 的项数 k，`samples` 的项数 n；`out.coverage` 和 `k ÷ n` 的差的绝对值必须不大于 0.000001 | `PS5-coverage-is-one.json` |

## 5. 口径

### 5.1 样本和首个样本

- 一个像素取多少个样本、用哪种采样图案、哪种像素滤波，由出这一帧的设置定，记在参考包的清单里（参考包契约 RP）。
- 样本按采样次序编号，从 0 起。首个样本是第 0 个。它落在像素内的哪个位置由采样图案定，不一定在像素中心。
- 首个样本什么都没打到时，`objectId` 的 `id` 是 0。这时别的 `first-sample` 通道写什么，见第 6 节。
- 两个出层方的首个样本落点不同时，物体边缘上的像素会取到不同的物体。差多少：`待探针：编号边缘，核心帧源和标准答案机的 id 不相同的像素占全画面的比例`。
- 首个样本取的是快门窗口里的哪个时刻，见第 6 节。

### 5.2 `color` 和分灯组

- `R`、`G`、`B` 是场景线性的辐亮度，原色是 Rec.709，没有过显示变换，没有降噪，没有夹到 `[0, 1]`。数值的量纲和 Cycles 合成层的读数相同。
- 取法是全部样本按像素滤波累积。
- `A` 是这个像素被场景遮住的比例，无单位，`[0, 1]`，同样是累积出来的。
- 分灯组只累积名字对应的那一组灯的贡献，别的规矩同 `color`。
- 线性度怎么量、过线多少，用帧源接口契约（F）5.3 的「颜色线性度」一项：`待探针：线性度，灰阶各级读数和已知反射率的相对误差`。
- 同一盏灯两个出层方的亮度差多少，用场景包契约（SP）5.5 的那一项探针，本契约不另立。

### 5.3 `depth`

- 首个样本命中点的平面深度，单位米。平面深度的定义见每帧元数据契约（M）第 2 节：沿相机 −Z 方向的分量，不是到相机的直线距离。
- 不做归一化，不取倒数，不写成裁剪空间的值。
- 它和已知距离差多少，用帧源接口契约（F）5.3 的「深度口径」一项：`待探针：深度口径，深度层读数和已知距离的相对误差中位`。

### 5.4 `objectId`

- `id` 是首个样本打到的那个实体的编号，和场景包实例表的实体编号、每帧元数据的 `entities[].id` 是同一个数；0 是背景。
- `coverage` 是从这个像素的全部样本数出来的：编号等于首个样本编号的样本数，除以样本总数。每个样本算一份，不乘像素滤波的权重。
- `coverage` 存成 32 位浮点，所以 PS5 留了 0.000001 的差。

### 5.5 `normal`

- 首个样本命中点的法线，相机空间：相机坐标照通用口径，相机看向自己的 −Z，Y 向上。
- 三个分量是带符号的原值，长度是 1，不搬到 `[0, 1]`。正对相机的面，`Z` 是正的。
- 镜像实例的法线照场景包契约（SP）5.4 处理之后再变到相机空间。
- 它和已知法线差多少，用帧源接口契约（F）5.3 的「法线空间」一项：`待探针：法线夹角中位，单位度`。

### 5.6 `motion`

- 取首个样本的命中点，把这个点在快门打开那一刻和快门关上那一刻的位置各投到屏幕上一次，得到两个屏幕位置。
- 值等于（关上那一刻的屏幕位置 − 打开那一刻的屏幕位置）÷（快门角 ÷ 360），单位是像素每帧。
- 屏幕坐标照每帧元数据契约（M）5.2：原点在左上角，x 向右，y 向下。
- 快门打开的时刻是时间键 `{ frame: F, sub: 0 }`，关上的时刻是 F 加上快门角 ÷ 360，照时间键契约（T）5.5。两个出层方的快门实际差多少，用 T 契约 5.5 的探针：`待探针：快门相位，同一运动场景下两个出层方的快门相位差，单位帧`。

### 5.7 `denoiseAlbedo` 和 `denoiseNormal`

- 两层都是全部样本的累积平均，规则照 Cycles 的降噪特征通道。
- 两个出层方的这两层差多少：`待探针：降噪特征通道，核心帧源和标准答案机的反照率层、法线层的逐像素差`。

### 5.8 为什么不取平均

写进条文的反例。一个像素压在两个物体的边上：前面的物体编号 3，离相机 2 米；后面的物体编号 7，离相机 5 米。这个像素取 4 个样本，依次打到 3、7、7、3。

- 合法：首个样本打到 3 号，所以 `depth` 是 2，`id` 是 3，`coverage` 是 2 ÷ 4 = 0.5。
- 不合法：把四个样本平均，`depth` 是 3.5，`id` 是 5。3.5 米处什么都没有；5 号要么不存在，要么是一个和这个像素毫无关系的实体。这违反 PS4。
- 法线和运动矢量同理：两个面的法线平均出来的方向哪个面都不是。

所以这四个通道在边缘上是锯齿状的，这是对的；要知道边缘上混了多少，看 `coverage`。

### 5.9 对拍比什么

- 对拍只比同名的通道。两侧的通道声明对不上（PS3）就不比。
- `accumulate` 的通道带噪声，两侧差多少算过，门槛从参考包的噪声地板来（参考包契约 RP）。
- `first-sample` 的通道不带噪声，但边缘上会因为首个样本落点不同而不同，见 5.1 的探针。

### 5.10 一致性测试

- 核心帧源交出的通道声明和标准答案机的通道声明逐项对得上（PS3）。
- 例子 `examples/table-full.json` 这份声明，两个出层方都能照着交出每一层。
