# 每帧元数据

版本：0.1.0-draft

## 1. 范围

管：

- 每帧元数据 `meta/0.1` 的全部字段：时间和画幅、相机、实体、灯、事件、文字框、读数、画面统计、来源信息、耗时、谁填的、哈希。
- 矩阵、屏幕坐标、包围盒、可见比例、屏占、深度范围的口径。
- 哪些字段可以是 `null`，各在什么时候。
- 哪些字段由宿主量、镜头代码不可写。
- 判定以上各条用的「元数据核对记录」。

不管：

- `render` 怎么调、能要哪些输出、能力声明、合规档的减免表、帧源名的值域：帧源接口契约（F）。
- 时间键、帧率、种子的写法：时间键契约（T）。
- 镜头代码经 `meta(f)` 交什么、实体名的写法：镜头契约（S）。
- 卡的引用的写法、各张卡的 `meta(f)` 的合并次序：卡的运行时接口契约（CR）。
- 事件表：事件表契约（EV）。
- 深度层、编号层的数值定义：输出通道契约（PS）。
- 元数据拿去判什么：谓词登记表契约（PR）。
- `source.renderer` 和锁文件、作业记录对不对得上：锁文件契约（LK）。
- `ext.<名字>` 帧源不交每帧元数据，见帧源接口契约（F）3.5，由它的 F28 判（`ext.<名字>` 的能力声明 `outputs.meta` 必须是 `false`）。

## 2. 术语

帧、全片帧号、镜头、镜头局部帧号、子帧相位、种子、帧率、快门角、辅助层、场景参考镜头、显示参考镜头、核对记录：见时间键契约（T）第 2 节。镜头代码、实体、实体名、锚点、母语对象、可信边界：见镜头契约（S）第 2 节。帧源、帧源名、宿主、能力声明、输出、颜色层、层文件、层引用、合规档、档位、只要元数据：见帧源接口契约（F）第 2 节和 3.3。卡的引用：见卡的运行时接口契约（CR）第 2 节。

| 词 | 含义 |
|---|---|
| 每帧元数据 | 随一帧交出的一份数据对象，说这一帧的相机、场景里有什么、画面怎么样、谁渲的。 |
| 角色 | 一个实体在这个镜头里的重要性标记：`hero` 是主体，`mustSee` 是必须看得见的东西。 |
| 编号 | 实体在镜头内的整数标识，从哪来、在什么范围里有意义见帧源接口契约（F）3.6；物体编号层的一个像素写的是叶子实体的编号，见 5.3；0 表示这个样本没打到任何实体，不是哪个实体的编号。 |
| 屏幕包围盒 | 实体投到画面上之后的轴对齐矩形。 |
| 三维包围盒 | 实体在世界坐标里的轴对齐盒子。 |
| 可见比例 | 实体和别的东西一起渲时占的像素数，除以它单独渲时占的像素数。 |
| 屏占 | 实体的屏幕包围盒落在画面内的面积，除以画面面积。 |
| 平面深度 | 一个点到相机的距离沿相机 −Z 方向的分量，不是到相机的直线距离。 |
| 文字框 | 画面上的一段文字和它占的矩形。 |
| 读数 | 镜头代码自己定义、自己交的一个数。 |
| 来源信息 | 元数据里的 `source`：这一帧是哪个帧源、哪个宿主、哪个版本、哪一档渲的。 |
| 出帧者 | 实际算出这一帧像素的帧源。 |
| 元数据核对记录 | 一致性测试把「每次 `render` 交了几份元数据、多大、里面的片子、镜头、帧率、帧号、种子、档位、帧源名是多少、和请求的对不对得上，里面的颜色哈希和尺寸和交回的颜色层文件对不对得上」写下来的数据对象，只用来判定不变量。 |

## 3. 结构

### 3.1 每帧元数据

顶层对象，`format` 是 `meta/0.1`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `meta/0.1` | 格式标识 |
| `film` | 字符串 | 无 | 是 | 不空 | 片子的标识，写法归片子描述契约（D）：片子描述的 `id`。对不对得上由 M18 管 |
| `shot` | 字符串 | 无 | 是 | 见 D 契约 5.1 | 镜头的标识：片子描述里这个镜头的条目的 `id`。对不对得上由 M19 管 |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 全片帧号 |
| `shotFrame` | 整数 | 帧 | 是 | ≥ 0 | 镜头局部帧号；和 `frame` 的关系由 M11 管。这份元数据量的是这一帧 `sub = 0` 的状态，和辅助层同一个样本 |
| `seed` | 整数 | 无 | 是 | 见 T 契约 3.3 | 镜头种子：这个镜头实际生效的种子，定义见锁文件契约（LK）第 2 节；有锁文件时取锁里记的值，没有锁文件时是镜头条目的 `seed`（F 契约 5.11）。对不对得上由 M12 管 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率：片子描述的 `output.fps`。对不对得上由 M20 管 |
| `size` | 数组 | 像素 | 是 | `[宽, 高]`，正整数 | 这一帧输出的尺寸：这次 `render` 交回的颜色层的宽和高，档位带缩放时是缩放之后的，由 M13 管。缩放之后怎么取整本契约不定，见 F 契约第 6 节；只要元数据时填什么见第 6 节 |
| `colorRef` | 字符串 | 无 | 是 | `scene`、`display` | 颜色层是场景参考还是显示参考，见 F 契约 5.2 |
| `units` | 对象 | 无 | 是 | 正好是 `{ "meter": 1, "up": "Y", "hand": "right" }` | 把通用口径原样写一遍，给不读契约的工具看 |
| `camera` | 对象或 `null` | 无 | 是 | 见 3.2 | 相机；`null` 的原因见 3.6 |
| `entities` | 数组或 `null` | 无 | 是 | 每项见 3.3 | 实体；`null` 的原因见 3.6 |
| `omittedParts` | 整数 | 个 | 否 | ≥ 1 | 为了不超过大小上限没列进 `entities` 的零件个数，见 5.9 |
| `lights` | 数组或 `null` | 无 | 是 | 每项见 3.4 | 灯；`null` 的原因见 3.6 |
| `events` | 数组 | 无 | 是 | 每项见 3.4 | 落在这一帧上的事件 |
| `texts` | 数组或 `null` | 无 | 是 | 每项见 3.4 | 文字框；`null` 的原因见 3.6 |
| `readings` | 对象 | 无 | 否 | `{ 名字: 双精度 }`，名字不空 | 读数 |
| `stats` | 对象或 `null` | 无 | 是 | 见 3.5 | 画面统计；`null` 的原因见 3.6 |
| `source` | 对象 | 无 | 是 | 见 3.5 | 来源信息 |
| `timing` | 对象 | 无 | 是 | 见 3.5 | 耗时 |
| `origin` | 对象 | 无 | 是 | 见 3.5 | 哪些字段是谁填的 |
| `hash` | 对象 | 无 | 是 | 见 3.5 | 哈希 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `camera`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `world` | 数组 | 米 | 是 | 16 个双精度 | 相机到世界的矩阵，列主序 |
| `proj` | 数组 | 无 | 是 | 16 个双精度 | 投影矩阵，列主序，OpenGL 约定；它和 `fovYDeg`、`near`、`far`、`size` 的关系见 5.1，由 M15 管 |
| `fovYDeg` | 双精度 | 度 | 是 | `(0, 180)` | 垂直视场角 |
| `near` | 双精度 | 米 | 是 | > 0 | 近裁剪面 |
| `far` | 双精度 | 米 | 是 | 大于 `near` | 远裁剪面 |
| `focusDist` | 双精度 | 米 | 否 | > 0 | 对焦距离。出现时必须同时带 `sensorHeightM` |
| `fstop` | 双精度 | 无 | 否 | > 0 | 光圈值。出现时必须同时带 `sensorHeightM` |
| `sensorHeightM` | 双精度 | 米 | `focusDist` 或 `fstop` 出现时必填 | > 0 | 传感器高度。镜头孔径怎么从它算，见场景包契约（SP）第 5 节 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | 这次 `render` 生效的快门角，来源见 F 契约 5.9；0 表示没有运动模糊 |

`focusDist` 和 `fstop` 都不出现，表示这一帧不做景深。`focusDist`、`fstop` 必须同时出现或同时不出现。这两个字段不得是 `null`。

### 3.3 `entities[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 整数 | 无 | 是 | ≥ 1 | 编号；从哪来见 F 契约 3.6，本契约不另定 |
| `name` | 字符串 | 无 | 是 | 实体名，写法见 S 契约 5.2 | 实体名 |
| `class` | 字符串 | 无 | 是 | 不空 | 类别；现在用到的有 `assembly`、`part`、`particles` |
| `role` | 字符串 | 无 | 否 | `hero`、`mustSee` | 角色；没有角色就不出现 |
| `bbox2d` | 数组 | 像素 | 是 | `[x0, y0, x1, y1]`，`x0 ≤ x1`，`y0 ≤ y1` | 屏幕包围盒 |
| `bbox3d` | 数组 | 米 | 否 | `[x0, y0, z0, x1, y1, z1]`，前三个不大于后三个 | 三维包围盒，世界坐标 |
| `visible` | 双精度或 `null` | 无 | 是 | `[0, 1]` | 可见比例，量法见 5.3；`null` 的原因见 3.6 |
| `pxArea` | 双精度 | 无 | 是 | `[0, 1]` | 屏占，算法见 5.4，由 M16 管 |
| `depth` | 数组 | 米 | 否 | `[近, 远]`，近不大于远 | 这个实体的平面深度范围 |
| `cards` | 数组 | 无 | 否 | 卡的引用 `<卡名>@<主版本>`，写法见 CR 契约 3.3 | 这个实体是哪几张卡带进来或驱动的。精确版本在锁文件里，这里不重复记 |
| `anchors` | 对象 | 无 | 否 | `{ 锚点名: { world, screen } }` | 锚点。`world` 是 `[x, y, z]`，米，世界坐标，由镜头代码交；`screen` 是 `[x, y]`，像素，由宿主把 `world` 投到屏幕上算出 |
| `motion` | 对象 | 无 | 否 | `{ speed, unit }` | `speed` 是这个实体在世界坐标里移动的速率，≥ 0，取哪两个状态见 5.11；`unit` 必须是 `m/frame` |
| `count` | 整数 | 个 | 否 | ≥ 0 | 这个实体里的个体数，例如粒子数 |

### 3.4 `lights[]`、`events[]`、`texts[]`

`lights[]`。灯的词以场景包契约（SP）3.6 为准：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 不空 | 灯的名字 |
| `type` | 字符串 | 无 | 是 | `area-rect`、`point`、`sun` | 灯的种类：矩形面光、点光、平行的日光 |
| `pos` | 数组 | 米 | `type` 是 `area-rect`、`point` 时必填，是 `sun` 时不得出现 | `[x, y, z]` | 世界坐标里的位置；`sun` 没有位置 |
| `watts` | 双精度 | 瓦 | `type` 是 `area-rect`、`point` 时必填，是 `sun` 时不得出现 | ≥ 0 | 功率 |
| `dir` | 数组 | 无 | `type` 是 `sun` 时必填，别的种类不得出现 | `[x, y, z]`，单位向量 | 指向光来的方向，世界坐标 |
| `irradiance` | 双精度 | 瓦每平方米 | `type` 是 `sun` 时必填，别的种类不得出现 | ≥ 0 | 辐照度 |
| `color` | 数组 | 无 | 是 | `[r, g, b]`，每个 ≥ 0 | 灯的颜色，场景线性，Rec.709 原色 |

`events[]`。事件从镜头输入的 `events` 拿（F 契约 3.2，上层已经把事件表展开成全片帧号）。列哪些条目以事件表契约（EV）5.4 为准：事件表里 `frame` 等于这一帧全片帧号的事件条目，切点条目、轨道条目也在内。镜头输入不带 `events` 时这个数组是空的：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 不空 | 事件的标识，见事件表契约（EV） |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 事件所在的全片帧号 |

`texts[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 否 | 不空；卡带进来的带 `<as>.` 前缀 | 这个文字框的标识 |
| `text` | 字符串 | 无 | 是 | 不空 | 画面上应该出现的文字 |
| `bbox2d` | 数组 | 像素 | 是 | `[x0, y0, x1, y1]`，`x0 ≤ x1`，`y0 ≤ y1` | 这段文字占的矩形 |

### 3.5 `stats`、`source`、`timing`、`origin`、`hash`

`stats`，在颜色层的线性编码数值上算：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `luma` | 对象 | 无 | 是 | `{ p1, p50, p99 }`，都 ≥ 0，`p1 ≤ p50 ≤ p99` | 亮度的第 1、50、99 百分位；亮度按 Rec.709 的权重从线性编码的三个通道算 |
| `clipHigh` | 双精度 | 无 | `colorRef` 是 `display` 时必填，是 `scene` 时不得出现（M10） | `[0, 1]` | 亮部溢出的像素占比：三个通道里任何一个的线性编码值不小于 1 的像素算溢出 |
| `clipLow` | 双精度 | 无 | `colorRef` 是 `display` 时必填，是 `scene` 时不得出现（M10） | `[0, 1]` | 暗部压死的像素占比：三个通道的线性编码值都不大于 0 的像素算压死 |
| `noise` | 双精度或 `null` | 无 | 是 | ≥ 0 | 噪声的估计；`null` 的原因见 3.6 |
| `tris` | 整数或 `null` | 个 | 是 | ≥ 0 | 这一帧场景里的三角形数；`null` 的原因见 3.6 |

`source`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 帧源名，见 F 契约 3.1 | 镜头条目顶层的 `source`，见 5.6，由 M17 管 |
| `renderer` | 字符串 | 无 | 是 | 帧源名，见 F 契约 3.1 | 出帧者，见 5.6 |
| `host` | 字符串 | 无 | 是 | 出帧者的能力声明 `hosts` 里的一项；`three` 的取值本契约不另列（按倾向定，合作者不同意时再改，见第 6 节） | 哪个宿主 |
| `version` | 字符串 | 无 | 是 | 不空；`three` 是 `0.187.0` | 出帧者的版本 |
| `tier` | 字符串 | 无 | 是 | `draft`、`final` | 这次运行的档位：`open` 时 `env.tier` 的值（F 契约 3.2），由 M14 管 |
| `gpu` | 字符串 | 无 | 否 | 不空 | 显卡型号 |
| `backend` | 字符串 | 无 | 否 | 不空 | 图形后端 |
| `samples` | 整数 | 次 | 否 | ≥ 1 | 这次 `render` 生效的每像素采样数，取法见 F 契约 3.3；现在没有判定，见第 6 节 |
| `denoise` | 字符串 | 无 | 否 | 不空 | 用的哪种降噪；没降噪就不出现 |

`timing`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `stateMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 写状态花的时间 |
| `renderMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 渲染花的时间；没出像素写 0 |
| `readbackMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 读回花的时间；没出像素写 0 |

三个数的口径：`renderMs` 从发起渲染算到渲染调用返回；`readbackMs` 从开始取像素算到像素拿到手，含等显卡把这一帧做完的时间。跨帧源比耗时只可以比三个数的和，单个数不得拿来做门。一个会话的第一次 `render` 含一次性的准备，它的耗时不得拿来比。

宿主可以读单调时钟量耗时（时间键契约（T）5.3 的白名单），读到的数只许写进 `timing` 和信封的 `cost`。`timing` 不得影响状态，不进任何哈希。

`origin`：三个键都必填，每个是路径的数组，不重复。路径的写法见 5.7。

| 字段 | 值域 | 说明 |
|---|---|---|
| `host` | `camera`、`entities`、`lights`、`stats`、`source`、`timing` | 由宿主直接从场景和渲染器量的字段 |
| `shot` | `entities.*.anchors`、`texts`、`readings` | 由镜头代码经 `meta(f)` 交的字段 |
| `kernel` | `events` | 由内核从事件表展开、经镜头输入的 `events` 交进来的字段 |

`hash`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `color` | 字符串或 `null` | 是 | `sha256:` 加 64 位小写十六进制 | 同一次 `render` 交出的颜色层文件内容的哈希；`null` 的原因见 3.6 |

### 3.6 可以是 `null` 的字段

只有下面这些字段可以是 `null`，别的字段一律不得是 `null`。

| 字段 | 哪一类 | 原因（通用口径里的哪一种） | 什么时候是 `null` |
|---|---|---|---|
| `entities[].visible` | 这次没算 | 这次没算 | 这一帧没出像素；或这个实体没有角色；或这一帧没被点名要算可见比例 |
| `stats` | 这次没算 | 这次没算 | 这一帧没出像素 |
| `hash.color` | 这次没算 | 这次没算 | 这一帧没出像素 |
| `camera` | 减免 | 这个帧源交不出 | 出帧者是 `legacy-page`（交每帧元数据的帧源里合规档是 `limited` 的只有它：F 契约的 F10 定了合规档是 `limited` 的只有它和 `ext.<名字>`，F28 定了 `ext.<名字>` 不交每帧元数据；见 M4） |
| `entities` | 减免 | 这个帧源交不出 | 出帧者是 `legacy-page`（交每帧元数据的帧源里合规档是 `limited` 的只有它：F 契约的 F10 定了合规档是 `limited` 的只有它和 `ext.<名字>`，F28 定了 `ext.<名字>` 不交每帧元数据；见 M4） |
| `stats.noise` | 可以声明 | 这个帧源交不出 | 出帧者在能力声明的 `metaNull` 里列了它 |
| `stats.tris` | 可以声明 | 这个帧源交不出 | 同上 |
| `texts` | 可以声明 | 这个帧源交不出 | 同上 |
| `lights` | 可以声明 | 这个帧源交不出 | 同上 |

「这一帧没出像素」就是这次 `render` 只要元数据。这时相机、屏幕包围盒、三维包围盒、屏占、深度范围、锚点、事件照常要有。

### 3.7 元数据核对记录

## 5. 口径

### 5.1 坐标和矩阵

- 长度、坐标系、相机朝向照通用口径。Blender 一侧的换轴由帧源接口契约（F）5.1 管，元数据里的坐标都是换过之后的。
- 矩阵是 16 个数，列主序：前四个数是第一列。
- `camera.world` 把相机坐标里的点变到世界坐标。它的第四列前三个数是相机在世界里的位置。
- `camera.proj` 是 OpenGL 约定的透视投影：相机看向 −Z，裁剪空间的深度范围是 `[−1, 1]`。它和 `fovYDeg`、`near`、`far`、`size` 的关系：第 6 个数等于 `1 ÷ tan(fovYDeg ÷ 2)`，第 1 个数等于第 6 个数乘以高再除以宽，第 11 个数等于 `−(far + near) ÷ (far − near)`，第 15 个数等于 `−2 × far × near ÷ (far − near)`。「第几个数」从 1 数起，高和宽是这份元数据的 `size`，角度先从度换成弧度。
- 上面四个关系由 M15 判，比的是相对差：写的数和算式的值之差的绝对值，除以算式的值的绝对值，不得超过 1e-12。第 1 个数对的是写出来的第 6 个数，所以视场角写错只算第 6 个数对不上。读数：最小出帧链路（`three` 帧源配页面宿主，320 乘 180 和 640 乘 360 两种画幅）的 78 份元数据上，四个数的最大相对差是 1.4e-16。1e-12 只容得下在双精度里换一种算式次序的差，适用范围见第 6 节。
- 本契约现在没有四元数字段；以后出现时次序是 `(x, y, z, w)`。

### 5.2 屏幕

- 单位是像素，原点在画面左上角，x 向右，y 向下。画面的范围是 `[0, 宽] × [0, 高]`。
- 世界坐标里的点 p 投到屏幕：先用 `camera.world` 的逆把 p 变到相机坐标，再乘 `camera.proj` 并做透视除法得到 `[−1, 1]` 里的 `(nx, ny)`，屏幕坐标是 `((nx + 1) ÷ 2 × 宽, (1 − ny) ÷ 2 × 高)`。
- `bbox2d` 是 `[x0, y0, x1, y1]`，`(x0, y0)` 是左上角。`anchors.*.screen` 照上面的投影算。

### 5.3 `visible`

- 编号层的一个像素写的是叶子实体的编号：打到的那些实体里名字最长的那个。
- 一个实体占的像素 = 编号是它自己、或者是名字以它的名字加 `.` 开头的实体的像素。所以装配体占的像素是它名下各个实体的像素合起来，角色可以给装配体。
- 可见比例等于这个实体合渲时在编号层里占的像素数，除以它单独渲时占的像素数。两个数都在四分之一分辨率的编号层上数。
- 只对有角色的实体算。也不是每帧都算：只在被抽查的帧和被点名查询的帧上算，别的帧写 `null`。
- 多渲的那一遍低分辨率编号层花多少时间：每个有角色的实体多渲一遍，three 帧源在 Mac 上约 0.8 毫秒，在 5090 上约 0.9 毫秒；Blender 帧源用 CPU 约 2 毫秒，用显卡约 276 到 398 毫秒（显卡每渲一次有约 0.3 秒以上的固定开销，和画面多小无关）。Blender 帧源多渲的这一遍必须用 CPU。出处：Mac 的读数是探针数据表第 10 行（three 的逐条读数在 `three.json` 的「可见比例的成本」一行，三个方块各 0.8 毫秒）；5090 上 three 的读数是 `three.linux-5090.json`「可见比例的成本」一行的逐条读数（三个方块各 0.9 毫秒，都是 11 次取中位），Blender 用显卡的读数是 `blender.linux-5090.json`「可见比例的成本」一行（275.9、398.0、374.2 毫秒）。

### 5.4 `pxArea`

把 `bbox2d` 和画面范围求交，交出来的矩形面积除以宽乘高；交不出矩形（包围盒整个在画面外）时是 0。不依赖像素，只要元数据时照算。

由 M16 判：拿这份元数据写着的 `bbox2d` 和 `size` 照上面这句在双精度里算一遍，`pxArea` 和它之差的绝对值不得超过 1e-12。两边用的是同一份元数据里写着的数，容差只容换一种算式次序的差。读数：同一批 78 份元数据的 180 个实体上，差是 0；这一批里没有伸出画面的包围盒，求交那一支没读到数，见第 6 节。

### 5.5 `depth`

平面深度，米。`[近, 远]` 是这个实体上离相机最近和最远的点的平面深度。不依赖像素，只要元数据时照算。它和深度层读数差多少，看 F 契约 5.3 的「深度口径」一项。

### 5.6 `source.id` 和 `source.renderer`

- `id` 是镜头输入的 `shot` 顶层的 `source`，`renderer` 是实际算出这一帧像素的帧源。镜头输入的 `shot` 是片子描述里这个镜头的条目，原样传、不改写（F 契约 3.2），所以带 `renderer` 对象的镜头这两个值都填得出来。镜头条目不带 `renderer` 对象时两者相同；带的时候（见片子描述契约（D）3.3），`renderer` 是 `renderer.source`，顶层的 `source` 那一套留作对照，不参与这次出片。
- `renderer` 由出帧的帧源进程自己填，镜头代码够不着。`id` 由宿主照镜头输入的 `shot` 顶层的 `source` 填。`id` 填得对不对由 M17 判：测试工具自己从片子描述读这个镜头的条目顶层的 `source`，和交回的元数据里的 `source.id` 比。
- 声称由 `core` 出的帧，`renderer` 不是 `core` 就不算数。

### 5.7 `origin` 里的路径

- 路径是顶层字段名，或用 `.` 连起来的字段名；`*` 代表数组里的每一项。
- 一个字段归谁，看能匹配它的最长的那条路径：`entities.*.anchors` 归镜头代码，`entities` 里的其余部分归宿主。
- 没被任何路径匹配到的顶层字段（`format`、`film`、`shot`、时间和画幅、`units`、`origin`、`hash`、`omittedParts`）由宿主填，镜头代码同样不得写。
- 落在这个镜头上的叠加层条目从镜头输入的 `overlays` 拿（F 契约 3.2）。宿主把每个条目展开成这个镜头的一个卡实例，它的文字框由这个实例的 `meta(f)` 交，和别的卡一样归 `origin.shot`。

### 5.8 「镜头代码不得写」怎么测

同一个镜头渲两遍同一帧：一遍用原样的镜头代码，一遍让它的 `meta(f)` 多交 `origin.host` 里的键（这本身违反 S8）。两遍元数据里 `origin.host` 列的字段去掉 `timing` 之后必须逐位相同。

### 5.9 大小和省略

- 大小量的是这份元数据照下面这一种写法序列化之后的字节数，落盘的文件怎么排版不影响这个数：JSON，UTF-8，不带缩进，键和值之间、各项之间不加空格和换行，末尾不加换行；数和字符串的写法照 ECMAScript 的 `JSON.stringify`（数是能读回同一个双精度的最短十进制写法；非 ASCII 字符照原样写，不转成 `\u` 转义）。键的次序不影响字节数。64 KB 按 65536 字节算。
- 实体太多放不下时，只有同时满足这三样的实体可以不列进 `entities`：`class` 是 `part`，没有 `role`，这一帧没在动。省掉了几个，必须写进 `omittedParts`。

### 5.10 确定性

同一帧渲两遍，元数据去掉 `timing` 之后必须逐位相同（哈希档），或除 `hash.color` 和 `stats` 之外逐位相同（容差档）。两个档见 F 契约第 2 节。

### 5.11 `motion.speed`

- f 是镜头局部帧号。`speed` 取第 f 帧和第 f − 1 帧 `sub = 0` 两个状态之间的位移，除以 1 帧，单位是米每帧。
- 镜头第 0 帧取第 1 帧和第 0 帧两个状态之间的位移。
- 只有 1 帧的镜头写 0。
