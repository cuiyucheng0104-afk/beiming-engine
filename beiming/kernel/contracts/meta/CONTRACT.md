# 每帧元数据

版本：0.1.0-draft

## 1. 范围

管：

- 每帧元数据 `meta/0.1` 的全部字段：时间和画幅、相机、实体、灯、事件、文字框、读数、画面统计、来源信息、耗时、谁填的、哈希。
- 矩阵、屏幕坐标、包围盒、可见比例、屏占、深度范围的口径。
- 哪些字段可以是 `null`，各在什么时候。
- 哪些字段由宿主量、镜头代码不可写。
- 判定以上各条用的「元数据核对记录」。

不管：

- `render` 怎么调、能要哪些输出、能力声明、合规档的减免表、帧源名的值域：帧源接口契约（F）。
- 时间键、帧率、种子的写法：时间键契约（T）。
- 镜头代码经 `meta(f)` 交什么、实体名的写法：镜头契约（S）。
- 卡的引用的写法、各张卡的 `meta(f)` 的合并次序：卡的运行时接口契约（CR）。
- 事件表：事件表契约（EV）。
- 深度层、编号层的数值定义：输出通道契约（PS）。
- 元数据拿去判什么：谓词登记表契约（PR）。
- `source.renderer` 和锁文件、作业记录对不对得上：锁文件契约（LK）。

## 2. 术语

帧、全片帧号、镜头、镜头局部帧号、子帧相位、种子、帧率、快门角、核对记录：见时间键契约（T）第 2 节。镜头代码、实体、实体名、锚点、母语对象、可信边界：见镜头契约（S）第 2 节。帧源、帧源名、宿主、能力声明、输出、颜色层、合规档、档位、只要元数据：见帧源接口契约（F）第 2 节和 3.3。卡的引用：见卡的运行时接口契约（CR）第 2 节。

| 词 | 含义 |
|---|---|
| 每帧元数据 | 随一帧交出的一份数据对象，说这一帧的相机、场景里有什么、画面怎么样、谁渲的。 |
| 角色 | 一个实体在这个镜头里的重要性标记：`hero` 是主体，`mustSee` 是必须看得见的东西。 |
| 编号 | 实体在镜头内的整数标识，和物体编号层里的像素值是同一个数；0 是背景。 |
| 屏幕包围盒 | 实体投到画面上之后的轴对齐矩形。 |
| 三维包围盒 | 实体在世界坐标里的轴对齐盒子。 |
| 可见比例 | 实体和别的东西一起渲时占的像素数，除以它单独渲时占的像素数。 |
| 屏占 | 实体的屏幕包围盒落在画面内的面积，除以画面面积。 |
| 平面深度 | 一个点到相机的距离沿相机 −Z 方向的分量，不是到相机的直线距离。 |
| 文字框 | 画面上的一段文字和它占的矩形。 |
| 读数 | 镜头代码自己定义、自己交的一个数。 |
| 来源信息 | 元数据里的 `source`：这一帧是哪个帧源、哪个宿主、哪个版本、哪一档渲的。 |
| 出帧者 | 实际算出这一帧像素的帧源。 |
| 元数据核对记录 | 一致性测试把「每次 `render` 交了几份元数据、多大、颜色层出自哪次调用」写下来的数据对象，只用来判定不变量。 |

## 3. 结构

### 3.1 每帧元数据

顶层对象，`format` 是 `meta/0.1`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `meta/0.1` | 格式标识 |
| `film` | 字符串 | 无 | 是 | 不空 | 片子的标识，写法归片子描述契约（D） |
| `shot` | 字符串 | 无 | 是 | 小写字母、数字、连字符 | 镜头的标识 |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 全片帧号 |
| `shotFrame` | 整数 | 帧 | 是 | ≥ 0 | 镜头局部帧号；和 `frame` 的关系由 T9 管 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 这份元数据量的是 `{ frame, sub }` 这一时刻的场景 |
| `seed` | 整数 | 无 | 是 | 见 T 契约 3.3 | 种子 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率 |
| `size` | 数组 | 像素 | 是 | `[宽, 高]`，正整数 | 这一帧输出的尺寸 |
| `colorRef` | 字符串 | 无 | 是 | `scene`、`display` | 颜色层是场景参考还是显示参考，见 F 契约 5.2 |
| `units` | 对象 | 无 | 是 | 正好是 `{ "meter": 1, "up": "Y", "hand": "right" }` | 把通用口径原样写一遍，给不读契约的工具看 |
| `camera` | 对象或 `null` | 无 | 是 | 见 3.2 | 相机 |
| `entities` | 数组或 `null` | 无 | 是 | 每项见 3.3 | 实体 |
| `omittedParts` | 整数 | 个 | 否 | ≥ 1 | 为了不超过大小上限没列进 `entities` 的零件个数，见 5.9 |
| `lights` | 数组或 `null` | 无 | 是 | 每项见 3.4 | 灯 |
| `events` | 数组 | 无 | 是 | 每项见 3.4 | 落在这一帧上的事件 |
| `texts` | 数组 | 无 | 是 | 每项见 3.4 | 文字框 |
| `readings` | 对象 | 无 | 否 | `{ 名字: 双精度 }`，名字不空 | 读数 |
| `stats` | 对象或 `null` | 无 | 是 | 见 3.5 | 画面统计 |
| `source` | 对象 | 无 | 是 | 见 3.5 | 来源信息 |
| `timing` | 对象 | 无 | 是 | 见 3.5 | 耗时 |
| `origin` | 对象 | 无 | 是 | 见 3.5 | 哪些字段是谁填的 |
| `hash` | 对象 | 无 | 是 | 见 3.5 | 哈希 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `camera`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `world` | 数组 | 米 | 是 | 16 个双精度 | 相机到世界的矩阵，列主序 |
| `proj` | 数组 | 无 | 是 | 16 个双精度 | 投影矩阵，列主序，OpenGL 约定 |
| `fovYDeg` | 双精度 | 度 | 是 | `(0, 180)` | 垂直视场角 |
| `near` | 双精度 | 米 | 是 | > 0 | 近裁剪面 |
| `far` | 双精度 | 米 | 是 | 大于 `near` | 远裁剪面 |
| `focusDist` | 双精度或 `null` | 米 | 是 | > 0 | 对焦距离 |
| `fstop` | 双精度或 `null` | 无 | 是 | > 0 | 光圈值 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | 快门角；0 表示没有运动模糊 |

### 3.3 `entities[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 整数 | 无 | 是 | ≥ 1 | 编号 |
| `name` | 字符串 | 无 | 是 | 实体名，写法见 S 契约 5.2 | 实体名 |
| `class` | 字符串 | 无 | 是 | 不空 | 类别；现在用到的有 `assembly`、`part`、`particles` |
| `role` | 字符串 | 无 | 否 | `hero`、`mustSee` | 角色；没有角色就不出现 |
| `bbox2d` | 数组 | 像素 | 是 | `[x0, y0, x1, y1]`，`x0 ≤ x1`，`y0 ≤ y1` | 屏幕包围盒 |
| `bbox3d` | 数组 | 米 | 否 | `[x0, y0, z0, x1, y1, z1]`，前三个不大于后三个 | 三维包围盒，世界坐标 |
| `visible` | 双精度或 `null` | 无 | 是 | `[0, 1]` | 可见比例，量法见 5.3 |
| `pxArea` | 双精度 | 无 | 是 | `[0, 1]` | 屏占，算法见 5.4 |
| `depth` | 数组 | 米 | 否 | `[近, 远]`，近不大于远 | 这个实体的平面深度范围 |
| `cards` | 数组 | 无 | 否 | 卡的引用，写法见 CR 契约 3.3 | 这个实体是哪几张卡带进来或驱动的 |
| `anchors` | 对象 | 无 | 否 | `{ 锚点名: { world, screen } }` | 锚点。`world` 是 `[x, y, z]`，米，世界坐标，由镜头代码交；`screen` 是 `[x, y]`，像素，由宿主把 `world` 投到屏幕上算出 |
| `motion` | 对象 | 无 | 否 | `{ speed, unit }` | `speed` 是这个实体这一帧在世界坐标里移动的速率，≥ 0；`unit` 必须是 `m/frame` |
| `count` | 整数 | 个 | 否 | ≥ 0 | 这个实体里的个体数，例如粒子数 |

`events[]`：

### 3.5 `stats`、`source`、`timing`、`origin`、`hash`

`stats`，在颜色层的线性编码数值上算：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `luma` | 对象 | 无 | 是 | `{ p1, p50, p99 }`，都 ≥ 0，`p1 ≤ p50 ≤ p99` | 亮度的第 1、50、99 百分位；亮度按 Rec.709 的权重从线性编码的三个通道算 |
| `clipHigh` | 双精度 | 无 | 是 | `[0, 1]` | 亮部溢出的像素占比 |
| `clipLow` | 双精度 | 无 | 是 | `[0, 1]` | 暗部压死的像素占比 |
| `noise` | 双精度或 `null` | 无 | 是 | ≥ 0 | 噪声的估计 |
| `tris` | 整数 | 个 | 是 | ≥ 0 | 这一帧场景里的三角形数 |

`source`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 帧源名，见 F 契约 3.1 | 片子描述里给这个镜头声明的帧源 |
| `renderer` | 字符串 | 无 | 是 | `blender`、`three`、`core`、`legacy-page` | 出帧者，见 5.6 |
| `host` | 字符串 | 无 | 是 | 出帧者的能力声明 `hosts` 里的一项；`three` 的取值 `待定：three 帧源的渲染器主干` | 哪个宿主 |
| `version` | 字符串 | 无 | 是 | 不空；`three` 的取值 `待定：three 的精确版本` | 出帧者的版本 |
| `tier` | 字符串 | 无 | 是 | `draft`、`final` | 档位 |
| `gpu` | 字符串 | 无 | 否 | 不空 | 显卡型号 |
| `backend` | 字符串 | 无 | 否 | 不空 | 图形后端 |
| `samples` | 整数 | 次 | 否 | ≥ 1 | 每像素采样数 |
| `denoise` | 字符串 | 无 | 否 | 不空 | 用的哪种降噪；没降噪就不出现 |

`timing`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `stateMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 写状态花的时间 |
| `renderMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 渲染花的时间；没出像素写 0 |
| `readbackMs` | 双精度 | 毫秒 | 是 | ≥ 0 | 读回花的时间；没出像素写 0 |

`origin`：三个键都必填，每个是路径的数组，不重复。路径的写法见 5.7。

| 字段 | 值域 | 说明 |
|---|---|---|
| `host` | `camera`、`entities`、`lights`、`stats`、`source`、`timing` | 由宿主直接从场景和渲染器量的字段 |
| `shot` | `entities.*.anchors`、`texts`、`readings` | 由镜头代码经 `meta(f)` 交的字段 |
| `kernel` | `events` | 由内核从事件表填的字段 |

`hash`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `color` | 字符串或 `null` | 是 | `sha256:` 加 64 位小写十六进制 | 同一次 `render` 交出的颜色层文件内容的哈希 |

### 3.6 可以是 `null` 的字段

只有下面这些字段可以是 `null`，别的字段一律不得是 `null`。

| 字段 | 哪一类 | 什么时候是 `null` |
|---|---|---|
| `entities[].visible` | 这次没算 | 这一帧没出像素；或这个实体没有角色；或这一帧没被点名要算可见比例 |
| `stats` | 这次没算 | 这一帧没出像素 |
| `hash.color` | 这次没算 | 这一帧没出像素 |
| `camera` | 减免 | 出帧者是 `legacy-page` |
| `entities` | 减免 | 出帧者是 `legacy-page` |
| `camera.focusDist` | 可以声明 | 出帧者在能力声明的 `metaNull` 里列了它 |
| `camera.fstop` | 可以声明 | 同上 |
| `stats.noise` | 可以声明 | 同上 |
| `lights` | 可以声明 | 同上 |

「这一帧没出像素」就是这次 `render` 只要元数据。这时相机、屏幕包围盒、三维包围盒、屏占、深度范围、锚点、事件照常要有。

### 3.7 元数据核对记录

顶层对象，`format` 是 `meta-check/0.1`。一份记录说一个镜头的若干次 `render`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `meta-check/0.1` | 格式标识 |
| `shot` | 字符串 | 无 | 是 | 小写字母、数字、连字符 | 镜头的标识 |
| `renders` | 数组 | 无 | 是 | 至少 1 项，`call` 不重复 | 每项是一次成功的 `render`，见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`renders[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `call` | 整数 | 无 | 是 | ≥ 0 | 这次调用在本记录里的序号 |
| `shotFrame` | 整数 | 帧 | 是 | ≥ 0 | 镜头局部帧号 |
| `metas` | 整数 | 份 | 是 | ≥ 0 | 这次调用交回了几份元数据 |
| `metaBytes` | 整数 | 字节 | 是 | ≥ 0 | 交回的元数据序列化后的大小，量法见 5.9 |
| `colorCall` | 整数 | 无 | 否 | ≥ 0 | 和这份元数据一起落盘的颜色层出自哪一次调用；没要颜色层就不出现 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| M1 | 每次成功的 `render` 必须正好交一份元数据，和它一起落盘的颜色层必须出自同一次 `render`。 | 元数据核对记录的 `renders` 每一项：`metas` 必须等于 1；`colorCall` 出现时必须等于 `call` | `M1-color-from-another-call.json` |
| M2 | `camera`、`entities`、`lights`、`stats`、`timing` 必须由宿主量并列在 `origin.host` 里，镜头代码不得写；镜头代码能写的只有 `origin.shot` 列的路径，`origin.shot` 只能列 `entities.*.anchors`、`texts`、`readings`。 | `origin.host` 去掉 `source` 之后作为集合必须等于这五项；`origin.shot` 每项必须是这三条路径之一；`origin.kernel` 每项必须是 `events`。行为上怎么测见 5.8 | `M2-shot-writes-camera.json` |
| M3 | 一份元数据序列化后不得超过 65536 字节。 | 元数据核对记录的 `renders` 每一项：`metaBytes` 必须不大于 65536 | `M3-over-64kb.json` |
| M4 | `null` 只能出现在 3.6 列出的字段上：减免类的只有出帧者是 `legacy-page` 时才能是 `null`，可以声明类的只有出帧者的能力声明 `metaNull` 列了它才能是 `null`，不得用编出来的数代替。 | 找出元数据里每一个 `null`（`ext` 里的不算）：它的路径必须在 3.6 的表里；是 `camera` 或 `entities` 时 `source.renderer` 必须是 `legacy-page`；是可以声明类时必须出现在出帧者能力声明的 `metaNull` 里 | `M4-null-camera-from-blender.json` |
| M5 | `source.renderer` 每帧必填，必须是 `blender`、`three`、`core`、`legacy-page` 之一，由出帧的那个帧源进程填，`origin.host` 里必须有 `source`。 | `source.renderer` 必须出现并且是这四个值之一；`origin.host` 必须含 `source` | `M5-renderer-not-a-source.json` |
| M6 | 没出像素的帧，`stats`、`hash.color` 和每个 `entities[].visible` 必须都是 `null`；出了像素的帧，`stats` 和 `hash.color` 都不得是 `null`。 | `hash.color` 是 `null` 当且仅当 `stats` 是 `null`；`hash.color` 是 `null` 时每个 `entities[].visible` 必须是 `null` | `M6-visible-without-pixels.json` |
| M7 | 可见比例只对有角色的实体算：`visible` 不是 `null` 的实体必须有 `role`。 | `entities` 每一项：`visible` 不是 `null` 时 `role` 必须出现 | `M7-visible-without-role.json` |
| M8 | 一份元数据里实体的编号不得重复，名字不得重复，编号不得是 0。 | `entities` 的 `id` 没有重复并且都 ≥ 1，`name` 没有重复 | `M8-duplicate-entity-id.json` |

## 5. 口径

### 5.1 坐标和矩阵

- 长度、坐标系、相机朝向照通用口径。Blender 一侧的换轴由帧源接口契约（F）5.1 管，元数据里的坐标都是换过之后的。
- 矩阵是 16 个数，列主序：前四个数是第一列。
- `camera.world` 把相机坐标里的点变到世界坐标。它的第四列前三个数是相机在世界里的位置。
- `camera.proj` 是 OpenGL 约定的透视投影：相机看向 −Z，裁剪空间的深度范围是 `[−1, 1]`。它和 `fovYDeg`、`near`、`far`、`size` 的关系：第 6 个数等于 `1 ÷ tan(fovYDeg ÷ 2)`，第 1 个数等于第 6 个数乘以高再除以宽，第 11 个数等于 `−(far + near) ÷ (far − near)`，第 15 个数等于 `−2 × far × near ÷ (far − near)`。
- 本契约现在没有四元数字段；以后出现时次序是 `(x, y, z, w)`。

### 5.2 屏幕

- 单位是像素，原点在画面左上角，x 向右，y 向下。画面的范围是 `[0, 宽] × [0, 高]`。
- 世界坐标里的点 p 投到屏幕：先用 `camera.world` 的逆把 p 变到相机坐标，再乘 `camera.proj` 并做透视除法得到 `[−1, 1]` 里的 `(nx, ny)`，屏幕坐标是 `((nx + 1) ÷ 2 × 宽, (1 − ny) ÷ 2 × 高)`。
- `bbox2d` 是 `[x0, y0, x1, y1]`，`(x0, y0)` 是左上角。`anchors.*.screen` 照上面的投影算。

### 5.3 `visible`

- 可见比例等于这个实体合渲时在编号层里占的像素数，除以它单独渲时占的像素数。两个数都在四分之一分辨率的编号层上数。
- 只对有角色的实体算。也不是每帧都算：只在被抽查的帧和被点名查询的帧上算，别的帧写 `null`。
- 多渲的那一遍低分辨率编号层花多少时间：`待探针：每个有角色的实体多渲一遍四分之一分辨率编号层的耗时`。

### 5.4 `pxArea`

把 `bbox2d` 和画面范围求交，交出来的矩形面积除以宽乘高。不依赖像素，只要元数据时照算。

### 5.5 `depth`

平面深度，米。`[近, 远]` 是这个实体上离相机最近和最远的点的平面深度。不依赖像素，只要元数据时照算。它和深度层读数差多少，看 F 契约 5.3 的「深度口径」一项。

### 5.6 `source.id` 和 `source.renderer`

- `id` 是片子描述里声明的帧源，`renderer` 是实际算出这一帧像素的帧源。平时两者相同；一个帧源接管了出帧、原来的帧源留作对照时，两者不同。
- `renderer` 由出帧的帧源进程自己填，镜头代码够不着。
- 声称由 `core` 出的帧，`renderer` 不是 `core` 就不算数。

### 5.7 `origin` 里的路径

- 路径是顶层字段名，或用 `.` 连起来的字段名；`*` 代表数组里的每一项。
- 一个字段归谁，看能匹配它的最长的那条路径：`entities.*.anchors` 归镜头代码，`entities` 里的其余部分归宿主。
- 没被任何路径匹配到的顶层字段（`format`、`film`、`shot`、时间和画幅、`units`、`origin`、`hash`、`omittedParts`）由宿主填，镜头代码同样不得写。

### 5.8 「镜头代码不得写」怎么测

同一个镜头渲两遍同一帧：一遍用原样的镜头代码，一遍让它的 `meta(f)` 多交 `origin.host` 里的键（这本身违反 S8）。两遍元数据里 `origin.host` 列的字段去掉 `timing` 之后必须逐位相同。

### 5.9 大小和省略

- 大小量的是这份元数据按 UTF-8 写成 JSON 文件之后的字节数。64 KB 按 65536 字节算。
- 实体太多放不下时，只有同时满足这三样的实体可以不列进 `entities`：`class` 是 `part`，没有 `role`，这一帧没在动。省掉了几个，必须写进 `omittedParts`。

### 5.10 确定性

同一帧渲两遍，元数据去掉 `timing` 之后必须逐位相同（哈希档），或除 `hash.color` 和 `stats` 之外逐位相同（容差档）。两个档见 F 契约第 2 节。
