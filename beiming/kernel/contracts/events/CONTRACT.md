# 事件表

版本：0.1.0-draft

## 1. 范围

管：

- 事件表 `events/0.1` 的全部字段。它是求值核的产物，文件名是 `events.json`。
- 片子描述里的事件和切点怎么展开成事件表里的事件条目。
- 从 `tracks` 并进来的事件条目长什么样。
- 事件条目的次序。
- 判定以上各条用的「事件核对记录」。

不管：

- 片子描述里事件怎么写、时刻算式的文法、切点的定义：片子描述契约（D）。
- 时间键、帧率的写法：时间键契约（T）。
- `tracks` 的数据格式，到位帧、爆发帧、震动帧怎么从 `tracks` 里认出来：不归本契约，归属见第 6 节。
- 每帧元数据里的 `events` 字段：每帧元数据契约（M）；它的事件条目从本契约的事件表里取。
- 声音怎么按事件表合成、`onset` 和 `pcenter` 各提前多少：不归本契约，归属见第 6 节。
- 谓词怎么用事件：谓词登记表契约（PR）。
- 事件表怎么进帧源：帧源接口契约（F）3.2 的镜头输入；本契约只给它的形状。

## 2. 术语

帧、全片帧号、子帧相位、时间键、帧率、镜头、核对记录：见时间键契约（T）第 2 节。实体名：见镜头契约（S）第 2 节。求值核、`tracks`：见卡的运行时接口契约（CR）第 2 节。片子描述、事件、切点、时刻算式、镜头区间：见片子描述契约（D）第 2 节。

| 词 | 含义 |
|---|---|
| 事件表 | 求值核把一部片子里全部有名字的时刻展开成帧号之后的时刻清单。声音和谓词只读它，不自己再从片子描述展开。 |
| 事件条目 | 事件表里的一项，说一个时刻。 |
| 命名条目 | 从片子描述的 `events` 展开来的事件条目。 |
| 切点条目 | 从切点来的事件条目。 |
| 轨道条目 | 从 `tracks` 并进来的事件条目：到位、爆发、震动。 |
| 事件核对记录 | 一致性测试把一份事件表和它对应的片子描述写下来的数据对象，只用来判定不变量。 |

## 3. 结构

事件表的任何一层都不得出现本节没列的键。

### 3.1 事件表

顶层对象，`format` 是 `events/0.1`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `events/0.1` | 格式标识 |
| `film` | 字符串 | 无 | 是 | 片子的 `id`，写法见 D 契约 5.1 | 哪部片子 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率，照抄片子描述 |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 总帧数，照抄片子描述 |
| `events` | 数组 | 无 | 是 | 每项见 3.2；可以是空数组 | 事件条目，次序见 EV1 |

### 3.2 `events[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 不空，不含空白；写法见 5.1 | 事件条目的标识 |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 全片帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 子帧相位。`frame` 和 `sub` 合起来是一个时间键。这个字段的写法按倾向定，合作者不同意时再改，见第 6 节 |
| `shot` | 字符串 | 无 | 否 | 片子描述里镜头的 `id` | 属于哪个镜头。切点条目不出现 |
| `kind` | 字符串 | 无 | 是 | `named`、`cut`、`arrive`、`burst`、`shake` | 命名条目、切点条目，还是轨道条目里的到位、爆发、震动 |
| `from` | 字符串 | 无 | 是 | `film`、`tracks` | 来自片子描述，还是来自 `tracks` |
| `entity` | 字符串 | 无 | `kind` 是 `arrive` 时必填 | 实体名，写法见 S 契约 5.2 | 这个时刻说的是哪个实体 |
| `audio` | 字符串 | 无 | 否 | 点分小写 | 这个时刻响什么，照抄片子描述 |
| `sync` | 字符串 | 无 | 与 `audio` 同时出现 | `onset`、`pcenter` | 声音怎么对帧；含义见 D 契约 3.4。片子描述里没写的，展开时写成 `onset` |

### 3.3 事件核对记录

顶层对象，`format` 是 `events-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。

「来历」一栏的四个词见契约写法约定 3.1。来历是相对测试工具说的，测试工具在展开事件表的求值核之外。格式标识和 `ext` 不是观测，来历写「—」。整份收进来的事件表是被判的东西本身，标 `自报`；哪几条的查法只读它，见第 6 节「只读事件表自己的条文」一行。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `events-check/0.1` | — | 格式标识 |
| `events` | 事件表 | 无 | 是 | 见 3.1 | `自报` | 被判的事件表：求值核展开出来交回的那一份，整份收进来，不改写 |
| `film` | 片子描述 | 无 | 否 | 见 D 契约 3.1 | `请求` | 测试工具交给求值核去展开的那份片子描述。出现才判 EV4、EV5、EV6 和 EV7 里带 `shot` 的那一半；EV7 的前一半（0 ≤ `frame` < `frames`）不带 `film` 也判 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| EV1 | 事件条目必须按 `frame` 升序排，`frame` 相同的按 `id` 升序排。 | 相邻两项：前一项的 `frame` 小于后一项的；相等时前一项的 `id` 按 5.2 的比法小于后一项的 | `EV1-out-of-order.json` |
| EV2 | 事件条目的 `id` 不得重复。 | 没有两项的 `id` 逐字符相同 | `EV2-duplicate-id.json` |
| EV3 | `kind` 是 `named` 或 `cut` 的事件条目 `from` 必须是 `film`，`kind` 是 `arrive`、`burst`、`shake` 的事件条目 `from` 必须是 `tracks`。 | 逐项比 `kind` 和 `from` | `EV3-cut-from-tracks.json` |
| EV4 | 片子描述的每个事件必须正好对应一个命名条目，命名条目也必须都来自片子描述，两边的 `id`、帧号、`shot`、`audio`、`sync` 必须对上。 | 片子描述 `events` 的 `id` 的集合等于 `kind` 是 `named` 的事件条目的 `id` 的集合；每一对：事件条目的 `frame` 等于事件的 `frame` 照 D 契约 5.3 展开的值，`sub` 等于 0；`shot`、`audio` 两边同时出现并相等，或同时不出现；有 `audio` 时事件条目的 `sync` 等于事件的 `sync`，事件没写时等于 `onset`。事件的 `frame` 是算式、又展开不了的（引用了没定义的事件，或者成环），这份片子描述违反 D 契约的 D2，求值核必须拒收、不交事件表；记录里它和事件表同时出现，这一对就算对不上 | `EV4-named-frame-not-expanded.json`、`EV4-unresolved-frame-delivered.json` |
| EV5 | 片子描述的每个切点必须正好对应一个切点条目，切点条目也必须都对着切点，事件条目的 `id` 必须是 `cut.` 加帧号，不得带 `shot`。 | 切点的集合照 D 契约 5.2 算；它等于 `kind` 是 `cut` 的事件条目的 `frame` 的集合，且没有两个切点条目的 `frame` 相等；每个切点条目的 `id` 等于 `cut.` 加 `frame` 的十进制写法，`sub` 等于 0，不出现 `shot` | `EV5-cut-missing.json` |
| EV6 | `film`、`fps`、`frames` 必须等于片子描述的 `id`、`output.fps`、`output.frames`。 | 三个值逐个比，字符串逐字符相同，整数相等 | `EV6-fps-differs.json` |
| EV7 | 每个事件条目的 `frame` 必须落在 `[0, frames)` 内，带 `shot` 的还必须落在那个镜头的区间内。 | 0 ≤ `frame` < `frames`，`frames` 取事件表自己的；这一半只用事件表就能判，单独的事件表和不带 `film` 的核对记录同样判。带 `shot` 时 `shot` 是片子描述里镜头的 `id`，并且镜头的 `in` ≤ `frame` < 镜头的 `out`；这一半只在核对记录带 `film` 时判 | `EV7-frame-past-end.json`、`EV7-arrive-outside-shot.json` |

## 5. 口径

### 5.1 `id` 的写法

| 事件条目 | `id` |
|---|---|
| 命名条目 | 片子描述里那个事件的 `id` |
| 切点条目 | `cut.<帧号>`，帧号是十进制，不带前导零，例如 `cut.180` |
| 到位 | `arrive.<实体名>`，例如 `arrive.kit.fan_L` |
| 爆发、震动 | 以 `burst.`、`shake.` 开头，后面怎么写见第 6 节 |

命名条目的 `id` 里没有 `.`（见 D 契约 5.1），所以不会和后三种撞名。

### 5.2 `id` 怎么比大小

逐字符按 Unicode 码点比，先不同的那一位码点小的在前；一个是另一个的前缀时，短的在前。不看语言环境，不忽略大小写。

### 5.3 展开

- 命名条目：`frame` 是事件的 `frame` 照 D 契约 5.3 展开的整数，`sub` 是 0。
- 切点条目：`frame` 是切点，`sub` 是 0。一部只有一个镜头的片子没有切点条目。
- 轨道条目：`frame` 和 `sub` 由求值核从 `tracks` 里取。
- 同样的片子描述和 `tracks` 必须展开出逐位相同的事件表。「逐位相同」指两份事件表作为 JSON 值逐键、逐项相等。
- 片子描述里 `events` 的书写顺序不要求；事件表（展开结果）必须按 EV1 排序。

### 5.4 谁读它

声音的合成和谓词的求值只从事件表读时刻。帧源也只从事件表读事件的帧号：上层把事件表放进镜头输入的 `events` 字段（F 契约 3.2），形状就是 3.1，里面的 `frame` 是全片帧号；片子没有事件表时这个字段不出现。每帧元数据的 `events` 列的是事件表里 `frame` 等于这一帧全片帧号的事件条目。

## 6. 待定

| 项 | 现在怎么写 | 等什么 |
|---|---|---|
| `sub` | 照时间键 `{ frame, sub }` 写；命名条目和切点条目固定是 0 | 离屏宿主的定位：按倾向定，合作者不同意时再改 |
| 排序里 `sub` 排第几 | 照需求来源写：只按 `frame`，再按 `id`，不看 `sub` | 轨道条目出现非 0 的 `sub` 时再定 |
| `sync` 的默认值在展开时写出来 | 照样例写：片子描述里没写 `sync` 的事件，事件条目里是 `onset` | 集成负责人确认 |
| 没有 `audio` 的事件条目带不带 `sync` | 【起草者补】不带；`sync` 和 `audio` 同时出现：出现一个就必须出现另一个，两个方向都由结构定义管 | 集成负责人确认 |
| 到位条目的 `id` 和 `entity` | 【起草者补】从唯一的一个样例定：`arrive.<实体名>`，`entity` 必填。`entity` 必填由结构定义管；`id` 的写法没立成不变量 | `tracks` 的格式定了以后立 |
| 爆发、震动条目的 `id`，带不带 `entity` | 不定，只定了前缀 | `tracks` 的格式定了以后立 |
| 同一个实体到位两次时 `id` 怎么不撞 | 不定 | `tracks` 的格式定了以后立 |
| 轨道条目带不带 `shot` | 样例里带；本契约只要求切点条目不带 | 集成负责人确认 |
| 到位帧、爆发帧、震动帧怎么从 `tracks` 里认出来，`tracks` 的格式归哪份契约 | 不定 | 集成负责人指派 |
| 轨道条目能不能带 `audio` | 结构里不禁止 | 集成负责人确认 |
| `onset`、`pcenter` 各自提前多少、怎么量 | 不归本契约 | `待探针：听感重心相对起音的提前量，单位帧` |
| 「声音和谓词只读事件表」 | 写在 5.4，没有立成不变量：现在没有能判它的数据 | 集成负责人定要不要加静态扫描的门 |
| 不合法的片子描述 | 求值核收到违反 D 契约的片子描述必须拒收，不交事件表。核对记录的 `events` 必填，带 `film` 的记录只写求值核交了事件表的情形，所以正例里的 `film` 必须是合法的片子描述，不得出现「拿不合法的片子照常交出事件」。本契约判得出的只有事件时刻展开不了这一种（EV4，展开时必然碰到）；片子描述别的不合法写法求值核拒没拒，判定函数不跑 D 契约的条文，记录里也没有拒收的结局，现在判不出 | 要判时在记录里加求值核拒收的结局（错误码）这一段再立条文 |
| 只读事件表自己的条文 | EV1、EV2、EV3 和 EV7 的前一半只读 `events`：判的是交上来的事件表本身排得对不对、前后对不对得上，不靠谁的说法。EV4、EV5、EV6 和 EV7 的后一半拿 `events` 对 `film`（`请求`）：判定时照 D 契约 5.2、5.3 从片子描述另算一遍再比，不取求值核自己的说法。轨道条目只有前一类条文管：记录里没有 `tracks`，它的时刻和 `tracks` 对不对现在没有条文 | `tracks` 的格式定了以后，在记录里加 `tracks` 这一段再立条文 |
