# 事件表

版本：0.1.0-draft

## 1. 范围

管：

- 事件表 `events/0.1` 的全部字段。它是求值核的产物，文件名是 `events.json`。
- 片子描述里的事件和切点怎么展开成事件表里的条目。
- 从 `tracks` 并进来的条目长什么样。
- 条目的次序。
- 判定以上各条用的「事件核对记录」。

不管：

- 片子描述里事件怎么写、时刻算式的文法、切点的定义：片子描述契约（D）。
- 时间键、帧率的写法：时间键契约（T）。
- `tracks` 的数据格式，到位帧、爆发帧、震动帧怎么从 `tracks` 里认出来：不归本契约，归属见第 6 节。
- 每帧元数据里的 `events` 字段：每帧元数据契约（M）；它的条目从本契约的事件表里取。
- 声音怎么按事件表合成、`onset` 和 `pcenter` 各提前多少：不归本契约，归属见第 6 节。
- 谓词怎么用事件：谓词登记表契约（PR）。

## 2. 术语

帧、全片帧号、子帧相位、时间键、帧率、镜头、核对记录：见时间键契约（T）第 2 节。实体名：见镜头契约（S）第 2 节。求值核、`tracks`：见卡的运行时接口契约（CR）第 2 节。片子描述、事件、切点、时刻算式、镜头区间：见片子描述契约（D）第 2 节。

| 词 | 含义 |
|---|---|
| 事件表 | 求值核把一部片子里全部有名字的时刻展开成帧号之后的清单。声音和谓词只读它，不自己再从片子描述展开。 |
| 条目 | 事件表里的一项，说一个时刻。 |
| 命名条目 | 从片子描述的 `events` 展开来的条目。 |
| 切点条目 | 从切点来的条目。 |
| 轨道条目 | 从 `tracks` 并进来的条目：到位、爆发、震动。 |
| 事件核对记录 | 一致性测试把一份事件表和它对应的片子描述写下来的数据对象，只用来判定不变量。 |

## 3. 结构

事件表的任何一层都不得出现本节没列的键。

### 3.1 事件表

顶层对象，`format` 是 `events/0.1`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `events/0.1` | 格式标识 |
| `film` | 字符串 | 无 | 是 | 片子的 `id`，写法见 D 契约 5.1 | 哪部片子 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率，照抄片子描述 |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 总帧数，照抄片子描述 |
| `events` | 数组 | 无 | 是 | 每项见 3.2；可以是空数组 | 条目，次序见 EV1 |

### 3.2 `events[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 不空，不含空白；写法见 5.1 | 条目的标识 |
| `frame` | 整数 | 帧 | 是 | ≥ 0 | 全片帧号 |
| `sub` | 双精度 | 帧 | 是 | `[0, 1)` | 子帧相位。`frame` 和 `sub` 合起来是一个时间键。`待定：离屏宿主的定位` |
| `shot` | 字符串 | 无 | 否 | 片子描述里镜头的 `id` | 属于哪个镜头。切点条目不出现 |
| `kind` | 字符串 | 无 | 是 | `named`、`cut`、`arrive`、`burst`、`shake` | 命名条目、切点条目，还是轨道条目里的到位、爆发、震动 |
| `from` | 字符串 | 无 | 是 | `film`、`tracks` | 来自片子描述，还是来自 `tracks` |
| `entity` | 字符串 | 无 | `kind` 是 `arrive` 时必填 | 实体名，写法见 S 契约 5.2 | 这个时刻说的是哪个实体 |
| `audio` | 字符串 | 无 | 否 | 点分小写 | 这个时刻响什么，照抄片子描述 |
| `sync` | 字符串 | 无 | 与 `audio` 同时出现 | `onset`、`pcenter` | 声音怎么对帧；含义见 D 契约 3.4。片子描述里没写的，展开时写成 `onset` |

### 3.3 事件核对记录

顶层对象，`format` 是 `events-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `events-check/0.1` | 格式标识 |
| `events` | 事件表 | 无 | 是 | 见 3.1 | 被判的事件表 |
| `film` | 片子描述 | 无 | 否 | 见 D 契约 3.1 | 这份事件表是从哪份片子描述展开的。出现才判 EV4 到 EV7 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| EV1 | 条目必须按 `frame` 升序排，`frame` 相同的按 `id` 升序排。 | 相邻两项：前一项的 `frame` 小于后一项的；相等时前一项的 `id` 按 5.2 的比法小于后一项的 | `EV1-out-of-order.json` |
| EV2 | 条目的 `id` 不得重复。 | 没有两项的 `id` 逐字符相同 | `EV2-duplicate-id.json` |
| EV3 | `kind` 是 `named` 或 `cut` 的条目 `from` 必须是 `film`，`kind` 是 `arrive`、`burst`、`shake` 的条目 `from` 必须是 `tracks`。 | 逐项比 `kind` 和 `from` | `EV3-cut-from-tracks.json` |
| EV4 | 片子描述的每个事件必须正好对应一个命名条目，命名条目也必须都来自片子描述，两边的 `id`、帧号、`shot`、`audio`、`sync` 必须对上。 | 片子描述 `events` 的 `id` 的集合等于 `kind` 是 `named` 的条目的 `id` 的集合；每一对：条目的 `frame` 等于事件的 `frame` 照 D 契约 5.3 展开的值，`sub` 等于 0；`shot`、`audio` 两边同时出现并相等，或同时不出现；有 `audio` 时条目的 `sync` 等于事件的 `sync`，事件没写时等于 `onset` | `EV4-named-frame-not-expanded.json` |
| EV5 | 片子描述的每个切点必须正好对应一个切点条目，切点条目也必须都对着切点，条目的 `id` 必须是 `cut.` 加帧号，不得带 `shot`。 | 切点的集合照 D 契约 5.2 算；它等于 `kind` 是 `cut` 的条目的 `frame` 的集合，且没有两个切点条目的 `frame` 相等；每个切点条目的 `id` 等于 `cut.` 加 `frame` 的十进制写法，`sub` 等于 0，不出现 `shot` | `EV5-cut-missing.json` |
| EV6 | `film`、`fps`、`frames` 必须等于片子描述的 `id`、`output.fps`、`output.frames`。 | 三个值逐个比，字符串逐字符相同，整数相等 | `EV6-fps-differs.json` |
| EV7 | 每个条目的 `frame` 必须落在 `[0, frames)` 内，带 `shot` 的还必须落在那个镜头的区间内。 | 0 ≤ `frame` < `frames`；带 `shot` 时 `shot` 是片子描述里镜头的 `id`，并且镜头的 `in` ≤ `frame` < 镜头的 `out` | `EV7-arrive-outside-shot.json` |

## 5. 口径

### 5.1 `id` 的写法

| 条目 | `id` |
|---|---|
| 命名条目 | 片子描述里那个事件的 `id` |
| 切点条目 | `cut.<帧号>`，帧号是十进制，不带前导零，例如 `cut.180` |
| 到位 | `arrive.<实体名>`，例如 `arrive.kit.fan_L` |
| 爆发、震动 | 以 `burst.`、`shake.` 开头，后面怎么写见第 6 节 |

命名条目的 `id` 里没有 `.`（见 D 契约 5.1），所以不会和后三种撞名。

### 5.2 `id` 怎么比大小

逐字符按 Unicode 码点比，先不同的那一位码点小的在前；一个是另一个的前缀时，短的在前。不看语言环境，不忽略大小写。

### 5.3 展开

- 命名条目：`frame` 是事件的 `frame` 照 D 契约 5.3 展开的整数，`sub` 是 0。
- 切点条目：`frame` 是切点，`sub` 是 0。一部只有一个镜头的片子没有切点条目。
- 轨道条目：`frame` 和 `sub` 由求值核从 `tracks` 里取。
- 同样的片子描述和 `tracks` 必须展开出逐位相同的事件表。「逐位相同」指两份事件表作为 JSON 值逐键、逐项相等。

### 5.4 谁读它

声音的合成和谓词的求值只从事件表读时刻。每帧元数据的 `events` 列的是事件表里 `frame` 等于这一帧全片帧号的条目。

## 6. 待定

| 项 | 现在怎么写 | 等什么 |
|---|---|---|
| 格式标识 | 需求来源写的是 `"schema": "events/0.1"`；通用口径要求字段名是 `format`。照通用口径写成 `"format": "events/0.1"` | 集成负责人确认 |
| `sub` | 照时间键 `{ frame, sub }` 写；命名条目和切点条目固定是 0 | `待定：离屏宿主的定位` |
| 排序里 `sub` 排第几 | 照需求来源写：只按 `frame`，再按 `id`，不看 `sub` | 轨道条目出现非 0 的 `sub` 时再定 |
| EV3 | 【起草者补】从「`from` 写这条来自片子描述还是 `tracks`」和样例立成条文 | 集成负责人确认 |
| EV2、EV6、EV7 | 【起草者补】从样例立成条文，编号是本契约自己编的 | 集成负责人确认 |
| `sync` 的默认值在展开时写出来 | 照样例写：片子描述里没写 `sync` 的事件，条目里是 `onset` | 集成负责人确认 |
| 没有 `audio` 的条目带不带 `sync` | 【起草者补】不带；`sync` 只和 `audio` 一起出现 | 集成负责人确认 |
| 到位条目的 `id` 和 `entity` | 【起草者补】从唯一的一个样例定：`arrive.<实体名>`，`entity` 必填。没立成不变量 | `tracks` 的格式定了以后立 |
| 爆发、震动条目的 `id`，带不带 `entity` | 不定，只定了前缀 | `tracks` 的格式定了以后立 |
| 同一个实体到位两次时 `id` 怎么不撞 | 不定 | `tracks` 的格式定了以后立 |

| 轨道条目能不能带 `audio` | 结构里不禁止 | 集成负责人确认 |
| `onset`、`pcenter` 各自提前多少、怎么量 | 不归本契约 | `待探针：听感重心相对起音的提前量，单位帧` |
