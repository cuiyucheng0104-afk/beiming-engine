# 锁文件

版本：0.1.0-draft

## 1. 范围

管：

- 锁文件 `lock/1.0` 的全部字段：种子、每个镜头的子帧采样数、帧源和宿主的版本、卡的版本和哈希、卡的验证状态、资产的哈希、模板的版本、显示变换查找表的哈希、机器类别。
- 四个全片级的键和叠加层怎么展开进锁文件的 `cards`。
- 锁文件和它锁的那份片子描述之间必须对上的地方。
- 每帧元数据里的来源信息和锁文件怎么对。
- 判定以上各条用的「锁核对记录」。
- 镜头种子怎么从全片种子派生。
- 卡的哈希怎么算。

不管：

- 片子描述里面的字段、四个全片级的键各绑哪张卡：片子描述契约（D）。
- 镜头引用的卡和资产在锁文件里找不找得到：D3。锁文件由谁生成、同一个修订号的锁变不变：D4。
- 种子的值域：时间键契约（T）。
- 帧源名的值域、每个帧源有哪些宿主：帧源接口契约（F）。
- 每帧元数据里来源信息的字段：每帧元数据契约（M）。
- 验证状态四级各自要满足什么条件、落点那套词各是什么意思：卡文件格式契约（CF）。
- 模板里有哪些谓词：谓词登记表契约（PR）。
- 场景包的格式：场景包契约（SP）。
- 内建能力和内建卡的对应、它们的实现放在哪：目录归属表契约（OW）。

## 2. 术语

镜头、核对记录：见时间键契约（T）第 2 节；种子的值域见 T 契约 3.3。帧源、帧源名、宿主、出帧者：见帧源接口契约（F）、每帧元数据契约（M）第 2 节。卡、卡的引用、求值核：见卡的运行时接口契约（CR）第 2 节。片子描述、修订号、全片级的键、模板、切点、叠加层、卡实例、资产别名：见片子描述契约（D）第 2 节。落点（`livesIn`）：见卡文件格式契约（CF）5.3。内建能力：见目录归属表契约（OW）。

| 词 | 含义 |
|---|---|
| 锁文件 | 按一份片子描述生成的版本和哈希清单，记下出这部片子用到的每样东西的精确版本和哈希。有两种：服务器按片子描述的某个修订号生成的，是片子的正式锁，文件名是 `film.lock`；本机的锁生成器在出帧的那台机器上生成的，是本机锁（5.8），不用这个文件名。 |
| 本机锁 | `issuer` 是 `local` 的锁文件。只给生成它的那台机器出帧用，不交给服务器，不是正式锁。 |
| 全片种子 | 片子描述顶层写了 `seed` 就是它，没写就由片子的 `id` 派生（5.7）；没写种子的镜头从它派生。服务器和本机算出来的一样。 |
| 镜头种子 | 一个镜头实际生效的种子：片子描述里写了就是那个值，没写就是派生出来的值。 |
| 内建卡 | 不用在片子描述里引用的三张卡：`time.timeline`、`time.events`、`time.seeded`。它们和四样内建能力的对应、实现放在哪，见目录归属表契约（OW）里的对应表。 |
| 落点 | 一张卡的实现放在哪。用卡文件格式契约（CF）5.3 的 `livesIn` 那套词。 |
| 验证状态 | 一张卡验到了哪一级，以及是在哪个宿主、哪个版本、哪块显卡上验的。 |
| 机器类别 | 出片机器的一类配置的名字。 |
| 锁核对记录 | 一致性测试把一份锁文件和它对应的片子描述、元数据观测写下来的数据对象，只用来判定不变量。 |

## 3. 结构

锁文件的任何一层都不得出现本节没列的键。锁文件由锁生成器生成，别人不手写：片子的正式锁由服务器生成（D4），本机锁由本机的锁生成器生成（5.8）。

### 3.1 锁文件

顶层对象，`format` 是 `lock/1.0`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `lock/1.0` | 格式标识 |
| `issuer` | 字符串 | 无 | 是 | `server`、`local` | 谁生成的：服务器，还是本机的锁生成器（5.8） |
| `film` | 字符串 | 无 | 是 | 片子的 `id`，写法见 D 契约 5.1 | 锁的是哪部片子 |
| `rev` | 整数 | 无 | `issuer` 是 `server` 时必填，是 `local` 时不得出现（LK13） | ≥ 0 | 锁的是片子描述的哪个修订号。本机锁不对应任何修订号 |
| `contracts` | 字符串 | 无 | 是 | 三段十进制数，用 `.` 连接 | 生成这份锁时契约集的版本 |
| `seeds` | 对象 | 无 | 是 | 见 3.2 | 全片种子和每个镜头的种子 |
| `shots` | 对象 | 无 | 是 | `{ 镜头的 id: 镜头锁条目 }`，见 3.2 | 每个镜头锁下来的值 |
| `sources` | 对象 | 无 | 是 | `{ 帧源名: 帧源锁条目 }`，至少 1 项，见 3.3 | 用到的每个帧源锁在哪个版本 |
| `cards` | 对象 | 无 | 是 | `{ 卡名: 卡锁条目 }`，见 3.4 | 用到的每张卡锁在哪个版本 |
| `assets` | 对象 | 无 | 是 | `{ 资产引用: 哈希 }`；资产引用的写法见 D 契约 5.5，哈希的写法见 5.1 | 片子描述里镜头的 `assets` 和全片 `assets` 引用的每个资产的哈希。没用资产写空对象 |
| `templates` | 对象 | 无 | 是 | `{ 名字: 版本 }`；版本是三段十进制数 | `predicates.base` 引用的最低谓词和每个模板锁在哪个版本 |
| `view` | 对象 | 无 | 是 | `{ 查找表名: 哈希 }`，哈希的写法见 5.1 | 显示变换查找表的哈希 |
| `machine` | 对象 | 无 | `issuer` 是 `server` 时必填（LK13），是 `local` 时可写可不写 | 见 3.5 | 出片的机器。本机锁写了就是生成它的那台机器 |

### 3.2 `seeds`、`shots`

`seeds`：

| 键 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `film` | 整数 | 是 | 见 T 契约 3.3 | 全片种子 |
| 每个镜头的 `id` | 整数 | 是 | 见 T 契约 3.3 | 这个镜头的镜头种子 |

`shots` 的镜头锁条目：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `shutterSamples` | 整数 | 次 | 是 | ≥ 1 | 这个镜头生效的子帧采样数：片子描述里写了 `shutter.samples` 就是那个值，没写就是照 F 契约 5.9 算出的值（生效的快门角是 0 取 1，不是 0 用帧源能力声明的 `motionBlur.samples`；能力声明里没有这个字段的帧源取什么，见 F 契约第 6 节和本契约第 6 节）。帧源不在出帧时另定一个数 |

### 3.3 `sources` 的帧源锁条目

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `version` | 字符串 | 是 | 不空；`three` 的取值是 `0.187.0` | 帧源的版本，和这个帧源能力声明里的 `version` 是同一个值 |
| `host` | 字符串 | 是 | 这个帧源的能力声明 `hosts` 里的一项；`three` 用页面宿主，`core` 用离屏宿主（按倾向定，合作者不同意时再改） | 用哪个宿主 |
| `image` | 字符串 | `issuer` 是 `server` 时必填，是 `local` 时不得出现（LK13） | 哈希，写法见 5.1 | 运行环境镜像的哈希。本机没有镜像，交不出 |
| `browser` | 字符串 | 否 | 不空 | 页面类宿主用的浏览器构建的标识 |
| `scenePacks` | 对象 | 否 | `{ 镜头的 id: 哈希 }` | 只有 `core` 用：`source` 或 `renderer.source` 是 `core` 的每个镜头的场景包的哈希（按倾向定，合作者不同意时再改） |

### 3.4 `cards` 的卡锁条目

键是卡名，不带版本。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `version` | 字符串 | 是 | 三段十进制数，用 `.` 连接 | 卡的精确版本 |
| `impl` | 数组 | 是 | 至少 1 项，不重复：`data`、`source:three`、`source:blender`、`source:core`、`bake`、`comp` | 落点。一张卡有几个落点就列几个 |
| `sha256` | 字符串 | 是 | 64 位小写十六进制 | 这张卡这个版本的内容的哈希，算法见 5.1 |
| `from` | 字符串 | 否 | `style.view`、`style.finish`、`delivery`、`audio`、`overlays` | 这张卡是从哪个全片级的键、或者从叠加层展开来的。镜头引用的卡和内建卡不出现 |
| `verified` | 对象 | 是 | 见下表 | 验证状态 |

`verified`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `level` | 字符串 | 是 | `read`、`reproduced`、`measured`、`film-verified` | 验到哪一级，从低到高：只读过、复现过、量测通过、成片验证过 |
| `host` | 字符串 | 是 | 不空 | 在哪个宿主上验的 |
| `source` | 字符串 | 是 | 不空 | 那个宿主所在的帧源或工具当时的版本 |
| `gpu` | 字符串 | 是 | 不空；没用显卡写 `none` | 在哪块显卡上验的 |

`host`、`source`、`gpu` 三个缺一个，验证状态就不成立。

### 3.5 `machine`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `class` | 字符串 | 是 | 小写字母、数字、连字符 | 机器类别 |
| `driver` | 字符串 | 是 | 不空 | 显卡驱动的版本 |

### 3.6 锁核对记录

顶层对象，`format` 是 `lock-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。观测了、结果是空的写空数组；没观测的段不出现。

「来历」一栏的四个词见契约写法约定 3.1。格式标识、`ext` 和各段的数组本身不是观测，来历写「—」，段里的字段各自标。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `lock-check/0.1` | — | 格式标识 |
| `lock` | 锁文件 | 无 | 是 | 见 3.1 | `自报` | 被判的锁文件，生成它的一方交出来的，整份收进来 |
| `film` | 片子描述 | 无 | 否 | 见 D 契约 3.1 | `请求` | 这份锁锁的那份片子描述（正式锁是那个修订号的）：测试工具交去生成锁的那一份 |
| `renders` | 数组 | 无 | 否 | 每项见下表 | — | 用这份锁出的帧，每帧元数据里的来源信息 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

`renders[]`：

| 字段 | 类型 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|
| `renderer` | 字符串 | 是 | 帧源名，见 F 契约 3.1 | `自报` | 元数据里的出帧者，`source.renderer` |
| `host` | 字符串 | 是 | 不空 | `自报` | 元数据里的 `source.host` |
| `version` | 字符串 | 是 | 不空 | `自报` | 元数据里的 `source.version` |

哪几条的查法靠的是 `自报` 的字段，见第 6 节「只对了两边自己的说法」一行。

## 5. 口径

### 5.1 哈希的写法

- 字段名里没有算法名的哈希（`sources.*.image`、`sources.*.scenePacks.*`、`assets.*`、`view.*`）：写法见契约写法约定第 5 节的通用口径。
- `cards.*.sha256`：字段名已经说了算法，只写 64 位小写十六进制。
- 卡的哈希对卡目录下的全部文件算：路径按字节序排，每个文件算 SHA-256，再对「路径、换行、哈希、换行」拼起来的串算一次。
- 别的哈希是对文件内容的字节算的。各样东西具体对哪些文件算，归各自的契约。

### 5.2 版本怎么比

三段的版本取第一段，按整数和主版本比。别的版本字符串一律逐字符比，没有容差。

### 5.3 四个键和叠加层怎么展开

锁生成器生成锁文件时（服务器和本机一样），对片子描述里出现的每个全片级的键，往 `cards` 里放它绑的那张卡，`from` 写这个键。键里写了 `card` 的，锁的版本的第一段必须等于它指定的主版本；没写的，取那张卡当前的主版本。展开进来的卡和镜头引用的卡一样锁 `version` 和 `sha256`。

片子描述的 `overlays` 不空时，往 `cards` 里放 `two-d.overlay`，`from` 写 `overlays`，锁的版本的第一段是 1：宿主展开叠加层用的是 `two-d.overlay@1`，见 D 契约 5.11。

片子描述里没出现的全片级的键，`cards` 里不得有 `from` 是它的项；片子描述没有叠加层时，`cards` 里不得有 `from` 是 `overlays` 的项（LK1、LK10）。

### 5.4 验证状态

- 四级从低到高：`read`、`reproduced`、`measured`、`film-verified`。
- 验证状态只对 `host`、`source`、`gpu` 这一组成立。锁文件里记的宿主或版本和它不一样，就是没验过，必须先重验再生成锁；LK2 判的就是这一点。
- `impl` 里没有帧源落点的卡（只有 `data`、`bake`、`comp`），`verified.host` 写合成工具、烘焙工具或求值核的名字，`verified.source` 写它的版本，LK2 不判。

### 5.5 和元数据怎么对

用这份锁出的每一帧，元数据的 `source.renderer`、`source.host`、`source.version` 拿来和 `sources` 比（LK6）。比的是出帧者，不是片子描述里声明的帧源：镜头写了 `renderer` 时，出帧者是 `renderer.source`。

### 5.6 重建

同一份片子描述加同一份正式锁，画面和声音素材都一样：片子描述里指向文件的值都经资产别名记进了 `assets`。重渲时，哈希档的帧源结果逐位相同，容差档的在容差内；两个档和容差见 F 契约。

### 5.7 镜头种子怎么派生

全片种子只用来派生镜头种子。片子描述里写了 `seed` 的镜头，镜头种子就是那个值。没写的：镜头种子 = 全片种子和镜头 `id` 的 SHA-256 的前 4 个字节按大端读成的无符号 32 位整数。被哈希的串是十进制写法的全片种子、一个 `:`、镜头的 `id`，UTF-8 编码。例：全片种子 7800、镜头 `s01`，被哈希的串是 `7800:s01`，镜头种子是 2013376959。没写 `seed` 的镜头，锁里的镜头种子对不对由 LK12 判。

全片种子：片子描述顶层写了 `seed`（D 契约 3.1）就是那个值；没写的 = 片子 `id` 的 SHA-256 的前 4 个字节按大端读成的无符号 32 位整数，被哈希的串就是 `id` 本身，UTF-8 编码。例：`id` 是 `toon-demo`，全片种子是 899845905。服务器和本机锁生成器都这样算，所以同一份片子描述在两边派生出的镜头种子一样。片子换了 `id`（比如在本机建的片子交给服务器时服务器另给了 `id`）又没写顶层 `seed`，没写种子的镜头的种子会跟着变；想让随机跟着片子描述走，就写顶层 `seed`。对不对由 LK14 判。

### 5.8 本机锁

本机不起服务器出帧时，由本机的锁生成器先生成一份本机锁，帧源带着它 `open`，和带着正式锁时走同一条路：帧源不看 `issuer`，不得因为它不同而改变出帧。

- 生成的办法和服务器一样：种子照 5.7 派生，子帧采样数照 3.2，卡、资产、模板、显示变换查找表的版本和哈希取这台机器上装着的那一份。本机找不到某样东西时，生成器报错，不出锁。
- 卡的 `verified` 取卡文件 `status` 里宿主和版本跟本机帧源相同的那一项；没有这样的一项，生成器报错，不出锁（和 5.4 一样，验证状态不能借）。
- 不写 `rev`，帧源锁条目不写 `image`：本机锁不对应任何修订号，本机没有运行环境镜像（LK13）。`machine` 可写可不写。
- 本机锁每次本机出帧之前现生成，用完不当作这部片子的锁留着：不写成 `film.lock`，不放进片子的目录。要留存，就和出帧的产物放在一起，文件名用 `film.local.lock`。这样改了片子描述以后，不会有一份旧的本机锁被接着拿来用。这一条现在只有声明，没有判定。
- 本机锁不交给服务器，服务器只认它自己生成的锁。认不认得出正式锁，靠的是片子核对记录里测试工具量到的 `writer`（D4）；`issuer` 是锁自己的说法，只用来让人和本机工具分清两种锁。
- 5.6 的「重建」只对正式锁成立：本机锁没锁住运行环境，换一台机器拿它重渲，画面不保证一样。
