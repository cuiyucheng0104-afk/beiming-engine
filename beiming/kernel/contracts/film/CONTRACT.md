# 片子描述

版本：0.1.0-draft

## 1. 范围

管：

- 片子描述 `film/3.0` 的全部字段：输出规格、节拍表、镜头表、切点、事件、叠加层、画风、声音、谓词引用、交付规格。
- 标识、时刻算式、路径、卡的引用、资产引用在片子描述里的写法。
- 四个全片级的键各绑哪张卡。
- 写入怎么带修订号，哪些字段只有服务器能写。
- `explain` 的结果 `Explain`，以及一个参数的四层覆盖顺序。
- 判定以上各条用的「片子核对记录」。

不管：

- 锁文件里面的字段：锁文件契约（LK）。本契约只管「片子描述引用的卡和资产在锁文件里找不找得到」（D3）和「锁由谁生成、同一个修订号的锁变不变」（D4）。
- 事件表展开之后的格式：事件表契约（EV）。
- 帧率、种子的写法，快门窗口：时间键契约（T）。
- 帧源名的值域、每个帧源有哪些宿主和作者模式：帧源接口契约（F）。
- 卡的参数表、参数含义、卡的类别：卡文件格式契约（CF）。`shots[].cards` 里每张卡的参数以卡文件为准。
- 入口文件里的 `build`、`ctx`、实体名的写法：镜头契约（S）。
- `predicates.extra` 里谓词小语言的文法、模板展开成哪些谓词：谓词登记表契约（PR）。
- 题号的写法：题目文件格式契约（QF）。
- 补丁的格式：补丁格式契约（PA）。本契约只管补丁里路径的写法（D5）。
- 请求和响应怎么包装、错误码的全表：信封契约（EN）、错误码表契约（ER）。

## 2. 术语

帧、全片帧号、镜头、种子、帧率、快门角、硬切、场景参考镜头、显示参考镜头、核对记录：见时间键契约（T）第 2 节。实体、实体名、锚点、画风令牌、入口文件、「卡加数据」模式：见镜头契约（S）第 2 节。帧源、帧源名、宿主、能力声明、作者模式、档位：见帧源接口契约（F）第 2 节。卡、卡的引用、求值核、`tracks`：见卡的运行时接口契约（CR）第 2 节。

| 词 | 含义 |
|---|---|
| 片子描述 | 一部片子的声明式数据：时间线、镜头、事件、相机和编排的规格、渲染分派、谓词引用、画风令牌。文件名是 `film.json`。 |
| 修订号 | 服务器给片子描述的每个已存版本编的整数，记作 `rev`。 |
| 锁文件 | 服务器按片子描述的某个修订号生成的版本和哈希清单，文件名是 `film.lock`；结构见锁文件契约（LK）。 |
| 镜头区间 | 一个镜头占的全片帧号区间 `[in, out)`。 |
| 切点 | 相邻两个镜头交界处的全片帧号，等于后一个镜头的 `in`。 |
| 余量帧 | 镜头在自己的区间之外多渲的帧，给叠化类转场用。 |
| 事件 | 一个有名字的时刻。 |
| 时刻算式 | 用切点或事件加一个偏移来写的时刻，写法见 5.3。 |
| 叠加层 | 贴在某个镜头画面上的一段二维文字。 |
| 全片级的键 | `style.view`、`style.finish`、`delivery`、`audio` 这四个键；每个绑一张对全片只有一份的卡。 |
| 路径 | 指向片子描述里某个值的字符串，写法见 5.4。 |
| 模板 | 一类片子共用的一组谓词，有名字和版本。 |
| 覆盖层 | 一个参数的值可能来自的四个地方之一，见 5.8。 |
| 片子核对记录 | 一致性测试把一份片子描述和对它的观测写下来的数据对象，只用来判定不变量。 |

## 3. 结构

片子描述的任何一层都不得出现本节没列的键。只有三处的键不由本契约列举：`shots[].cards` 里每张卡的参数、`shots[].params`、`style.tokens`。这三处的键必须符合 5.1 的「自由键」写法。

### 3.1 片子描述

顶层对象，`format` 是 `film/3.0`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `film/3.0` | 格式标识 |
| `id` | 字符串 | 无 | 是 | 见 5.1 | 片子的标识，由服务器给 |
| `title` | 字符串 | 无 | 否 | 不空 | 片名 |
| `exam` | 字符串 | 无 | 否 | 不空 | 这部片在做哪道题。只能在创建片子时给 |
| `output` | 对象 | 无 | 是 | 见 3.2 | 输出规格 |
| `timeline` | 对象 | 无 | 否 | 见 3.2 | 节拍表 |
| `shots` | 数组 | 无 | 是 | 至少 1 项，每项见 3.3 | 镜头表，按时间先后写 |
| `transitions` | 数组 | 无 | 否 | 每项见 3.4 | 切点上的转场 |
| `events` | 数组 | 无 | 否 | 每项见 3.4 | 事件 |
| `overlays` | 数组 | 无 | 否 | 每项见 3.4 | 叠加层 |
| `style` | 对象 | 无 | 是 | 见 3.5 | 画风 |
| `audio` | 对象 | 无 | 否 | 见 3.5 | 声音。不出现表示这部片子不出声音 |
| `predicates` | 对象 | 无 | 是 | 见 3.5 | 谓词 |
| `delivery` | 对象 | 无 | 是 | 见 3.5 | 交付规格 |

### 3.2 `output`、`timeline`

| `tiers` | 对象 | 无 | 否 | 见下表 | 两个档位各自的采样数和缩放 |

### 3.6 四个全片级的键怎么绑卡

这四张卡对全片只有一份，不写在 `shots[].cards` 里，由四个全片级的键引用。

| 键 | 绑的卡 | 这个键什么时候算出现 |
|---|---|---|
| `style.view` | `comp.display` | 总是 |
| `style.finish` | `comp.finish` | 片子描述里有 `style.finish` |
| `delivery` | `deliver.encode` | 总是 |
| `audio` | `audio.master` | 片子描述里有 `audio` |

键里不写 `card`，取这张卡当前的主版本；要指定，就在键里写 `"card": "<卡名>@<主版本>"`，例如 `"card": "comp.display@1"`。服务器生成锁文件时把出现的键展开进锁文件的 `cards`，见 LK 契约。

### 3.7 `Explain`

`explain` 回答「路径上这个参数的最终值来自哪一层」。接口值，不带 `format`，不得有别的字段。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `path` | 字符串 | 无 | 是 | 路径，见 5.4 | 问的是哪个参数 |
| `value` | 任意 JSON 值 | 见 `unit` | 是 | 不得是 `null` | 最终生效的值 |
| `unit` | 字符串 | 无 | 是 | 不空 | `value` 的单位，给人看 |
| `layers` | 数组 | 无 | 是 | 至少 1 项，每项见下表 | 每一层给了什么，从弱到强 |
| `coupling` | 数组 | 无 | 否 | 字符串，不空 | 这个参数的效果还取决于什么 |
| `affects` | 对象 | 无 | 是 | 见下表 | 改这个参数会影响哪些镜头、哪些帧 |

`layers[]`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `layer` | 字符串 | 是 | `card-default`、`template`、`film`、`job` | 哪一层，见 5.8 |
| `from` | 字符串 | 是 | 不空 | 这一项的出处，给人看：哪张卡哪个版本、哪个模板、哪个修订号 |
| `value` | 任意 JSON 值 | 否 | 不得是 `null` | 这一层给的值。这一层没给值就不出现 |

`affects`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `shots` | 数组 | 无 | 是 | `shots` 里的 `id`，不重复 | 受影响的镜头 |
| `frames` | 数组 | 帧 | 是 | `[起, 止]`，全片帧号，半开区间 `[起, 止)`，起 < 止 | 受影响的帧 |

### 3.8 片子核对记录

顶层对象，`format` 是 `film-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `film-check/0.1` | 格式标识 |
| `film` | 片子描述 | 无 | 是 | 见 3.1 | 被判的片子描述 |
| `lock` | 锁文件 | 无 | 否 | 见 LK 契约 | 这份片子描述对应的锁文件 |
| `locks` | 数组 | 无 | 否 | 每项见下表 | 对锁文件的观测 |
| `paths` | 数组 | 无 | 否 | 每项见下表 | 系统各处吐出来或收进去的路径 |
| `writes` | 数组 | 无 | 否 | 每项见下表 | 对这份片子描述的写入 |
| `explains` | 数组 | 无 | 否 | 每项是 `Explain`，见 3.7 | `explain` 的结果 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`locks[]`：某一时刻读到的一份锁文件。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `rev` | 整数 | 是 | ≥ 0 | 这份锁的修订号 |
| `writer` | 字符串 | 是 | `server`、`agent` | 这份锁的内容是谁写出来的 |
| `digest` | 字符串 | 是 | 小写十六进制，8 到 64 位 | 这份锁的文件内容的摘要 |

`paths[]`：

| 字段 | 类型 | 必填 | 值域 | 说明 |

## 5. 口径

### 5.1 标识和键的写法

| 东西 | 写法 |
|---|---|
| 片子的 `id` | 小写字母、数字、下划线、连字符，不空，以小写字母开头 |
| 镜头、事件、叠加层的 `id` | 小写字母、数字、连字符，以小写字母开头。镜头的 `id` 不得是 `film`：锁文件用这个键记全片种子 |
| 资产的别名 | 一段实体名：ASCII 字母、数字、下划线，不空 |
| 自由键 | 不空，不含 `/`、`#`，不含空白 |

两个标识逐字符相同才算同一个。镜头、事件、叠加层的 `id` 以字母开头，所以不会和数组下标混。

### 5.2 切点

`shots` 里除第一个之外，每个镜头的 `in` 是一个切点。一部只有一个镜头的片子没有切点。切点不靠 `transitions` 定义：`transitions` 只给已有的切点写转场种类。

### 5.3 时刻算式

`events[].frame`、`overlays[].in`、`overlays[].out` 可以写整数，也可以写算式。算式是字符串，文法：

```
算式 = 基点 | 基点 " + " 偏移
基点 = "cut(" 帧号 ")" | "event(" 事件的 id ")"
偏移 = 正整数，十进制，不带前导零
帧号 = 非负整数，十进制，不带前导零
```

- 括号里没有空格；`+` 两边各正好一个空格。别的写法都不合法。
- 展开：`cut(N)` 等于 N；`event(x)` 等于事件 x 的 `frame` 展开后的值；带偏移就再加上偏移。结果是全片帧号，单位帧。
- 例：切点在 180 时，`cut(180) + 12` 等于 192；事件 `lock` 在第 150 帧时，`event(lock) + 6` 等于 156。
- 卡的参数里也可以出现时刻算式（哪个参数是时刻，由卡文件说）。它们同样受 D2 管，判定归卡文件格式契约（CF）。

### 5.4 路径

全系统只有这一种写法。诊断的 `at`、修法的 `path`、`explain` 的 `path`、补丁的路径都用它。

- 从片子描述的根起，一段一段用 `/` 连接，第一段是 3.1 那张表里的字段名。不以 `/` 开头或结尾，没有空段，不带文件名前缀，不含 `#`。
- 对象里的一段是键的原文，例如 `camera.fit@1`。
- `shots`、`events`、`overlays` 这三个数组里的一段是条目的 `id`。不得写下标。
- 别的数组（`transitions`、`shots[].roles.mustSee`、`predicates.base`、`predicates.extra`、`style.colorScript.*.key`、`output.size`）不能单独寻址到条目，路径止于数组本身。
- 例：`shots/s01/cards/camera.fit@1/margin`、`shots/s01`、`style/finish/grain`。不合法：`shots/0`、`/shots/s01`、`film.json#/shots/s01`。

### 5.5 卡的引用和资产引用

- 片子描述里卡的引用只写主版本：`<卡名>@<主版本>`，卡名的写法见 CR 契约 3.3，主版本是不带前导零的十进制正整数。例：`camera.fit@1`。
- 资产引用：`asset:<名>@<版本>`，名是小写字母、数字、连字符，版本是不带前导零的十进制正整数。例：`asset:rtx-card@3`。
- 主版本怎么和锁文件比：锁文件里的 `version` 是三段，取第一段，按整数比。

### 5.6 `cards` 的先后

`shots[].cards` 是对象。「书写顺序」指键在 JSON 文本里出现的先后；读写片子描述的程序必须保住这个先后。CR 契约里固定装载脚本用的就是这个先后。

### 5.7 修订号

片子描述每被接受一次写入，服务器给它一个新的修订号。修订号不写在片子描述里，随读写的响应交回。「服务器当前的修订号」指服务器收到写入那一刻片子描述的修订号。

### 5.8 四个覆盖层

从弱到强：

| 次序 | `layer` | 是什么 |
|---|---|---|
| 1 | `card-default` | 卡的默认值 |
| 2 | `template` | 模板和画风令牌 |
| 3 | `film` | 片子描述里写的值。同一层里修订号大的更强 |
| 4 | `job` | 一次作业里的临时覆盖，扫参用，不落盘 |

强的层盖住弱的层。「逐值相等」指两个 JSON 值的类型相同、数相等、字符串逐字符相同、数组逐项相等、对象逐键相等。

### 5.9 颜色

色值写成 `#RRGGBB`：`#` 加 6 位十六进制，字母大写。它是显示空间的值，sRGB 编码，Rec.709 原色。`style.tokens` 和 `style.colorScript.*.key` 都是这种。

### 5.10 没列出的键

片子描述里出现本契约没列的键就是非法，不得静默合并，也不得静默丢掉。
