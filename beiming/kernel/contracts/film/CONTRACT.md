# 片子描述

版本：0.1.0-draft

## 1. 范围

管：

- 片子描述 `film/3.0` 的全部字段：输出规格、节拍表、全片资产、镜头表、切点、事件、叠加层、画风、声音、谓词引用、成片交付规格。
- 标识、时刻算式、路径、卡的引用、卡实例名、资产引用和资产别名在片子描述里的写法。
- 四个全片级的键各绑哪张卡。
- 叠加层怎么展开成卡实例。
- 写入怎么带修订号，哪些字段只有服务器能写。
- `explain` 的结果 `Explain`，以及一个参数的四层覆盖顺序。
- 判定以上各条用的「片子核对记录」。

不管：

- 锁文件里面的字段：锁文件契约（LK）。本契约只管「片子描述引用的卡和资产在锁文件里找不找得到」（D3）和「锁由谁生成、同一个修订号的锁变不变」（D4）。镜头种子怎么从全片种子派生：LK 契约 5.7。
- 事件表展开之后的格式：事件表契约（EV）。
- 帧率、种子的写法，快门窗口：时间键契约（T）。
- 帧源名的值域、每个帧源有哪些宿主和作者模式、三个作者模式各是什么、一次 `render` 生效的快门从哪来：帧源接口契约（F）。
- 卡名的写法、卡的参数表、参数的类型和含义、卡的类别：卡文件格式契约（CF）。`shots[].cards[].params` 里的参数以卡文件为准。
- 入口文件里的 `build`、`ctx`、实体名的写法、`ctx.cards.use`：镜头契约（S）。
- 卡实例带进来的实体叫什么、卡和叠加层的装载顺序：卡的运行时接口契约（CR）。
- 通道名的值域：输出通道契约（PS）。
- `predicates.extra` 里谓词小语言的文法、模板名的写法、模板展开成哪些谓词、最低谓词怎么扣掉 `deliberate` 声明的区间：谓词登记表契约（PR）。
- 题号的写法：题目文件格式契约（QF）。
- 补丁的格式：补丁格式契约（PA）。本契约只管补丁里路径的写法（D5）。
- 请求和响应怎么包装、错误码的全表：信封契约（EN）、错误码表契约（ER）。

## 2. 术语

帧、全片帧号、镜头、帧率、快门角、硬切、场景参考镜头、显示参考镜头、核对记录：见时间键契约（T）第 2 节。实体、实体名、锚点、画风令牌、入口文件、「卡加数据」模式：见镜头契约（S）第 2 节。帧源、帧源名、宿主、出帧者、能力声明、作者模式、档位：见帧源接口契约（F）、每帧元数据契约（M）第 2 节。卡、卡的引用、求值核、`tracks`：见卡的运行时接口契约（CR）第 2 节。锁文件、全片种子、镜头种子：见锁文件契约（LK）第 2 节；本契约里说「种子」都指镜头种子。卡名：见卡文件格式契约（CF）5.1。通道名：见输出通道契约（PS）3.1。

| 词 | 含义 |
|---|---|
| 片子描述 | 一部片子的声明式数据：时间线、镜头、事件、相机和编排的规格、渲染分派、谓词引用、画风令牌。文件名是 `film.json`。 |
| 修订号 | 服务器给片子描述的每个已存版本编的整数，记作 `rev`。 |
| 镜头区间 | 一个镜头占的全片帧号区间 `[in, out)`。 |
| 切点 | 相邻两个镜头交界处的全片帧号，等于后一个镜头的 `in`。 |
| 余量帧 | 镜头在自己的区间之外多渲的帧，给叠化类转场用。 |
| 事件 | 一个有名字的时刻。 |
| 时刻算式 | 用切点或事件加上或减去一个偏移来写的时刻，写法见 5.3。 |
| 叠加层 | 贴在某个镜头画面上的一段二维文字。 |
| 全片级的键 | `style.view`、`style.finish`、`delivery`、`audio` 这四个键；每个绑一张对全片只有一份的卡。 |
| 路径 | 指向片子描述里某个值的字符串，写法见 5.4。 |
| 模板 | 一类片子共用的一组谓词，有名字和版本。 |
| 覆盖层 | 一个参数的值可能来自的四个地方之一，见 5.8。 |
| 卡实例 | 镜头的 `cards` 里的一项：一张卡带着一组参数在这个镜头里用一次。它的名字 `as` 叫实例名。 |
| 资产别名 | 镜头的 `assets` 或全片 `assets` 里的键。片子描述里别处用它指一个资产。 |
| 片子核对记录 | 一致性测试把一份片子描述和对它的观测写下来的数据对象，只用来判定不变量。 |

## 3. 结构

片子描述的任何一层都不得出现本节没列的键，也不收 `ext`（见通用口径）。只有三处的键不由本契约列举：`shots[].cards[].params`、`shots[].params`、`style.tokens`。这三处的键必须符合 5.1 的「自由键」写法。

### 3.1 片子描述

顶层对象，`format` 是 `film/3.0`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `film/3.0` | 格式标识 |
| `id` | 字符串 | 无 | 是 | 见 5.1 | 片子的标识。创建片子时定下，之后不得改（D15）；有服务器时由服务器给 |
| `title` | 字符串 | 无 | 否 | 不空 | 片名 |
| `exam` | 字符串 | 无 | 否 | 题号，见 QF 契约 5.1 | 这部片在做哪道题。只能在创建片子时给 |
| `output` | 对象 | 无 | 是 | 见 3.2 | 输出规格 |
| `timeline` | 对象 | 无 | 否 | 见 3.2 | 节拍表 |
| `assets` | 对象 | 无 | 否 | `{ 别名: 资产引用 }`，写法见 5.5 | 全片用的资产：不属于某一个镜头的文件（旁白录音、音轨）放这里 |
| `shots` | 数组 | 无 | 是 | 至少 1 项，每项见 3.3 | 镜头表，按时间先后写 |
| `transitions` | 数组 | 无 | 否 | 每项见 3.4 | 切点上的转场 |
| `events` | 数组 | 无 | 否 | 每项见 3.4 | 事件。书写顺序不要求 |
| `overlays` | 数组 | 无 | 否 | 每项见 3.4 | 叠加层 |
| `style` | 对象 | 无 | 是 | 见 3.5 | 画风 |
| `audio` | 对象 | 无 | 否 | 见 3.5 | 声音。不出现表示这部片子不出声音 |
| `predicates` | 对象 | 无 | 是 | 见 3.5 | 谓词 |
| `delivery` | 对象 | 无 | 是 | 见 3.5 | 成片交付规格 |

### 3.2 `output`、`timeline`

`output`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `size` | 数组 | 像素 | 是 | `[宽, 高]`，正整数 | 画幅 |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率。全片只有这一处 |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 总帧数 |

`timeline`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `bpm` | 双精度 | 拍每分钟 | 否 | > 0 | 每分钟拍数 |
| `beatFrames` | 整数 | 帧 | 否 | ≥ 1 | 一拍几帧 |

### 3.3 `shots[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 见 5.1 | 镜头的标识 |
| `in` | 整数 | 帧 | 是 | ≥ 0 | 镜头区间的起点，全片帧号 |
| `out` | 整数 | 帧 | 是 | ≥ 1 | 镜头区间的终点，全片帧号，不含 |
| `source` | 字符串 | 无 | 是 | 帧源名，见 F 契约 3.1 | 哪个帧源渲。写了 `renderer` 时，`source`、`host`、`mode`、`entry` 这一套留作对照，不参与这次出片 |
| `host` | 字符串 | 无 | 是 | 这个帧源的能力声明 `hosts` 里的一项，登记表见 F 契约 3.4；`three`、`core` 两个帧源下的取值按倾向定，合作者不同意时再改（见第 6 节） | 哪个宿主 |
| `mode` | 字符串 | 无 | 是 | `cards-data`、`build-script`、`native-code` | 作者模式。三个词各是什么，见 F 契约 3.4 |
| `entry` | 字符串 | 无 | 见 D12、D17 | 相对路径，写法照通用口径 | 入口文件。`build-script` 和 `native-code` 必填，`cards-data` 不得出现；`source` 是 `ext.<名字>` 的镜头不得出现。片子描述里只有这一处可以写文件路径。路径相对片子描述所在的目录，这个目录由 `env.filmDir` 交给帧源（F 契约 3.2） |
| `colorRef` | 字符串 | 无 | 是 | `scene`、`display` | 场景参考镜头，还是显示参考镜头 |
| `seed` | 整数 | 无 | 否 | 见 T 契约 3.3 | 这个镜头的镜头种子。不给就由服务器从全片种子派生（算法见 LK 契约 5.7），结果记在锁文件里。没有锁文件时必须写（F 契约 5.11） |
| `assets` | 对象 | 无 | 否 | `{ 别名: 资产引用 }`，写法见 5.5 | 这个镜头用的资产 |
| `cards` | 数组 | 无 | 否 | 每项见下表 | 这个镜头的卡实例。数组顺序就是装载的书写顺序，见 5.6 |
| `params` | 对象 | 无 | 否 | 自由键 | 交给入口文件的参数，就是 `ctx.params`。`source` 是 `ext.<名字>` 的镜头必须带 `piece`，值是资产别名，说重放哪个作品 |
| `roles` | 对象 | 无 | 否 | 见下表 | 角色。模板要不要它，由模板说 |
| `shutter` | 对象 | 无 | 否 | 见下表 | 快门 |
| `tiers` | 对象 | 无 | 否 | 见下表 | 两个档位各自的采样数和缩放 |
| `handles` | 对象 | 无 | 否 | 见下表 | 余量帧。本版只留位：宿主不渲余量帧 |
| `deliberate` | 数组 | 无 | 否 | 每项见下表 | 刻意的静止和黑场。最低谓词判黑帧和冻结时先除去这里声明的区间，见 PR 契约 5.6 |
| `renderer` | 对象 | 无 | 否 | 见下表 | 实际出帧的是谁。不出现表示出帧者就是 `source` |

`cards[]`：一项是一个卡实例。同一张卡可以出现多次。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `as` | 字符串 | 是 | 实体名里一段的写法（S 契约 5.2）：ASCII 字母、数字、下划线，不空 | 实例名。在一个镜头里不得重复（D18）。卡带进来的实体怎么用它起名，见 CR 契约 |
| `use` | 字符串 | 是 | 卡的引用 `<卡名>@<主版本>`，写法见 5.5 | 用哪张卡 |
| `params` | 对象 | 是 | 自由键；可以是空对象 | 这个实例的参数。参数表以卡文件为准 |

`roles`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `hero` | 字符串 | 否 | 实体名，写法见 S 契约 5.2 | 主体 |
| `mustSee` | 数组 | 否 | 实体名，不重复 | 必须看得见的东西 |

`shutter`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `angleDeg` | 双精度 | 度 | 是 | `[0, 360]` | 快门角。0 是不开运动模糊。`shutter` 不出现等于 0 |
| `samples` | 整数 | 次 | 否 | ≥ 1 | 子帧采样数。不出现时照 F 契约 5.9 取：生效的快门角是 0 就取 1，不是 0 就用帧源能力声明的 `motionBlur.samples`；能力声明里没有这个字段的帧源（原生运动模糊）取什么，见 F 契约第 6 节。有锁文件时，锁文件的 `shots.<id>.shutterSamples` 记的就是这个值 |

一次 `render` 生效的快门角和子帧采样数：`RenderOpts.shutter` 出现就用它，不出现就用这里的 `angleDeg` 和 `samples`，见 F 契约 5.9。快门角是 0 而采样数大于 1 时帧源报错，码是 `contract.shutter-conflict`。

`tiers`：键只能是 `draft`、`final`，两个都可以不出现；每个的值是下表的对象。不出现的项用能力声明定下的值。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `samples` | 整数 | 次 | 否 | ≥ 1 | 每像素采样数 |
| `scale` | 双精度 | 无 | 否 | `(0, 1]` | 输出尺寸的缩放 |

`handles`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `head` | 整数 | 帧 | 是 | ≥ 0 | 区间起点之前多渲几帧 |
| `tail` | 整数 | 帧 | 是 | ≥ 0 | 区间终点之后多渲几帧 |

`deliberate[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `kind` | 字符串 | 无 | 是 | `freeze`、`black` | 静止，还是黑场 |
| `in` | 整数 | 帧 | 是 | ≥ 0 | 区间起点，全片帧号 |
| `out` | 整数 | 帧 | 是 | ≥ 1 | 区间终点，全片帧号，不含。`[in, out)` 必须落在这个镜头里（D19） |
| `why` | 字符串 | 无 | 是 | 不空 | 为什么这样做，给人看 |

`renderer`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `source` | 字符串 | 是 | 帧源名，见 F 契约 3.1 | 实际出帧的帧源 |
| `host` | 字符串 | 是 | 同 `shots[].host` | 它的宿主 |
| `mode` | 字符串 | 是 | 同 `shots[].mode` | 它的作者模式 |
| `entry` | 字符串 | 同 `shots[].entry`，按 `renderer.mode` 判 | 相对路径 | 它的入口文件 |

`renderer` 出现时，这次出片用的是它这一套，镜头顶层的 `source`、`host`、`mode`、`entry` 留作对照。`open(input, env)` 收到的镜头输入里，`shot` 就是片子描述里这个镜头的条目，原样，不改写：顶层那一套和 `renderer` 对象都照旧在里面，出帧的那一对自己读 `renderer` 对象，照它那一套做。镜头输入由上层从片子描述算出来，见 F 契约 3.2。

片子描述顶层的三样东西经镜头输入的三个可选字段进帧源（F 契约 3.2），不出现表示没有：`assets` 是全片的 `assets` 表，原样；`events` 是已经展开成全片帧号的事件表，形状见 EV 契约；`overlays` 是 `shot` 等于这个镜头的 `id` 的叠加层条目，原样。帧源里的宿主要这三样时只从这三个字段拿。

### 3.4 `transitions[]`、`events[]`、`overlays[]`

`transitions[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 见 5.1 | 这个转场的标识 |
| `at` | 整数 | 帧 | 是 | 切点 | 哪个切点 |
| `type` | 字符串 | 无 | 是 | `cut` | 转场种类。本版只有硬切 |

没在 `transitions` 里写的切点，也是硬切。

`events[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 见 5.1 | 事件的标识 |
| `frame` | 整数或字符串 | 帧 | 是 | 整数时 ≥ 0；字符串时是时刻算式，见 5.3 | 事件所在的全片帧号 |
| `shot` | 字符串 | 无 | 否 | `shots` 里的 `id` | 这个事件属于哪个镜头 |
| `audio` | 字符串 | 无 | 否 | 点分小写 | 这个时刻响什么，音效库里的名字 |
| `sync` | 字符串 | 无 | 否 | `onset`、`pcenter` | 声音怎么对帧。`onset` 是起音对上事件帧；`pcenter` 是听感重心对上事件帧，起音会提前。不出现等于 `onset` |

`events` 的书写顺序不要求；展开出来的事件表必须按 EV1 排序，见 EV 契约。

`overlays[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `id` | 字符串 | 无 | 是 | 小写字母、数字，以小写字母开头 | 叠加层的标识。不得带连字符：它要当卡的实例名 |
| `shot` | 字符串 | 无 | 是 | `shots` 里的 `id` | 贴在哪个镜头上 |
| `anchor` | 字符串 | 无 | 是 | `实体名#锚点名`，或 `screen` | 跟着哪个锚点走。`screen` 是贴在屏幕固定位置 |
| `pos` | 数组 | 无 | `anchor` 是 `screen` 时必填，否则不得出现 | `[u, v]`，两个数都在 `[0, 1]` | 屏幕上的位置。归一化坐标，原点在左上 |
| `text` | 字符串 | 无 | 是 | 不空 | 文字 |
| `in` | 整数或字符串 | 帧 | 是 | 同 `events[].frame` | 出现的全片帧号 |
| `out` | 整数或字符串 | 帧 | 是 | 同 `events[].frame` | 消失的全片帧号，不含 |

每个叠加层由宿主展开成它那个镜头的一个卡实例；宿主从镜头输入的 `overlays` 拿到贴在这个镜头上的叠加层，见 5.11。

### 3.5 `style`、`audio`、`predicates`、`delivery`

`style`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `tokens` | 对象 | 无 | 否 | `{ 名字: 色值 }`；名字是自由键，色值见 5.9 | 画风令牌。本版只有颜色类令牌，都是显示空间 |
| `view` | 对象 | 无 | 是 | 见下表 | 两类镜头各用什么显示变换 |
| `colorScript` | 对象 | 无 | 否 | `{ 镜头的 id: { key, tol } }` | 色彩脚本，见下表 |
| `finish` | 对象 | 无 | 否 | 见下表 | 收尾层的参数 |

`style.view`：

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `scene` | 字符串 | 是 | 查找表名：小写字母、数字、连字符 | 场景参考镜头用的显示变换 |
| `display` | 字符串 | 是 | `srgb` | 显示参考镜头用的显示变换 |
| `card` | 字符串 | 否 | 卡的引用，见 3.6 | 指定绑的卡的主版本 |

`style.colorScript` 的每一项：

### 3.6 四个全片级的键怎么绑卡

这四张卡对全片只有一份，不写在 `shots[].cards` 里，由四个全片级的键引用。

|---|---|---|
| `style.view` | `comp.display` | 总是 |
| `style.finish` | `comp.finish` | 片子描述里有 `style.finish` |
| `delivery` | `deliver.encode` | 总是 |
| `audio` | `audio.master` | 片子描述里有 `audio` |

### 3.8 片子核对记录

顶层对象，`format` 是 `film-check/0.1`。记录里出现哪一段，就判哪几条不变量；没出现的段不判。观测了、结果是空的写空数组；没观测的段不出现。

「来历」一栏的四个词见契约写法约定 3.1。格式标识、`ext` 和各段的数组本身不是观测，来历写「—」，段里的字段各自标。整份收进来的片子描述、锁文件和 `Explain` 是被判的东西本身，标 `自报`；哪几条的查法只读它们，见第 6 节「只读被判对象自己的条文」一行。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `film-check/0.1` | — | 格式标识 |
| `film` | 片子描述 | 无 | 是 | 见 3.1 | `自报` | 被判的片子描述，整份收进来 |
| `lock` | 锁文件 | 无 | 否 | 见 LK 契约 | `自报` | 这份片子描述对应的锁文件，整份收进来 |
| `locks` | 数组 | 无 | 否 | 每项见下表 | — | 对锁文件的观测 |
| `paths` | 数组 | 无 | 否 | 每项见下表 | — | 系统各处吐出来或收进去的路径 |
| `writes` | 数组 | 无 | 否 | 每项见下表 | — | 对这份片子描述的写入 |
| `explains` | 数组 | 无 | 否 | 每项是 `Explain`，见 3.7 | `自报` | `explain` 交回的结果，每项整份收进来 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

`locks[]`：某一时刻读到的一份锁文件。

| 字段 | 类型 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|
| `rev` | 整数 | 是 | ≥ 0 | `自报` | 这份锁的修订号，从读到的锁文件里直接抄出来 |
| `writer` | 字符串 | 是 | `server`、`agent` | `量的` | 这份锁的内容是谁写出来的。测试工具以调用方的身份往锁文件的位置写过内容、读到的这份锁的字节和它写的逐位相同，记 `agent`；否则记 `server`。不取写的一方自己的说法 |
| `digest` | 字符串 | 是 | 哈希，写法见通用口径 | `量的` | 这份锁的文件内容的哈希，不是状态摘要；测试工具自己对读到的字节算 |

`paths[]`：

| 字段 | 类型 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|
| `use` | 字符串 | 是 | `diagnostic.at`、`fix.path`、`explain.path`、`patch.path` | `量的` | 这条路径出现在哪里：诊断的 `at`、修法的 `path`、`explain` 的 `path`、补丁的路径 |
| `path` | 字符串 | 是 | 不空 | `量的` | 路径的原文，从那一处读回来，不改写 |

`writes[]`：一次写入请求和服务器的处理。只记片子创建之后的写入，创建片子的那一次不记进来。测试工具站在服务器外面：它自己发的写入记一项；它没发、前后两次读回的片子描述却不一样的改动，是服务器自己发起的，每个变了的值也记一项。

| 字段 | 类型 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|
| `by` | 字符串 | 是 | `agent`、`server` | `量的` | 谁发起的。测试工具自己发的写入记 `agent`；测试工具没发、它前后两次读回的片子描述比出来的改动记 `server` |
| `path` | 字符串 | 是 | 不空 | `请求` | 写的是哪里，路径的原文。`by` 是 `agent` 的项是测试工具发出去的路径；`by` 是 `server` 的项是读回来比出不一样的那个值的路径，这种项的这一格是量出来的 |
| `rev` | 整数 | 是 | ≥ 0 | `请求` | 写入带上的修订号。`by` 是 `agent` 的项是测试工具发出去的那个；`by` 是 `server` 的项写改动之前读到的修订号，这种项的这一格是量出来的 |
| `serverRev` | 整数 | 是 | ≥ 0 | `量的` | 服务器收到写入时片子描述的修订号，测试工具在这次写入之前读一次得到 |
| `outcome` | 字符串 | 是 | `accepted`、`rejected` | `量的` | 生效了，还是被拒绝：写入之后把片子描述读回来比 |
| `code` | 字符串 | 否 | 错误码，写法见 ER 契约 5.2 | `量的` | 交回的错误码；被拒绝却没交回错误码就不出现 |
| `latestRev` | 整数 | 否 | ≥ 0 | `自报` | 拒绝时服务器交回的最新修订号，从拒绝的响应里直接抄出来。D6 拿它对测试工具量的 `serverRev` |

## 5. 口径

### 5.1 标识和键的写法

| 东西 | 写法 |
|---|---|
| 片子的 `id` | 小写字母、数字、下划线、连字符，不空，以小写字母开头 |
| 镜头、转场、事件、叠加层、旁白的 `id` | 小写字母、数字、连字符，以小写字母开头。镜头的 `id` 不得是 `film`：锁文件用这个键记全片种子。叠加层的 `id` 不得带连字符：它要当卡的实例名 |
| 资产的别名、卡实例的 `as` | 一段实体名：ASCII 字母、数字、下划线，不空 |
| 自由键 | 不空，不含 `/`、`#`，不含空白 |

两个标识逐字符相同才算同一个。上表第二行那些 `id` 以字母开头，所以不会和数组下标混。

### 5.2 切点

`shots` 里除第一个之外，每个镜头的 `in` 是一个切点。一部只有一个镜头的片子没有切点。切点不靠 `transitions` 定义：`transitions` 只给已有的切点写转场种类。

### 5.3 时刻算式

`events[].frame`、`overlays[].in`、`overlays[].out`、`audio.narration[].at` 可以写整数，也可以写算式。算式是字符串，文法：

```
算式 = 基点 | 基点 " + " 偏移 | 基点 " - " 偏移
基点 = "cut(" 帧号 ")" | "event(" 事件的 id ")"
偏移 = 正整数，十进制，不带前导零；单位是帧，不带后缀
帧号 = 非负整数，十进制，不带前导零
```

- 括号里没有空格；`+`、`-` 两边各正好一个空格。别的写法都不合法。全系统的时刻只有这一种写法，谓词小语言的范围用的是同一种算式（PR 契约 5.5）。
- 展开：`cut(N)` 等于 N；`event(x)` 等于事件 x 的 `frame` 展开后的值；带偏移就再加上或减去偏移。结果是全片帧号，单位帧。
- 例：切点在 180 时，`cut(180) + 12` 等于 192；事件 `lock` 在第 150 帧时，`event(lock) + 6` 等于 156；事件 `title` 在第 192 帧时，`event(title) - 2` 等于 190。
- 卡的参数里也可以出现时刻（哪个参数是时刻，由卡文件说），写全片帧号或时刻算式，同样受 D2 管，判定归卡文件格式契约（CF）。宿主交给卡之前必须展开并减去镜头的 `in`：`cut(N)` 直接取 N；`event(x)` 的值取镜头输入的 `events` 里 `id` 是 x 的命名条目的 `frame`（事件的帧号由上层展开一次，结果就是这份事件表，见 F 契约 3.2、EV 契约），宿主不从片子描述再展开一遍事件。所以卡拿到的帧号一律是镜头局部帧号；结果可以是负数，也可以不小于镜头的帧数，表示时刻在镜头之外。
- 卡参数里类型是 `data` 的值（见 CF 契约 3.3），里面的帧号直接写镜头局部帧号，宿主不换算。

### 5.4 路径

全系统只有这一种写法。诊断的 `at`、修法的 `path`、`explain` 的 `path`、补丁的路径都用它。

- 从片子描述的根起，一段一段用 `/` 连接，第一段是 3.1 那张表里的字段名。不以 `/` 开头或结尾，没有空段，不带文件名前缀，不含 `#`。
- 对象里的一段是键的原文，例如 `style/colorScript/s01`。
- `shots`、`transitions`、`events`、`overlays`、`audio.narration` 这五个数组里的一段是那一项的 `id`；`shots[].cards` 里的一段是卡实例的 `as`。不得写下标。卡的参数写成 `shots/<镜头的 id>/cards/<as>/params/<键>`。
- 别的数组（`shots[].roles.mustSee`、`shots[].deliberate`、`overlays[].pos`、`predicates.base`、`predicates.extra`、`style.colorScript.*.key`、`delivery.layers`、`output.size`）不能单独寻址到数组里的项，路径止于数组本身。
- 例：`shots/s01/cards/cam/params/margin`、`shots/s01`、`style/finish/grain`、`audio/narration/vo-open/at`。不合法：`shots/0`、`/shots/s01`、`film.json#/shots/s01`。

### 5.5 卡的引用和资产引用

- 片子描述里卡的引用只写主版本：`<卡名>@<主版本>`，卡名的写法见 CF 契约 5.1，主版本是不带前导零的十进制正整数。例：`camera.fit@1`。
- 资产引用：`asset:<名>@<版本>`，名是小写字母、数字、连字符，版本是不带前导零的十进制正整数。例：`asset:rtx-card@3`。
- 主版本怎么和锁文件比：锁文件里的 `version` 是三段，取第一段，按整数比。
- 资产别名怎么找：镜头里的值先在这个镜头的 `assets` 里找，找不到再到全片 `assets` 里找；`audio` 里的值只在全片 `assets` 里找。在帧源里，这个镜头的 `assets` 在镜头输入的 `shot` 里，全片的 `assets` 在镜头输入的 `assets` 字段里（F 契约 3.2）。
- 片子描述里凡是指向文件的值（编排数据、音轨、旁白录音、贴图、第三方作品）都写资产别名，不写路径，这样它们都进锁；入口文件 `entry` 是唯一的例外（D16）。卡的参数里哪个值指向文件，看卡文件里它的类型是不是 `asset`。

### 5.6 `cards` 的先后

`shots[].cards` 是数组，装载的「书写顺序」就是数组顺序。CR 契约里固定装载脚本用的就是这个先后。

### 5.7 修订号

片子描述每被接受一次写入，服务器给它一个新的修订号。修订号不写在片子描述里，随读写的响应交回。「服务器当前的修订号」指服务器收到写入那一刻片子描述的修订号。

### 5.8 四个覆盖层

从弱到强：

| 次序 | `layer` | 是什么 |
|---|---|---|
| 1 | `card-default` | 卡的默认值 |
| 2 | `template` | 模板和画风令牌 |
| 3 | `film` | 片子描述里写的值。同一层里修订号大的更强 |
| 4 | `job` | 一次作业里的临时覆盖，扫参用，不落盘 |

强的层盖住弱的层。「逐值相等」指两个 JSON 值的类型相同、数相等、字符串逐字符相同、数组逐项相等、对象逐键相等。

入口文件不提供参数层：入口文件里 `ctx.cards.use(as, runtime?)` 用到的卡，参数只从这四层来；`runtime` 只放写不进 JSON 的东西，不是参数层，见 S 契约。

### 5.9 颜色

色值写成 `#RRGGBB`：`#` 加 6 位十六进制，字母大写。它是显示空间的值，sRGB 编码，Rec.709 原色。`style.tokens` 和 `style.colorScript.*.key` 都是这种。

### 5.10 没列出的键

片子描述里出现本契约没列的键就是非法，不得静默合并，也不得静默丢掉。

### 5.11 叠加层怎么展开

宿主把镜头输入的 `overlays` 里的每个叠加层展开成这个镜头的一个卡实例。镜头输入的 `overlays` 是片子描述里 `shot` 等于这个镜头的 `id` 的叠加层条目，原样（F 契约 3.2）；不出现表示这个镜头上没有叠加层。展开出来的卡是 `two-d.overlay@1`，实例名是叠加层的 `id`，装在镜头自己的卡之后（固定装载顺序见 CR 契约）。叠加层的 `in`、`out` 是算式时，`event(x)` 的值和卡参数里的时刻一样从镜头输入的 `events` 取（5.3）。这张卡进锁，锁文件里它的 `from` 是 `overlays`（见 LK 契约）。文字框由这个实例交，见 M 契约。实例名在一个镜头里不得重复，所以叠加层的 `id` 不得和它那个镜头 `cards` 里的 `as` 相同（D18）。

### 5.12 只出帧的链路

只出帧、不合成、不验收、不编码的链路不读 `style.view`、`predicates`、`delivery`。这三样照旧必填：片子描述说的是一部要交付的片子，不因为某条链路短就少写。
