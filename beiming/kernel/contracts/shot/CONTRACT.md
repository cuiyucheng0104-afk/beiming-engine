# 镜头契约

版本：0.1.0-draft

## 1. 范围

管：

- 镜头入口 `build(ctx)` 的形状，两种语言相同。
- `ctx` 的字段。
- `build` 交回的镜头对象有哪些成员。
- 镜头代码和宿主谁交什么。
- 搭镜头的三种模式：`cards-data`、`build-script`、`native-code`。
- 判定以上各条用的「镜头核对记录」。

不管：

- 时间键、帧率、种子、流名、`hold`、快门：时间键契约（T）。
- 卡的 `Handle`、`create`、`evaluate`，固定装载脚本的步骤：卡的运行时接口契约（CR）。
- 镜头在片子描述里怎么声明（参数、资产、`cards` 数组）：片子描述契约（D）。
- `texts`、`anchors`、`readings` 里面的结构，宿主量出的元数据：每帧元数据契约（M）。
- 帧源名的值域、帧源的求帧接口：帧源接口契约（F）。
- `tracks` 的数据格式、片段补丁的写法、资产引用的写法：不归本契约，归属见第 6 节。

## 2. 术语

镜头、镜头局部帧号、子帧相位、种子、命名随机流、纯函数、墙钟、状态摘要、核对记录：见时间键契约（T）第 2 节。帧源、宿主、帧源名：见帧源接口契约（F）第 2 节。

| 词 | 含义 |
|---|---|
| 镜头代码 | 一个镜头自己写的那份代码，镜头入口是 `build`。 |
| 入口文件 | 放镜头代码的那一个文件，对外只导出 `build`。 |
| 语言 | 镜头代码用的编程语言，值域是 `js`、`python`。 |
| `ctx` | 宿主调用 `build` 时传进去的上下文对象，镜头代码的全部依赖都从它取。 |
| 镜头对象 | `build` 的返回值。 |
| 母语对象 | 帧源所在环境里的原生对象，例如 three 的 `Object3D`、Blender 的物体。 |
| 句柄 | 交给宿主、让宿主能直接量场景的母语对象：`camera`、`entities`、`scene`。 |
| 实体 | 镜头里一个有名字的母语对象，感知和元数据都按这个名字指它。 |
| 实体名 | 实体的名字，点分路径，例如 `kit.fan_L`。 |
| 锚点 | 实体上一个有名字的点，写成 `实体名#锚点名`，例如 `kit.fan_L#hub`。 |
| 画风令牌 | 片子描述里统一定下的画风取值（颜色、线宽这类），镜头代码只读。 |
| 搭镜头的模式 | 一个镜头用哪种办法搭出来，值域是 `cards-data`、`build-script`、`native-code` 三个词，以 F 契约 3.4 为准；对应表在本节末尾。 |
| 「卡加数据」模式 | 就是 `cards-data`：镜头没有入口文件，只在片子描述里列出资产、卡和参数，宿主替它搭镜头。 |
| 出帧者 | 一次出片里实际出这个镜头的帧的那个帧源：片子描述的镜头条目带 `renderer` 时是 `renderer.source`，不带时是 `source`；见片子描述契约（D）3.3。镜头条目原样进镜头输入（F 契约 3.2），带 `renderer` 时出帧者自己读这个对象，照 `renderer` 里的那一套搭。 |
| 固定装载脚本 | 宿主里替「卡加数据」模式的镜头搭镜头的那一份脚本；步骤见卡的运行时接口契约（CR）。 |
| 片段补丁 | 往渲染库内置着色器的源码里按锚点插入或替换的一段着色器代码。 |
| 可信边界 | 元数据里由宿主直接从场景量出、镜头代码改不了的那一部分和其余部分之间的分界。 |

搭镜头的三种模式：

| `mode` | 入口文件 | 怎么搭、每帧谁求值 |
|---|---|---|
| `native-code` | 有，是镜头代码 | 宿主调它的 `build`，之后每帧调它的 `apply`：在本契约里就是镜头对象的 `state(f, sub)` |
| `build-script` | 有，只在构建时跑一次 | 入口文件把场景搭进帧源自己的场景和时间线，之后逐帧由帧源求值 |
| `cards-data` | 没有 | 宿主用固定装载脚本搭，步骤见 CR 契约 3.4 |

`source` 是 `ext.<名字>` 的镜头：`mode` 必须是 `native-code`，不得有入口文件；重放哪个作品怎么写见 D 契约 3.3。

## 3. 结构

### 3.1 镜头入口

| 函数 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `build(ctx)` | `ctx`，见 3.2 | 镜头对象，见 3.3 | JS 里可以是异步函数。Python 里返回字典，键名和 JS 的成员名相同 |

### 3.2 `ctx` 的字段

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `tracks` | 对象 | 无 | 是 | | 求值核算好的数据轨道。`tracks.apply(f, sub)` 把这一时刻的轨道值写进场景；有相机轨道时带 `tracks.camera`。片子没给这个镜头任何轨道时，`tracks.apply(f, sub)` 是空操作，不报错，`tracks.camera` 不出现 |
| `cards` | 对象 | 无 | 是 | | 技术卡运行库。`cards.use(as, runtime?)` 返回 `Handle`（见 CR 契约）：`as` 是片子描述里这个镜头 `cards` 声明过的实例名，卡的参数只从片子描述来，`runtime` 只放写不进 JSON 的东西；见 5.8 |
| `params` | 对象 | 无 | 是 | | 片子描述里这个镜头的参数 |
| `seed` | 整数 | 无 | 是 | 见 T 契约 3.3 | 这个镜头的镜头种子：这次装载生效的那一个，有锁文件取锁里记的，没有取镜头条目的 `seed`（F 契约 5.11）。`ctx.rng` 展开流名用的必须是同一个值 |
| `rng` | 函数 | 无 | 是 | | `rng("<用途>/<对象>")` 返回一条命名随机流，流名展开见 T 契约 3.4。流对象必须带只读的 `name`：字符串，值是展开好的流名。取数方法还没定，见第 6 节 |
| `assets` | 对象 | 无 | 是 | | 资产。`assets.load("asset:<名>@<版本>")` 返回资产。这个镜头能用的资产只有两处：镜头输入里镜头条目的 `assets`，和镜头输入的 `assets`（全片的 `assets` 表，不出现表示全片没有）；镜头输入见 F 契约 3.2，两处先找哪一处见 D 契约 5.5。要的资产在这两处都对不上时必须报错，不得交回空值；报哪个错误码：`待定：assets.load 找不到资产时报的错误码` |
| `anchor` | 函数 | 米 | 是 | | `anchor("<实体名>", "<锚点名>")` 返回这个锚点的世界坐标 `[x, y, z]`，形状同每帧元数据契约（M）3.3 `anchors` 的 `world`。实体或锚点找不到时必须报错，不得交回猜的坐标；报哪个错误码：`待定：ctx.anchor 找不到锚点时报的错误码` |
| `tokens` | 对象 | 无 | 是 | | 画风令牌：镜头输入的 `tokens`（F 契约 3.2），也就是片子描述的 `style.tokens` 原样；镜头输入不带时是空对象。颜色类令牌是场景线性还是显示空间，由片子描述契约（D）逐个写明 |
| `size` | 数组 | 像素 | 是 | `[宽, 高]`，正整数 | 输出尺寸：镜头输入的 `output.size`（F 契约 3.2）。这次装载的档位生效的缩放不是 1 时它跟不跟着缩放：`待定：ctx.size 随不随缩放变` |
| `fps` | 字符串 | 帧每秒 | 是 | 见 T 契约 3.2 | 全片帧率：镜头输入的 `output.fps` |
| `frames` | 整数 | 帧 | 是 | ≥ 1 | 这个镜头的帧数：镜头条目的 `out` 减 `in` |
| `shot` | 对象 | 帧 | 是 | `{ id, in, frames }` | 只读。这个镜头的标识、起始帧、帧数；`in` 是全片帧号 |
| `events` | 对象 | 帧 | 是 | 键是事件名，值是整数 | 只读。取自镜头输入的 `events`（已经展开成全片帧号的事件表，见 F 契约 3.2；形状见事件表契约（EV））：每个命名条目（`kind` 是 `named`）一项，键是它的 `id`，值是它的 `frame` 减去 `in`，是镜头局部帧号，可以是负数或不小于镜头帧数。时刻算式由上层展开一次，宿主不再从片子描述展开。镜头输入不带 `events` 时是空对象。换算见 T 契约 5.8 |
| `THREE`、`renderer` | 母语对象 | 无 | three 帧源必填 | 版本 `0.187.0` | 宿主注入的渲染库和渲染器 |
| `bpy`、`hostScene` | 母语对象 | 无 | Blender 帧源必填 | | 宿主注入的 Blender 模块和场景 |

`ctx` 里没有当前帧号。交给镜头代码和卡的帧号一律是镜头局部帧号（T9）。Python 里 `cards.use` 的 `runtime` 用关键字参数传，JS 里用一个对象传。

### 3.3 镜头对象

| 成员 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `state(f, sub)` | 函数，没有返回值 | 是 | 把 `(f, sub)` 这一时刻的状态写进场景。`f` 是镜头局部帧号，`sub` 是子帧相位 |
| `meta(f)` | 函数，返回对象 | 是 | 交宿主量不出来的三样：`texts`（文字框）、`anchors`（锚点）、`readings`（自定义读数），三个键都可以不出现 |
| `dispose()` | 函数，没有返回值 | 是 | 释放这个镜头占的资源 |
| `camera` | 母语对象 | 是 | 相机句柄 |
| `entities` | 对象，`{ 实体名: 母语对象 }` | 是 | 实体句柄 |
| `scene` | 母语对象 | three 帧源必填，Blender 帧源不出现 | 场景句柄 |

### 3.4 谁交什么

| 东西 | 谁交 | 说明 |
|---|---|---|
| `camera`、`entities`、`scene` | 镜头代码交句柄 | 宿主靠它们出元数据和辅助层 |
| 文字框、锚点、自定义读数 | 镜头代码经 `meta(f)` 交 | 宿主量不出来的只有这三样 |
| 相机参数、包围盒、可见比例、深度范围、渲染统计 | 宿主直接从场景里量 | 镜头代码不得交，也改不了 |

### 3.5 写法示意

两段里的 `title`、`light` 是片子描述里这个镜头 `cards` 声明过的实例名。

three 帧源，JS：

```js
export async function build(ctx) {
  const { THREE } = ctx
  const scene = new THREE.Scene()
  const title = ctx.cards.use('title')
  scene.add(title.object)
  const camera = new THREE.PerspectiveCamera(35, ctx.size[0] / ctx.size[1], 0.1, 100)
  camera.position.set(0, 0, 6)
  return {
    scene, camera,
    entities: { title: title.object },
    state(f, sub) { title.apply(f, sub) },
    meta(f) { return title.meta(f) },
    dispose() { title.dispose() },
  }
}
```

Blender 帧源，Python：

```python
def build(ctx):
    kit = ctx.assets.load("asset:rtx-card@3")
    ctx.cards.use("light")

    def state(f, sub):
        ctx.tracks.apply(f, sub)

    def meta(f):
        return {"anchors": {"kit.fan_L#hub": ctx.anchor("kit.fan_L", "hub")}}

    def dispose():
        pass

    return {"camera": ctx.hostScene.camera, "entities": kit.by_name,
            "state": state, "meta": meta, "dispose": dispose}
```

### 3.6 镜头核对记录

顶层对象，`format` 是 `shot-check/0.1`。出现哪一段就判哪几条，没出现的段不判。

「来历」一栏的四个词见契约写法约定 3.1。格式标识和 `ext` 不是观测，来历写「—」；带子字段的段，子字段各自标。来历是相对测试工具说的：测试工具在被测的那一对（渲染器加宿主，见 F 契约第 2 节）之外。那一对里面任何代码产出的值，包括宿主自己记的账，都是 `自报`，不得填进 `旁观` 或 `量的` 的字段；测试工具放进夹具镜头代码里的观测点得到的值是 `旁观`，前提是观测点是测试工具自己的代码，不是帧源或宿主的代码；测试工具自己读文件、读产物算出来的是 `量的`；从元数据里直接抄出来的是 `自报`。这份记录判三方：S1、S7、S8 判镜头代码；S2、S4、S5、S9、S10 判装载这个镜头的那一对；S3、S6 判这次出片把镜头派给了谁、怎么搭。哪几条的查法只靠 `自报` 的字段，见第 6 节。

| 字段 | 类型 | 单位 | 必填 | 值域 | 来历 | 说明 |
|---|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `shot-check/0.1` | — | 格式标识 |
| `shot` | 字符串 | 无 | 是 | 见 D 契约 5.1 | `请求` | 镜头的标识：测试工具装载的是哪个镜头 |
| `mode` | 字符串 | 无 | 是 | `cards-data`、`build-script`、`native-code` | `请求` | 搭镜头的模式，见第 2 节的对应表；取自镜头输入里镜头条目的出帧者那一套：带 `renderer` 时是 `renderer.mode`，不带时是顶层的 `mode` |
| `entry` | 字符串 | 无 | `mode` 是 `build-script` 或 `native-code` 时必填，`sources` 里有 `ext.<名字>` 的除外 | 相对路径 | `请求` | 入口文件；取自镜头输入里镜头条目的出帧者那一套：带 `renderer` 时是 `renderer.entry`，不带时是顶层的 `entry` |
| `sources` | 数组 | 无 | 是 | 至少 1 项，帧源名 | `自报` | 这一次出片里出这个镜头的帧的帧源，数法见 5.1；取自交回的各帧元数据里帧源自己写的出帧者（M 契约 3.5 的 `renderer`） |
| `languages` | 数组 | 无 | 是 | 至少 1 项，`js`、`python` | `量的` | 这个镜头用到的语言，数法见 5.1；测试工具从入口文件和用到的卡的实现上认，不取帧源报的 |
| `buildCalls` | 整数 | 次 | 否 | ≥ 0 | `旁观` | 一次装载里 `build` 跑了几次，夹具镜头代码外面的观测点数的：观测点包在入口文件的 `build` 外面，`build` 每被调一次它数一次。没有入口文件的镜头放不了观测点，这一项不得出现；有入口文件但没放观测点时也不出现。宿主自己数的是 `自报`，不得填进这个字段 |
| `build` | 字符串 | 无 | 是 | `ok`、`failed` | `量的` | 构建的结论：装载这个镜头的那次调用成功还是报错 |
| `error` | 字符串 | 无 | 否 | 错误码，写法见 ER 契约 5.2 | `量的` | 构建失败时报的错误码；没报错误码就不出现 |
| `entities` | 数组 | 无 | 是 | 字符串 | `自报` | 构建交出的全部实体名，含卡带进来的；取自帧源交回的实体清单（F 契约 3.6） |
| `omittable` | 数组 | 无 | 否 | `entities` 里的名字，不重复 | `自报` | `entities` 里类别是 `part`、没有角色的实体名；类别取自帧源交回的实体清单。不出现表示一个也没有 |
| `metaEntities` | 数组 | 无 | 否 | 每项 `{ f, names, omittedParts? }` | `f`：`请求`；`names`、`omittedParts`：`自报` | 抽帧时每帧元数据里列出的实体名；`f` 是镜头局部帧号，`names` 是实体名的数组，不重复，`omittedParts` 是这一帧元数据的 `omittedParts`（整数，≥ 1，单位个；不出现表示这一帧一个也没省）。同一帧渲了不止一次时，同一个 `f` 可以出现不止一项，各项独立判，不合并 |
| `evaluations` | 数组 | 无 | 否 | 每项 `{ f, sub, mode, digest }` | `f`、`sub`、`mode`：`请求`；`digest`：`量的` | 对 `state` 的纯函数门观测；`mode` 的值域是 `single`、`shuffled`、`sequential`、`after-other-shot`，`digest` 是状态摘要，由测试工具自己的代码对场景状态算（T 契约 5.2），不取镜头代码报的，也不取宿主算的：宿主算的摘要是 `自报`，不得填进这个字段 |
| `patches` | 数组 | 无 | 否 | 每项 `{ id, hits }` | `id`、`hits`：`自报` | 片段补丁，宿主记的；`id` 是补丁的名字，`hits` 是命中处数，整数，≥ 0 |
| `metaKeys` | 数组 | 无 | 否 | 字符串 | `旁观` | 镜头代码的 `meta(f)` 的返回值里出现过的键，夹具镜头代码外面的观测点数的：观测点把 `build` 交回的 `meta(f)` 包一层，在返回值上读键。没有入口文件的镜头这一项不得出现。宿主在接返回值的地方记的是 `自报`，不得填进这个字段 |
| `declaredCards` | 数组 | 无 | `cardUses` 出现时必填 | 字符串，不重复 | `请求` | 片子描述里这个镜头 `cards` 声明过的实例名 |
| `cardUses` | 数组 | 无 | 否 | 每项 `{ as, runtimeKeys?, paramKeys? }` | `as`、`runtimeKeys`：`旁观`；`paramKeys`：`请求` | 镜头代码对 `ctx.cards.use` 的每一次调用，不记内建卡，夹具镜头代码外面的观测点数的：观测点把交给 `build` 的 `ctx.cards.use` 包一层，每次调用记下传进来的参数。`as` 是传进去的实例名，`runtimeKeys` 是 `runtime` 的键，`paramKeys` 是这张卡声明的参数名，取自卡的声明。没有入口文件的镜头这一项不得出现。宿主在 `ctx.cards.use` 里记的是 `自报`，不得填进这个字段 |
| `scan` | 对象 | 无 | 否 | `{ wallClock, unseededRandom }` | `量的` | 对镜头代码的静态扫描命中，结构同 T 契约 3.6 的 `scan`；测试工具自己扫文件 |
| `ctx` | 数组 | 无 | 否 | 每项 `{ want, seen }` | `want`：`请求`；`seen`：`旁观` | 交给镜头代码的 `ctx` 里五个值的观测，一次装载一项；同一个镜头装载了不止一次时各项独立判，不合并。`want` 是这五个值该是什么，测试工具照自己发出去的镜头输入和 `env` 算：`{ seed, fps, frames, shotIn, size? }`，算法见 5.10；`shotIn` 对的是 `ctx.shot.in`，单位帧；`fps` 的值域同镜头输入的 `output.fps`（T 契约 3.2）；`size` 在缩放不是 1 的装载里不出现。`seen` 是观测点在 `build` 收到的 `ctx` 上读到的 `{ seed?, fps?, frames?, shotIn?, size? }`，类型同 `want`，不限值域；`ctx` 里没有的那一项不出现。观测点是测试工具放在夹具镜头代码外面的代码，不是帧源或宿主的代码；宿主自己报的不得填进 `seen` |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | — | 私有数据 |

## 4. 不变量

## 5. 口径

### 5.1 帧源和语言怎么数

只数这一次出片的出帧者那一套：片子描述的镜头条目带 `renderer` 时，留作对照的 `source` 那一套不计入。数入口文件，加上它经 `ctx.cards.use` 用到的每张卡的实现。「卡加数据」模式下数片子描述里这个镜头列出的、形状是 `create` 的卡的实现。形状是 `evaluate` 的卡在求值核里跑，不计入。

### 5.2 实体名的写法

一段或多段，用 `.` 连接；每段只含 ASCII 字母、数字和下划线，不空。`#` 留给锚点，不得出现在实体名里。两个名字逐字符相同才算同一个。

### 5.3 元数据里的实体名怎么查

每次 `verify` 抽帧，把抽到的每一帧元数据里列出的实体名和构建交出的 `entities` 比：元数据里的名字必须是 `entities` 的子集；缺的个数必须等于这一帧的 `omittedParts`（不出现算 0）；缺的只能是类别为 `part`、没有角色的实体。类别、角色、`omittedParts` 见 M 契约。

### 5.4 纯函数门

求值方式 `single`、`shuffled`、`sequential` 同 T 契约 5.4。`after-other-shot` 是先把另一个镜头从构建跑到 `dispose`，再求这个时刻。「逐位相同」同 T 契约 5.2。

### 5.5 片段补丁「命中」

在目标着色器的源码里找到补丁的锚点并完成了插入或替换，算命中 1 处。`hits` 是 0 就是没命中。

### 5.6 坐标

`ctx.anchor` 返回的是世界坐标，单位和坐标系照通用口径。

### 5.7 静态扫描

扫描清单同 T 契约 5.3，扫描范围是入口文件和它直接引用的本镜头文件。

### 5.8 `ctx.cards.use`

- `as` 必须是片子描述里这个镜头 `cards` 声明过的实例名（`cards[].as`，见 D 契约）。没声明就是构建失败，码是 `contract.undeclared-card`。
- 卡的参数只从片子描述来，入口文件不提供参数层（D 契约 5.8）。
- `runtime` 只放写不进 JSON 的东西：宿主对象、函数。它的键不得和这张卡声明的参数同名，同名是构建失败，码是 `contract.runtime-shadows-param`。
- 一次构建只报一个错误码。两种违反同时出现时，报调用次序里先出现的那一次调用犯的那一种；同一次调用里 `as` 没声明、`runtime` 的键又和核对记录里这一项的 `paramKeys` 同名时，算没声明那一种。
- 内建卡不用声明。哪几张是内建卡见目录归属表契约（OW）。

### 5.9 数据从哪进

- 成块的静态数据（规格表、查找表这一类）放在入口文件旁边的本镜头文件里，由入口文件直接引用：本镜头文件是和入口文件在同一个目录里的文件，它们在 5.7 的扫描范围里，和入口文件一样不进锁文件（见锁文件契约（LK）第 6 节）。
- `ctx.params` 放调参用的值。
- 要记版本和哈希的数据走资产，从 `ctx.assets` 取；「卡加数据」模式没有入口文件，数据只能走卡的参数或资产。

本镜头文件的大小，本契约不设上限。

### 5.10 `ctx` 里的五个值怎么对

`want` 由测试工具照自己这次 `open` 传的镜头输入和 `env`（F 契约 3.2）算，不取帧源报的：

- `seed`：这次装载生效的镜头种子。`env.lock` 不是 `null` 时是锁文件里这个镜头的镜头种子，是 `null` 时是镜头条目的 `seed`（F 契约 5.11）。
- `fps`：镜头输入的 `output.fps`，原样，写法见 T 契约 3.2（例如 `24/1`）。
- `frames`：镜头条目的 `out` 减 `in`。
- `shotIn`：镜头条目的 `in`，全片帧号。
- `size`：镜头输入的 `output.size`。这次装载的档位生效的缩放（F 契约 3.3）不是 1 时，`ctx.size` 跟不跟着缩放还没定（见第 6 节），这种装载的 `want` 不记 `size`，S10 对它的 `size` 不判。

`seen` 由观测点读：观测点包在夹具镜头代码的 `build` 外面，`build` 每被调一次，它在收到的 `ctx` 上读这五项，原样交给测试工具；怎么交由测试工具定。`shotIn` 读的是 `ctx.shot.in`。`ctx` 里没有某一项时（`ctx` 没有 `shot`、或者 `shot` 里没有 `in`，算没有 `shotIn`）`seen` 不写这一项，S10 判它缺。

S10 只对 `ctx` 里这五项负责；`ctx` 其余各项现在有没有观测见第 6 节。`shotIn` 只在起始帧不是 0 的镜头上有判力：起始帧是 0 的镜头，把 `ctx.shot.in` 恒交成 0 的那一对也对得上。夹具的要求同 T 契约 5.4：至少两个镜头，并且装载非首镜头。这一句是对夹具的要求，不立不变量。
