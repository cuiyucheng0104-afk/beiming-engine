# 补丁格式

版本：0.1.0-draft

## 1. 范围

管：

- 补丁 `patch/0.1` 的全部字段：对片子描述的一组修改。
- 四种操作各自带什么、怎么作用。
- 一个补丁要么全成、要么全不成。
- 修法的形状，以及修法和补丁操作的关系。
- 判定以上各条用的「补丁核对记录」。

不管：

- 路径的写法：片子描述契约（D）5.4、D5。
- 修订号对不上时怎么拒：D6。哪些字段只有服务器能写：D7。
- 修改之后的片子描述合不合法：片子描述契约（D）。
- 修法写在返回的哪里：信封契约（EN）3.4、谓词登记表契约（PR）3.5。
- 镜头契约（S）里的「片段补丁」：那是往着色器源码里插代码，和本契约无关。

## 2. 术语

片子描述、修订号、路径：见片子描述契约（D）第 2 节。核对记录：见时间键契约（T）第 2 节。

| 词 | 含义 |
|---|---|
| 补丁 | 带着修订号、对片子描述的一组有次序的操作。 |
| 操作 | 补丁里的一项：`set`、`remove`、`rename`、`add` 之一。 |
| 可作用 | 一个操作在当前的片子描述上满足 5.2 的前提。 |
| 修法 | 诊断或判定里给出的一个机械修改：一个操作加上 `applicability`。 |
| 补丁核对记录 | 一致性测试把一次打补丁前后的片子描述和结果写下来的数据对象，只用来判定不变量。 |

## 3. 结构

补丁、修法、补丁核对记录的任何一层都不得出现本节没列的键；`value`、`before`、`after` 里面不受这一条管。

### 3.1 补丁

顶层对象，`format` 是 `patch/0.1`。补丁不收 `ext`，见通用口径「未知字段」。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `format` | 字符串 | 是 | `patch/0.1` | 格式标识 |
| `rev` | 整数 | 是 | ≥ 0 | 提交者读到的修订号 |
| `ops` | 数组 | 是 | 至少 1 项，每项见 3.2 | 操作，按书写顺序作用 |

### 3.2 `ops[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `op` | 字符串 | 是 | `set`、`remove`、`rename`、`add` | 哪种操作 |
| `path` | 字符串 | 是 | 路径，写法见 D 契约 5.4 | 作用在哪 |
| `value` | 任意 JSON 值 | 见 PA1 | | `set` 写进去的值；`add` 加进去的数组条目 |
| `to` | 字符串 | 见 PA1 | 一段键名：不空，不含 `/`、`#`，不含空白 | `rename` 的新键名 |

### 3.3 修法

不是顶层对象，嵌在诊断和判定条目里，不带 `format`。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `op`、`path`、`value`、`to` | 同 3.2 | 同 3.2 | 同 3.2 | 一个操作 |
| `applicability` | 字符串 | 是 | `machine`、`maybe`、`placeholder`、`none` | 这条修法能不能直接用，见 5.5 |

### 3.4 补丁核对记录

顶层对象，`format` 是 `patch-check/0.1`。只记修订号对得上的写入；对不上的归 D6。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `format` | 字符串 | 是 | `patch-check/0.1` | 格式标识 |
| `before` | 对象 | 是 | 片子描述，或它的一部分 | 打补丁之前 |
| `patch` | 补丁 | 是 | 见 3.1 | 提交的补丁 |
| `outcome` | 字符串 | 是 | `applied`、`rejected` | 服务器接受了还是拒了 |
| `code` | 字符串 | 否 | 错误码，写法见 ER 契约 5.2 | 被拒时的错误码 |
| `after` | 对象 | 是 | 和 `before` 同一个范围 | 这次写入之后服务器存着的内容 |
| `ext` | 对象 | 否 | 键带点分前缀 | 私有数据 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| PA1 | `set` 和 `add` 必须带 `value`、不得带 `to`，`rename` 必须带 `to`、不得带 `value`，`remove` 两个都不得带。 | 逐个操作按 `op` 看 `value`、`to` 两个键在不在 | `PA1-rename-without-to.json` |
| PA2 | 补丁被拒时，片子描述必须一点都没变。 | `outcome` 是 `rejected` 时，`after` 必须和 `before` 相等，比法见 5.4 | `PA2-rejected-half-applied.json` |
| PA3 | 补丁里每个操作都可作用、补丁被接受时，结果必须等于把操作按书写顺序逐个作用之后的片子描述。 | 照 5.2 在 `before` 上逐个作用 `ops`；全部可作用且 `outcome` 是 `applied` 时，算出来的结果必须和 `after` 相等 | `PA3-applied-op-missing.json` |
| PA4 | 补丁里有一个操作不可作用时，整个补丁必须被拒。 | 照 5.2 在 `before` 上逐个作用 `ops`；作用到某一个时不可作用，`outcome` 必须是 `rejected` | `PA4-inapplicable-not-rejected.json` |
| PA5 | 修法去掉 `applicability` 之后必须是一个满足 PA1 的操作。 | 按修法的 `op` 看 `value`、`to` 两个键在不在，要求同 PA1 | `PA5-fix-rename-without-to.json` |

## 5. 口径

### 5.1 路径怎么落到值上

路径从片子描述的根起，一段一段往下走。当前值是对象时，这一段是它的键。当前值是按标识寻址的数组时，这一段是数组条目的标识。按标识寻址的数组有六个：`shots`、`events`、`overlays`、`transitions`、`audio/narration`，标识是条目的 `id`；镜头条目里的 `cards`，标识是条目的 `as`。别的数组不能再往下走，路径止于数组本身。例：`shots/s01/cards/fit/params/margin` 落在镜头 `s01` 里实例名是 `fit` 的那一项的参数 `margin` 上；`transitions/cut-180/type` 落在 `id` 是 `cut-180` 的那个转场的 `type` 上。

### 5.2 四种操作

操作按书写顺序作用，后一个看到的是前一个作用之后的结果。

| `op` | 前提（都满足才可作用） | 作用 |
|---|---|---|
| `set` | 路径除最后一段之外，每一段都落在已有的值上。最后一段的上一层是对象，或者是按标识寻址的数组且最后一段是已有条目的标识、`value` 是标识和它相同的对象 | 上一层是对象：这个键有就改成 `value`，没有就建。上一层是数组：把那个条目换成 `value` |
| `remove` | 路径落在已有的值上 | 删掉这个键；落在按标识寻址的数组的条目上时删掉这个条目 |
| `rename` | 路径落在一个对象的已有的键上；这个对象里还没有名叫 `to` 的键 | 把键名改成 `to`，值不变 |
| `add` | 路径落在按标识寻址的数组上；`value` 是带标识（`id`，`cards` 里是 `as`）的对象；数组里还没有这个标识 | 把 `value` 加在数组的末尾 |

别的数组只能用 `set` 整个换掉。

### 5.3 全成或全不成

服务器先在一份副本上逐个作用。有一个不可作用，或者作用完的片子描述过不了写入检查，就整个拒掉，已存的内容不动，修订号不变。

### 5.4 两份片子描述相等

作为 JSON 值逐键、逐项相等：对象不看键的次序，数组看次序，数按数值比。

### 5.5 `applicability` 四档

| 档 | 含义 | 谁来应用 |
|---|---|---|
| `machine` | 可以直接自动应用 | 写入时带 `applyFixes=machine`，服务器把上一次诊断里这一档的修法全部应用 |
| `maybe` | 多半对，要复核 | 调用方判断后应用，再验 |
| `placeholder` | 修法里有要填的值 | 调用方填好再应用 |
| `none` | 没有机械的修法 | 不应用，看 `hint` |

修法和操作是同一套形状，所以一条修法去掉 `applicability` 就可以原样放进补丁的 `ops`。

## 6. 待定

| 项 | 现在怎么写 | 等什么 |
|---|---|---|
| `set` 能不能换掉按标识寻址的数组里的整个条目 | 【起草者补】能，`value` 的标识必须和路径最后一段相同；新条目只能用 `add` 加 | 集成负责人确认 |
| `rename` 能不能改条目的 `id` | 【起草者补】不能，`rename` 只改对象的键；改 `id` 用 `set` 写那个条目的 `id` 字段 | 集成负责人确认 |
| `add` 加在数组的哪里 | 【起草者补】末尾。镜头表和事件要不要按时间排，由片子描述契约判 | 集成负责人确认 |
| `rename` 遇到同名的键 | 【起草者补】不可作用 | 集成负责人确认 |
| 镜头条目的 `cards` | 【起草者补】`cards` 改成带 `as` 的数组之后，照 `shots`、`events`、`overlays` 的办法处理：路径按 `as` 走，`set` 换整项，`remove` 删，`add` 加在末尾 | 集成负责人确认 |
| 路径最后一段指向还不存在的键 | 只有 `set` 可以，见 5.2 | 不用等 |
| 操作不可作用时报哪个错误码 | 不定，核对记录的 `code` 是可选的 | 错误码表契约（ER）登记 |
| `none` 这一档的修法带不带 `op`、`path` | 需求来源说修法只有一种形状，所以必带；这一档具体写什么不定 | 集成负责人确认 |
| `placeholder` 这一档里要填的值怎么标 | 不定 | 集成负责人确认 |
| 整份提交片子描述时带不带 `format`、`rev` 写在哪 | 不归本契约 | 片子描述契约（D）、信封契约（EN） |
| `before`、`after` | 【起草者补】核对记录里可以只放片子描述里和补丁有关的那一部分；例子里就是这样 | 集成负责人确认 |
