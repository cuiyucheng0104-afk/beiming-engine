# 参考包

版本：0.1.0-draft

## 1. 范围

管：

- 参考包的目录布局、参考包清单 `ref-pack/0.1` 的全部字段。
- 参考包清单必须记齐的东西：版本、设备、种子、采样数、渲染口径、参考噪声地板。
- 两套渲染口径 `physical`、`production` 各自的设置。
- 参考包里的多层 EXR 怎么装各个通道。
- 参考噪声地板是什么、谁填、没填的包不能当裁判。
- 参考包不覆盖、按内容寻址、做题的一方读不到。
- 判定以上各条用的「参考包核对记录」。

不管：

- 每个通道的名字、分量、位深、色彩空间、取法：输出通道契约（PS）。本契约只引用通道名。
- 被渲的场景：场景包契约（SP）。参考包清单里只记场景包的包哈希。
- 种子的值域：时间键契约（T）3.3。
- 核心帧源自己交的各层：帧源接口契约（F）和输出通道契约（PS）。参考包只由标准答案机出。
- 降噪之后的参考、过了显示变换的参考：不放进参考包，另外出。
- 门的系数 k 取多少、拿哪个量去比：谓词登记表契约（PR）。
- 参考包放在哪个目录、谁有写权限：目录归属表契约（OW）。

## 2. 术语

帧、种子、辅助层、核对记录：见时间键契约（T）第 2 节。通道、分量、位深、标准答案机、出层方、样本、辅助样本、样本累积、像素滤波、通道对拍：见输出通道契约（PS）第 2 节。场景包、包哈希：见场景包契约（SP）第 2 节。

| 词 | 含义 |
|---|---|
| 参考包 | 一个目录，装着标准答案机对一个场景的一帧渲出的全部通道：一份参考包清单加若干多层 EXR 文件。 |
| 参考包清单 | 参考包里名叫 `ref.json` 的那个文件，结构见 3.2。 |
| 多层 EXR | 一个 OpenEXR 文件里装着多个有名字的层，每层是一个通道。 |
| 采样数 | 每个像素取多少个样本。 |
| 渲染口径 | 渲参考答案时用的一整套设置，参考包清单里的 `profile`；有 `physical`、`production` 两套。 |
| 物理参考 | 渲染口径是 `physical` 的参考包：关掉夹取和滤光泽。 |
| 生产参考 | 渲染口径是 `production` 的参考包：照成片的设置。 |
| 夹取 | 把单个样本的亮度压到一个上限以内的做法。 |
| 滤光泽 | 为了少噪点，把光泽反射在后续反弹里故意模糊的做法。 |
| 种子图 | 用参考包清单里的一个种子、`samples` 个样本渲出的一个 EXR 文件。 |
| 合并图 | 参考包清单里 `converged` 说的那个 EXR 文件，采样数比单张种子图高。 |
| 参考噪声地板 | 标准答案机自己和自己比出来的差：同一个种子重渲是否逐位相同，两个种子之间差多少。参考包清单里的 `floor`。 |
| 裁判 | 拿参考包去判别人渲的画面过不过的程序。 |
| 做题的一方 | 被裁判判的那一方，包括替它写代码的程序。 |
| 门 | 裁判判「过」或「不过」用的一个门槛。 |
| 地址 | 存放处用来取一个参考包的字符串。 |
| 参考包核对记录 | 一致性测试把对一个参考包的观测写下来的数据对象，只用来判定不变量；标准答案机不需要产出它。 |

## 3. 结构

### 3.1 目录布局

一个参考包是一个目录，说的是一个场景的一帧在一套渲染口径下的答案。参考包清单必须叫 `ref.json`，放在目录的根上。别的文件叫什么由参考包清单的 `files` 说了算，路径都从这个目录算起。

| 文件 | 个数 | 内容 |
|---|---|---|
| `ref.json` | 1 | 参考包清单，见 3.2 |
| 多层 EXR，`.exr` | 1 个或更多 | 种子图和合并图，见 5.1、5.3 |

### 3.2 参考包清单 `RefPack`

顶层对象，`format` 是 `ref-pack/0.1`。除 `ext` 之外的字段全部必填。可以是 `null` 的字段只有 `floor` 的三个键，见 3.3。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `ref-pack/0.1` | 格式标识 |
| `ref` | 字符串 | 无 | 是 | 一段或几段，用 `/` 隔开；每段是小写字母、数字、连字符、点，以字母或数字开头 | 这个参考包的名字，例如 `studio/part-pair/f0000/phys` |
| `scenePack` | 字符串 | 无 | 是 | `sha256:` 加 64 位小写十六进制 | 被渲的那个场景包的包哈希 |
| `producer` | 字符串 | 无 | 是 | `oracle` | 谁出的 |
| `blender` | 字符串 | 无 | 是 | 不空 | 标准答案机用的 Blender 的版本号 |
| `build` | 字符串 | 无 | 是 | 不空 | 那个 Blender 的构建哈希 |
| `device` | 字符串 | 无 | 是 | 不空；现在用到的有 `CPU` | 用什么设备渲的 |
| `gpu` | 字符串 | 无 | 是 | 不空 | 这台机器的显卡型号 |
| `driver` | 字符串 | 无 | 是 | 不空 | 显卡驱动的版本号 |
| `oidn` | 字符串 | 无 | 是 | 不空 | 这台机器上降噪库 OIDN 的版本号 |
| `ocioConfigSha256` | 字符串 | 无 | 是 | 64 位小写十六进制 | 色彩管理配置文件内容的 SHA-256 |
| `profile` | 字符串 | 无 | 是 | `physical`、`production` | 渲染口径，见 5.2 |
| `samples` | 整数 | 次 | 是 | ≥ 1 | 每张种子图的采样数 |
| `shutterAngleDeg` | 双精度 | 度 | 是 | `[0, 360]` | 快门角。标准答案机照它渲颜色层；辅助层不用它，见 5.3 |
| `seeds` | 数组 | 无 | 是 | 至少 1 项，不重复；每项是整数，值域见 T 契约 3.3 | 渲了哪几个种子，一个种子一张种子图 |
| `converged` | 对象 | 无 | 是 | 见下表 | 合并图 |
| `adaptive` | 布尔 | 无 | 是 | | 开没开自适应采样 |
| `denoised` | 布尔 | 无 | 是 | 取值由 RP2 管 | 包里的颜色降没降噪 |
| `clamp` | 对象 | 无 | 是 | 见下表 | 夹取 |
| `filterGlossy` | 双精度 | 无 | 是 | ≥ 0 | 滤光泽的强度；0 是关掉 |
| `bounces` | 对象 | 无 | 是 | 见下表 | 最多反弹几次 |
| `pattern` | 字符串 | 无 | 是 | 不空；`待定：采样图案的取值` | 采样图案。全部参考包必须用同一种 |
| `pixelFilter` | 字符串 | 无 | 是 | 不空；`待定：像素滤波的写法` | 像素滤波的类型和宽度 |
| `channels` | 数组 | 无 | 是 | 每项是输出通道契约（PS）3.1 的通道名，不重复；必须含哪些由 PS1 管 | 每个 EXR 文件里有哪些通道 |
| `auxSample` | 数组 | 无 | 是 | 每项是 `channels` 里的名字，不重复；取值由 RP1 管 | `channels` 里的辅助层：取辅助样本、不做样本累积的那几个 |
| `files` | 数组 | 无 | 是 | 至少 1 项，不重复；每项是相对路径，以 `.exr` 结尾 | 包里的 EXR 文件 |
| `floor` | 对象 | 无 | 是 | 见 3.3 | 参考噪声地板 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`converged`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `samples` | 整数 | 次 | 是 | ≥ 1 | 合并图的采样数 |
| `subsets` | 整数 | 份 | 是 | ≥ 1 | 合并图分成几份来渲 |

`clamp`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `direct` | 双精度 | 和 `color` 通道同一个量纲 | 是 | ≥ 0 | 直接光的夹取上限；0 是不夹 |
| `indirect` | 双精度 | 同上 | 是 | ≥ 0 | 间接光的夹取上限；0 是不夹 |

`bounces`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `max` | 整数 | 次 | 是 | ≥ 0 | 总的反弹上限 |
| `diffuse` | 整数 | 次 | 是 | ≥ 0 | 漫反射的反弹上限 |
| `glossy` | 整数 | 次 | 是 | ≥ 0 | 光泽反射的反弹上限 |
| `transmission` | 整数 | 次 | 是 | ≥ 0 | 透射的反弹上限 |

### 3.3 `floor`

三个键都必填，都可以是 `null`。`null` 表示「这次没算」：标准答案机还没把这一项量出来。别的字段一律不得是 `null`。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `rerunBitExact` | 布尔或 `null` | 无 | 是 | | 同一个种子重渲一遍，结果是不是逐位相同；`null` 表示这次没算 |
| `seedVsSeedPsnr` | 双精度或 `null` | 分贝 | 是 | > 0 | 两个种子的 `color` 通道之间的峰值信噪比；`null` 表示这次没算 |
| `seedVsSeedFlipMean` | 双精度或 `null` | 无 | 是 | `[0, 1]` | 两个种子的 `color` 通道之间 FLIP 差异图的平均值；`null` 表示这次没算 |

### 3.4 参考包核对记录

顶层对象，`format` 是 `ref-pack-check/0.1`。一份记录说一个参考包。记录里出现哪一段，就判哪几条不变量；没出现的段不判。只看参考包清单就能判的不变量（RP1、RP2 的 `denoised`、RP8）对单独的一份参考包清单也照判。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `ref-pack-check/0.1` | 格式标识 |
| `pack` | `RefPack` | 无 | 是 | 见 3.2 | 被测的参考包清单 |
| `colorTransfer` | 字符串 | 无 | 否 | `linear`、`encoded` | 量出来的 `color` 通道是线性编码，还是过了传递函数；量法见 5.2 |
| `judgings` | 数组 | 无 | 否 | | 拿这个参考包当裁判的观测，一道门一项，每项见下表 |
| `previous` | `RefPack` | 无 | 否 | 见 3.2；`ref` 由 RP9 管 | 存放处里之前用同一个 `ref` 存过的那份参考包清单 |
| `stored` | 对象 | 无 | 否 | 见下表 | 存放处给这个包的地址，和照内容算出的包哈希 |
| `reads` | 数组 | 无 | 否 | | 有人去读这个包的观测，每项见下表 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

`judgings[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `metric` | 字符串 | 无 | 是 | `seedVsSeedPsnr`、`seedVsSeedFlipMean` | 这道门比的是参考噪声地板的哪一项 |
| `k` | 双精度 | 无 | 是 | > 0 | 系数 |
| `threshold` | 双精度 | 同 `floor` 里那一项 | 是 | | 裁判实际用的门槛 |

`stored`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `address` | 字符串 | 无 | 是 | `sha256:` 加 64 位小写十六进制 | 存放处给这个包的地址 |
| `hash` | 字符串 | 无 | 是 | 同上 | 对这个包目录照 5.6 算出的包哈希 |

`reads[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `reader` | 字符串 | 无 | 是 | `judge`、`solver` | 谁去读：裁判，还是做题的一方 |
| `status` | 字符串 | 无 | 是 | `ok`、`denied` | 读到了，还是被拒绝 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| RP1 | `auxSample` 必须正好是 `channels` 里在通道登记表中取法是 `sub0` 的那些通道名，也就是辅助层。 | 把 `channels` 里属于「输出通道契约（PS）3.1 的通道登记表中取法是 `sub0` 的通道名」的那些挑出来成一个集合，`auxSample` 作为集合必须等于它：少一个、多一个都算违反 | `RP1-object-id-not-aux.json`、`RP1-color-in-aux.json` |
| RP2 | 参考包里的颜色必须是场景线性、未降噪的：`denoised` 必须是 `false`，量出来的 `color` 通道必须是线性编码。 | `denoised` 必须是 `false`；`colorTransfer` 出现时必须是 `linear` | `RP2-denoised-reference.json`、`RP2-encoded-color.json` |
| RP3 | `floor` 的三个键里有任何一个是 `null` 的参考包，不得拿来当裁判。 | `pack.floor` 的三个键有一个是 `null` 时，`judgings` 必须是空数组 | `RP3-judge-without-floor.json`、`RP3-only-rerun-not-measured.json`、`RP3-only-psnr-not-measured.json`、`RP3-only-flip-not-measured.json` |
| RP4 | 拿参考包当裁判时，每道门的门槛必须等于参考噪声地板里对应的那一项乘以系数 k，不得写死成别的数。 | `judgings` 每一项：`pack.floor[metric]` 不是 `null` 时，`threshold` 和 `pack.floor[metric] × k` 的差的绝对值必须不大于后者的十亿分之一。是 `null` 的归 RP3，这一条不判 | `RP4-fixed-threshold.json` |
| RP5 | 参考包清单里除 `floor` 之外的任何一项变了，就必须是另一个参考包、用另一个 `ref`，不得覆盖旧的。 | `previous` 出现并且 `previous.ref` 等于 `pack.ref` 时：它和 `pack` 除 `floor` 之外的全部字段（`ext` 不算）必须逐项相同。`channels`、`auxSample` 按集合比，次序不算（和 RP1 一致）；`seeds`、`files` 按次序比，同样的项换了次序算不同。`previous.ref` 不等于 `pack.ref` 的归 RP9，这一条不判 | `RP5-overwritten-after-driver-change.json`、`RP5-channel-added.json`、`RP5-seeds-reordered.json`、`RP5-files-reordered.json` |
| RP6 | 参考包必须按内容寻址：它的地址必须等于由它的全部文件算出的包哈希。 | `stored.address` 必须等于 `stored.hash`，按字符串比 | `RP6-address-not-content-hash.json` |
| RP7 | 做题的一方不得读到参考包。 | `reads` 里 `reader` 是 `solver` 的每一项，`status` 必须是 `denied` | `RP7-solver-reads-reference.json` |
| RP8 | 渲染口径是 `physical` 时，`clamp.direct`、`clamp.indirect`、`filterGlossy` 必须都是 0。 | `profile` 是 `physical` 时这三个数逐个和 0 比，没有容差 | `RP8-physical-with-clamp.json`、`RP8-physical-with-direct-clamp.json`、`RP8-physical-with-filter-glossy.json` |
| RP9 | 参考包核对记录里的 `previous` 必须是用同一个 `ref` 存过的那份：`previous.ref` 必须等于 `pack.ref`。 | `previous` 出现时：`previous.ref` 和 `pack.ref` 按字符串比，必须相等 | `RP9-previous-other-ref.json` |

## 5. 口径

### 5.1 EXR 文件

- 每个文件是一个多层 OpenEXR，装着一帧的全部通道。`channels` 里的每个通道是一层，层名就是通道名；层里的分量名和次序照输出通道契约（PS）3.1。
- 位深：`f32` 的分量存成 EXR 的 32 位浮点，`u32` 的分量存成 EXR 的 32 位无符号整数。不得存成 16 位浮点。
- 压缩必须是无损的。
- 一个包里全部文件的画面尺寸必须相同。
- 浮点分量不得出现 `NaN` 和无穷。
- 色彩空间、取法照输出通道契约（PS）：`color` 和分灯组是场景线性、Rec.709 原色，没有降噪，没有过显示变换。

### 5.2 两套渲染口径

- `physical`，物理参考：关掉夹取（`clamp.direct`、`clamp.indirect` 都是 0）和滤光泽（`filterGlossy` 是 0），由 RP8 管。它回答「物理上应该是什么样」。
- `production`，生产参考：`clamp`、`filterGlossy`、`bounces`、`adaptive` 都照成片的设置填。它回答「成片的设置下应该是什么样」。
- 两套渲染口径下 `denoised` 都必须是 `false`（RP2）。
- `colorTransfer` 的量法照帧源接口契约（F）5.2：渲一张已知反射率的灰阶，各级读数和反射率成正比记 `linear`，否则记 `encoded`。过线多少用 F 契约 5.3 的探针：`待探针：线性度，灰阶各级读数和已知反射率的相对误差`。

### 5.3 种子图和合并图

- `seeds` 里的每个种子渲一张种子图，每张都是 `samples` 个样本，别的设置全部相同。
- 合并图的采样数是 `converged.samples`，分 `converged.subsets` 份渲。
- 文件名的写法照例子：种子图叫 `seed<两位序号>.exr`，序号是这个种子在 `seeds` 里的位置，从 00 起；合并图叫 `converged.exr`。
- 颜色层照 `shutterAngleDeg` 渲。
- 辅助层（`depth`、`objectId`、`normal`、`motion`）不跟着颜色层出：标准答案机另渲一遍，孔径 0、快门 0、1 个样本、取像素中心，时刻是这一帧的 `sub = 0`（输出通道契约 PS 5.1）。这一遍和种子无关，每个 EXR 文件里放的都是这一遍的结果。`objectId` 的 `coverage` 例外：它从所在文件颜色层的样本数（输出通道契约 PS 5.4）。

### 5.4 参考噪声地板

- 由标准答案机第一次出这个包的时候自己量、自己填，别人不得填。
- `rerunBitExact`：拿同一个种子把同一张种子图重渲一遍，两个文件的像素数据逐位相同记 `true`，否则记 `false`。
- `seedVsSeedPsnr`、`seedVsSeedFlipMean`：两张种子图的 `color` 通道相比。
- 同种子重渲量过了（探针数据表第 11 行和「5090 读数」一节；Mac 和 5090 两台机器，六个校准场景、64 采样、不降噪）：用 CPU 渲，两遍的全部层逐位相同；用显卡渲（OptiX、CUDA 都一样），量过的辅助层（深度、编号、位置）逐位相同，颜色层不逐位相同，最大相对差 1.7e-6；`normal`、`motion` 两层探针没量。
- 照这个读数，同一个种子重渲两遍：辅助层必须逐位相同；颜色层（`color` 通道）在 `device` 是 `CPU` 时必须逐位相同；用显卡渲时颜色层逐分量的相对差必须不超过 1e-5，相对差 = |a − b| ÷ max(|a|, 1e-12)，a、b 是两遍里同一个像素同一个分量的读数，无单位。`rerunBitExact` 仍照上面那一条填。
- 另两个数现在还没有：`待探针：参考噪声地板，两个种子之间的峰值信噪比，单位分贝`、`待探针：参考噪声地板，两个种子之间 FLIP 差异图的平均值`。
- 三个键都不是 `null`，才叫「地板填了」。

### 5.5 当裁判

- 裁判的每道门写成「参考噪声地板的某一项乘以 k」。`threshold` 是裁判实际拿去比的数。
- RP4 的容差是相对的十亿分之一，只为浮点乘法的舍入留的。
- `rerunBitExact` 不是数，不参加乘 k。

### 5.6 地址和包哈希

- 参考包的包哈希照场景包契约（SP）5.7 的算法算，对象换成参考包目录里的全部文件（包括 `ref.json`）。
- 地址就是这个包哈希。存进去之后不得改：改了内容，哈希就变，就是另一个包。
- 参考包清单里的 `scenePack` 是被渲的场景包的包哈希，不是参考包自己的。

### 5.7 谁能读

- 参考包只给裁判读。做题的一方去读必须被拒绝，拒绝之后拿不到任何文件内容，包括参考包清单。
- 怎么拦（目录权限、进程隔离）不归本契约，本契约只看读的结果。

### 5.8 一致性测试

- 标准答案机对同一个场景、同一份设置出两次参考包，两次的 `color` 通道之差必须不超过它自己填的参考噪声地板。
- 核心帧源的通道声明和参考包的 `channels` 逐项对得上：照输出通道契约（PS）的 PS3 比。
