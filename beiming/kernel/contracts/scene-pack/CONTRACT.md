# 场景包

版本：0.1.0-draft

## 1. 范围

管：

- 场景包的目录布局、场景包清单 `scene-pack/0.1` 的全部字段。
- 几何文件、实例表、每帧状态表这三种二进制文件的形状、列和单位。
- 材质参数和图案节点的登记表。
- 镜像实例怎么标、读入方怎么处理它的法线。
- 包哈希怎么算。
- 判定以上各条用的「场景包核对记录」。

不管：

- 哪个帧源吃场景包、怎么声明：帧源接口契约（F）的 `Caps.input`。
- 坐标系、长度单位、Blender 一侧的换轴：通用口径和帧源接口契约（F）5.1。
- 实体名的写法：镜头契约（S）5.2。实体名的通配：帧源接口契约（F）5.5。
- 实体编号在每帧元数据里怎么出现：每帧元数据契约（M）。
- 实体的角色：片子描述契约（D）。场景包里只有实体名、编号和类别。
- 时间键、帧号、快门：时间键契约（T）。
- 锁文件怎么记包哈希：锁文件契约（LK）。
- 读入场景包之后渲出来的各层的数值口径：输出通道契约（PS）。
- 错误怎么包装、错误码的全表：信封契约（EN）、错误码表契约（ER）。

## 2. 术语

帧、镜头局部帧号、子帧相位、核对记录：见时间键契约（T）第 2 节。实体、实体名：见镜头契约（S）第 2 节。帧源、宿主：见帧源接口契约（F）第 2 节。编号：见每帧元数据契约（M）第 2 节。

| 词 | 含义 |
|---|---|
| 场景包 | 一个目录，装着一个镜头的场景在每一帧的全部求值后的数据：一份场景包清单加若干二进制文件。 |
| 场景包清单 | 场景包里名叫 `pack.json` 的那个文件，结构见 3.2。 |
| 求值后的数据 | 修改器、约束、驱动、脚本都已经算完之后剩下的数：顶点、法线、矩阵、参数。 |
| 修改器 | 建模软件里挂在网格上、渲染前才算的操作，例如倒角、布尔。 |
| 网格 | 几何文件里一组有名字的三角形。 |
| 每角法线 | 按三角形的角给的法线：同一个位置在不同三角形里可以有不同的法线。 |
| 实例 | 把一个网格用一个矩阵摆进场景里的一次使用，对应实例表的一行。 |
| 镜像实例 | 矩阵左上 3×3 的行列式为负的实例。 |
| 叶子实体 | 名字加上 `.` 不是别的实体名的开头的实体。实例表只列叶子实体。 |
| 装配体 | 名字加上 `.` 是别的实体名的开头的实体。它不占实例表的行，由名字前缀推出。 |
| 实例表 | 一张 32 位无符号整数的二进制表，一行一个实例，四列。 |
| 闭包 | 材质的大类：`surface`、`toon`、`emission`、`transparent`。 |
| 图案节点 | 材质里按次序求值的一步运算，用来在参数上叠加圆角、遮蔽、描线这类效果。 |
| 值名 | 图案节点的输出起的名字，供后面的节点引用。 |
| 灯光链接 | 一盏灯只照哪些实体的名单。 |
| 每帧状态表 | 一张 32 位浮点的二进制表，第一维是帧。 |
| 列 | 每帧状态表最后一维里有名字的一段，宽度是 1 个或 16 个数。 |
| 动态网格 | 每一帧都重建的网格，例如粒子面片。 |
| 导出器 | 写出场景包的程序。 |
| 读入方 | 读场景包来渲染的程序。 |
| 包哈希 | 由包里全部文件的路径和内容算出的一个字符串，算法见 5.7。 |
| 场景包核对记录 | 一致性测试把对一个场景包的观测写下来的数据对象，只用来判定不变量；导出器和读入方都不需要产出它。 |

## 3. 结构

### 3.1 目录布局

一个场景包是一个目录。场景包清单必须叫 `pack.json`，放在目录的根上。别的文件叫什么由场景包清单里的路径说了算，路径都从这个目录算起。

| 文件 | 个数 | 内容 |
|---|---|---|
| `pack.json` | 1 | 场景包清单，见 3.2 |
| 几何文件，`.glb` | 1 | 静态网格，见 5.3 |
| 实例表，`.u32` | 1 | 见 3.4 |
| 每帧状态表，`.f32` | 3 或 4 | 见 3.8 |
| 动态网格的文件 | 0 个或更多 | 见 3.9 |

### 3.2 场景包清单 `ScenePack`

顶层对象，`format` 是 `scene-pack/0.1`。本契约里没有可以是 `null` 的字段。

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `format` | 字符串 | 无 | 是 | `scene-pack/0.1` | 格式标识 |
| `id` | 字符串 | 无 | 是 | `pack:<名字>@<版本>`；名字是小写字母、数字、连字符，版本是正整数 | 包的标识 |
| `units` | 对象 | 无 | 是 | 三个键 `meter`、`up`、`hand`；取值由 SP2 管 | 把通用口径原样写一遍 |
| `geometry` | 对象 | 无 | 是 | 见 3.3 | 几何 |
| `instances` | 对象 | 无 | 是 | 见 3.4 | 实例 |
| `materials` | 数组 | 无 | 是 | 至少 1 项，`name` 不重复；每项见 3.5 | 材质 |
| `lights` | 数组 | 无 | 是 | `name` 不重复；每项见 3.6 | 灯；没有灯写空数组 |
| `world` | 对象 | 无 | 是 | 见 3.6 | 背景 |
| `camera` | 对象 | 无 | 是 | 见 3.7 | 相机里不随帧变的部分 |
| `frames` | 对象 | 无 | 是 | 见 3.8 | 每帧状态表 |
| `dynamic` | 数组 | 无 | 否 | 至少 1 项，`name` 不重复；每项见 3.9 | 动态网格 |
| `source` | 对象 | 无 | 是 | 见 3.10 | 这个包是谁、从什么导出的 |
| `ext` | 对象 | 无 | 否 | 键带点分前缀 | 私有数据 |

### 3.3 `geometry`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `file` | 字符串 | 无 | 是 | 相对路径，以 `.glb` 结尾 | 几何文件 |
| `meshes` | 数组 | 无 | 是 | 至少 1 项，`name` 不重复 | 几何文件里的网格，每项见下表；次序就是实例表里的网格下标 |

`meshes[]`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 不空 | 网格名，等于几何文件里那个网格的名字 |
| `tris` | 整数 | 个 | 是 | ≥ 1 | 三角形数 |
| `attrs` | 数组 | 无 | 是 | `position`、`cornerNormal`，不重复；两个都要有由 SP11 管 | 这个网格带哪些顶点属性，见 5.3 |

### 3.4 `instances` 和实例表

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `file` | 字符串 | 无 | 是 | 相对路径，以 `.u32` 结尾 | 实例表 |
| `shape` | 数组 | 无 | 是 | 2 个整数；取值由 SP8 管 | `[实例数, 4]` |
| `names` | 数组 | 无 | 是 | 每项是实体名，写法见镜头契约（S）5.2；写法由 SP19 管 | 第 i 项是实例表第 i 行所属实体的名字；只能是叶子实体，见 5.9 |
| `class` | 数组 | 无 | 是 | 每项是类别，值域见 M 契约 3.3 | 第 i 项是实例表第 i 行所属实体的类别；项数由 SP8 管 |

实例表的四列，都是 32 位无符号整数，行号从 0 起：

| 列 | 是什么 | 单位 | 值域 | 说明 |
|---|---|---|---|---|
| 0 | 网格下标 | 无 | `geometry.meshes` 的下标，从 0 起 | 这个实例用哪个网格 |
| 1 | 材质下标 | 无 | `materials` 的下标，从 0 起 | 这个实例用哪个材质 |
| 2 | 实体编号 | 无 | ≥ 1 | 这个实例属于哪个实体；和每帧元数据里的 `entities[].id`、物体编号层里的像素值是同一个数 |
| 3 | 是否镜像 | 无 | 0、1 | 1 表示镜像实例，见 5.4 |

一个实体可以占多行。行的值域由 SP9 管，编号和名字的对应由 SP10 管，只列叶子实体由 SP14 管，同一个实体各行的 `class` 由 SP15 管。

### 3.5 `materials[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 不空 | 材质名 |
| `closure` | 字符串 | 无 | 是 | `surface`、`toon`、`emission`、`transparent` | 闭包 |
| `params` | 对象 | 无 | 是 | 键只能是下面参数登记表里的名字 | 材质参数 |
| `pattern` | 数组 | 无 | 否 | 至少 1 项；`out` 在同一个材质里不重复 | 图案节点，按数组次序求值，每项见下面的节点登记表 |

参数登记表。名字照 Principled 着色器的输入，改成小驼峰：

| 参数 | 类型 | 单位 | 值域 | 说明 |
|---|---|---|---|---|
| `baseColor` | 数组 | 无 | `[r, g, b]`，每个在 `[0, 1]` | 底色，反射率；场景线性，Rec.709 原色 |
| `metallic` | 双精度 | 无 | `[0, 1]` | 金属度 |
| `roughness` | 双精度 | 无 | `[0, 1]` | 粗糙度 |

`closure` 是 `surface` 时这三个参数都必填。另外三种闭包各用哪些参数：`待定：材质参数登记`。

节点登记表。每个节点是一个对象，`node` 是节点名，其余字段见表，不得有别的字段。词汇照 Cycles 的节点：

| `node` | 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|---|
| `bevel` | `radius` | 双精度 | 米，世界空间 | 是 | > 0 | 圆角半径 |
| | `samples` | 整数 | 次 | 是 | ≥ 1 | 采样数 |
| | `out` | 字符串 | 无 | 是 | `normal` | 算出把棱边磨圆之后的法线，替换着色法线 |
| `ao` | `distance` | 双精度 | 米，世界空间 | 是 | > 0 | 遮蔽的探测距离 |
| | `samples` | 整数 | 次 | 是 | ≥ 1 | 采样数 |
| | `onlyLocal` | 布尔 | 无 | 是 | | `true` 时只算这个实例自己对自己的遮蔽 |
| | `out` | 字符串 | 无 | 是 | 值名 | 遮蔽系数，无单位，`[0, 1]`，1 是完全没被遮 |
| `smoothstep` | `in` | 字符串 | 无 | 是 | 值名 | 输入 |
| | `edges` | 数组 | 无 | 是 | `[e0, e1]`，`e0 < e1` | 两个阈值，和输入同一个量纲 |
| | `out` | 字符串 | 无 | 是 | 值名 | 输出，无单位，`[0, 1]`，算法见 5.6 |
| `mix` | `by` | 字符串 | 无 | 是 | 值名 | 混合系数 |
| | `set` | 对象 | 无 | 是 | 至少 1 个键；键是参数登记表里的名字，值照那个参数的类型和值域 | 往哪组参数值上混，算法见 5.6 |

值名是小写字母开头的字母和数字。`normal` 这个名字只能当 `bevel` 的 `out`。`in` 和 `by` 指向谁由 SP13 管；出现登记表之外的节点名，导出方由 SP5 管，读入方由 SP17 管。

### 3.6 `lights[]` 和 `world`

`lights[]`，次序就是灯表里灯的下标：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 不空 | 灯的名字 |
| `type` | 字符串 | 无 | 是 | `area-rect`、`point`、`sun` | 矩形面光、点光，或平行光 |
| `size` | 数组 | 米 | `type` 是 `area-rect` 时必填，别的类型不得出现 | `[宽, 高]`，都 > 0 | 发光面的尺寸，方向见 5.1 |
| `watts` | 双精度 | 瓦 | `type` 是 `sun` 时不得出现，别的类型必填 | ≥ 0 | 功率，口径见 5.5 |
| `dir` | 数组 | 无 | `type` 是 `sun` 时必填，别的类型不得出现 | `[x, y, z]`，长度和 1 的差不大于 0.000001 | 指向光来的方向的单位向量，世界坐标。`sun` 没有位置 |
| `irradiance` | 双精度 | 瓦每平方米 | `type` 是 `sun` 时必填，别的类型不得出现 | ≥ 0 | 垂直于光线的面上收到的辐照度，口径见 5.5 |
| `color` | 数组 | 无 | 是 | `[r, g, b]`，每个 ≥ 0 | 灯色，乘在功率或辐照度上的系数；场景线性，Rec.709 原色 |
| `visibleToCamera` | 布尔 | 无 | 是 | | 相机能不能直接看见这盏灯的发光面 |
| `link` | 数组 | 无 | 否 | 至少 1 项；每项是实体名，或带通配的实体名（写法见 F 契约 5.5）；写法由 SP19 管 | 灯光链接：这盏灯只照名单里的实体。不出现表示照全部实体。不带通配的一项只和同名的叶子实体相配；装配体必须写成 `前缀.*`，装配体的本名不匹配它下面的叶子实体 |
| `group` | 字符串 | 无 | 否 | 小写字母、数字、连字符，以字母或数字开头 | 分灯组名，输出通道契约（PS）的 `lightgroup:<名>` 取它。不出现时组名就是灯名，这时 `name` 必须符合同一种写法 |

`type` 是 `sun` 的灯在灯表里仍占一行，读入方不读这一行，方向只看 `dir`。这一行写什么：`待定：sun 在灯表里的那一行`。

`world`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `color` | 数组 | 辐亮度，和 Cycles 世界色乘强度之后的数同一个口径 | 是 | `[r, g, b]`，每个 ≥ 0 | 背景朝场景里发的光；场景线性，Rec.709 原色 |
| `visibleToCamera` | 布尔 | 无 | 是 | | 相机能不能直接看见背景色 |

### 3.7 `camera`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `type` | 字符串 | 无 | 是 | `persp`、`ortho` | 透视，或正交 |
| `near` | 双精度 | 米 | 是 | > 0 | 近裁剪面 |
| `far` | 双精度 | 米 | 是 | 大于 `near` | 远裁剪面 |
| `sensorHeight` | 双精度 | 米 | 相机表带 `focusDist`、`fstop` 两列时必填，由 SP16 管；不带时可以出现 | > 0 | 传感器高度，算景深用，见 5.11 |

相机随帧变的部分在 3.8 的相机表里。

### 3.8 `frames` 和每帧状态表

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `count` | 整数 | 帧 | 是 | ≥ 1 | 这个包有几帧 |
| `instances` | `Table` | 无 | 是 | `fields` 正好是 `["mat16"]` | 实例表每一行在每一帧的矩阵 |
| `camera` | `Table` | 无 | 是 | `fields` 必须有 `mat16`、`fovY`；`focusDist`、`fstop` 要么都有，要么都没有 | 相机每一帧的状态。没有 `focusDist`、`fstop` 表示不做景深；有这两列时 `camera.sensorHeight` 必须出现（SP16） |
| `lights` | `Table` | 无 | 是 | `fields` 必须有 `mat16`，可以有 `watts` | 每盏灯在每一帧的状态 |
| `materials` | `Table` | 无 | 否 | `fields` 的词汇：`待定：材质逐帧表的列` | 材质参数在每一帧的值 |

`Table`：

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `file` | 字符串 | 无 | 是 | 相对路径，以 `.f32` 结尾 | 这张表的文件 |
| `shape` | 数组 | 无 | 是 | 2 个或 3 个整数，每个 ≥ 0；取值由 SP8 管 | 各维的大小，第一维是帧 |
| `fields` | 数组 | 无 | 是 | 至少 1 项，不重复 | 最后一维里依次排着哪些列 |

三张表的形状：

| 表 | `shape` | 第 k 帧里的一行说的是 |
|---|---|---|
| `instances` | `[count, 实例数, 列宽]` | 实例表的一行 |
| `camera` | `[count, 列宽]` | 相机 |
| `lights` | `[count, 灯数, 列宽]` | `lights` 里的一盏灯 |

列的登记表：

| 列 | 宽度 | 单位 | 用在哪张表 | 值域 | 说明 |
|---|---|---|---|---|---|
| `mat16` | 16 | 平移分量是米，其余无单位 | `instances`、`camera`、`lights` | 第 4、8、12 个数是 0，第 16 个数是 1 | 这个东西自己的坐标到世界坐标的矩阵，列主序 |
| `fovY` | 1 | 弧度 | `camera` | `(0, π)` | 垂直视场角 |
| `focusDist` | 1 | 米 | `camera` | > 0 | 对焦距离 |
| `fstop` | 1 | 无 | `camera` | > 0 | 光圈值 |
| `watts` | 1 | 瓦 | `lights` | ≥ 0 | 这一帧的功率，口径见 5.5 |

### 3.9 `dynamic[]`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `name` | 字符串 | 无 | 是 | 不空 | 动态网格的名字 |
| `files` | 字符串 | 无 | 是 | 不空；写法 `待定：动态网格的文件命名` | 每帧一个文件，这里写它们的路径 |

### 3.10 `source`

| 字段 | 类型 | 单位 | 必填 | 值域 | 说明 |
|---|---|---|---|---|---|
| `exporter` | 字符串 | 无 | 是 | `<名字>@<版本>`，两段都不空 | 导出器和它的版本，例如 `sources/blender@0.1` |
| `blender` | 字符串 | 无 | 是 | 不空 | 导出时用的 Blender 的版本号 |
| `sha256` | 字符串 | 无 | 是 | 64 位小写十六进制 | 导出时读的那个源场景文件内容的 SHA-256 |

### 3.11 场景包核对记录

顶层对象，`format` 是 `scene-pack-check/0.1`。一份记录说一个场景包。记录里出现哪一段，就判哪几条不变量；没出现的段不判。只看场景包清单就能判的不变量（SP2 的 `units`、SP5 的节点名、SP8 的形状、SP11、SP12、SP13、SP14、SP15、SP16）对单独的一份场景包清单也照判。`loads` 至少有 1 项的记录是拿来测读入方的：它的清单里出现登记表之外的节点名只归 SP17，SP5 不判这份记录。观测了、结果是空的写空数组；没观测的段不出现。

## 5. 口径

### 5.1 坐标和矩阵

- 长度、坐标系、相机朝向照通用口径。从 Blender 导出时的换轴照帧源接口契约（F）5.1，包里的全部坐标、法线、矩阵都是换过之后的。
- 矩阵是 16 个数，列主序：前四个数是第一列。它把这个东西自己坐标里的点变到世界坐标，第 13 到 15 个数是它在世界里的位置。这和每帧元数据契约（M）5.1 是同一种写法。
- 实例的矩阵作用在网格自己的坐标上。相机的矩阵就是每帧元数据里的 `camera.world`。
- `sun` 不看矩阵，光从 `dir` 指的方向来。别的灯朝自己的 −Z 发光。矩形面光的发光面在自己的 XY 平面上，`size` 的宽沿 X，高沿 Y。

### 5.2 二进制表

- 实例表是 32 位无符号整数，每帧状态表是 IEEE 754 的 32 位浮点，都是小端。
- 多维的表按行主序排：最后一维变得最快。文件里只有数，没有文件头，所以文件的字节数等于 `shape` 各项之积乘以 4。
- 表里不得出现 `NaN` 和无穷。
- 每帧状态表第一维的下标 k 就是镜头局部帧号 k，这一行是 `{ frame: k, sub: 0 }` 这一时刻的状态。

### 5.3 几何文件

- 几何文件是 GLB，也就是 glTF 2.0 的二进制写法。场景包清单里的一个网格是文件里一个同名的网格，只有一个三角形图元。
- `attrs` 的词和 glTF 属性的对应：`position` 是 `POSITION`，单位米，网格自己的坐标；`cornerNormal` 是 `NORMAL`，无单位，长度是 1。
- 每角法线写进文件时，同一个位置上法线不同的角拆成不同的顶点。
- 在网格自己的坐标里，一个三角形的三个顶点 p0、p1、p2 逆时针排着的那一面是正面，`(p1 − p0) × (p2 − p0)` 指向正面。
- 读入方只按名字读网格。文件里的节点变换、材质、相机、灯都不算数：摆放只看每帧状态表，材质只看场景包清单。

### 5.4 镜像实例

- 行列式：矩阵的 16 个数记作 m1 到 m16，左上 3×3 的行列式等于 `m1 × (m6 × m11 − m7 × m10) − m5 × (m2 × m11 − m3 × m10) + m9 × (m2 × m7 − m3 × m6)`。把表里的 32 位浮点原样拿来按双精度算，不加容差；行列式等于 0 的那一帧 SP3 不判，不管九个数是不是全是 0。
- 位置用矩阵直接变。每角法线用左上 3×3 的余子式矩阵去变，行列式为负时再取反，然后归一化。余子式矩阵第 i 行第 j 列的数，是左上 3×3 去掉第 i 行和第 j 列之后剩下的 2×2 的行列式，乘以 −1 的 (i + j) 次方。
- 缩放三个分量全是 0（左上 3×3 的九个数全是 0）的那一帧，读入方不画这个实例。
- `raw` 的算法：把三角形的三个顶点变到世界坐标得到 q0、q1、q2，`raw = (q1 − q0) × (q2 − q0)`。
- 行列式为正时，`raw` 和变过去的每角法线在同一侧。行列式为负时，`raw` 落到另一侧，读入方必须把它取反再用，或者等价地把顺时针的那一面当正面。
- 写进条文的反例。网格里有一个三角形 p0 = (0, 0, 0)，p1 = (1, 0, 0)，p2 = (0, 1, 0)，三个角的法线都是 (0, 0, 1)。实例的矩阵把 x 取反，别的不动：左上 3×3 是对角线 (−1, 1, 1)，行列式是 −1。变过去之后 q0 = (0, 0, 0)，q1 = (−1, 0, 0)，q2 = (0, 1, 0)，`raw = (0, 0, −1)`；余子式矩阵是对角线 (1, −1, −1)，每角法线乘过去是 (0, 0, −1)，行列式为负，取反之后还是 (0, 0, 1)。两个方向相反。这时候第四列写成 0（违反 SP3），或者第四列是 1 而读入方没有取反（违反 SP7），这个面都会被当成背面：正对相机的面被剔掉，或者按背面来照明，镜像的那一半发黑。合法的做法是第四列写 1，读入方用 `used = (0, 0, 1)`。

### 5.5 功率

- 包里的功率就是源场景里那盏灯的功率，单位瓦。导出器只换轴，不乘也不除。
- 功率换成辐亮度由读入方做，照 Cycles 的口径。换算之后两边差多少：`待探针：同一盏矩形面光、同一个功率下核心帧源和 Cycles 的画面亮度比`。
- `sun` 没有功率。`irradiance` 就是源场景里那盏灯的强度，单位瓦每平方米，导出器同样不乘也不除。
- 灯表有 `watts` 列时，每一帧的功率取表里的值；没有这一列时，每一帧都取场景包清单里的 `watts`。

### 5.6 图案节点怎么求值

- 一个材质的图案节点照数组次序依次求值，每个着色点各算一遍。
- `smoothstep`：输入记作 x，`t = (x − e0) ÷ (e1 − e0)` 再夹到 `[0, 1]`，输出是 `t × t × (3 − 2 × t)`。
- `mix`：`set` 里列的每个参数，结果等于 `(1 − by) × params 里的值 + by × set 里的值`；`set` 里没列的参数不动。
- 读入方不认识的节点名照 SP17 报错。节点名认识、字段不对的，是结构非法。

### 5.7 包哈希

1. 包目录里的每个文件（包括 `pack.json`）各算一个 SHA-256，写成 64 位小写十六进制。
2. 把文件按路径的 UTF-8 字节序从小到大排。
3. 每个文件写一行：哈希、两个空格、路径、换行符（`\n`）。
4. 对这段文本的 UTF-8 字节算 SHA-256，前面加上 `sha256:`，就是包哈希。

「逐位相同」指两个包哈希作为字符串完全相等。要让读入再写出之后哈希不变，写出方必须是确定的：同样的内容写出同样的字节。

### 5.8 读每帧状态

- `single`：新开一次读取，只读这一帧。`shuffled`：把一批帧打乱次序读。`sequential`：按帧号从小到大读。`repeat`：同一次读取里把这一帧再读一遍。
- `digest` 是读到的这一帧在这张表里的全部字节的 SHA-256，写法照通用口径。
- 这四种读法都是测试工具自己读表文件：照 5.2 的排法从 `shape` 算出这一帧在文件里的字节范围，读出来算摘要。不经过读入方，也不取读入方的说法。
- 表里只有数，没有表达式和代码。读入方不得用前一帧的结果去改后一帧读到的值；这一句对读入方现在只有声明，没有判定，见第 6 节。

### 5.9 实体

- 实例表里的实体编号和 `instances.names`，就是帧源的实体清单（F 契约 3.6）和每帧元数据（M 契约 3.3）里的编号和名字；`instances.class` 就是那里的 `class`。编号从哪来、在多大范围里有意义、没有场景包的镜头怎么编号，只在 F 契约 3.6 定：镜头由场景包描述时，那里以这张实例表为准。
- 实例表只列叶子实体。装配体不占行，由名字前缀推出：一个名字去掉最后若干个点分段得到的每个前缀，都是它所属的一个装配体，例如 `kit.arm.bolt` 属于装配体 `kit.arm` 和 `kit`。
- 物体编号层的一个像素写的是叶子实体的编号。一个装配体占哪些像素，照每帧元数据契约（M）5.3 由名字前缀算。
- 一个叶子实体可以由多个实例组成，这些行的实体编号相同、实体名相同、`class` 相同。
- 实体的角色不进场景包，由片子描述给（片子描述契约 D）。

### 5.10 一致性测试

- 导出、读入、再写出，包哈希相同（SP6）。
- 例子 `examples/part.json` 这个包能被吃场景包的帧源读入并渲出一帧。

### 5.11 景深

- 相机表不带 `focusDist`、`fstop` 两列表示不做景深，镜头孔径按 0。
- 带这两列时，镜头孔径的直径 = `sensorHeight` ÷ (2 × tan(`fovY` ÷ 2)) ÷ `fstop`，单位米；`fovY` 用弧度。式子的前半段 `sensorHeight` ÷ (2 × tan(`fovY` ÷ 2)) 是焦距。
