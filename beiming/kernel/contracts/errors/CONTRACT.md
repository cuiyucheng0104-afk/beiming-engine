# 错误码表

版本：0.1.0-draft

## 1. 范围

管：

- 错误码表 `errors/0.1` 的结构。表本身是数据，放在本目录的 `errors.json`。
- 错误码的写法。
- 前缀对哪个退出码。
- 新错误码怎么加。

不管：

- 错误码写在返回的哪个字段：信封契约（EN）。
- 每个错误码在什么情况下报：点名它的那份契约。本表只登记名字和一句话含义。
- 修订号对不上时怎么拒：D6。

## 2. 术语

| 词 | 含义 |
|---|---|
| 错误码 | 一种错误的稳定名字，点分小写，例如 `busy.rev-conflict`。 |
| 前缀 | 错误码从开头到第一个 `.`（含）的那一段，例如 `busy.`。 |
| 退出码 | 一次调用结束时交回的整数，0 是成功。 |
| 错误码表 | 全系统登记前缀和错误码的唯一一张表。 |

## 3. 结构

错误码表的任何一层都不得出现本节没列的键。

### 3.1 错误码表

顶层对象，`format` 是 `errors/0.1`。

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `format` | 字符串 | 是 | `errors/0.1` | 格式标识 |
| `prefixes` | 数组 | 是 | 每项见 3.2 | 前缀对退出码 |
| `codes` | 数组 | 是 | 每项见 3.3；可以是空数组 | 登记过的错误码 |
| `ext` | 对象 | 否 | 键带点分前缀 | 私有数据 |

### 3.2 `prefixes[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `prefix` | 字符串 | 是 | 小写字母加一个 `.` | 前缀 |
| `exitCode` | 整数 | 是 | 1 到 255 | 这个前缀的错误码对到的退出码 |
| `meaning` | 字符串 | 是 | 不空 | 这一类错误是什么 |

### 3.3 `codes[]`

| 字段 | 类型 | 必填 | 值域 | 说明 |
|---|---|---|---|---|
| `code` | 字符串 | 是 | 写法见 5.2 | 错误码 |
| `meaning` | 字符串 | 是 | 不空 | 一句话含义 |

## 4. 不变量

| 编号 | 条文 | 怎么查 | 反例文件 |
|---|---|---|---|
| ER1 | 每个错误码必须以 `prefixes` 里某一项的 `prefix` 开头。 | 逐个 `code`：`prefixes` 里有一项的 `prefix` 是它的开头 | `ER1-code-without-prefix.json` |
| ER2 | `prefixes` 必须正好是 5.1 表里的七项，前缀和退出码都相同。 | 两边按 `prefix` 对：项数相等，每个 `prefix` 两边都有，`exitCode` 相等；次序不看 | `ER2-busy-maps-to-4.json` |
| ER3 | `codes` 里的 `code` 不得重复。 | 没有两项的 `code` 逐字符相同 | `ER3-duplicate-code.json` |

## 5. 口径

### 5.1 前缀对退出码

| 前缀 | 退出码 | 含义 |
|---|---|---|
| `usage.` | 2 | 用法错误 |
| `env.` | 3 | 环境或依赖缺失、不合格 |
| `contract.` | 4 | 契约、验收或闸门不通过 |
| `busy.` | 5 | 资源忙 |
| `timeout.` | 124 | 超时 |
| `failure.` | 1 | 运行失败 |
| `auth.` | 4 | 没有权限做这次写入 |

七个前缀互不为前缀，所以一个错误码最多对到一项。`auth.` 和 `contract.` 对到同一个退出码；要分开两类，看错误码的前缀。退出码只由前缀决定，表里不给单个错误码另记退出码。

### 5.2 错误码的写法

两段以上，用 `.` 连接；每一段是小写字母、数字、连字符，不以连字符开头或结尾。第一段加 `.` 是前缀。例：`contract.unknown-key`、`busy.rev-conflict`。

### 5.3 现在登记的码

| 错误码 | 含义 | 哪条条文点名的 |
|---|---|---|
| `auth.base-readonly` | 服务器之外的一方写 `predicates.base` | D7 |
| `busy.rev-conflict` | 写入带的修订号和服务器当前的修订号不同 | D6 |
| `contract.bad-path` | 写入路径不合片子描述契约（D）5.4：按下标寻址、写进数组项、指到叶子下面；某一段不是契约定义的键时报 `contract.unknown-key`，不报这个码 | D5 |
| `contract.immutable-key` | 改了创建之后不得改的键 | D15 |
| `contract.output-conflict` | 开着原生运动模糊时要了和它冲突的输出 | F5 |
| `contract.order-cycle` | 卡的先后要求排不出次序：成环，或提到了镜头里没有的卡 | CR 契约 5.2（CR9 不比码） |
| `contract.patch-not-applicable` | 补丁里有一个操作不可作用 | PA 契约 5.3（PA4 不比码） |
| `contract.runtime-shadows-param` | `ctx.cards.use` 的 `runtime` 里有键和这张卡声明的参数同名 | 镜头契约（S）管 `ctx.cards.use` 的那条不变量 |
| `contract.shutter-conflict` | 快门角是 0 而子帧采样数大于 1 | 帧源接口契约（F）管快门的条文 |
| `contract.undeclared-card` | `ctx.cards.use` 用了这个镜头的 `cards` 里没声明过的实例名 | 镜头契约（S）管 `ctx.cards.use` 的那条不变量 |
| `contract.unknown-key` | 出现了契约没定义的键 | 契约写法约定通用口径「未知字段」一行 |
| `contract.unknown-node` | 场景包里出现了节点登记表之外的图案节点 | SP17 |
| `contract.unsupported-input` | 镜头输入里有帧源装不了的卡、资产或叠加层 | F26 |
| `contract.unsupported-mode` | 镜头条目的宿主或作者模式不在帧源的能力声明里 | F16 |
| `contract.unsupported-object` | 场景里有对象放不进这次要的某个输出 | F19 |
| `contract.unsupported-option` | `RenderOpts` 给了帧源交不出的每像素采样数或缩放 | F18 |
| `contract.unsupported-output` | 要了帧源没声明过的输出 | F3 |
| `contract.unsupported-query` | 问了帧源没声明过的场景查询种类 | F8 |
| `env.lock-required` | 没有锁文件，镜头却要用只有锁文件里才有的东西 | F14 |
| `usage.bad-argument` | 调用的参数出了值域 | F23 |

### 5.4 新错误码怎么加

别的契约的条文里要点名一个新错误码，先提变更单把它加进 `errors.json`，再写条文。没登记的码不得出现在信封里（EN4）。

### 5.5 `contract.unknown-key` 的诊断

报这个码的诊断，`at` 写那个没定义的键的路径。能找到最接近的键时，`hint` 写出它，并带一条 `op` 是 `rename`、`applicability` 是 `machine` 的修法；找不到时不带修法。

## 6. 待定

| 项 | 现在怎么写 | 等什么 |
|---|---|---|
| `failure.` 对 1 | 需求来源只列了五个前缀；仓库里现有的做法是别的码一律对 1。【起草者补】把它写成第六个前缀 `failure.`，这样每个码都有前缀 | 集成负责人确认 |
| `auth.` 对 4 | 【起草者补】新增的第七个前缀。没有另起退出码，和 `contract.` 一样对 4（被拒的写入），信封的 `exitCode` 值域不用变；要另起一个退出码时改 5.1、`errors.json`、本目录 `check.mjs` 里抄的那份前缀表和信封契约 3.1 | 集成负责人确认 |
| 中断信号的两个码和退出码 130、143 | 现有命令行有；本表不收 | 命令行外壳起草时定 |
| `timeout.` 带不带点 | 现有实现匹配的是不带点的 `timeout`；照需求来源写成 `timeout.` | 集成负责人确认 |
| 「别的契约点名的码都在表里」 | 写在 5.4，没有立成不变量：要扫全部契约的条文才能判 | 集成负责人定要不要加静态扫描的门 |
| 「最接近的键」怎么算 | 不定；现有命令行用的是带换位的编辑距离，差太多就不提示 | 集成负责人确认 |
| 每个码要不要记是哪份契约点名的 | 【起草者补】不记在数据里，只写在 5.3 | 集成负责人确认 |
| `codes` 要不要按 `code` 排序 | 不要求 | 集成负责人确认 |
| `usage.bad-argument` 由哪条条文点名 | 已定：帧源接口契约的 F23。它只管 `render`、`query` 的参数，值域的表在那份契约的 5.13；别的调用的参数出值域报什么，那份契约的第 6 节挂着 | 已定 |
| 帧源装不了卡、资产、叠加层时用哪个码 | 已定：三样共用一个码 `contract.unsupported-input`，由帧源接口契约的 F26 点名。帧源不得少装一样照常出帧：那样上层看到的是一张缺东西却「成功」的帧，换不了帧源，也查不出原因。没有借用 `contract.unsupported-mode` 或 `contract.unsupported-option`，借用之后两种失败在记录里分不开 | 已定 |
