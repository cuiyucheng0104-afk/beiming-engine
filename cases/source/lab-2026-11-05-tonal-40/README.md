# 北冥引擎 · 色阶实验 01

**40 个配色与色阶组合，全部在 RTX 5090 上渲染。**

打开 [离线对比页](delivery/index.html)，或直接看 [40 版总览](delivery/40版总览.jpg)。每个编号同时有 2400 × 1350 的远景和近景 PNG；模型、参数、源代码均保留。

## 本轮的素材与范围

用户提供九张东方山水、楼阁、人物与烛光参考。本轮选第 4 张的楼阁作为三维主资产，其余图片用于判断青灰暗部、暖金受光、雾中层次和舟船尺度。此轮集中校准楼阁山水；人物脸部、衣料和室内烛光需在下一组资产上验证。

- `refs/01.jpg` 至 `09.jpg`：原始参考的原样副本，校验值见 `refs/manifest.json`。
- TRELLIS.2 输入：`models/trellis_input.png`，由现有工作站的 BiRefNet 去背景、CropToMask 得到。
- 原始生成约 2,367 万面；RemeshMesh(udf) → DecimateMesh 后，展示模型为 **248,723 个三角面**。完整生成记录执行时间 **115.4 秒**，包含首次模型装载等开销，不能当作纯推理耗时。
- `models/pavilion_vc.glb` 为顶点色版；`models/pavilion_tex.glb` 为贴图版。本轮渲染使用顶点色版。
- 山体、松树、小村落、舟船、人形与飞鸟为程序几何；水面使用真实平面反射，天空为程序渐变。

## 40 版如何组织

8 行配色 × 5 列色阶。**一个场景、一份楼阁模型、固定光向、固定机位、固定随机种子 1105。** 没有为每版重新生成模型。

| 行 | 配色 |
|---|---|
| A | 黛青鎏金 |
| B | 月白青瓷 |
| C | 松烟赭石 |
| D | 石青石绿 |
| E | 朱砂玄墨 |
| F | 雾紫霞金 |
| G | 宣纸淡墨 |
| H | 夜蓝灯火 |

| 列 | 名称 | 光照分界 | 羽化宽度 | 档位亮度 |
|---|---|---|---|---|
| 1 | 二阶硬切 | 0.54 | 0.012 | 0.12 / 1 |
| 2 | 三阶硬切 | 0.34 / 0.66 | 0.015 | 0.08 / 0.48 / 1 |
| 3 | 三阶柔边 | 0.34 / 0.66 | 0.11 | 0.08 / 0.48 / 1 |
| 4 | 四阶叠色 | 0.24 / 0.48 / 0.73 | 0.035 | 0.06 / 0.29 / 0.61 / 1 |
| 5 | 六阶塑形 | 0.16 / 0.31 / 0.47 / 0.64 / 0.81 | 0.065 | 0.04 / 0.18 / 0.35 / 0.55 / 0.77 / 1 |

横向比较时，材质配色、描边、纸纹不变，只改上述光照分阶。纵向比较同时改变配色及与该配色绑定的少量描边、纸纹参数，因此不是纯粹的单色相测试。

色阶数量约束的是**表面明暗函数**；贴图、空气透视、波纹、反射、抗锯齿会继续带来连续颜色。因此“二阶”不等于整张图只有两个颜色。

## 三维与着色实现

引擎基于 `@@WORKSPACE_ROOT@@/beiming-engine` 的 a65c172 源码快照，three.js r170。原仓库和原样片未修改。

- `lab/material.js`：使用北冥 `toonKind` 扩展多档色阶家族。第一盏平行光的方向、真实投影决定入射亮度，再按阈值、羽化和档位亮度混合固有色。
- AI 模型原有颜色含烘焙光照。本轮按源颜色分区重映射到屋瓦、山石、植被、木料与墙面色板，压缩原亮度变化。**这是美术性的压光处理，不是物理反照率恢复**。
- `lab/scene.js`：搭景、程序几何、GLB 加载、固定相机、阴影、反射、描边与后期。
- `lab/presets.js`：40 个组合的唯一参数来源；`delivery/presets.json` 为此次实际渲染使用值。
- 北冥 `engine/look`：深度/ID 描边、很轻的 Kuwahara、纸纹与颗粒。后期没有对整张输入参考做色阶滤镜。

GPU 核验字符串：`ANGLE (NVIDIA, Vulkan 1.4.357 (NVIDIA NVIDIA GeForce RTX 5090 (0x00002B85)), NVIDIA)`。主图与近景日志分别在 `out/renders/render-log.json`、`out/detail/render-log.json`。

本轮没有使用光线追踪、DLSS 或 RTX VSR。5090 承担 TRELLIS.2 的 CUDA 推理及 WebGL 经 Vulkan 的实际渲染。

Windows 工程：`D:\北冥\experiments\tonal-40`，ASCII 兼容路径 `D:\beiming\experiments\tonal-40`。

在已有依赖的工作站中重渲：

```powershell
$env:BEIMING_CHROME = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:BEIMING_ANGLE = 'vulkan'
node tools/render-grid.mjs
node tools/render-grid.mjs --detail
```

批量脚本检查 GPU 字符串、捕捉 GLSL 编译失败，并输出无损 PNG。PNG 数量、分辨率、唯一哈希及色阶差异见 `delivery/verification.json`。图册脚本仅缩放、编排已有渲染图，不修改主图。

另外提供 `delivery/五套色阶_光照校准.jpg`：同一中性球体，关闭雾、反射和后期，验证表面明暗分阶。A2 近景在两个独立 Chrome 进程中的输出 SHA-256 完全相同。大远景中的天空、雾与水面占比较高，横向色阶差异比校准球和近景细微，这是观看时应区分的因素。

## 当前结论与边界

这 40 版是**可复现的配色/色阶候选**，用于筛选下一步的美术方向，尚不是 40 套经过全片运动验证的完整画风系统。

侧面和背面检查确认楼阁是立体网格；背面墙体的结构简化、窗棂的软化和部分不规则轮廓仍然可见。图生 3D 的几何缺陷不会靠换色阶消失；近景制作还需修模。

这次没有把九张参考逐张复刻。选定候选后，应保留同一套参数，换入人物、烛光静物和另一处山水，检验跨资产一致性，再做短运动测试。

原始参考与本地实验成果未发布到公共仓库。
