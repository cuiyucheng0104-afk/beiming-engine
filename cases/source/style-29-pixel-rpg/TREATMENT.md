# 宝箱怪 · TREATMENT

风格：16-bit 像素 RPG（pixel-rpg）· 1920×1080（原生 320×180，×6 最近邻）· 24 fps · 19.58 s · 无旁白无字幕，文字只出现在游戏 UI 里。

## 0. 三个候选结构

1. **单线旅程**：勇者一路走进地牢 → 宝箱怪伏击 → 战斗 → 对话 → 升级。线性、好读，节拍点最清楚。
2. **两次开箱（前后对照）**：开头勇者开箱被咬（失败），读档重来，第二次选“对话”——用存档当记忆。概念巧，但 15–20 秒装不下两遍，且“读档”会抢掉“对话”这个转折。
3. **菜单即剧本**：整片锁在战斗画面里，所有剧情都由系统消息和菜单讲（极简）。原生，但开头缺“走向宝箱”的空间感，主体太小、运镜单调。

**选 1，并借 3 的手法**：故事线性推进，转折段完全交给 UI（光标停、系统消息“它在发抖…”、对话框、EXP 条），结尾回到开头的地牢横版，勇者身后多了一个蹦跳的宝箱——首尾呼应：独行 → 同行。

## 1. Logline 与弧线

一个勇者被宝箱怪伏击，光标停在“攻击”上犹豫了一拍，最后选了“对话”——发抖的宝箱怪害羞地吐出一把钥匙，勇者升级的不是力量，是友情。

- 建置：地牢、宝箱、金色的诱惑（金色 = 保护色，全片的线）。
- 转折：战斗菜单。系统消息说“它在发抖…”，光标停止跳动，一格一格移到“对话”。全静。
- 结局：心跳一声、脸红（粉色 = 第二个保护色），吐钥匙，EXP 条涨满前再静一拍 → LEVEL UP；结尾两人同行。

## 2. 对标

- **对标**：90 年代中期主机 RPG 的系统语法（遇敌漩涡、侧视战斗、指令菜单、系统消息、获得道具的号角、升级画面）；独立游戏里“可以和怪物对话”的那种温柔设计（作为语法：菜单选项本身就是道德选择）。
- **学**：UI 即叙事（光标停顿=犹豫）、遇敌转场的节奏（音效先于画面）、战斗曲 144 BPM 驱动感、升级号角当标点、调色板即情绪（脸红用调色板换色而不是叠透明）。
- **不学**：任何现成游戏的角色、UI 边框、字体、旋律、音效、怪物设计；不出现任何游戏名或商标。宝箱怪、勇者、菜单框、像素字体、所有旋律都原创。

## 5. Cue map

- **A 段 地牢**：96 BPM，3/4 拍，1 拍 = 0.625 s = **15 帧**。2 小节（6 拍），0.000–3.750。小调华尔兹：三角波贝斯、12.5% 方波琶音、25% 方波稀疏旋律，SNES 式回声。
- **B 段起 144 BPM，4/4**，1 拍 = 0.41667 s = **10 帧**，1 小节 = 40 帧。小节 0 下拍 = 3.750（咬合）。
  - 小节 0（3.750）：咬合刺音；拍 1–3 遇敌漩涡 + 鼓加花。
  - 小节 1（5.417）：战斗曲全编制（50% 方波主旋律、三角波 8 分贝斯、LFSR 噪声鼓、wavetable 和声）。
  - 小节 2（7.083）：光标出现，战斗曲第二句。
  - 小节 3（8.750）：抽层（鼓、旋律、和声逐拍离开）；拍 1、2 光标音；拍 3（10.000）确认音。
  - 小节 4（10.417）：静默贯穿至拍 2（11.250）心跳；拍 3（11.667）起文字音。
  - 小节 5（12.083）：友情主题（关系大调），八音盒/钢片琴 + 三角波半速；拍 2（12.917）接钥匙道具号角。
  - 小节 6（13.750）：渐强：8 分 EXP 滴答 + 军鼓 8 分 + 方波上行琶音；**拍 3（15.000）切到真零**。
  - 小节 7（15.417）：LEVEL UP 号角（采样小号+圆号经 SNES 32 kHz 低通/8-bit 处理 + 方波 + 定音鼓 + 噪声镲）。
  - 小节 8（17.083）：号角第二句；拍 2（17.917）马赛克切回地牢，下行琶音。
  - 小节 9（18.750）：主和弦收束，回声尾巴 0.8 s 内自然到零。
- **为什么是 144 而不是分镜写的 150 BPM**：24 fps 下 150 BPM 的一拍 = 9.6 帧，不是整帧。要么画面事件四舍五入到最近帧（每拍最多偏 17 ms，违背“0 ms 卡拍”），要么用 10/10/9/10/9 帧交替的拍网格（拍长在 375 ms 与 417 ms 之间来回跳，±5% 的抖动在 16 分军鼓上听得出来）。144 BPM = 一拍正好 10 帧，所有剪切、动作、文字落定和音乐起音都能落在同一个整帧网格上，速度只比分镜慢 4%，听感仍是同一档“战斗曲”。这是有意的偏离。
- **速度变化**：96（3/4）→ 144（4/4）的明显加速发生在咬合那一拍；转折段的抽层 + 静默是减速；EXP 段 8 分滴答是再次加速。

## 7. 画面内文字设计（无字幕）

- 对话框 = 字幕：底部 1/4，圆角三层边（墨 / 白 / 银），深蓝 Bayer 抖动底，左侧 32×32 头像；中文像素字（Noto Sans SC 子集化后在帧缓冲内二值化，1 px 阴影）；打字时有文字音，完成后 ▼ 闪。
- 战斗/系统消息：顶部细窗。菜单：左下“攻击 / 魔法 / 对话 / 逃跑”，手形光标。
- 拉丁与数字（HP、Lv、EXP、LEVEL UP!）：自绘原创 5×7 可变宽像素字。LEVEL UP! 为 2× 大字，8 邻域墨描边、逐行渐变。
- 所有文字的停留时长都过 readcheck（中文字 ÷ 4.5 + 1.5 s）。

## 8. 保护色

- **金（钥匙/宝箱金边）**：不受任何调色板效果影响；开头是诱惑，中段是礼物，高潮时金色以抖动波淹没画面。
- **粉（脸红/爱心）**：只在宝箱怪害羞时出现，结尾的心是它的回声。

## 10. 制作中的修订

- 漩涡第一帧：画面原本要到第 101 帧才动，改成在 100 帧白闪（调色板 3 阶退回：75% → 50% → 25%）同时开始扭转，与鼓加花同拍。
- 战斗入场：白 → 画面的 Bayer 溶解从 4 帧缩到 2 帧，画面最大变化落在战斗曲下拍（130）上。
- 选“对话”：勇者收剑的姿态从 +2 帧提前到 240 帧，与确认音、收剑声同帧。
- LEVEL UP：光柱抖动不再盖住勇者（用无勇者的同帧做遮罩），金色波的色阶去掉了偏红的两级。
- 拍点核对（tools/cuecheck.py）：画面事件 ↔ 拍点网格 0 ms；画面事件 ↔ 音乐事件 0 ms；混音实测起音 ≤ 2 ms（检测分辨率）；成片逐帧差的最大变化帧全部落在对应拍点帧上；两段静默为数字真零。

### 返修一轮（审片意见）

- **LEVEL UP 钥匙挡脸**（STYLE §9 side view 道具挡脸）：钥匙不再跟着手在脸前，改成举过头顶，底边离头顶 5 px、在手的正上方；`raise` 姿态的前臂改从后脑一侧举起（负角 = 朝身后），手臂只压在头发上、不经过脸，后臂同向抬在头后。三颗闪光跟着钥匙走。
- **金色扩散波**：原来按亮度把墙映射到 7 级暖色，暗墙落在橙棕两级，看上去是锈铜色的半圆。现在波前只用调色板里最亮的两级（#fff3b0 / #fee761）做 Bayer 抖动，后沿再抖回“亮一步”（LIGHT[]）；圆心下移到勇者脚下，扁椭圆（纵向 ×1.3），上沿与左右边同时出画，不再是被画面顶边切掉的半圆；波经过“LEVEL UP!”标题框时不上色，保住标题的墨描边。速度 20 px/帧，约 8 帧扫满全屏。
- **静默 1 开头的回声尾巴**：回声（含反馈环）改成按静默分段处理，尾巴不跨静默；所有总线在静默窗口前 1 帧用 64 采样淡出后硬清零，给 AAC 的 1024 采样帧留出余量。cuecheck 新增一项：直接解码成片音轨，核对两个窗口内是否为真零。
- **空的系统窗**：“获得 钥匙！”顶窗从提前 3 帧滑入改成提前 2 帧、2 帧滑完，窗口落定的那一帧就出现第一个字，最后一字仍落在接钥匙那一拍（f310）。
