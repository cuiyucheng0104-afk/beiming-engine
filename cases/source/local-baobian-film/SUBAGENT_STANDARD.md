# 《豹变》子代理规范 v2.1

本规范约束这个项目里所有子代理。主会话按本规范派活、验收；子代理开工前必须通读本文件、`BRIEF.md` 和本版的 `STYLE.md`。

> v2.1（2026-11-04，第三轮起）：封装改成线性响度、有限范围 BT.709；`audio.json` 可以设片尾淡出；从成片抽帧一律用 `tools/grab.sh`；`out/v2/` 是第二轮成片的冻结存档，只读，用来对比有没有改坏。见第五、六、八节。

## 0. 模型与努力

- 所有子代理一律**继承主会话的模型和努力**（当前是 Opus 5.5、max）。不再指定 Sonnet，也不降低努力。
- 一个子代理只担一个角色、只管一个版本。不要替别的角色做决定，有分歧写进汇报，交给主会话。

## 1. 角色与交付

每个角色都写明三件事：它读什么、它产出什么、做到什么程度才算完成。凡是"完成"，都要拿得出证据：文件路径、门禁报告、5090 渲出来的静帧。

| 角色 | 读 | 产出（都在 `films/<版本>/` 下） | 完成标准 |
|---|---|---|---|
| 美术设计 Designer（每版两位，角度不同） | BRIEF、STYLE、参考静帧、配乐分析 | `_work/design/DESIGN_<角度>.md` | 逐镜头给出构图、分层、色值、着色参数、转场机关、精确到帧的时间表、资产清单（含提示词和参考图编号），每一条都能直接拿去执行 |
| 设计定稿 Design Judge | 两份设计、参考静帧 | `DESIGN.md`（定稿） | 逐项打分、取长补短，留下唯一一套可执行方案，写明为什么这样选 |
| 资产 Asset | DESIGN.md、参考静帧 | `assets/`、`assets/manifest.json`、`_work/assets_sheet.jpg` | 清单里每一项都有图，每张图都亲眼看过（Read 打开）；角色先出设定图，再拿设定图当参考图出其余姿态，保证一致；需要抠底的层确认是透明底，没有白边、没有残留棋盘格 |
| 搭建 Builder | DESIGN.md、assets、引擎 | `index.html` 与 JS、`NOTES.md`、`audio.json`（可选） | 门禁 `tools/gate.sh` 全部通过；`_work/gate/main/sheet.jpg` 亲眼逐格看过，30 秒每一段的内容都对得上分镜 |
| 评审 Reviewer（三个视角：画风还原 / 叙事与镜头 / 技术与质感） | BRIEF、STYLE、DESIGN、参考静帧 | 结构化问题单（JSON） | 自己在 5090 上重新渲图来审，不信别人的截图；每个问题都写清时间点、位置、原因、改法和优先级；不说"挺好""可以再优化"这类空话 |
| 返修 Fixer | 问题单、代码 | 修改后的影片、`NOTES.md` 里的「返修记录」 | 每一条问题都写明"已修/未修及原因"；门禁重新全部通过 |
| 复核 Verifier（对抗式） | 问题单、返修记录 | 逐条核实结论（JSON）+ 六项打分 | 默认不信"已修"，逐条去 5090 上渲图核对；分数按第四节的口径给 |
| 渲染 Renderer | — | `out/豹变_<版本>.mp4`、`out/check_<版本>/` | `tools/finish.sh` 跑完：720 帧、30.000 秒、有声音、−14 LUFS 左右、没有长黑场、色彩标记是 yuv420p / tv / bt709。只改了配乐或 `audio.json` 时用 `sh tools/finish.sh <版本> --mux-only`，不重渲 |
| 终检 Final QA | 成片 | 逐秒检查报告 | 从成片里抽帧看（不是看静帧），确认与门禁静帧一致，列出剩余瑕疵 |

## 2. 铁律

1. **只改自己负责的东西。**`engine/`、`tools/`、`films/_lib/`、`refs/`、`BRIEF.md`、本规范、别的版本，一律只读。工具有 bug 就写进汇报，不要自己改。
2. **渲染全部在 5090 上做。**静帧用 `tools/rog_stills.sh`，门禁用 `tools/gate.sh`，整片用 `tools/finish.sh`。Mac 只用来写代码、出资产图和看图，不在 Mac 上跑 `still.mjs` 和 `video.mjs`。
3. **结论要有证据。**说"好了"之前，必须在 5090 上渲过，并且用 Read 亲眼看过那张图。汇报里写证据路径。没验证过的就写"未验证"。
4. **确定性。**`render(t)` 必须是 t 的纯函数：不准用 `Math.random`、`Date.now`、`performance.now`、`new Date`，也不准跨帧累积状态。要随机就用种子哈希。粒子、雨、雾都按 t 直接算出来。
5. **按 H/1040 缩放。**所有像素尺寸（线宽、字号、粒子大小、屏幕空间偏移）都乘以 `K = innerHeight / 1040`，这样 4K 渲出来构图不变（门禁 G5 会查）。
6. **文件名用 ASCII**，小写字母加下划线，不带空格，也不带中文。
7. **画面红线：**人物不出正脸；不出现任何品牌、logo 或无关文字；参考静帧只能当生图的参考图，不能原样放进画面；字幕只用 `fonts/` 里那三款书法子集字体，只写「君子豹变 其文蔚也」。
8. **共用 5090：**不动别人的进程。工具脚本自带锁、排队和 GPU 忙等，不要绕开它们去直接 ssh 渲染。
9. **全中文：**文档、注释、汇报一律用中文。
10. **资产图**用 Magpie（`mcp__magpie-image__generate_image`）。参考静帧已经得到版权方授权，可以直接当 `reference_images` 用。每张图都要等结果出来、亲眼看过；不满意就改提示词重出，同样的失败出现两次就换思路。提示词末尾加上：`normal body structure, natural proportions, stable clear face, no text, no watermark`。

## 3. 门禁（`sh tools/gate.sh films/<版本>`，全部 PASS 才算能交）

| 项 | 查什么 |
|---|---|
| G0 | 静态检查：代码里不出现 `Math.random` / `Date.now` / `performance.now` / `new Date(` |
| G1 | 加载：5090 上的 Chrome 走的是 NVIDIA（Vulkan），页面到了 READY；没有页面报错、控制台报错、外部请求，26 个关键时刻的静帧一张不缺 |
| G2 | 覆盖：每张关键时刻静帧都不是空白或纯色（29.8 秒之后的淡出除外） |
| G3 | 确定性：另起一个浏览器重渲同一时刻，逐像素平均差小于 0.5 |
| G4 | 性能：5090 上每帧的中位耗时小于 1500 毫秒 |
| G5 | 4K 一致：3840×2080 版缩小后和 1080 版的平均差小于 10 |
| G6 | 时长：`window.DUR = 30` |

门禁只能证明"没坏"，证明不了"好看"。好不好看由评审和复核按第四节判断。

## 4. 质量标尺（评审和复核统一口径，每项 1–10 分）

| 维度 | 10 分是什么样 | 低于 8 分的典型问题 |
|---|---|---|
| 画风还原 | 截一帧放进参考板里，看不出是外人做的 | 像通用"国风插画"或 AI 图；色板、笔触、留白不对 |
| 三渲二质感 | 3D 层和手绘底板浑然一体，色阶、交界、描线、纸纹都对 | 一眼看出塑料 3D 感；贴片边缘生硬；光照和底板打架 |
| 叙事清楚 | 不看任务书也能看懂七个段落；墨渍→豹斑→光斑这条母题成立 | 不知道这段在演什么；母题没出来 |
| 镜头与转场 | 两个透视转场和匹配剪辑都成立，而且漂亮 | 转场只是淡入淡出；镜头不动或乱动 |
| 构图与留白 | 每帧都能当画看；主体清楚，留白有意图 | 画面堵、主体淹没、空得无意义 |
| 技术干净 | 没有穿帮、闪烁、拉伸、黑块、白边、错字 | 任何一处明显穿帮 |

**交付线：**六项都在 8 分以上，并且没有 P0、P1 级问题。

问题分级：

- **P0**：报错、黑屏、穿帮，或者整段看不懂。
- **P1**：明显偏离画风，或者转场不成立。
- **P2**：能看出来的瑕疵。
- **P3**：锦上添花的改进。

## 5. 配乐对位

- 配乐在 `audio/<版本>.wav`，分析报告在 `audio/<版本>_report.txt`，能量曲线图在 `audio/<版本>_curve.png`。
- 分镜里每段的起止时间可以在 **±1.0 秒**内调整，让关键动作踩在音乐上：T1 入书、S3 进集市、S5 起跳、片尾字幕。
- 也可以在 `films/<版本>/audio.json` 里写 `{"offset": 秒}` 指定从配乐第几秒开始截，或写 `{"anchor": 秒}` 让脚本把最大涌起对到这一秒。
- 现有配乐实在不合适的话，可以用 `sh tools/rog_music.sh <版本> "<英文描述>" 44 --seed N` 重新生成。生成要排队，一次大约 1 分钟。
- 片尾淡出：默认从片内 28.3 秒起线性淡出 1.7 秒。配乐在片尾还在往上走、听起来像被掐断时，在 `audio.json` 里写 `"fade_out_st"`（片内秒数）、`"fade_out_d"`（秒）、`"fade_out_curve"`（ffmpeg afade 曲线名，例如 `hsin`、`par`、`cub`），开头淡入写 `"fade_in"`。改完用 `ffmpeg -i audio/<版本>_30.wav -af ebur128=framelog=info -f null -` 看最后 3 秒的瞬时响度（M）是不是平稳往下走。
- 封装（`engine/render/mux.sh`）按整段线性增益把响度拉到 −14 LUFS，不压动态；只在峰值放不下时做过采样限幅。配乐自己的强弱对比会原样保留，所以安静段要真的安静、高潮要真的起来，靠配乐本身和 `offset`，不要指望封装去补。

## 6. 看图方法

1. 先看整片接触印样，再逐段看大图。
2. 和参考静帧并排比：`.venv/bin/python tools/compare.py --out x.jpg 本片.jpg -- refs/<版本>/ref_03.jpg ...`
3. 色板对比：`.venv/bin/python tools/palette.py --out p.png 图...`
4. 看动作和节奏时，渲相邻帧（相差 1/24 秒）连着看。角色要一拍二：每两帧才换一次姿态。
5. 从成片 mp4 抽帧一律用 `sh tools/grab.sh <成片.mp4> <输出目录> <帧号> [帧号 …]`（帧号 = 秒 × 24）。成片是有限范围 BT.709；ffmpeg 默认的快速转换会让抽出的帧整体暗约 2 级，拿去和门禁静帧比会误报"偏暗"。要批量抽帧时，在滤镜里加 `scale=flags=accurate_rnd+full_chroma_int,format=rgb24`。

## 7. 汇报

最后一条消息就是交付物：

- 用结构化字段写：做了什么、证据路径、门禁结果、自评六项分数、剩余问题。
- 不写过程流水账，不写"希望""应该可以"。

## 8. 第三轮补充

- `out/v2/` 是第二轮四版成片的冻结存档：`out/v2/豹变_<版本>_v2.mp4`、`out/v2/check_<版本>/`（QA.md、0.5 秒一格的 `frames/s_<秒>.jpg`、`qa_sheet.jpg`）、`out/v2/SUMMARY.md`。只读，不要改、不要删。返修和复核都要拿它当基线，确认改过的地方变好了、没改的地方没变坏。
- 问题编号：沿用第二轮的编号（`style-`、`story-`、`tech-`、`self-`、`v1-` 到 `v3-`）；`qa2-` 是第二轮终检从成片里抽帧发现的；`zs-` 是总审横评提的；`main3-` 是主会话第三轮补充的；第三轮复核新发现的写 `r4-`、`r5-`、`r6-`（按总轮次编号）。
- 复核打分时，每一项都要写一句扣分理由（`score_notes`），没扣分也写为什么给这个分。
