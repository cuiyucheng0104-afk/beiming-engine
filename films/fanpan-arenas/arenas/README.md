# 对战盘场景（试玩用）

七套可以换着看的对战盘场景。地址带 `?arena=<名字>` 时，整局都用这一套，不再跟着对手阵营换场地；不带这个参数，游戏和原来一样。

| 名字 | 场景 | 文件夹 | 独有的东西 |
|---|---|---|---|
| `c` | 林间寨擂 | `c-zhai/` | 寨门、竹栅、茅屋、灯笼、穿过树冠的斜阳 |
| `b` | 沉水擂台 | `b-shui/` | 霜祠和焰祠、兽面水口、莲叶、水面上的灯 |
| `harvest` | 丰收麦场 | `mai-chang/` | 水车磨坊、红谷仓、篝火、南瓜灯、麦浪 |
| `sea` | 珊瑚龙宫 | `shan-gong/` | 珍珠贝座、骷髅礁、珊瑚丛、鱼群 |
| `forge` | 齿轮熔炉 | `lu-fang/` | 铜锅炉、熔炉门、齿轮组、警戒条纹地台 |
| `sky` | 云上浮岛 | `yun-dao/` | 风车塔、热气球、浮岛瀑布、石栏 |
| `chapel` | 彩窗圣堂 | `sheng-tang/` | 蓝宝石礼拜龛、红宝石门楼、烛台阵、彩窗光斑 |

例：`http://localhost:8770/board.html?arena=harvest`。

## 规矩

- 一套一个文件夹，各用各的画法和贴图，文件夹之间不互相引用。
- 全部用代码逐像素画，没有外部图片，不请求任何网址。
- 只管「看起来是什么地方」：规则、棋子、格子的点击、城堡血量牌都还是游戏自己的。

## 接口

名字和文件夹的对照表在 `board3d.js` 开头的 `ARENAS`。每个文件夹的 `arena.js` 导出一个函数：

```js
export function build(ctx) { /* 搭场景 */ return { tick(t, dt) { /* 每帧动一下 */ } }; }
```

`build` 只调一次；`tick` 的 `t` 是场景自己的钟（秒），开了「减少动态效果」时不调。`ctx` 里有：

| 字段 | 是什么 |
|---|---|
| `THREE`、`scene`、`camera`、`renderer` | three.js 和游戏的场景、镜头、渲染器 |
| `amb`、`sun` | 游戏的环境光和主光，可以改颜色、强度、方向 |
| `tiles`、`lines` | 20 块格子的网格和三条分路线，可以换贴图 |
| `castles` | 两座城堡的组（`[本方, 对面]`），往里面搭自己的门；挨打下沉的动作还是游戏做 |
| `post` | 后期：`bloom`（泛光）、`tiltH` / `tiltV`（移轴虚化，`focus`、`band`、`amt`）、`grade`（调色，平时关着）。低画质档不走后期 |
| `low`、`calm` | 是不是低画质档、是不是减少动态效果 |
| `team` | 两边的阵营色 |
| `grid` | 棋盘尺寸：`ROWS`、`COLS`、`LX`、`LZ`、`HALF`、`DEPTH`、`HPY`、`SHORT`、`tileX(r)`、`tileZ(c)` |

场景文件载入失败时，控制台报一条错，游戏改用原来的场地。

## 已知的不足

- 这七套都只在电脑上自动对局、看截图检查过，还没有人实际玩过一轮来提意见。
- 桌面端对面城堡的血量牌有一部分被右上角的对局记录面板压住（原来的场地也这样）。
- 手机横屏上，个别场景的城堡顶部会被画面边缘裁掉一点。
- 没有进 `tools/build_h5.py` 的打包清单，线上的试玩包不带这些场景。
