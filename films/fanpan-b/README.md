# 沉水擂台（B 版 · 北冥原生 · BNE）

《一步翻盘》对战盘的风格样张：4 路 × 5 格的石板擂台立在一片暗紫色的水里，左边是霜祠（本方），右边是焰祠（敌方），后面是嵌着兽面水口的残墙，水面上漂着莲叶和灯。6 秒循环（144 帧，24 fps，1920×1080），没有声音。

[C 版](../fanpan-c/README.md)是另一个场面（林间寨子），两版**不共用任何代码和素材**：各自的像素画法、贴图、小件、调度、棋子阵容都是分开写的。

这个场面后来用 three.js 另写了一遍，成了游戏里可以对局的场景 `?arena=b`（不含原生运行时的任何东西），源码和另外六套一起在 [fanpan-arenas](../fanpan-arenas/README.md)。

状态：只出了风格关键帧，look、animatic、final 三道闸都没有用户认可。

## 画法

画法参考 `cases/vendor/lemo-opuscar/styles/hd-2d/STYLE.md`（MIT，LemoLab），只取方法，代码自己写。用户给的样图是美术参考（不是游戏里的真实场景），这一版主要照第 3 张量景深和光影：

- 像素画法是「浮雕着色」：每张图先写每个像素有多高、用哪一组颜色，再按左上方来光算明暗，量化成 6 级色阶，半级用 2×2 棋盘抖动。色阶不是手填的：给一个本色，暗部往深紫拉、亮部往暖金拉（样图的暗部偏品红紫、高光偏金）。密度每米 48 像素
- 有体积的东西（水面、擂台、两座祠、残墙、柱、岸、树干、船）用 three.js 搭好，资产桥导成 GLB；平的像素小件（莲叶、蕨、旗、冰晶、灯笼、符文、血量碑、火、瀑布、交手的光效……共 67 种、六百多张）在 `film.tsx` 里拼成几张网格
- 光：偏紫的冷暗环境，穿过树冠豁口的暖金斜阳（一块只投影的镂空板挡出光斑），青 / 橙 / 金三色的 14 盏点光，灯用真实单位
- 景深是镜头自己的（焦距 + 光圈）：焦点压在盘面偏后，近处糊得重、远处略虚
- 棋子的显眼度：贴身一圈深色描边再加一圈队色，脚下有队色的圈、光池和战力牌，盘面石板压暗压冷

## 文件

| 文件 | 管什么 |
|---|---|
| `plan.js` | 场面调度：棋盘尺寸、谁站哪一格、灯、镜头、太阳，以及每一张像素片摆在哪。只有数字和纯函数 |
| `ink.js` | 像素画法：色阶、噪声、浮雕着色、点阵数字、软边图 |
| `stone.js` | 贴在模型上的贴图：盘面、砌石、饰带、兽面、木栈板、水面、草岸、岩壁、树皮、瓦、石柱、冰、漆木 |
| `cards.js` | 平的像素小件和软光图，以及给棋子序列帧加描边 |
| `ruin.js` | 场景实体，`createRuin({ part })`：`cast` 是受光、会投影的部分，`soft` 是发光件 |
| `bake.mjs` | 把小件拼成图集、把棋子描好边，写到 `baked/` |
| `film.tsx` | 画面编排：镜头、灯、模型、像素片、棋子、软光、浮尘、后期。调画面改开头的 `LOOK` |
| `film.json` | 作品描述：尺寸、帧数、素材清单（`native.images`、`native.models`）、署名 |
| `units/` | 十条棋子待机序列帧（CC0，敌方已左右翻转） |
| `baked/` | `bake.mjs` 的产物（图集、坐标表、描边后的棋子），随仓库提交；`media/` 是准备好的素材，不提交 |
| `tools/` | 制作过程里用的脚本，不参与出图：`prep_units.py` 从游戏仓库取棋子并翻转敌方，`unit-sheet.py` 拼候选棋子图，`shot.sh` 出一张草图帧并量明暗和景深（量法脚本借用 C 版 `tools/measure1.py`，只是量图，不是画面素材） |
| `BRIEF.md` | 重做这一版时的任务书原文，留作过程记录 |

## 出图

在仓库根目录，先设好原生运行时的路径（`export RAEA_BIN=<可执行文件>`）：

```sh
node films/fanpan-b/bake.mjs
node engine/native/prepare.mjs films/fanpan-b
node engine/render/native.mjs films/fanpan-b --check-only
node engine/render/native.mjs films/fanpan-b --at 72 --max-gpu-util 40
```

改了 `cards.js`、`ink.js` 或 `plan.js` 里的棋子与血量，要重跑 `bake.mjs`；改了 `ruin.js`、`stone.js` 或 `baked/`，要重跑 `prepare.mjs`；只改 `film.tsx` 或 `plan.js` 里的摆放，直接渲。静帧在 `films/fanpan-b/out/<run-id>/stills/f<帧号>.png`。桌面上开着别的吃显卡的程序时要带 `--max-gpu-util`，默认超过 10% 就拒绝渲染。

## 踩过的坑

- 两个模型本来是一个场景的两半，互相穿插，`<Model>` 都要写 `allowOverlap`，否则穿模检查报错
- 贴图写成 `{ path }` 时必须带 `sampler`，否则报错
- 资产桥不保留透明度裁切，所以镂空的像素片不放进 GLB，而是在 `film.tsx` 里拼成网格、用 `alpha_mode={{ Mask: .5 }}` 画
- 不受光（`unlit`）的材质不吃曝光，会发灰；要亮的东西用「黑底 + 贴图自发光」
- 一次渲多帧和单独渲一帧，同一个帧号出来的图不完全一样（差在棋子的待机姿势）；要拿某一帧对比就单独渲它
- `bake.mjs` 的无头页面地址用 `.invalid` 结尾：`.local` 会被合规扫描当成内网地址拦下
