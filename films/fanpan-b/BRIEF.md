## 设计：沉水遗迹里的擂台（美术参考是样图 3：`films/fanpan-c/out/ref/3.jpg`，先自己再看一遍）
- 4 路 × 5 格的棋盘是一座从沼泽水面里露出来的雕花石台，不是「砖墙围着的格子」。左边我方（青绿）、右边敌方（红）各有一处有辨识度的「城门」：比如我方是嵌着青色晶石的神龛/石碑，敌方是点着火的兽面石像，各带血量牌（我方 10、敌方 6）。棋盘规格和阵营色来自游戏，别的都重新设计。
- 环境要丰富、有大量小组件：刻着兽面和回纹的石柱（有倒的、有断的）、长苔的残墙和台阶、木栈桥、骨白色的灯柱和吊灯、睡莲叶（发亮的黄绿）、芦苇、藤蔓、蕨、蘑菇、陶罐、小船、碎石、水面倒影和波光、背景的瀑布或光幕、巨树根。前景要有几样压在画面底部、被景深糊掉的东西（样图 3 底部的灯柱和栈桥就是）。
- 特效要多：水面高光与涟漪、萤火、浮尘、灯的光晕与闪烁、光柱、晶石和火的上升粒子、薄雾、棋盘上一两处「正在发生」的效果（比如某格的法阵、前线的亮线、某个棋子脚下的光环）。
- 「逐像素点」：贴图全部按固定像素密度逐像素画（建议每米 48 像素，镜头在棋盘处大约 3 个屏幕像素对 1 个贴图像素，棋子高约 120–150 屏幕像素），最近邻采样，每种材料 5–6 级色阶、窄抖动带；小组件要画到能认出是什么。地面/水面可以是一整张不平铺的大贴图。
- 棋子要显眼：棋盘石面比周围安静（纹理对比低、饱和度低一档），最亮的一块光落在棋盘上，棋子自己带一点自发光托底、脚下有阵营色的圈和接触阴影、战力牌清楚；周围越远越暗越糊。出图后自己检查：缩到 1/3 大小还能一眼数清 10 个棋子、分清敌我。

## 我从 4 张参考图量出来的指标（方法脚本 `films/fanpan-c/out/ref/analyze.py <目录>` 和 `dof.py <目录>`，你可以拷一份到自己的 out/ 里拿你的出图去量，放一个只有你那张图、命名成 1.jpg–4.jpg 的目录或改脚本）
- 景深：清楚带在画面高度 25%–55%；上方只轻微发虚（等效高斯 σ ≤ 1.3 px，按 1920 宽）；下方从约 65% 高度起渐糊，到底边 σ ≈ 4–5 px。近处糊得远比远处重，不是上下对称的移轴。
- 明暗（sRGB 亮度 0–1）：P25 0.02–0.06，中位 0.07–0.18，P95 0.43–0.58，P99 0.68–0.87，均值 0.13–0.22。暗部压得很死但不是一片纯黑，高光不过曝。
- 颜色：HSV 饱和度均值 0.5–0.72（用户要高饱和，往 0.65–0.75 靠）；高光暖金（色相约 42°，饱和 0.45–0.55）；样图 3 的中间调偏红褐、暗部是品红紫（色相约 299°，饱和 0.86）；睡莲叶是画面里唯一的亮绿。
- 暗角：四角亮度 / 中心 ≈ 0.2–0.35。

## 流程与已知的坑（都在本会话的总结里，这里只提要）
- 每条命令：`在北冥仓库根目录：export RAEA_BIN=$HOME/.cache/beiming/raea/0.1.4/linux-x64/raea/bin/raea;`，然后 `node films/fanpan-b/marks.mjs`（如果还用这种导图方式）→ `node engine/native/prepare.mjs films/fanpan-b` → `node engine/render/native.mjs films/fanpan-b --check-only` → `node engine/render/native.mjs films/fanpan-b --at 72 --max-gpu-util 40`。交付用单独渲的第 72 帧。我这边 C 版也会短暂占用显卡，被拒绝就等几秒重试。
- unlit 材质不吃曝光会发灰，要亮的东西用「黑底 + 贴图自发光」；资产桥会把「不受光且带贴图」的材质变成白色自发光；`<Model>` 互相穿插要 `allowOverlap`；贴图写 `{ path }` 要带 `sampler`；合规扫描拦 `*.local`。
- 每出一版图都自己看（Read 图片，可以先缩小），对照样图 3 和上面的指标改，至少迭代到你自己认为比旧版明显精细为止。不要自己宣布「通过」，三道闸只有用户能批。
- 更新 `films/fanpan-b/README.md` 和 `film.json`（片名可改成《沉水擂台》；署名、aigc、素材清单跟着实际情况改），最后跑 `npm run check:repo` 看有没有这部作品的报错。
