# 画面设计规范

> **解决什么**：把"画风"写成能执行、能验收的规则，防四类失败——画风漂移（每镜各调各的、色板被冲淡）、主体读不出（剪影、明度、尺度、文化符号出错）、镜头之间不连贯（轴线、视线、光向跳）、IP 与事实出错；并给出"好不好看"的可执行复核办法，不把技术通过当成审美通过。
> **按什么顺序用**：§1 画风锁定 → §2 色彩脚本 → §3 风格帧与明度、剪影 → §4 构图、镜头语法与连续性 → §5 分层时钟 → §6 显示层与字幕 → §7 IP、品牌与地图 → §8 画面与审美 QA 清单。§1 的字段按 [templates/STYLE-LOCK.md](templates/STYLE-LOCK.md) 填进 `style-lock.json`；导演流程里它对应 [DIRECTING.md](DIRECTING.md) 第 5、6、9 步；实现细节在 [craft/](craft/README.md)。
> **标注**：【仓库实证】【通用工艺】【推断】【未实现】，含义同 [craft/README.md §2](craft/README.md)。凡括号里给出 `文件:行号` 或命令的说法，都属【仓库实证】，正文不再逐条加标签；没有路径的判断，要么标【通用工艺】或【推断】，要么是对前后实证的归纳。`$甲`、`$乙` 的展开见文末「出处与许可」。案例状态口径同 DIRECTING §0：historical-render 不等于认可，rejected 只作反例、不作任何正面依据。C 路线范例的技法多来自 `$甲` 的风格说明，来源见 [SOURCES.md §3](SOURCES.md)。路径简写同 DIRECTING §0：`style-NN-…/`、`ppt-…/`、`keynote-…/` 开头的路径在 `cases/source/` 下，`<案例 id>:行` 指其 `TREATMENT.md`。

## 1. 画风锁定：锁规则，不锁每镜的数值

**原则**【仓库实证】风格版本锁的是规则；允许镜头级调整的字段、范围和理由写进版本记录；换色板、光照公式或后期顺序就建新版本，并重做跨镜头对照（`docs/routes/beiming-style.md:175`）。景别改变笔触半径就是有记录的合法调整（`:128`）。

**两个反例**（都是 rejected）：九分钟版用源文件哈希锁住原版十秒，政策写"原有色板、3 档材质、后期不改"，实际把全片锁在破晓色里（`cases/source/local-beiming-film-9min/docs/style-lock.json:2-12`；【推断】这是被否的原因之一）；纸上江山 E 组把画风写成导出常量，但只有一套数值、没有版本和允许范围（`cases/source/lab-2026-11-05-e-paper-15s/src/style.js:1-8`）。

**颜色规则的四条通则**【仓库实证】

1. **强调色只给一类东西或一个主体**，并把它当剧情资源：第三色只出现两次、标题因此改成单版来保护它（`style-12-risograph/TREATMENT.md:34,107`）；一点红只给灯笼（`style-75:104`）；唯一颜色是帽带一圈暗红，被遮挡时一起擦掉（`style-34-silent-film/TREATMENT.md:109`）。
2. **材料色不等于强调色**：壁画朱砂取风化偏橙的 `#B4552F`，与印章朱红 `#BE3A2E` 明确区分（`keynote-seg2-caizhi/TREATMENT.md:138`）。
3. **同色叠加先拉开色阶，再加分隔缝**（`style-09-papercut-red/TREATMENT.md:115`：相邻鱼交替用亮一档和深一档的纸，每条鱼外加深色"底纸缝"）。
4. **只写色名不能验收**。阐述写十六进制和职责，代码实现多套光照，两边互相引用（`style-12` 的色值与 `riso.js:9-13` 一致）。互引也会漂移：`style-16` 的页面、纸、墨、信号红与 `film.js:4` 一致，三种灰线里两种已对不上（`TREATMENT.md:34` 写 `#D3D2CD / #E1E0DB`，代码是 `#DDDCD7 / #CFCEC9`），所以色值要由一处导出，或用脚本核对。

**写进阐述的色值要注明来源**：`style-17-spy-titles` 的四个色值与示例文件逐字相同（`$甲/styles/spy-titles/demo/paper.js:5-6`），"写进了阐述"不等于"是本片的设计"。

**实现状态**：A 路线没有风格版本数据结构（T06 planned）；`docs/routes/templates/project-beiming.json` 只有 `style{id, version, baseline}`，渲染器不读【未实现】。本规范的 `templates/style-lock.json` 是草案；其中 `metrics`（调色后像素到最近色板色的 OKLab 距离分布、每百万像素的墨线长度、Kuwahara 有效半径）是给"同帧对照"配的辅助数字，计算脚本【未实现】。

## 2. 色彩脚本

**定义**：全片按段落列主色、明度键、主光、强调色是否出现、情绪含义；每段再落成每种材质的色指定（亮／一影／二影／线／高光）。实际做片时，最先决定观感的是每段的明度键（高调还是低调）和明暗面积比，只写"色名＋情绪"的色彩脚本不能指导出图【通用工艺】。

**北冥的定调**【仓库实证】由冷到暖五段：雾夜青灰蓝灰（困、钝）→ 城市灯海钠灯橙与霓虹品红、自下而上（假的暖）→ 月光下江银蓝、海草冷绿荧光（轻、自由）→ 关灯近黑、只剩两点航行灯（静、悬）→ 日出粉紫橙金、逆光（真的暖：柔、透、从背后来）（`docs/作品.md:55-65`）。**10 秒样片只落了日出一段**；其余四段没有任何参数、底板或预设【未实现】。style-lock 草案给这四段写了目标明度键（由 `docs/作品.md:59-62` 的色与含义推出，【推断】），免得新片全停在日出段的中高调。

**规则**

- 同一角色换光照时，按色指定换色，不整帧套滤镜（[craft/toon.md](craft/toon.md) 判据 11；`style-27-cel-anime-80s/pal.js` 白天、黄金时刻、日落、逆光四套）。
- 夜景不是整体压暗：按亮度保持向月光色混合，中性色混得多、饱和色混得少，让窗灯成为夜里唯一的暖点（`style-43-lowpoly-island/TREATMENT.md:118`：中性 78%、饱和 45%、亮度 ×0.66）。九分钟版关灯场把所有底板乘 0.11 压黑（`cases/source/local-beiming-film-9min/src/world.js:84-85`），【推断】这正是"只压暗"的做法。
- 冷暖由叙事决定：北冥里"假的暖"在下方（下方补光 `fillDir [0,-1,0]`，`src/toon.js:28`），"真的暖"在背后（低角度逆光与背光边缘光）。
- 色彩变化写成参数曲线，不靠剪辑跳色：镜头 C 的 9–10 秒把城市补光从 1 降到 0.62、材质曝光 1→1.12、调色暖度 0.12→0.2、暗角 0.24→0.16，就是一段代码里的色彩脚本（`src/shotC.js:197-210`）。
- 能量与色彩同表：结构表里每章同时写主色、音乐段落和实测响度（`keynote-C-quanpian/TREATMENT.md:20-30`）。

**模板**（写进阐述 §9 或 style-lock 的 `colorScript`）

| 段 | 帧区间 | 主色 | 明度键（主体／背景／最暗／最亮，OKLab L 或 0–10 灰阶） | 明暗面积比 | 主光（方位／仰角／强度） | 补光与天光 | 强调色出现吗 | 情绪 | 已实现？ |
|---|---|---|---|---|---|---|---|---|---|

**色彩脚本条**：每镜一张低分辨率关键帧，用正片代码出，按时间顺序并排成一张图；它是 DIRECTING 步骤 5 的产出物、⛔2 的确认对象。仓库没有出这种图的工具，可以用 `node engine/render/still.mjs . <每镜一个时刻> --out <目录>` 出静帧，再用 `tools/contact_sheet.py` 拼【仓库实证：两个工具都存在；拼色彩脚本条的用法是本规范的建议】。

**强调色**【通用工艺·建议】：面积不超过画面的约 5%–10%；主体彩度最高，背景降彩；强调色只给 style-lock 里 `only` 写明的对象。

## 3. 风格帧：先证明，再制作

**做什么**：有角色时造型表加 2 张风格帧，无角色时 3 张风格帧（其中一张是招牌镜头）；全部用正片的绘制代码出（`$甲/DIRECTOR.md §5`）。另出一张"基准与新画风"的同帧对照（`$甲/MY-STYLES.md §4`）。

**怎么调**【仓库实证】按六步顺序各存一组对照：灰模与轮廓 → 反照率（关后期）→ 分档与投影 → 边缘光与表面纹理 → 底板、雾与空间 → 线宽、笔触、纸纹与颗粒，最后才加文字（`docs/routes/beiming-style.md:140-147`）。先改单一变量，再组合；每组留一个共享基准（`:169`）。每张记源提交、参数 JSON、资产哈希、相机与灯位、时刻和无损图（`:149`）。

**判定**

- 先弄清这种画风在现实里对应什么材料和工序，再照那套工序去造：拼贴是桌上有厚度、有撕边纤维、有窗光阴影的纸，黏土是带指纹和微抖的手捏泥（风格库乙把这一条列为质量标准的第一条，`$乙/AGENTS.md:10-14`）；浮雕木刻里墨色是留下来的木面、白是刀刻掉的部分，亮处靠多刻（`$甲/styles/woodcut/STYLE.md:10`）。本仓库 `cases/source/style-15-woodcut/TREATMENT.md:33-38` 把"光是刻出来的"写成了镜头表里的刀法规则。只在屏幕上叠滤镜的画风，一动就露馅【通用工艺】。
- **灰度缩略图**【通用工艺·建议】：整帧转亮度，缩到 240 px 宽，高斯模糊 σ≈2，看主体是不是第一落点；远层不能比近层更黑（[craft/two-five-d.md §1.4](craft/two-five-d.md)）。主体与紧邻背景的明度差建议不少于约 0.15（OKLab ΔL）；不够时，必须由墨线、边缘光、色相差、彩度差中至少两项承担分离，并写进 style-lock。命令：`ffmpeg -i <帧>.png -vf "format=gray,scale=240:-2,gblur=sigma=2" <缩略图>.png`。验收表也有灰阶项（`docs/routes/validation-and-rtx.md:318`）。
  - 【仓库实证·复算】北冥样片：观众在逆光里看到的鲲主色是一影 `#4E5888`（OKLab L 0.473），天顶 `#4F5BBF` 是 0.515，ΔL 只有约 0.04；灰度里鲲背会和天空并在一起，分离实际由墨线、暖补光和色相差承担（色板见 `src/toon.js:15-17`，换算命令见 [craft/toon.md §5.2](craft/toon.md)）。迁到原生路线（GLB 不带屏幕墨线，`AGENTS.md:39`）或换成不画墨线的风格时，主体会直接化进天空，必须先重定明度。
- **剪影**【通用工艺·建议】：关掉后期，给主体换纯黑不受光的材质（或用 `scene.overrideMaterial`）渲一帧，缩到 160 px 宽，仍要认得出物种和动作。仓库没有现成的剪影开关，需在作品里自写【未实现】。反例：豹变的评审正是在这里出问题（豹读成灵缇、黄鼠狼、泰迪熊），见 `cases/source/local-baobian-film/tools/w2_review_render.js:25`。
- 文化符号：远山、建筑、纹样不能读成别的地域符号（豹变 C 版远山读成富士山，同一评审文件）。
- 不把后期滤镜当成三维建模：给照片加阴影不等于建了三维场景，减弱描边也不会自动变成写实渲染（`AGENTS.md:36`；`docs/routes/beiming-style.md:173`）。三渲二说的是三维物体输出二维视觉语言，并不要求背景、人物、特效都做成三维（用户对 E 组的纠正，记录位置见文末出处段）。
- 好不好看另有复核办法：眯眼缩略图、水平翻转、5 秒复述、与基准帧并排比数字（§8"审美复核"），技术通过不等于这几项通过。
- 用户确认有记录（DIRECTING 关口 2）。

**仓库现状**：A 路线的校准场景（T05，`lab/style-calibration/`）不存在【未实现】；`lab/kun.js` 用临时描边、`lab/look.js` 用测试材质，都不能单独证明正片一致（`docs/routes/beiming-style.md:151`）。

## 4. 构图与镜头语法

### 4.1 主体读得出

- 关键时刻主体要读得出：在灰度缩略图里是第一落点（§3）。表演和情绪镜头的主体宜占画高 1/3 以上（`$甲/DIRECTOR.md §8`）；尺度揭示镜头例外，但要有参照物。量法写明：细长或稀疏的主体用轮廓面积或最短边像素，不用包围盒（反例 `style-60-teardown/TREATMENT.md:115`）。
- 焦点＋上下文：关键拍让全画面褪色，只留主体的颜色（`style-24-iso-infographic/film.js:196`，邮戳急推和静默时褪成暖灰、只留红信）。
- 文字不压主体（`style-52-hologram-hud/TREATMENT.md:137`）。
- 北冥定调：不做长时间正面特写，情绪交给手、背影、侧脸和镜片反光（`docs/作品.md:71`）。

### 4.2 2.5D 多平面

规则摘要（展开见 [craft/two-five-d.md](craft/two-five-d.md)）：

- **先排版，再给深度**：在 1920×1040 设计稿上排好每层的屏幕矩形，再给每层一个视深 D；起始帧的画面与 D 无关，D 只决定视差和遮挡（`engine/stage/camera.js:30-38`）。
- **压缩由深度比决定**：视场只决定每米运动换算成多少像素；想压在一起的几层，D 的比例要小（镜头 A 城市一带 1300／1450／1500 m）；想舒展，就放进几十米的近景层。
- **D 与绘制顺序同序**：越远 renderOrder 越小，否则视差与遮挡互相矛盾（`engine/stage/plates.js:29-31`）。
- **截断边永远在画外**；每侧出血不少于 o＋羽化＋余量（two-five-d §2.1 公式）。几度以上的摇镜改用穹顶（`engine/stage/dome.js:1-3`）。
- **纹素密度**：最终输出、最大放大时 ρ ≥ 1，云边和天际线剪影尤其要守；镜头 A 的天空与江面、镜头 C 的穹顶在 4K 下都低于 1（【仓库实证·复算】two-five-d §2.2）。
- **近处要细笔触就用抠像面片**，普通底板不写深度，笔触粗细取决于它背后有什么（two-five-d §1.6）。
- **防纸板感**：前后层夹住主体、雾盖接缝、加色辉光近似光包裹、尾迹与水面接触、底板微动、统一笔触与纸面（two-five-d §4.1）。一层跨越很大深度（地面、水面）就拆成几条或改用真正的水平面（§4.2）。
- **底板不烘焙文字**；生成的底板要画掉伪文字、水印、签名和标识（two-five-d §2.6）。

### 4.3 镜头语法

- **北冥定调**：默认固定机位或缓推；不变焦、不甩镜、不斜构图；城市段长焦、竖向压迫；海面段广角、横向舒展；由慢到更慢，再突然爆发（`docs/作品.md:69-72`）。样片三镜竖直视场 16°／30°／31°，约合全画幅 85／45／43 mm（【仓库实证·复算】two-five-d §3.2）。
- **运镜词汇写成三列**：运镜｜表达什么｜可服务什么内容；词汇表里不规定开场、高潮、结尾必须用哪一招（`$甲/styles/_template/STYLE.md §6`）。
- **转场在媒介内完成**，并成一套语法（`$甲/DIRECTOR.md §8`）：套印、越框、折剪展、硬切即新压印、网点擦除、裂纹白闪、字号拉远、穿汽（`style-08`、`style-09`、`style-15`、`style-13`、`style-20`、`style-22`、`style-75` 的阐述）。不默认用叠化和黑场；例外写理由。
- **相机与标注共用一个 world→screen 函数**，镜头一动标注就跟着主体走（`style-13-halftone-dossier/TREATMENT.md:35`）。
- **屏幕方向与视线连续，特写前先交代空间**，规则展开在 §4.4【通用工艺】。运动方向本身也可以讲转折：转折前后主体换一个屏幕方向运动，观众不用台词就读出"变了"【通用工艺】。
- **相机默认不量化**：相机与底板一拍一；相机按一拍二步进，所有层一起跳，纵深感就没了（two-five-d §3.5）。例外与副作用：相机跟拍一拍 n 的主体时，主体会在画框里按拍跳动、相对画框发抖。二选一处理——主体根运动走平滑、只让姿态按拍（渡船的做法，`src/shotA.js:113-117`）；或相机瞄准连续轨迹（镜头 C 的 `trackAim` 用连续、未量化的姿态求瞄准点，`src/shotC.js:136-145`）。只有整幅画面就是一张画、不需要表达纵深时，才考虑相机与主体同拍步进（[craft/animation.md §2.6](craft/animation.md)）。

### 4.4 镜头间连续性

【通用工艺】多镜头短片里最显外行的，是切点两侧对不上。每场在镜头表里写清下面六项；做法属通行剪辑规则，仓库没有检查工具，校验脚本【未实现】。

1. **轴线与屏幕方向**：每场写谁在画左、往哪走；越轴要有过渡镜头（中性方向的镜头、可见的越轴运镜），或写明理由。
2. **视线匹配**：看与被看的两镜，视线方向相反、高度一致。
3. **视觉落点（eye-trace）**：切点前后主体中心的屏幕距离建议不超过画宽的约 1/4；超过要写理由（有意的"打开"）【通用工艺·建议】。
4. **动作匹配剪辑**：动作在切点两侧连贯。【通用工艺·建议】可在后一镜重复 2–4 帧动作，免得被切点吃掉，需看片确认。
5. **同场光向、色温、曝光一致**：同一场内主光方位、色温和曝光跨镜一致；有意的变化写进色彩脚本。样片镜头 A、C 的主光都在画左，镜头 B 的光晕在画右（[craft/two-five-d.md §2.5](craft/two-five-d.md)），这种关系要在阐述里说明是反打还是另一场【推断】。
6. **运动中切**：两侧的屏幕速度同向、量级接近。

仓库可借的写法：段落交接帧完全一致、并排两张静帧自检（`ppt-jianlong/jianlong/ARCH.md:122-125`）；切点吸附到 0.5 秒网格（`ppt-jianlong/时间表.md:1`）。

## 5. 分层时钟

画面里不同对象用不同的动画节拍，是北冥的叙事手法之一（`docs/作品.md:74-84`）。实现现状：

| 对象 | 定调 | 实现 | 出处 |
|---|---|---|---|
| 镜头、雾、水、颗粒 | 每帧 | 按未量化的时间 | `src/shotA.js:91-98`；`engine/look/index.js:137` |
| 人物、墨线沸腾、鸽群、倒影 | 一拍二 | `q12`／`boilFps 12`／`hold(f,2)` | `src/girl.js:4,78`；`src/look.js:27`；`src/shotA.js:99-100` |
| 鲲（被困）、海草、云丝、镜片里的鲲 | 一拍三 | `heldTime(f,3)` | `src/shotA.js:103`；`src/shotC.js:165`；`src/kun.js:353,377-378` |
| 鲲（苏醒） | 一拍二 | 【未实现】 | — |
| 鹏（化鹏后） | 一拍一 | 【未实现】现有将化模型是身体一拍三、翅膀一拍二 | `src/kun_peng.js:10-11` |

**规则**（展开见 [craft/animation.md §0、§2](craft/animation.md)）：时间只从整数帧推导；每条轨道一个 n；被量化对象的所有输入（含条件判断、注视目标、材质里画的线的沸腾）也按它的拍号取——墨线沸腾的节拍等于该物体的绘制节拍，环境与底板上的线可以另定【通用工艺】；样片的已知偏差：鲲身材质线随全局墨线时钟一拍二沸腾，而鲲姿态一拍三，二者干涉成 2-1-1-2 的变化节奏，是否保留由看片决定（`src/shotC.js:165,198`；`src/kun.js:182-183`）；切点与节拍切换放在公倍数帧（一拍二＋一拍三取 6 的倍数）；周期动作的频率不超过 fps/(2n)，否则会混叠（鸽群扑翼 7.9–9.9 Hz 一拍二取样后成了 2–4 Hz 的错序扑翼，【仓库实证·复算】）；着色器里的时间也要按轨道分（鲲的顶点着色器读量化后的 `uKunT`，`src/kun.js:501`）。

C 路线的分对象节拍可以借：浪片 12 fps、人偶与镜头 24 fps（`style-07-shadow-puppet/TREATMENT.md:3`）；变换 30 fps、线抖 10 fps（`style-13`）；凤凰 8 fps 且每拍重新起算（`style-20:109`）；手摇采样以拍为锚，每拍起点必定是一次采样（`style-34-silent-film/TREATMENT.md:88`；手摇采样本身来自 `$甲/styles/silent-film/STYLE.md:39-40`）。

## 6. 显示层与字幕

### 6.1 两层世界

【仓库实证】现实层是三渲二形体、手绘底板、抖动墨线和颗粒，走全套后期；显示层是代码画的矢量线与字，最后叠加，不加颗粒、不受泛光、永远锐利，只在戴着眼镜时出现（`docs/作品.md:45-53`）。工程上显示层是叠在最上层、不经后期的 2D 画布（`engine/stage/film.js:2,30-33`）。声音也照此分层：眼镜提示音是干声、居中、不进世界混响（`audio/design.py:6-7`）。

**"显示层"有两个意思，新片要写明用哪个**：叙事上"戴镜才看得见"，与工程上"不经后期的画布"不是一回事。鲲在叙事上属于前者，工程上走现实层的三渲二管线（`src/shotC.js:77-83`）。把鲲画进不经后期的画布，它就失去了墨线、笔触和纸纹。

### 6.2 界面的语义

- **只画真实功能**：镜片层只表现眼镜真实能做的事，装在镜框里并标"功能名"；讲故事用的地图、标签、连线属于故事层，两套视觉语言不混用（`cases/source/ppt-in-sight/方案.md:12-20`）。
- **能力边界标在画面上**：需要配套内容或只是构想的功能，就在画面里写明（`cases/source/ppt-dance-mentor/方案.md:58-62`）。
- **科技是环境，不是奇观**：同时最多两行字；识别失败只做 0.4 秒内衰减完的小抖动；导航线越远越细（`src/hud.js:53,131,203-210`；`docs/作品.md:90`）。
- **界面随叙事退场**（`ppt-dance-mentor/方案.md:18-21`：从第 50 小节起包装全部退场）。
- 收到"像电路板"一类反馈后立"不做清单"（`cases/source/ppt-painting-treasure/方案.md:49-53`）。

### 6.3 字幕与画内文字

- 读字时长、字幕起止、每行字数、双语、易混字、字体子集：见 [DIRECTING.md 步骤 9](DIRECTING.md)。
- 画面文字白名单写成文件，代码画字时校验，白名单外的字直接报错（`ppt-jianlong/jianlong/ARCH.md:71`；`keynote-C-quanpian/ARCH.md:236`）。
- 文字要么完整在画内，要么完全在画外（`style-06-whiteboard/TREATMENT.md:129-131`）。
- 片名属于画面世界；书法片名按笔顺写骨架、只给收笔快的笔画加飞白（`src/hud.js:282-308`）。
- 安全区：改画幅或分辨率时复查构图、字幕与线宽（`docs/routes/validation-and-rtx.md` 第 2 节"尺寸"行）。字幕放底部 5% 安全区内（`ppt-jianlong/制作规范.md:96`）。
- **版式与字幕的建议数字**【通用工艺·建议；出处见 [SOURCES.md §2.3](SOURCES.md)；都要在目标设备上实看】：
  - 安全区：图文安全区 90%（每边 5%），动作安全区 93%（EBU R95、SMPTE ST 2046-1），与上面的仓库先例一致。
  - 字号与对比：1080 高下中文字幕字高约为画高的 4%–5%，字重不低于中等；配描边、阴影或底板，文字与背景的明度对比可按 WCAG 4.5:1 的量级自检。
  - 断行：中文遵守避头尾（W3C clreq），不在词中间断行。
  - 字幕时长：每条最长约 7 s、最多两行；相邻两条间隔不少于 2 帧（24 fps 下约 0.083 s；`ppt-jianlong/jianlong/tools/subs.py:6` 留的 0.05 s 在 30 fps 下只有 1.5 帧，会读成闪一下）；起止离切点不足约 12 帧时吸附到切点。读速以每秒字数上限复核，取发布平台规范的值。
  - 画在世界里的字（木牌、招牌）要经过 Kuwahara、纸纹和颗粒：字所在区域取近景小笔触半径、字高不小于画高约 4%，并出 4K 与 1080 对照帧确认笔画没被抹掉（同类问题见 [craft/toon.md §5.3](craft/toon.md)）。
- 分辨率：显示层按 H/1040 缩放；Canvas 2D 的 `blur()` 与 `shadowBlur` 不随变换缩放，要手动乘倍率（`engine/overlay/text.js:11,47-48`；`src/shotB.js:36,40`）。
- 页面通过 `window.TEXTS(t)` 报告每一时刻画面上的文字与方框（`src/hud.js:362-381`），只覆盖显示层；可读时长检查器 A 路线还没有，世界内文字也要自己投影成屏幕框再加入 `TEXTS`【未实现】。C 路线有把世界内文字四角投影成屏幕框的写法（`cases/source/style-77-desktop-flythrough/src/main.js:49-60`，代码来自 `$甲` 示例，见 SOURCES §3）。

## 7. IP 与品牌图像规则

### 7.1 权利底线

【仓库实证】历史 PPT 原画、设定、品牌标识、演员配音、生成音乐、影片和素材包只作展示与学习参考，归档不额外授予商业复用权（`cases/NOTICES.md:9`）。《北冥》影片、底板、展示图保留所有权利，代码许可不授权直接使用这些素材（`THIRD-PARTY.md:18`；`docs/raea/architecture.md:189`）。

**通则**：新片里出现的任何第三方作品、角色、品牌、事件、地图数据，都要有权利依据——用户拥有，或有书面授权；授权证据（谁授权、范围、期限）写进 CREDITS 和阐述 §2。没有权利依据的一律画虚构替身（改编自 `$甲/DIRECTOR.md §12`）。用户交来的图、标志、素材，也要用户确认有权使用。历史作品取得的授权只限那个项目，不随归档转给新作品。

### 7.2 他人的 IP 图（角色、原画）

**前提**：只适用于用户拥有或书面授权的 IP（§7.1）。装裱方式和"像素不改"是授权之后的呈现约束，不能代替授权。下面这组规则出自一组给 IP 方做的发布会片，素材是对方提供的（`cases/source/keynote-shared/制作规范.md:25-29,100`；该条目的 catalog 状态是 support）：

- 只能装在装裱位里出现：立轴、扇面、册页、斗方、窗花框、幕布、灯箱窗口。
- 占画面 35–55%，不全屏。
- 用墨晕、剪开、透光等方式显影。
- 原图像素不改：不改色、不变形、不重画、不抠图、不让角色动；只允许整体光照明暗和不超过 15% 的纸面纹理叠加。
- CREDITS 写明 IP 来源、授权与放大处理。

落实手段由弱到强：文字条款 → 每图一行的表（装裱位、显示尺寸与占比、显影方式，`keynote-seg2-caizhi/TREATMENT.md:145-157`）→ 逐帧实测占比（`keynote-seg1-kaijuan/TREATMENT.md:179`：微距阶段画面里该 IP 的彩色像素为 0）→ 工厂函数强制（`keynote-C-quanpian/ARCH.md:227`：IP 卡只能整张印成带白边的卡，可以移动、翻转、受光，图本身不改）。规则写在代码入口里，比写在文档里更不容易违反。

### 7.3 品牌与产品

- 频道、厂牌、队名、节目、城市、线网、产品一律虚构，并在画面或 CREDITS 里注明（`style-63-caption-news/TREATMENT.md:38`；`style-69-telestrator/TREATMENT.md:34`；`style-70-news-package/TREATMENT.md:3`；`style-72-transit-map/TREATMENT.md:7`）。

  - 片子不讲边界就不画边界：画海岸线、地形、影像或街道，不画国界和省界；能用区域图就不用世界图，争议地区放到画外（仓库先例：`style-64-newsreel/TREATMENT.md:123`）。

  - 常用开源数据（Natural Earth、world-atlas、OpenStreetMap）的默认边界不能用来画中国；需要边界时用中国视角的数据并对照标准地图，或用国家标准地图服务。
  - 文字口径与地图一致：标签、图例、字幕、旁白、数据表里都不把台湾、香港、澳门列为国家；含它们的名单叫"国家和地区"。数据集的国家字段先清洗再画图。
  - 交付前放大逐个核对地图镜头；CREDITS 写明地图数据、来源与视角。
- 可识别的普通人不做慢动作主体（出处见文末）。

### 7.5 事实、推算与示意

- 事实片配 FACTS.md：画面说法｜依据｜来源原文，再加"示意或简化"一栏。范例：措辞按原文证据强度降级（`style-63-caption-news/FACTS.md:11-17`）；推断一律带"≈"（`style-67-visual-investigation/FACTS.md:19-25`）；示意数值在画面上三处标 SCHEMATIC（`style-70-news-package/TREATMENT.md:3`）；数字从自家渲染画面测得（`style-69-telestrator/FACTS.md:5-12`）；"浴缸模型 · 示意"（`style-58-white-model/TREATMENT.md:11`）；"代码模型 · 尺寸为模型实测"（`style-60-teardown/TREATMENT.md:8`）；原片没有标尺就不出 µm 数字（`style-61-microscope/TREATMENT.md:14`）。
