## 0. 七条硬规则

1. **时间只用整数帧推导。** 页面入口把秒换成全局帧一次，之后所有量化、区间判断、事件比较都在整数域里做；秒只出现在输入和显示上。
2. **每条轨道有自己的 n。** 镜头、光、雾、水、颗粒一拍一；节拍是导演定调的叙事手段，不是性能开关。
3. **被量化对象的所有输入都按它的拍号取。** 包括 `if` 条件、注视目标的切换；否则会在一张"停帧"里单独跳一下。
4. **切点和节拍切换点落在公倍数帧上。** 一拍二加一拍三就落在 6 的倍数；再叠音乐网格就取它与每拍帧数的公倍数。
5. **姿势表 = 整数帧关键帧 + 单调插值。** 要"弹"就把过冲写成关键帧，不靠样条自己冲出去。
6. **拍点帧是结果帧。** 撞击、落定、字落稳出现在拍点那一帧，起步放在它之前。
7. **画面、声音、字幕读同一张事件表。** 同一个事件不在两处各写一个数。

## 1. 时间只有一个单位：整数帧

### 1.1 仓库里的时钟原语

【仓库实证】

| 原语 | 定义 | 用途 | 出处 |
|---|---|---|---|
| `frameOf(t, fps=24)` | `Math.round(t * fps)` | 秒 → 全局帧，页面入口用一次 | `engine/core/clock.js:11`；`engine/stage/film.js:40` |
| `hold(f, n)` | `Math.floor(f / n)` | 拍号；墨线沸腾、水波抖动的种子 | `clock.js:12`；`src/shotA.js:99-100,142` |
| `heldTime(f, n, fps)` | `floor(f/n)*n/fps` | 一拍 n 的姿态时间 | `clock.js:13`；`src/shotA.js:103,113`；`src/shotC.js:165` |
| `tick(t, rate)` | `floor(t*rate + 1e-6)` | 只拿得到秒的绘制函数；1e-6 防边界 | `clock.js:14` |
| `snapTime(t, rate)` | `tick(t, rate) / rate` | 同上，返回秒 | `clock.js:15`；`src/birds.js:67` |
| `hashi(n)` | 整数 → [0, 1) | 同一拍取同一个随机值 | `engine/core/math.js:20` |

`clock.js:2-3` 的注释本身就写明了原则：不同东西走不同帧率，量化一律从整数帧号出发。页面约定要求 `render(t)` 确定性、任意帧可单独重渲（`engine/render/page.mjs:3-7`）；`engine/render/video.mjs:35` 按 `f / FPS` 求值，所以页面里的 `frameOf` 能精确还原输出帧号；影片外壳每帧先算 `f` 再交给镜头 `update(t, f)`（`engine/stage/film.js:40-42`）。

### 1.2 为什么不能拿浮点秒直接量化

浮点秒乘一个速率再取整，错在三个地方：

**① 时间是怎么得来的，决定了会不会错拍。**【仓库实证·复算】10 分钟（14400 帧）逐帧比较（附录 A 的探针）：

| 时间来源 | 浮点量化 | 与整数量化不一致的帧 |
|---|---|---|
| `t = f/24` | `floor(t*8)` vs `floor(f/3)` | 0（巧合：24 正好是 8 的倍数） |
| 镜头局部时间 `t − 3` | `floor((t−3)*12)` vs `floor((f−72)/2)` | 12 |
| 逐帧累加 `t += 1/24` | `floor(t*8)` vs `floor(f/3)` | 1638 |
| 上面两种 t | `tick(t, 8)`（带 1e-6） | 0 |

**② 上游把事件时间舍入过，ε 就不够用。**【仓库实证】`cases/source/style-25-dark-keynote/TREATMENT.md:143` 的返修记录：拍点时间被舍入到 1e-6 s 后比 `f/24` 晚半微秒，画面因此晚了一帧；最后在 `film.js:293` 统一给 t 加 10 µs。`tick` 的 1e-6 能救大多数情况，但它依赖"误差小于 1e-6"这个前提，上游一旦换舍入方式就会再错。

**③ 用秒数阈值圈拍，容易多圈或少圈一拍。**【仓库实证】`src/girl.js:384` 写 `tq >= 0.5 && tq < 0.67`，注释说"一拍二下就是两拍"；复算覆盖拍号 6、7、8 三拍（全局帧 84–89，共 6 帧），因为 8/12 = 0.6667 < 0.67。差一拍不算大事，但说明"注释里的意图"和"实际圈到的拍"可以对不上。

**规则**

- 入口 `f = frameOf(t)` 只算一次；轨道内用整数：`hf = anchor + Math.floor((f − anchor) / n) * n`，需要秒时再 `hf / fps`。
- 区间判断写成拍号比较：`const h = hold(f, 2); const press = h >= 42 && h < 44;`（42 = 第 84 帧所在拍号）。
- 音乐拍点换帧先确认"每拍整帧"（§5.2），用整数乘法得帧号，不用浮点除法再取整。
- 时长从帧数推出：`engine/production/project.js:197-200` 拒绝独立填写的 duration，要求它等于 `frameCount / fps`。

### 1.3 全局帧、镜头局部帧、动作相位

【仓库实证】三者分开记录是仓库的明文要求（`AGENTS.md:37`；`docs/TRACKS.md:60`；`docs/routes/contracts.md:62-64,69`）。样片的做法：

- 所有镜头拿全局帧 `f`（`engine/stage/film.js:40-42`）。鲲的 `uKunT = heldTime(f, 3)`（`src/shotA.js:103,108`；`src/shotC.js:165,169`），所以游动相位跨切点连续——这正是 `contracts.md:64`"切镜头不能默认从零启动同一只鲲"的要求，也是 T03 的验收项（`docs/routes/work-plan.json:128`，状态 planned）。
- 人物用镜头局部时间 `tl = t − 3`（`src/shotB.js:32`）。镜头 B 起点第 72 帧是偶数，所以局部一拍二和全局一拍二完全同拍（复算 0 帧不一致）。**镜头若起在奇数帧**，局部量化的人物与全局量化的墨线、水波就会错开一帧换张，变化频率翻倍，画面发"碎"。（镜头 B 本身关掉了屏幕墨线，`src/shotB.js:59`，人物墨线也走局部时钟，所以样片里没有这个问题；这是给新镜头的提醒。）

## 2. 分层时钟：本仓库的签名

### 2.1 定调与实现对照

【仓库实证】定调在 `docs/作品.md:74-84`：人物一拍二；鲲被困时一拍三、苏醒时一拍二、化鹏后一拍一；镜头、云、水每帧都动。"同一个模型，只改动画时钟的量化方式"（同文件 :84）。实现现状：

| 轨道 | 定调 | 实际实现 | 出处 |
|---|---|---|---|
| 镜头推/摇、雾、水面贴图 | 每帧 | 按未量化 t | `src/shotA.js:91-98`；`src/shotC.js:30-41,147-162` |
| 颗粒 | （未定调） | 每帧换种子 `floor(t*fps)` | `engine/look/index.js:137` |
| 人物"她" | 一拍二 | 统一时钟 `q12`；发丝、手、呼吸、抬头、墨线都从它取 | `src/girl.js:4,78,370,411` |
| 墨线沸腾 | — | 屏幕墨线 `boilFps: 12`；材质墨线 `inkTime = hold(f, 2)` | `engine/look/ink.js:2,128`；`src/look.js:27`；`src/shotA.js:142`；`src/shotC.js:198` |
| 鸽群 | 一拍二 | `snapTime(t, 12)` | `src/birds.js:3,67` |
| 倒影、灯影抖动 | — | `hashi(hold(f, 2))` | `src/shotA.js:99-100,132` |
| 渡船 | — | 位移按 t 平滑，起伏与摇晃一拍二 | `src/shotA.js:113-117` |
| 鲲（被困） | 一拍三 | `heldTime(f, 3)`；海草、云丝读同一个 `uKunT`，也一拍三 | `src/shotA.js:103`；`src/shotC.js:165`；`src/kun.js:353,377-378,555` |
| 镜片倒影里的鲲 | — | `q8`，与镜头 C 的鲲一致 | `src/girl.js:5,79,658` |
| 鲲（苏醒） | 一拍二 | 【未实现】样片只有三个镜头 | `src/main.js:38-41` |
| 鹏（化鹏后） | 一拍一 | 【未实现】现有"鲲鹏将化"模型是身体一拍三、翅膀一拍二 | `src/kun_peng.js:1,10-11`；`lab/kun_peng.js:4,138-139` |

【通用工艺】为什么这样分层有效：一拍二是手绘动画的常态，人物动作带着"画出来"的颗粒；一拍三更省张、更慢更重，在这里被赋予"困、钝"的语义（`docs/作品.md:59`）；镜头与光每帧都动，否则观众会把镜头的跳读成卡顿。巨兽最后与镜头同拍，观众说不出原因却感到"突然顺滑"——前提是此前观众已经长时间看着它一拍三，对比才成立。

【通用工艺】三渲二要点：**着色器里的时间也要分轨道。** 鲲的顶点着色器读的是量化后的 `uKunT`（`src/kun.js:501`），海草、云丝的摆动写在着色器里（`src/kun.js:377-378,555`），所以它们自动跟着一拍三。若着色器统一读一个全局 `uTime`，分层时钟就在 GPU 里被悄悄抹平。three.js 自带的 `Clock`/`AnimationMixer` 按真实时间推进、有内部状态，离线逐帧渲染时不要用 `getDelta()`；要用骨骼动画片段，就每帧按该轨道的量化时间 `setTime()`。

### 2.2 每条轨道一个 n，关键帧落在该轨道的画格上

【仓库实证】一拍三的标准写法：`floor(globalFrame / 3) * 3 / 24`，非零起点先减去该角色的起点帧（`docs/routes/contracts.md:69`）；"动作是否量化由轨道决定，不能把所有参数统一降帧"（同行）。

**关键帧只能落在轨道的画格上**：一拍二轨道的关键帧只能在偶数帧（以锚点计），一拍三只能在 3 的倍数。不在画格上的关键帧会被"吃掉"或推迟。【仓库实证·复算】人物手部的时间线用秒写（0.12 抬起、0.42 悬停、0.50 贴上、0.95 放下、1.42 出画，`src/girl.js:381-383`），只有 0.50 落在 1/12 s 的画格上。按拍复算手的竖向偏移（mH，镜头内拍号 k = tl·12）：

```
k:  2   3   4   5   6  … 12  13  14   15   16   17
dy: 863 567 218 40  0  …  1  21  92  244  510  920
```

注释说 0.95 起放下，画面上真正看得出动（21 mH）是在第 13 拍（全局第 98 帧）。建议：一拍 n 的轨道把关键帧写成"轨道帧号"，不写秒。

### 2.3 切点与节拍切换落在公倍数帧

【仓库实证·复算】样片切点 0 / 3 / 5 秒 = 第 0 / 72 / 120 帧，都是 6 的倍数，所以任何一条一拍二或一拍三轨道都不会在切点处被截成半拍。

规则：

- 镜头的 `inFrame` 选该镜所用全部节拍的最小公倍数（一拍二+一拍三 → 6）。
- 节拍切换（一拍三 → 一拍二 → 一拍一）也放在公倍数帧上；故事要求放在别处，就以切换帧为新锚点重新起拍（§2.9 的写法），不要只改 n。
- 叠了音乐网格时，"全对齐点"是 `lcm(每拍帧数, 6)`：90 BPM、24 fps 下每拍 16 帧，`lcm(16, 6) = 48`，即每 3 拍一个点；最重的事件（切点、节拍切换、高潮落定）优先放在这些点上。

### 2.4 一个角色内的多时钟

【仓库实证】`src/kun_xuan.js:9,402,811` 与 `lab/kun_xuan.js:3,154`：身体一拍三，飘带、须、背鳍一拍二——`setPose` 第二个参数给原始时间，附属物在模块内部自己量化。`src/kun_peng.js:10-11`：身体时钟 `ts` 一拍三，翅膀时钟 `wingT` 一拍二，不给就跟身体一样。

【通用工艺】经验：附属物（发丝、飘带、尾翎、翅尖）的节拍应该等于或密于主体，不要更稀——它们离转轴更远、速度更快，取样稀了会读成"拖不上"。主体一拍三、附属一拍二，就是"大块重、梢头活"。

### 2.5 不该量化的东西，以及"量化对象的输入也要量化"

【仓库实证】不量化的：镜头推摇、天光、光尘、镜片内缘光（`src/girl.js:6,23,362-367,630-634`）；人物层的推镜变换每帧更新，墨线粗细随推镜平滑变化，姿态和墨线形状才一拍二（`src/girl.js:372-373,411`）。镜头 C 的跟拍函数特意用"连续、未量化的姿态"求瞄准点，避免镜头跟着鲲一拍三地跳（`src/shotC.js:136-145`）——但跟拍增益 `tk` 默认是 0（`src/shotC.js:152`），成片里实际没开。

**反例：一张停帧里眼睛单独跳了一下。**【仓库实证·复算】`src/shotC.js:165` 鲲按 `ts = heldTime(f, 3)` 一拍三，`:168` 却用未量化的 t 决定眼珠是否看镜头（`t < 7.2`）。第 171、172、173 帧同属一拍（ts = 7.125 s）：171–172 看镜头，173 帧 `look` 变空，`poseEyes` 把眼珠复位到眼窝正前方（`engine/form/eye.js:29`）。复位幅度最多到偏航 0.35、俯仰 0.28 弧度的限幅（`eye.js:25`）；在画面上有多明显，需要抽第 172、173 两帧对看（本章未渲染核实）。修法：条件改用 `ts`，或者更好——把视线释放放进眨眼闭合的那几帧里（§4.1）。同类的小问题：注视目标是每帧移动的相机位置，眼珠朝向因此每帧重算，即使身体停在一拍三；本镜相机移动很慢，量级应该很小（推断），规则不变——被量化角色的输入要按它的拍号采样。

### 2.6 整体平移：跟拍子，还是走平滑

【仓库实证】样片两种都用了：渡船位移按 t 平滑、只有起伏一拍二（`src/shotA.js:113-117`）；鲲的位置和姿态都用 `ts`，整体一格一格地移（`src/shotA.js:103-106`；`src/shotC.js:165-166`）。

【通用工艺】取舍：平移也跟拍子，物体在平滑镜头里会"一格一格跳"，这是手绘感，也是"重"；代价是快速移动时每拍位移太大，读成频闪。平移走平滑，物体像贴在镜头运动里，只有自身动作带拍子。规则：真实器物、离镜头近、与镜头同向运动的，平移走平滑；被定调为"画出来"的主体，平移跟拍子，并检查加速段每拍的屏幕位移【通用工艺·建议】：一拍 n 的相邻两张在运动方向上应有重叠，位移宜不超过主体自身宽度的约 1/2；超过时改一拍一，或加拖影、速度线（A 路线目前没有，见 §8）。位移到了主体宽度的量级，已经是"读成两个物体"的失败边界，不是安全边界。

### 2.7 输出帧率必须等于动画时钟

【仓库实证·复算】`engine/render/video.mjs:14` 接受 `--fps`，但影片外壳内部的 fps 默认 24（`engine/stage/film.js:35`），样片调用时没有传（`src/main.js:38-50`）。若用 `--fps 30` 输出，一拍二的画面会按 2、3、2、3 帧交替停留——相当于给手绘节奏强加了下拉节奏。规则：换输出帧率就把 fps 一起传进 `film.run`，并按新帧率重新定义一拍 n（30 fps 下一拍二 = 每秒 15 张）；C 路线里 30 fps 的片子（如《见龙》《这条街照常过年》）是整片按 30 设计的（`cases/source/ppt-jianlong/制作规范.md:12`；`cases/source/ppt-new-year-street/film/build.py:23-24`）。 渲染端（`video.mjs --fps` 与页面时钟不一致时不报错）的风险与修法见 [video.md §2.2](video.md)。

### 2.8 节拍干涉与周期运动的混叠

**节拍干涉。**【仓库实证·复算】鲲的姿态一拍三，鲲身上的墨线沸腾一拍二（材质墨线与屏幕墨线都是全局时钟，`engine/shade/toon.js:28,42`；`engine/look/ink.js:128`）。两者叠在一起，"画面有变化"的帧间隔是 2、1、1、2 循环。按"沸腾节拍等于该物体的绘制节拍"（[toon.md](toon.md) 判据 8），这是一处**已知偏差**：一个停帧的物体不该在自己的两张画之间抖线；是否保留由看片决定，检查方法是固定镜头看（`lab/look.js:9,271` 的 `still=1` 模式就是为此准备的）。修法：让鲲的墨线种子跟鲲的拍号走——【未实现】目前墨线时钟是全场共享的一个值（toon §8）。

**周期运动的混叠。**【仓库实证·复算】鸽群扑翼频率 7.87–9.89 Hz（`src/birds.js:26`），一拍二取样 12 次/秒，每张画面相位前进 0.66–0.82 圈，超过半圈——看到的是 2.1–4.1 Hz、次序错乱的扑翼。远景小鸟能否接受要看片，但规则很明确：

- 一拍 n 时，周期动作频率不超过 `fps / (2n)`；要读出"一下一下"，每个周期至少 4 张——一拍二时不超过约 3 Hz。
- 想要快扑翼：扑翼单独走一拍一；或者干脆用"画面索引"做循环（拍号 mod 4 取 上/中/下/中 四个翼姿），这是手绘的做法，比连续相位更稳。

### 2.9 化鹏一拍一：建议实现

【未实现】下面是建议写法，仓库里没有。

```js
// 一条轨道的节拍表：[起始全局帧, n]。切换帧尽量取 6 的倍数；不得已时以切换帧为锚重新起拍
const KUN_CADENCE = [[0, 3], [F_WAKE, 2], [F_PENG, 1]];
function heldFrame(f, table) {
  let anchor = table[0][0], n = table[0][1];
  for (const [s, m] of table) if (f >= s) { anchor = s; n = m; }
  return anchor + Math.floor((f - anchor) / n) * n;   // 切换后第一张画是完整的一拍
}
// 用法：const ts = heldFrame(f, KUN_CADENCE) / 24; kun.setPose(ts, …)
```

导演层面的提醒：

- **切换时机**：节拍切换本身是一个"事件"，放在动作的起点或静止处，不要放在动作中段——中段切换会让同一个动作前半截一拍三、后半截一拍一，读成"突然被快进"。
- **先例**：C 路线《追帽子》把采样率当叙事手段（散步 16 fps → 追逐 18 fps → 狂奔 24 fps；手摇采样与"速度就是情绪"来自 `$甲/styles/silent-film/STYLE.md:39-40`），并让每个节拍起点必定是一次采样，拍点上的姿势正好落在该帧（`cases/source/style-34-silent-film/TREATMENT.md:88,113`；`timeline.js:71-75`）；复算散步段在 24 fps 输出里的保持帧数是 2、1、2、1——手摇感来自不均匀，这是该风格要的，北冥不要。另一例：《一伞三景》（`cases/source/style-08-ukiyoe/main.js:377`）让撕纸"弹起"的前 0.25 秒一拍一，之后的飘动回到一拍三——快动作要密帧。
- **频闪风险**：化鹏是全片最快的动作（`docs/作品.md:72`），一拍一且没有运动模糊时，大幅快速运动在 24 fps 下会频闪。A 路线目前没有运动模糊或拖影帧【未实现】；C 路线有三种子帧累积的现成写法可参照（[two-five-d.md §3.3](two-five-d.md)，其中两段代码来自风格库甲的示例）；原生路线的运行时登记了运动模糊插件（`docs/raea/architecture.md:77`），但那是另一条执行面。

### 3.1 预备

【仓库实证】
- A：人物 0.42 s 手悬停、0.50 指腹才贴上镜腿（`src/girl.js:381-383`），这是接触前的预备停顿。镜头 C 的鲲在 6.2–8.0 秒从 4 缓到 80 m/s，片尾 8.4–10 秒再加 70 m/s，终速约 150 m/s（`src/shotC.js:91,94`），两段都没有反向预备。
- C：一拍甩出的关键帧表在拍点前一帧先反向 4%（`cases/source/style-25-dark-keynote/film.js:25-29`；`TREATMENT.md:145`）；《追帽子》起跑前下蹲 0.5 秒（`cases/source/style-34-silent-film/TREATMENT.md:49`）。

【通用工艺】预备的量取经验值：幅度约为主动作的 5–20%，时长约为主动作的四分之一到三分之一；越重的东西预备越长、越小。巨兽的预备不是"往后缩"，是质量的重新分配——提速前尾部先往下沉一拍，再把力传到头。

### 3.2 跟随与重叠：沿脊柱的相位差就是行波

【仓库实证】`engine/form/bend.js:2` 的弯曲公式：包络 `s = (半长 − x) / 全长`，头部为 0、往尾巴按 smoothstep 加大；相位 `2π·s·波数 − 角频率·t`。相位随 s 增大而落后，波从头传向尾——这就是"沿脊柱的相位差"。鲲的参数在 `src/kun.js:153`（幅度 15 m、波数 0.8、角频率 2π/5）。【复算】头尾相位差 288°；波从头传到尾 4 秒；周期 5 秒；尾端峰峰值约为体长的 5%。

其余几处同一个思想：
- 胸鳍根部用同一公式的 JS 镜像跟着脊柱弯（`src/kun.js:504-506`），自己按 6 秒周期划水，左右相差 0.35 弧度（`:507`）——与身体 5 秒周期错开，不同步、不机械。
- 海草：一项是随风后倒加慢摆，一项是相位里带 `−高度×2.4` 的侧摆，波从根传到梢，幅度按高度平方增长（`src/kun.js:371-379`）；每根海草有随机初相（`:365`）。
- 云丝：相位沿管长加 `aAlong·7`（`src/kun.js:555`）。
- 发丝：噪声自变量是 `u·wave[1] − t·f·wave[2]`，波从根传到梢，摆幅正比于 u，风越大发丝越长（`engine/paint/strand.js:5-7,20-21`）。
- 头与身体：呼吸让身体平移 4 mH，头只跟 0.8 倍（`src/girl.js:374,378-379`）——两部件相对错动，是最小的重叠。
- C 路线的停后余动：鸟落枝"收翼、身体下沉再回弹"（`cases/source/style-03-ink-wash/film.js:270-276`）；机构锁定时加速撞进去、再回弹 0.25 mm（`cases/source/style-60-teardown/src/motion.js:18-21`）。

【通用工艺】调参顺序：先定"从哪里传到哪里"（根→梢、头→尾），再定传播时间（越长越柔、越重），最后定幅度增长曲线（自由端最大）。传播时间接近一个周期时整条身体呈一个完整的 S，读起来最"游"；传播太快整条一起摆，像一块板。

### 3.3 缓入缓出：用对缓动

【仓库实证】`engine/core/math.js:12-17` 提供五种缓动：`ss`（三次 smoothstep）、`ss5`（五次，起止速度与加速度都为零，注释写明镜头推拉用它更柔）、`ei`（三次缓入）、`eo`（三次缓出）、`eio`。仓库里的分工：
- 镜头大摇移用 `ss5`，且两段摇移重叠 0.35 秒，镜头不会在两段之间停死（`src/shotC.js:31,156-157`）。
- 推镜"几乎匀速、尾部略收"：`u·(1.18 − 0.18u)`，切入时已在动，结束时速度降到约七成（`src/shotA.js:92`）。
- 揭开、落定用 `eo`：云墙 0.62 秒拉开（`src/shotC.js:67`）。（C 路线 `style-62` 的放大镜"拍点前 0.4 秒起步、快出缓停"那段代码，与 `$甲/styles/archive-lighttable/demo/film.js:124-129` 逐行相同，是上游示例的写法，见 [../SOURCES.md §3](../SOURCES.md)。）
- 离场用 `ei`：手放下时加速出画（`src/girl.js:383`；复算每拍位移 1→20→71→152→266→410 mH）。
- 抬手用 `ss`：起步慢、中段快、末端减速贴上（复算每拍位移 57→296→349→178→40 mH）。

【通用工艺】处处对称的 `ss` 就是"飘"。有重量的动作不对称：落地是加速撞进去（撞击帧速度最大），然后接停顿或回弹；离开是缓起；只有"要让观众看清的停点"才缓入。

【通用工艺】把"有重量"写成可检查的数，用**时距表**（spacing chart）：每个关键动作列出相邻两张之间的位移序列，序列的形状就是缓入缓出——两头小中间大是 `ss`，一头大一头小是 `eo`／`ei`，撞击是最后一格最大、随后归零或反弹。上面两条复算就是现成的时距表：抬手 57→296→349→178→40 mH，放手 1→20→71→152→266→410 mH。中割（两张关键姿势之间加的画）的位置决定节奏：二分是匀速，三分而靠近一端是缓入或缓出。写表演时先定关键姿势与张数，再写每格位移，最后才挑缓动函数。

### 3.4 关键姿势：关键帧表 + 单调插值

【仓库实证】`engine/core/math.js:33-55` 提供 Fritsch–Carlson 单调三次插值 `monotone(keys)`，注释写明适合镜头、速度、亮度这类不许回弹的曲线。**但 A 路线目前只把它用在造型轮廓上**（`engine/form/loft.js:22`；`src/kun_peng.js:60`；`src/kun_qinglv.js:107`），动作和镜头时间线都是 `seg` + 缓动分段（`src/girl.js:381-385`；`src/shotC.js:30-41`）。A 路线自己的 `monotone` 就够用（见下面的建议写法）。C 路线 `style-62` 那张按拍点写的相机关键帧表（单调三次插值、缩放在对数域插值），与 `$甲/styles/archive-lighttable/demo/film.js:19,95-98` 同构，属于上游示例的写法，不作本仓库模板。

为什么要单调：【复算】平台型关键帧 `[0,0] [1,1] [2,1] [3,0.2] [4,0.2]`，单调插值最大值 1.000、末段最小 0.200；均匀 Catmull-Rom 最大 1.113、末段最小 0.141——普通样条会在"停住"的两个关键帧之间自己冲出去再回来，这就是"漂"。

分段 `seg + ss` 的特点：每段两端速度为零。用于刻意的停点（手 0.42 秒悬停）是对的；连续动作被拆成多段就会一顿一顿。

【通用工艺】建议写法（A 路线未实现，可直接在新片里用 `monotone`）：

```js
import { monotone } from '../engine/core/math.js';
// 关键帧写成轨道帧号（一拍二轨道只用偶数帧），值是姿态参数
const HEAD_TILT = monotone([[0, -13.5], [36, -13.5], [54, -16.4], [60, -15.9], [144, -15.9]]); // 54 帧略过头，60 帧回落
const tilt = HEAD_TILT(heldFrame(localFrame, GIRL_CADENCE));   // heldFrame 见 §2.9（建议写法）；localFrame = 全局帧 − 镜头起点
// 多维姿态逐通道建表；缩放在对数域插值；角度先展开再插值
```

### 3.5 要"弹"的地方：故意过冲

单调插值不会超出关键帧的值，所以**过冲必须显式写出来**。仓库里三种写法：

1. **把过冲写进关键帧表**。【仓库实证】`cases/source/style-25-dark-keynote/film.js:25-30`：拍点前一帧 −4%（预备），拍点帧 8%，之后第 1 帧 18%、第 2 帧 30%（"前三帧只到 30%"），第 6 帧冲到 103.5%（过冲），落格前一帧 102%，b15 那一帧落定 100%。插值函数来自第三方风格库的公共模块（见 §9）。
2. **阻尼振荡**。【仓库实证】《追帽子》卡片末字回弹：位移 `−26·e^(−9u)·cos(26u)`、缩放 `1 + 0.12·e^(−10u)`（`cases/source/style-34-silent-film/film.js:41-47`）；逐字落定后再轻轻一沉 `7·e^(−14u)·sin(30u)`（`:49-58`）；《一伞三景》的撕纸弹过 90° 再回稳（`cases/source/style-08-ukiyoe/main.js:378`）。
3. **back 型缓动**。【仓库实证】`cases/source/style-25-dark-keynote/film.js:75,274,286`。

A 路线的 `engine/core/math.js` 没有 back 或阻尼弹簧类缓动，`src/` 里也没有用过过冲【未实现】。

【通用工艺】分寸：过冲幅度常用 3–10%，回弹 1–3 次快速衰减；越重越不弹——600 米的鲲不该"弹"，它的过冲是整体质量慢慢越过目标再回来，周期以秒计；字、卡片、小道具才弹得起来。

### 3.6 停顿与"活的停顿"

- **停帧 + 线在呼吸**。【仓库实证】一拍 n 本身就是停帧；手绘传统让停帧活着的办法是线条沸腾，仓库同样如此：屏幕墨线同一拍内不动、换拍整体沸腾一次（`engine/look/ink.js:2`），鲲身上画的线随墨线时钟"呼吸"（`src/kun.js:182-183`），颗粒每帧都换（`engine/look/index.js:137`）。
- **姿态里的微动**。【仓库实证】人物呼吸 3.3 秒一周期、±4 mH，复算在 1040 高的画面上约 ±2.8 像素；仰角另有 0.4° 微晃（`src/girl.js:374-376`）。镜头 C 的"头部微晃"小于 1°，用几条频率不成整数比的正弦相加，明确不做手持抖动（`src/shotC.js:35-38`）。
- **定格当叙事**。【仓库实证】《她的舞蹈导师》的镜头带定格区间，相机进度扣掉定格时长（`cases/source/ppt-dance-mentor/film/build.py:240-252`）。验收文档明确：一拍三角色不算静帧失败，刻意停顿要按分镜逐项豁免，不能放宽阈值掩盖卡帧（`docs/routes/validation-and-rtx.md:285`）。
- **静默是声音里的停顿**。【仓库实证】《追帽子》静默后的第一声是揭晓（`cases/source/style-34-silent-film/TREATMENT.md:35,65-67`）；发布会开场片把两处静默与之后的第一声写进声音表（`cases/source/keynote-C-kaitou/TREATMENT.md:123-147`）。"转折前给真静默、静默后的第一声专门选"这条规则本身改编自 `$甲/DIRECTOR.md` §6。

【通用工艺】一个停顿至少 6–8 帧才被"看见"；三维里完全静止的姿态会死，所以用 1–3% 幅度的慢漂移做"活的停顿"；但在一拍 n 的风格里，停帧 + 沸腾本身就是活的，不需要再给停帧加漂移——两样一起加，停顿反而不像停顿。

### 3.7 次级动作

【仓库实证】次级动作要被事件驱动：人物镜头里，暗影掠过时（0.8–1.15 秒）起一阵风，风让发丝变长、摆幅变大（`src/girl.js:450`；`engine/paint/strand.js:7,16,21`）；同一时段镜片倒影转成粉色天光（`src/girl.js:648-656`）。光尘是环境层，24 fps 平滑、不量化（`src/girl.js:23,609-627`）。

【通用工艺】次级动作的两条纪律：不和主动作抢——幅度和对比都低一档；有因果——由主动作或剧情事件触发，而不是永远同一个频率在摆。

### 3.8 弧线

【仓库实证】
- 巨兽：位置按"航向 × 速度"逐帧积分（`engine/stage/motion.js:4-5,16-22`），位移方向永远沿着鼻尖，不会横着"滑"；转身以身体后段为支点，头扭向远处时尾巴不会甩到镜头前（`src/shotC.js:92-102`）。
- 鸽群：抛物线轨迹，身体朝向跟速度方向（`src/birds.js:71-76`）。
- 手：x、y 由同一个 `rise` 驱动（`src/girl.js:385-389`），进场路径是一条斜直线，最后 40 mH 竖直贴上。

【通用工艺】手臂绕肩、肘转动，手的路径天然是弧。代码里最省事的办法：两个轴用不同的缓动（例如横向 `eo`、竖向 `ss`），路径自然弯成弧；或者在关节空间插值（转角度），不在屏幕空间插值（移位置）。

### 3.9 夸张与分寸

【仓库实证】北冥的基调是克制：默认固定机位或缓推，不变焦、不甩镜、不斜构图，情绪靠手、背影、侧脸（`docs/作品.md:69-71`）；鲲尾端峰峰值约 5% 体长、镜头微晃小于 1°、呼吸约 ±2.8 像素（§3.2、§3.6 复算）。夸张留给节奏：由慢到更慢，再突然爆发，化鹏最快（`docs/作品.md:72`）。C 路线的默片是另一极：两帧回头、险险擦过、跳帧追逐（`cases/source/style-34-silent-film/TREATMENT.md:48,53,61`）。

【通用工艺】克制的片子要给夸张做"预算"：一部 10 秒样片最多一两个夸张时刻；越克制的基调，那一次夸张越有力。鲸类真实游动的尾叶摆幅比 5% 体长大得多，鲲现在的幅度是被刻意压低的——这和"被困、钝"的定调一致，苏醒、化鹏时再逐步放开。

**尺度与时间**【通用工艺；起点值属【推断】】：越大的东西，同类动作的周期越长、起停越慢——尺度要靠时间来卖。重力主导的运动按弗劳德相似，时间随尺度的平方根放大（微缩模型拍摄按缩尺的平方根升格，就是这个道理）；游动不完全由重力主导，但作为观感上的起点值可以借用。以参照体换算：大型鲸约 25 m，游动周期是数秒量级；鲲约 600 m（`docs/作品.md:30`），600/25 ≈ 24，√24 ≈ 4.9，周期要拉到约 20–25 s 才像"一座岛在动"。【仓库实证】样片里鲲的行波周期是 5 s（`src/kun.js:153`：`uKunOmega = TAU/5`），尾端峰峰值约 5% 体长（§3.2）：只压低振幅，读得出"钝"，读不出"大"。如果为了让 10 秒样片看得见游动而不放慢，就把它写成有意的风格取舍，记进阐述的决定日志。眨眼、转头、起步同理要放慢（§4.1、§4.6）。

## 4. 表演

### 4.1 眼睛

**眨眼。**【仓库实证】`engine/form/eye.js:17-20`：每个周期开头 0.5 秒眨一下，闭合度依次 0.6 → 1 → 0.55 → 0.15 → 0，每档 0.125 秒。鲲一拍三取样后，每档正好是一张画（3 帧）：1 张半闭、1 张全闭、2 张睁开——快闭慢睁，睁眼最后一张只差一点点，是合格的收尾。【复算】镜头 C 第 153–164 帧逐帧闭合度：0.6×3、1×3、0.55×3、0.15×3。周期 4 秒，镜头 A 首次 1.5 秒、镜头 C 首次 2.375 秒（`src/kun.js:137,144`；`src/shotA.js:59`；`src/shotC.js:78`）。镜头 C 唯一的一次眨眼落在 6.375 秒（第 153 帧），紧跟在 6.3 秒转身开始之后（`src/shotC.js:90`）——眨眼标记"念头转换"，是表演上正确的位置；代码没有注明这是刻意安排。

【通用工艺】人眨一次眼量级是 0.1–0.4 秒；一拍二时常见 3–4 张（半闭、全闭、半睁、将睁）。鲲的 0.5 秒是动物量级的眨眼，读不出"大"；要显得大，可以放慢到 1–2 秒，并加长全闭的时间（§3.9）。眨眼不要做成严格周期——`autoBlink` 是严格周期的（`eye.js:18`），长镜头里会变成节拍器。眨眼挂在表演节点上：转头、换视线、切点之后、听到声音之后。

**注视。**【仓库实证】`poseEyes` 让眼珠转向世界坐标目标，偏航、俯仰各自限幅（`engine/form/eye.js:25,31-36`；鲲约 ±20°/±16°，`src/kun.js:138`）。高光固定在眼窝坐标，不随眼珠转（`eye.js:39-42`；`src/kun.js:129,512`）——这符合手绘惯例：眼神光跟着光源，不跟着瞳孔。眼睑边缘平面换算到眼珠坐标交给着色器，眼珠转动时被眼睑正确遮挡（`eye.js:43-45`）。

**扫视、眼睑跟随。**【未实现】注视是直接设到目标方向，没有扫视（快速跳到、轻微过冲、稳住），也没有扫视之间的微小跳动；眼睑只随闭合度转（`eye.js:27-28`），不随瞳孔上下跟随。

【通用工艺】
- 换视线是一次扫视：一拍一时 1–2 帧完成，一拍二时一张画；头比眼慢 4–8 帧跟上；大角度换视线常伴一次眨眼。
- 上眼睑跟着瞳孔上沿走：往下看时上睑一起下来，往上看时露出更多眼白——这是"活"的关键，比眨眼更重要。
- 长时间盯视时，每 0.5–1 秒给 1–2 像素的微跳，盯视就不会像玻璃眼珠。
- **在眨眼里换视线**：把视线切换放在全闭的那张画里，观众看不到跳变。对镜头 C 的具体建议：把 7.2 秒的视线释放挪进 6.375 秒眨眼的全闭帧（第 156–158 帧），或至少改用 `ts` 判断（§2.5）。

**"她"的眼睛。**【仓库实证】瞳孔固定在头部局部坐标（`src/girl.js:221,528-530`），2 秒镜头里没有眨眼和眼动；抬头只是头部仰角变化（`:375-376`）。2 秒不眨眼是自然的。但 `docs/routes/beiming-style.md:197` 的表演夹具要求"眼神先移，头部随后抬起"——目前的人物做不到眼先于头【未实现】。

### 4.2 手与接触点

【仓库实证】接触是"构造出来"的，不是"对准出来"的：
- 手的局部原点就是食指指尖（`src/girl.js:287`）；
- 手的矩阵挂在头部矩阵之下：`M.chain(head, translate(TOUCH_AT + 偏移), rotate)`（`src/girl.js:386-389`），偏移归零时指尖正好落在头部坐标的触点 `TOUCH_AT` 上（`:284`）——头怎么仰、怎么随呼吸起伏，指尖都粘在镜腿上。

接触要通过四条通道"卖"给观众，仓库都做了：

| 通道 | 做法 | 出处 |
|---|---|---|
| 位置锁定 | 父子化到头部 + 指尖原点 | `src/girl.js:284,287,386-389` |
| 压入 | 接触后指尖再压 4 mH | `src/girl.js:384-385` |
| 光 | 镜片内缘光 70 ms 亮起、0.5 s 回落到 42%；指尖染上镜片的青光 | `src/girl.js:630-634,692-695` |
| 声 | 3.55 s 轻"嗒"，3.6 s 极轻提示音 | `audio/cues.json:112,122` |

【复算】因果顺序：指尖第 84 帧贴上（拍号 42）→ 3.55 s（第 85.2 帧位置）"嗒"→ 内缘光第 86 帧首次可见（0.46）、第 87 帧满亮 → 3.6 s（第 86.4 帧位置）提示音。结果比原因晚 2 帧出现，读得出因果。注意压入实际持续 3 拍（§1.2）。

遮挡：手单独画在最上层的离屏画布上（`src/girl.js:588,674-701`），远侧镜框先画好再垫到脸后面（`:544-555`）——接触点上的前后关系由绘制顺序保证。

【未实现】通用接触求解或反向运动学；帧状态里的视线与左右手目标只是设计稿（`docs/routes/contracts.md:86`）。

【通用工艺】接触三拍：先到位（接触帧）→ 压入 1–2 张 → 回稳；离开时指尖"粘"一下再抬起。接触点一旦定下，任何上级部件动都不能让它滑——所以手要挂在被接触物的坐标系里，而不是挂在身体上再去追。

### 4.3 呼吸与重心

【仓库实证】
- 呼吸：3.3 秒一周期，±4 mH（复算 1040 高约 ±2.8 像素、2080 高约 ±5.7 像素），头只跟 0.8 倍（`src/girl.js:374,378-379`）。
- 巨兽的重心：转身以身体后段为支点（`src/shotC.js:98-102`）；航向与滚转都是缓动过渡（`:92-93`）；片尾加速远去（`:94`）。
- 渡船的重量：起伏 0.25 m、俯仰约 0.012 弧度（`src/shotA.js:116-117`），小而慢，读出"重"。

【通用工艺】胸像镜头里重心靠三件事读：吸气时胸先起、肩后起；动作停下时头比身体晚一点停（轻微过冲后回稳）；呼气时肩略沉。巨兽的重心靠支点选择和起停时间：支点越靠后越"推"，起停越慢越"重"。

### 4.4 Canvas 2D 人物：不重画形状也能表演

【仓库实证】`src/girl.js` 的做法可以抽成一套配方：

1. **形状只写一次**：全部是手工贝塞尔路径，单位 mH（头高的千分之一），在头部局部坐标里描（`src/girl.js:10-12,91-118`）。
2. **矩阵层级做大动作**：身体矩阵含呼吸平移；头部矩阵绕颈部转轴转仰角，并只跟 0.8 倍呼吸；手的矩阵挂在头部下面（`:369-391`）。
3. **点形变函数做软部件**：后脑头发底块用 `mapPath(路径, 矩阵, hairDeform)`，按区域权重决定自由度——越靠后、越靠下越自由，发梢最自由（`:419-428,491-492`）。
4. **程序化发簇**：每簇头发是沿方向积分出的中心线再收尖成轮廓，摆动波从根传到梢（`:416-417`；`engine/paint/strand.js`）。
5. **墨线每拍换形**：抖动种子是拍号，线宽随推镜平滑变化（`:411`）。
6. **光随形**：轮廓光、渗光每帧在变换后的路径上重算（`:467-504`），姿态一动，光自动跟着走。
7. **分层与遮挡**：远侧层垫到下面、主层、手层（`:447,544-555,676`）。
8. **锚点导出**：镜片、触点、鼻尖、下巴、耳朵的画面坐标交给合成、景深和声音对位（`:395-403`）。

局限：这不是通用二维骨架。形状本身变化的动作——换手型、张嘴、表情——需要另画姿态并做替换或插值【未实现】。仓库文档也明确"当前人物效果不证明已有通用骨骼表演系统"（`docs/routes/beiming-style.md:42,201`）；二维人物关键姿态与完整动作事件是 T07，状态 planned，验收要求"完整观看确认事件推进，非只有呼吸摆动"（`docs/routes/work-plan.json:224-248`）。

【通用工艺】往下扩展的三条路，按投入从小到大：
- **姿态库替换**：同一部件画几套形状（手型、嘴型、眉形），按拍号整张替换——最贴近手绘一拍二的质感；
- **兼容路径插值**：两套命令数相同的路径逐点插值，适合眨眼、嘴的开合这类连续变形；
- **剪纸骨架**：部件挂关节，加前后层级切换表，适合大幅转身。

### 5.2 选速度：每拍整帧

【复算】每拍帧数 = 帧率 × 60 / BPM：

| BPM | 24 fps 每拍 | 八分 | 十六分 | 30 fps 每拍 |
|---|---|---|---|---|
| 72 | 20 | 10 | 5 | 25 |
| 80 | 18 | 9 | 4.5 | 22.5 |
| 90 | 16 | 8 | 4 | 20 |
| 96 | 15 | 7.5 | 3.75 | 18.75 |
| 100 | 14.4 | 7.2 | 3.6 | 18 |
| 120 | 12 | 6 | 3 | 15 |
| 144 | 10 | 5 | 2.5 | 12.5 |

【仓库实证】
- 《追帽子》明写"所有拍点都是整帧：120 = 12 帧/拍，144 = 10 帧/拍，90 = 16 帧/拍"（`cases/source/style-34-silent-film/TREATMENT.md:75`；`timeline.js:2`）。
- 《她的舞蹈导师》90 BPM、24 fps（`cases/source/ppt-dance-mentor/film/build.py:18-19`）；《这条街照常过年》100 BPM 配 30 fps，每拍 18 帧（`cases/source/ppt-new-year-street/film/build.py:23-24`）。
- 外部生成的配乐要先测速再拉到网格：《她的舞蹈导师》测出各段 85.1–94.2 BPM（`cases/source/ppt-dance-mentor/音乐/beats.json`；测速方法 `tools/beats.py:1-2,18-31`），再"统一拉到 90 BPM 再对齐小节"（`film/build.py:4`）。
- **子拍也要看**：《十二秒》96 BPM 每拍 15 帧，但半拍 7.5 帧；【复算】48 个事件里 20 个落在两帧之间，最多要等 36 ms 才被画出来（`cases/source/style-62-archive-lighttable/events.json`；其核对脚本也报告这一项，`tools/cuecheck.py:37,48`）——画面晚于声音，正是 §5.7 说的不宜方向；按 §5.7 的量化规则，这类事件的画面结果帧应取 floor。24 fps 下 90 BPM 一路到 32 分音符（2 帧）都是整帧，是最"帧友好"的速度之一。

### 5.3 事件表：单一时间源

【仓库实证·正例】
- 《追帽子》：`timeline.js` 是唯一时间源，画面、配乐、拟音、拍点核对都读它（`cases/source/style-34-silent-film/timeline.js:1`）。
- 《十二秒》：每个关键动作写成拍号，导出 JSON 给配乐、拟音和核对脚本（`cases/source/style-62-archive-lighttable/timeline.js:1-4`）。"一份时间线驱动一切"的主张来自 `$甲/TECHNIQUE.md` §3；该片整体改编自上游示例（SOURCES §3），这里只引用它的时间轴写法。
- 《见龙》：画面动作的时刻从事件表取，规范原话的意思是"不要在 JS 里另写一个数"，这样声画同源、误差 0 帧（`cases/source/ppt-jianlong/jianlong/ARCH.md:69`）；标签的打字声与打字动画用同一个事件（`ARCH.md:89`）。

【仓库实证·反例】北冥样片的显示层时间表写在 `src/hud.js:49-57`（并被 `src/main.js:31` 改写），声音表在 `audio/cues.json` 里又各写了一遍（识别 5.45、未能识别 6.25、导航 7.0、片名 9.0）。目前数值一致，但描述已经漂移：画面 12 只鸽子、9/12 向右（`src/birds.js:15-16`），声音按 10 只、72% 向右合成（`audio/cues.json:73`；`audio/design.py:99-101`）；画面扑翼 7.9–9.9 Hz 被一拍二取样成 2–4 Hz 的视觉频率，声音扑翼 6.5–10 Hz（`audio/design.py:108`）。远景鸽群看不出问题，主角的动作就会。

【通用工艺·建议格式】A 路线没有节拍网格模块【未实现】，C 路线每部片各写一份。新片可用：

```js
// timeline.js：拍号是唯一输入，帧号由整数运算得到
export const FPS = 24, BPM = 90, FPB = FPS * 60 / BPM;            // 16
if (!Number.isInteger(FPB)) throw new Error('每拍帧数不是整数：换速度或帧率');
export const SECS = [['calm', 0, 12], ['wake', 12, 12], ['peng', 24, 9]];   // [段, 起拍, 拍数]
export const HITS = { touch: ['calm', 3], blink: ['wake', 0], cutC: ['wake', 6] };
export function hitFrame(name) {
  const [sec, b] = HITS[name], s = SECS.find(x => x[0] === sec), f = (s[1] + b) * FPB;
  if (!Number.isInteger(f)) throw new Error(`${name} 不落整帧`);
  return f;
}
// 导出 events.json：[{ id, frame, beat, type, … }]，画面、混音、字幕、核对都只读这一份
```

### 5.4 动作落强拍：拍点帧是结果帧

【仓库实证】
- 《Lumen》：落定后的回弹从拍点帧就开始，拍点帧已走约 35%（`cases/source/style-25-dark-keynote/film.js:75`）；另一处展开动作在拍点帧已达约 80%（`film.js:274`）；数字收起改为"提前一帧"，拍点帧已压扁约 80%（`TREATMENT.md:144`）。
- 《追帽子》：卡片上的字提前 3 帧（0.125 秒）从上方落下，正好在拍点上落稳（`cases/source/style-34-silent-film/film.js:49-58`；`TREATMENT.md:63`）；"帽子先跳走 3 帧，手才合上"——抓空的笑点在于手合上时帽子已经不在（`TREATMENT.md:57`）。散步段每拍一步木鱼，追逐段半拍一步（`TREATMENT.md:45,50`）。
- 《十二秒》的放大镜在拍点前 0.4 秒起步、快出缓停地落在 b4（`cases/source/style-62-archive-lighttable/TREATMENT.md:40,56`）；这段代码与 `$甲/styles/archive-lighttable/demo/film.js:124-129` 逐行相同，是上游示例的写法（SOURCES §3）。

【通用工艺】观众在声音响起的那一刻判断"打没打在点上"，所以拍点那一帧必须已经是结果：撞击、落定、字落稳。动作的提前量等于动作本身的时长——0.4 秒的落下就从拍点前 0.4 秒开始，3 帧的落字就从拍点前 3 帧开始。重音放在小节第一拍，次要动作放在弱拍；不要每拍都给动作，留出空拍让观众看。

### 5.5 切点

【仓库实证】
- 切点落在小节线或拍点：《她的舞蹈导师》的镜头表直接用小节号写起止（`cases/source/ppt-dance-mentor/film/build.py:446-470`），全片"每一刀都落在拍点上"（`:4`）；《追帽子》切到字幕卡时，第一个字随切点落定（`TREATMENT.md:62`）；《见龙》切点吸附到 0.5 秒（`时间表.md:1`）。
- 切点对齐动画时钟：样片切点都是 6 的倍数帧（§2.3）。
- 声音跨切点：《见龙》S04 段尾提前 1.1 秒、0.8 秒放进下一场的雨声（先闻其声再见其景，`cases/source/ppt-jianlong/jianlong/sfx/S04.json:3,11-12`）；北冥样片 B→C 是声画同时硬切，暗影的低频在 5.00 秒切掉、换成一口很宽的空气（`audio/cues.json:135,146`）。两种都对，取决于要"衔接"还是"打开"。
- 不硬切的转场：《见龙》要求上一段最后一帧与下一段第一帧完全一致，并用两张静帧并排自检（`cases/source/ppt-jianlong/jianlong/ARCH.md:122-125`）。

【通用工艺】动作中切（在动作进行中切到下一镜，运动方向连贯）比静止时切更顺；切点不要落在一拍 n 轨道的半拍中间；镜头长度要有变化，同一长度连切三次就开始拖。

### 5.6 字幕与旁白落拍

【仓库实证】
- 旁白起点写成（小节，拍）：《她的舞蹈导师》`VOAT` 表（`cases/source/ppt-dance-mentor/film/build.py:30-35`）。
- 字幕跟声音：按字数比例切块，比开口提前 80 ms 淡入、结束后 120 ms 淡出（`build.py:577-598`）；《见龙》按逐字时间戳切成每行不超过 18 字（`cases/source/ppt-jianlong/制作规范.md:94`），少数短于 1.8 秒的字幕是"下一句紧接着开口"造成的（`jianlong/ARCH.md:261`）。
- 画内字逐拍落定：《追帽子》卡 1 的"顶、帽、子"各落在一拍上（`cases/source/style-34-silent-film/TREATMENT.md:63`）。
- 冲击帧对字：《见龙》S04 的"要"字。【复算】旁白起点 35.344 + 字内 4.667 = 40.011 s，事件 34.5 + 5.511 = 40.011 s，差 0 ms（30 fps 下第 1200.33 帧位置；逐字数据 `jianlong/data/words.json`，事件 `sfx/S04.json:10`）。`ARCH.md:256` 写明该段脚本会校验二者相差不超过 1 帧、否则渲染报错；但分段脚本没有归档（目录文件表 322 项里没有 `src/segs`），这条断言无法在仓库内复核。
- 爆发放进旁白的停顿：S18 的爆发落在前一句结束后 0.24–0.30 秒、下一句开口前 0.49–0.58 秒（`ARCH.md:259`）。
- 阅读时长有检查，并真的判过不合格（`ARCH.md:279`）。

【通用工艺】有旁白时字幕跟着声音起止（开口前后一两帧内出现）；没有旁白时画内字跟着拍点落；字幕尽量不跨切点，必须跨就整句跨过去，不在切点前后几帧内起止。

### 5.7 核对

【仓库实证】
- 《十二秒》的核对脚本逐个事件比较四项：音乐网格、24 fps 画格、成片音频的实测起音、同一时刻是否有乐谱音符；网格偏差超过 0.5 ms 或起音超过 12 ms 即失败（`cases/source/style-62-archive-lighttable/tools/cuecheck.py:1-6,52`）。用法：`python -I tools/cuecheck.py <项目目录>`。它用的是对称窗口；本规范改用下面的不对称窗口。
- 《见龙》用成片音轨与旁白做互相关核对落位，全部偏 +2 ms（AAC 编码延迟）（`jianlong/ARCH.md:269`）。
- 北冥样片的声音自检只查响度、频段、切点爆音（`audio/check.py:49-59`），不查声画对位【未实现】。
- 验收文档要求切点和分段边界前后至少 3 帧、起点/峰值/终点帧加带声片段（`docs/routes/validation-and-rtx.md:321-322`）；"动作事件用全局时码对齐声音，最终对 AAC 复测"（`docs/routes/beiming-style.md:46`）。

**同步容差表**（DIRECTING 步骤 7、PRODUCTION-SPEC §4 与 §11 只引用这一处）【通用工艺；依据见 [../SOURCES.md §2.3](../SOURCES.md)】：声画不同步的容忍度不对称，声音超前比滞后更容易被察觉，所以宁可画面结果帧在前、声音在后。

| 层 | 规则 |
|---|---|
| 数据 | 事件帧号与声音时刻同源（同一份事件表），偏差为 0 |
| 量化 | 拍点不落整帧时，画面结果帧取 floor（画面先到），声音留在网格原位；这样误差只可能是"声音比画面晚不到 1 帧" |
| 成片实测（以最终 AAC 为准） | 声音晚于结果帧 0–1 帧可以接受；早于结果帧不超过约 0.25 帧（24 fps 下约 10 ms）；口型类声音可以比口型晚 1–2 帧（口型先到） |
| 参考阈 | ITU-R BT.1359 的可察觉阈：声音超前约 45 ms、滞后约 125 ms；EBU R37 的端到端容差：+40／−60 ms。生产环节要给播放链留余量，所以上一行比察觉阈严 |

AAC 编码本身会带来固定的小延迟：《见龙》的互相关核对全部偏 +2 ms（`jianlong/ARCH.md:269`），核对时先扣掉这一项。

## 7. 开工与验收清单（给 agent）

开工：
1. 写节拍轨道表：每个对象一个 n（1/2/3），写进镜头文件头注释和事件表；着色器时间也按轨道分。
2. 定帧率与速度：每拍整帧；需要子拍落帧就选 90 BPM @ 24 fps 这类速度；输出帧率与 `film.run` 的 fps 一致。
3. 先写事件表（单一来源），再写动画；画面、混音、字幕、核对都只读它。
4. 关键姿势先写表：整数帧（落在轨道画格上）+ `monotone`；要弹就写过冲关键帧。
5. 切点和节拍切换放在公倍数帧；量化对象的条件判断只用拍号。

验收：
1. 确定性：单帧、乱序、顺序三种渲染逐帧一致（`docs/routes/validation-and-rtx.md:193-196`）。
2. 拍内无跳变：同一拍号内该轨道姿态不变【未实现：没有现成脚本，可按每帧姿态哈希比较】。
3. 周期动作频率 ≤ fps/(2n)；每拍屏幕位移不过大。
4. 联系表：`node engine/render/still.mjs . --range 起:止:0.5 --out out/stills`（`build.sh:20`），关键动作用 0.2 秒步长；切点前后 3 帧逐帧看。
5. 有音乐时跑对位核对（C 路线 `tools/cuecheck.py` 可参照），按 §5.7 的容差表判定；agent 交代理审片证据，全速带声的完整观看由人做（DIRECTING 步骤 10）。
6. 状态三分离：已输出、技术通过、用户认可分开记录（`docs/TRACKS.md:57`）。

自测入口：`index.html?test=<名字>` 加载 `lab/<名字>.js`（`src/boot.js:1-5`）；`lab/kun_peng.js:5-6` 的 `wt=` / `bt=` 可以单独冻结翅膀或身体时钟调姿态；`lab/look.js:9,271` 的 `still=1` 固定镜头只看沸腾和停帧。C 路线案例先 `python3 tools/casebook.py restore <id>` 还原到独立工作区（`AGENTS.md:57`）。

## 附录 A：复算方法

本章标"复算"的数字来自两个只读探针脚本（放在本次研究工作目录 `<研究工作区>/anim-probe/probe.mjs`、`probe2.mjs`，未入库），只导入 `engine/core/clock.js`、`engine/core/math.js` 这类纯函数模块，或逐行照抄源码里的公式，不渲染、不写仓库。关键几段可以直接在仓库根用 `node --input-type=module -e` 重跑：

```js
// ① 浮点量化 vs 整数量化（10 分钟）
import { tick } from './engine/core/clock.js';
let a = 0, b = 0, acc = 0;
for (let f = 0; f < 14400; f++) {
  const t = f / 24;
  if (f >= 72 && Math.floor((t - 3) * 12) !== Math.floor((f - 72) / 2)) a++;
  if (Math.floor(acc * 8) !== Math.floor(f / 3)) b++;
  acc += 1 / 24;
}
console.log({ 局部时间错拍: a, 累加时间错拍: b });   // 12, 1638

// ② 人物压入实际覆盖的拍（src/girl.js:78,384）
const q12 = t => Math.floor(t * 12 + 1e-6) / 12, fr = [];
for (let f = 72; f < 120; f++) { const tq = q12(f / 24 - 3); if (tq >= 0.5 && tq < 0.67) fr.push(f); }
console.log(fr);                                    // [84..89]，三拍

// ③ 镜头 C 视线释放与一拍三（src/shotC.js:165,168）
for (let f = 170; f <= 175; f++) console.log(f, Math.floor(f / 3) * 3 / 24, f / 24 < 7.2 ? '看镜头' : '松开');
```
