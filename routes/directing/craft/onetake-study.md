# OneTake 技术考察：连续承接怎样进入制作和验收

考察对象为 `feitangyuan/onetake` 的提交 `4e024be4c6c696b260f39a35aee6bd56d303b679`。文章中的「文档」指 README、SKILL 和案例记录的说法，「源码」指该提交的可执行行为，「实测」指本轮的浏览器、编码或解码取证，「推断」指从这些证据外推的制作判断。北冥的可执行入口是 [C 路线](../../c-style/README.md)、[长镜头工艺](continuous-take.md)和[《校准环》的复现实验](../../../films/calibration-ring/ONETAKE-LAB.md)。

## 从参考片到看片，哪些数据真的相通

1. **参考片先给问题。** `analyze_ref.py` 把成片重采样到 12 fps、320 px 宽，算相邻灰度帧的平均绝对差。差值 <0.5 算静止，<2 算低动作，>18 是疑似切点，1.5 s 内至少三次 >8 是 burst。四秒一行的字符图定位节奏区，4 fps 联系表和另取的九张帧用来辨认究竟是剪辑、曝光还是运动。第一帧差为零。OpenCV 可选，DIS 光流常用 30 fps 并按 1920 宽归一，低帧率源按自身帧率取样后再归一速度；快速帧的沿运动/垂直方向梯度能量比 <0.78 是模糊提示。两种输出都只看画面，既无物体身份，也无法区分推镜、灯变和剪辑；大面积移动会触发切点候选，小主体快动可能近乎静止。 [scripts/analyze_ref.py:35–123](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/analyze_ref.py#L35-L123)  [scripts/analyze_ref.py:125–151](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/analyze_ref.py#L125-L151)
2. **概念和节拍表靠作者接线。** 上游方法要求三个真正不同的画面构想，选一个后写「哪一拍、谁动、谁静、谁跨到下一拍」。源代码没有把参考数据自动转成关键帧。先用缩略图找出被看见的动作原因，再给有意保留的对比标时间范围，最后才填镜头和曲线。文档中的 4 倍镜头长短差、约 1/3 静止、70% 留白来自特定产品片语法。它们适合有爆发段、阅读段的宣传片做起点，稳定观察或持续运镜的题材应从实际观看目标出发。北冥把结构写进阐述，把可执行的时间写进 `film.json`。 [SKILL.md:41–88](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/SKILL.md#L41-L88)  [SKILL.md:199–214](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/SKILL.md#L199-L214) [北冥导演流程](../DIRECTING.md#1-十步总览) [作品时间](../../../engine/production/README.md#2-时间)
3. **合成把时间变成图像与观测。** 模板以一条手部样条驱动画内组件和指针，`__ready` 等字体、量字、预计算模拟并首绘，`__seek` 改 DOM/CSS/Canvas 并等素材。截图序列和同轴声音在 FFmpeg 汇合。探针从页面另采一遍轨迹；机器验收将页面轨迹、编码成片能量和音频读数并列，未校验它们是否来自同一次构建。作者应把版本、参数与媒体一起记下。模板前段做的是 motion-web 的特定故事，且用示例录制帧与手势路径；其价值在同一原因驱动多种响应。 [templates/comp.html:93–122](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/templates/comp.html#L93-L122)  [templates/comp.html:135–173](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/templates/comp.html#L135-L173)  [templates/comp.html:197–237](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/templates/comp.html#L197-L237)  [scripts/verify_promo.py:57–121](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/verify_promo.py#L57-L121)
4. **最后回到观看。** 上游的拒稿记录里，换成全画幅素材仍败在均匀节奏，节奏过关的 Pocket Weather 早版仍败在每拍替换上一拍。模板故事被照搬的一版甚至拿到 carry 1.00。北冥自动或人工审片流程由作品交付模式决定，成片的用户认可仍需要全速带声看完并记录原话。 [references/rhythm.md:10–55](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/references/rhythm.md#L10-L55)  [references/rhythm.md:58–101](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/references/rhythm.md#L58-L101)  [SKILL.md:68–74](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/SKILL.md#L68-L74) [北冥闸门与状态](../../../engine/production/README.md#4-创作闸门与状态) [人工评分](../../../docs/quality/RUBRIC.md)

## carry score 的计量口径

- **先找替换再问谁承接。** 采样默认 30 fps，页面先 seek 后 track。每帧按 ID 建表，每项权重是 `可见盒面积 × opacity ÷ 视口面积`。同 ID 且 key 相同贡献两帧权重的 min 到交集、max 到并集；变 ID 或变 key 只计两边并集。这个 Jaccard 没有坐标交并，分母为 0 时返回 1。内容总权重 <0.004 的首端跳过，末端不足则从 0.4 s 窗末向前推进到有内容的样本（最多约 1.5 s）。J<0.2 的相交窗口合并，取最低 J 的首末样本，平局保留较早窗口。报告时刻取两采样中点，`--from` 非零时该时刻按相对样本序号计算，和原片绝对时间会错开，复核应读原采样或使用整片起点。 [scripts/probe.py:147–165](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/probe.py#L147-L165)  [scripts/probe.py:182–245](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/probe.py#L182-L245)
- **查同一个 ID 的首末状态。** 两端 opacity 各 ≥0.15 才参与。中心跨 ≥视口对角线的 2%，或面积开根后的尺度对数比绝对值 ≥0.1，就算 carried，此处分支没有再次要求 key 相同。在 1080p 横片前者约为 44 px。若未达到移动/缩放线，同 key 且较小端面积仍 ≥画面的 3%，就只是 anchored。没有两者时是 bare。一个无关的大装饰位移也可能算 carried；缓慢传递、细小主体经遮挡或跨画法更换 ID，可能被列为 bare。 [scripts/probe.py:241–260](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/probe.py#L241-L260)
- **排除项决定分母。** 相邻样本两侧都有内容且 J<0.3 时记候选切点，间隔 ≤0.6 s 串成组，至少三次才作 burst 并向两侧扩 0.25 s。这个分组会链式拉长，和归纳亮度的 1.5 s 窗是两套检测。若事件中点落在该组、最后 1.2 s 或声明 cuts 的 ±0.25 s 内，就不入均值。carried/anchored/bare 分别记 1/0.5/0，未豁免事件等权；零事件返回 1.00。验收对四舍五入到两位的分数执行 <0.50 FAIL、<0.70 WARN。分数应随事件数、豁免及每个窗口的证据一起读。 [scripts/probe.py:203–270](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/probe.py#L203-L270)  [scripts/verify_promo.py:80–86](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/verify_promo.py#L80-L86)
- **速度是另一条线。** probe 从同 ID 的连贯轨迹算 `中心位移 + 0.5×线性尺寸变化`，归一到 1920 宽；孤立的 >60 px 步且两邻步各 <它的 10% 会被清零。默认至少 4 步且路径 ≥30 px 才算一个动作，速度门在峰值 >80 px/帧且无快门证据时失败，t80 和 soft share 只提示。t80 是达到总路径 80% 占自身动作时长的比例，和编解码光流口径不同。光流的遮挡与亮度变化、轨迹的身份跳变会影响两边。 [scripts/probe.py:274–350](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/probe.py#L274-L350)  [scripts/verify_promo.py:87–107](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/verify_promo.py#L87-L107)

**实测。** 以同一条匀速白圆为对照，仅换 ID 时 120 帧的解码 RGB 完全相同，carry 从 1.00 变成 0.00，报告 1.80 s；真实的编号切换在 2.00 s。只让圆在交接瞬移 240 px 并保持 ID，解码第 59→60 帧实测 243 px，carry 仍为 1.00、峰值仍报 9 px/帧（归一后），第 60→61 帧恢复 3 px。它同时触发了「稳定身份不启动替换事件」和「曲线去除孤立跳步」两个盲点。北冥按预先登记的交接帧看轮廓及相邻位移、再读 `visual.jumps`。分数只定位值得复查的窗口。 [实测、图表与命令](../../../films/calibration-ring/ONETAKE-LAB.md) [北冥画面检查](../../../docs/quality/QA-GATE.md#42-visual画面异常一次解码缩到--480-宽的亮度流按标签换算成观众看到的-0255)

## 把相机、动作和剪辑分开诊断

- **相机决定观众眼前的轨迹。** 源码的 `camera` 插值 x/y、zoom 与角度，`view` 给出绕视点的 2D 仿射矩阵，深度只是视差参数；`projectBox` 变换四角后取屏幕 AABB，`screenTravel` 还包含中心位移、缩放和旋转边缘扫过的量。三维应走 `P·V·M` 和透视除法后映射到屏幕，检查在前方的有效投影点、轮廓和遮挡；不能把 3D 世界单位送去当 px，也别用两个盒子相交证明可识别。《校准环》在同一缺口轮廓上同时绑定投影中心、尺寸与转角，后续才让俯仰和侧壁出现。核对前后至少各两帧，再关掉相机漂移、固定物体或分别导出两条轨迹，区分构图变化来自谁。 [lib/motion.js:344–413](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/lib/motion.js#L344-L413)  [references/composition.md:130–185](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/references/composition.md#L130-L185) [《校准环》的投影实现](../../../films/calibration-ring/film.js#L155-L201)

## 浏览器渲染、快门与确定性

**源码。** 180° 的曝光长度是半帧（30 fps 为 1/60 s）。render 在全片时刻 `f/fps` 两侧排均匀子区间的中点，首末夹到 `[0, dur−1e−6]`；先 seek 最早和最晚样本，再倒回取中间样本。自适应数为 `ceil(travel × deviceScale / gap)` 夹在 4–48，gap 默认 6 设备像素。大运动达到上限时仍会离散，固定 count 也不会在输出改成 4K 时自动增大。端点 PNG 字节相同就直接写第一张，曝光内发生后复原的动画会被跳过。 [scripts/render.py:120–150](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/render.py#L120-L150)  [scripts/render.py:187–217](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/render.py#L187-L217)

当至少四张子样本时，灰度缩小 8 倍后的相邻平均绝对差若有一个非零峰 ≥其余峰的三倍，只合成包含帧时刻的那一侧（跨中心时选后一侧）。这是像素启发式，未读取 `__meta.cuts`；闪白、液晶跳字、单一运动高峰可能被当作硬切，等亮度换色、局部切换或多个跌跳则可能漏掉。保留的截图 RGB 经 sRGB 查表转线性、等权平均，再查表回 sRGB。它积分的是已经绘好和合成过的 8-bit 像素，不能恢复渲染前的 HDR 或材质层。FFmpeg 做 BT.709 矩阵、有限范围和 yuv420p 转换，`setparams` 写原色、传递、矩阵和范围标记；该行没有单列 sRGB 到 BT.709 OETF 的重编码。声音给定才 mux AAC，`-shortest` 可因短音轨缩短视频，sidecar 帧数仍是计划渲染数。 [scripts/render.py:43–95](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/render.py#L43-L95)  [scripts/render.py:225–246](https://github.com/feitangyuan/onetake/blob/4e024be4c6c696b260f39a35aee6bd56d303b679/scripts/render.py#L225-L246)

## 给北冥作者的操作顺序

1. **新片**用 `npm run new -- c <作品名> --title <片名>`，既有片先存一次同规格原版。选一处最容易迷失主体、看不清反馈或感觉声音落后的交接，写下首帧、下一拍和应留存的识别线索。现有片修真实切点用 `retime`，留在同一镜头内的变化登记事件。
2. **先出关键帧。** 制作联系表包含交接前两帧、边界帧、后两帧和结果帧。记录主体投影中心、外接尺寸、方向、运动速度变化，并把没检出的取样列出来。若为 2D→3D，用同一特征点在两空间投影，处理视场角、景深/遮挡后才做局部速度。锚点稳定但画面仍难读时，核对能否从上一拍动作预见下一拍。
3. **再出动态预演和声音。** 对照上一版整段单次改一个变量：跟随目标、轨迹曲线、节拍留白、曝光或声音起音。动作交接先去声看因果，再带临时声音核对发布结果；拟音按作者的事件帧，以 AAC 解码复核。高运动才按同尺度对比快门，随机回跳不稳先缩到一个镜头并拿单 worker 基线。
4. **最终验证。** 跑 `film -- build` 与机器 QA，比较实际编码帧、位移/时间证据和视觉提示。给审片人同一时间码、A/B 版本、要回答的问题（原因、目标、结果、听见什么），请其全速带声完整看完并依北冥规则记原话。 [C 路线入口](../../c-style/README.md#最快上手) [《校准环》片源与复现](../../../films/calibration-ring/README.md) [人评口径](../../../docs/quality/RUBRIC.md)
